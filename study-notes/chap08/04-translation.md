## 4-1. 평행 이동이란: 공식과 비유

### 4-1-a. 비유: 창문 너머로 사진 밀기

**창틀(목적 영상)은 벽에 고정**돼 있고, 그 뒤에 있는 **사진(원본)을 손으로 민다**고 상상해 보세요.

```
      처음                              사진을 오른쪽 아래로 밈
 ┌─────────────┐  ← 창틀(고정)          ┌─────────────┐
 │ 사진        │                        │░░░░░░░░░░░░░│ ← 빈 곳 (검정)
 │  🐱         │                        │░░┌──────────┤
 │             │                        │░░│ 사진      │
 │             │                        │░░│  🐱       │
 └─────────────┘                        └──┴──────────┘ → 오른쪽·아래 끝은
                                                          창틀 밖으로 잘려 나감
```

사진을 밀면 **두 가지 일**이 동시에 일어나요.
- 미는 방향 쪽 끝은 창틀 밖으로 나가서 **잘려요.**
- 반대쪽에는 사진이 없는 **빈 곳**이 생겨서 검정(0)으로 보여요.

Part 0-1-b에서 오른쪽으로 1칸 옮겼을 때 `40, 80, 120`이 사라지고 왼쪽 첫 열이 0이 됐던 게 바로 이거예요.

### 4-1-b. 공식

```
순방향 (원본 → 목적):    x' = x + tx       y' = y + ty
역방향 (목적 → 원본):    x  = x' − tx      y  = y' − ty
```

| 기호 | 뜻 | 부호 |
|---|---|---|
| `tx` | 가로 이동량 | **+ 오른쪽**, − 왼쪽 |
| `ty` | 세로 이동량 | **+ 아래쪽** ⚠️, − 위쪽 |

> ⚠️ Part 0-2에서 본 것처럼 이미지 좌표계는 **y가 아래로** 커져요. 그래서 `ty = +80`은 "**아래로** 80"이에요. 수학 시간 감각("+는 위")과 반대니까 주의하세요.

크기 변경과 비교하면 **곱셈(×ratio) 자리에 덧셈(+t)**이 들어갔을 뿐이에요. 역공식도 나눗셈 대신 **뺄셈**이에요.

## 4-2. 역방향 + 범위 검사: 상황 ⓒ 처리하기

### 4-2-a. 왜 역방향인가

이번에도 **목적 영상의 모든 칸을 돌면서** "나는 원본 어디서 왔지?"라고 물어요. 목적 `(i, j)`의 원본 위치는:
```
x = j − tx
y = i − ty
```

### 4-2-b. 원본 밖을 가리키면?

`tx = 30`이면 목적의 `j = 0`(맨 왼쪽 열)은 원본 `x = 0 − 30 = −30`에서 와야 해요. **그런 열은 없어요.** 이게 Part 0의 **상황 ⓒ**예요.

> ⚠️ **파이썬의 함정**: 원본 밖이면 numpy가 에러를 내 줄 것 같지만, 음수 인덱스는 에러가 아니에요!
> ```
> img[0, -30]   →  에러 없음! 오른쪽 끝에서 30번째 열을 읽음
> ```
> 그래서 검사를 안 하면 빈 곳이 검정이 아니라 **반대편 끝의 그림**으로 채워지는 이상한 결과가 나와요(그림이 한 바퀴 감기는 효과). 반대로 `img[400, 0]`처럼 너무 큰 인덱스는 IndexError가 나요. 둘 다 막으려면 직접 검사해야 해요.

### 4-2-c. `contain()`: 범위 검사 함수

```python
def contain(p, shape):              # p = (y, x) 순서!
    return 0 <= p[0] < shape[0] and 0 <= p[1] < shape[1]
```

| 조건 | 뜻 |
|---|---|
| `0 <= p[0] < shape[0]` | y가 0 이상, 높이 미만 |
| `0 <= p[1] < shape[1]` | x가 0 이상, 너비 미만 |

`shape`가 (h, w) 순서라서 `p`도 **(y, x) 순서**로 넘겨야 짝이 맞아요(Part 0-2-e의 규칙).

**translate.jpg (380, 300)에서 실제로 넣어 보면:**

| p = (y, x) | 0≤y<380 | 0≤x<300 | 결과 |
|---|---|---|---|
| (100, 50) | ✅ | ✅ | `True` → 원본 값을 가져옴 |
| (−80, 50) | ❌ | ✅ | `False` → 0으로 둠 |
| (100, −30) | ✅ | ❌ | `False` |
| (379, 299) | ✅ | ✅ | `True` (마지막 화소) |
| (380, 0) | ❌ (380은 미만이 아님) | ✅ | `False` |

`False`면 아무것도 안 하고 넘어가요. `dst`가 처음에 `np.zeros`로 만들어졌으니 그 자리는 **0(검정)**으로 남아요.

## 4-3. 5×5로 끝까지 따라가기

### 4-3-a. 오른쪽 2, 아래 1 이동: `translate(a, (2, 1))`

```
원본 a (5×5)
       x=0  x=1  x=2  x=3  x=4
y=0  [   1    2    3    4    5 ]
y=1  [  11   12   13   14   15 ]
y=2  [  21   22   23   24   25 ]
y=3  [  31   32   33   34   35 ]
y=4  [  41   42   43   44   45 ]
```

**목적 칸 몇 개를 골라서 역방향으로 물어보기** (`x = j − 2`, `y = i − 1`)

| 목적 (i, j) | x = j − 2 | y = i − 1 | contain((y, x))? | dst[i, j] |
|---|---|---|---|---|
| (0, 0) | −2 | −1 | ❌ | 0 |
| (0, 3) | 1 | −1 | ❌ (y가 음수) | 0 |
| (1, 1) | −1 | 0 | ❌ (x가 음수) | 0 |
| (1, 2) | 0 | 0 | ✅ | a[0, 0] = **1** |
| (2, 4) | 2 | 1 | ✅ | a[1, 2] = **13** |
| (4, 4) | 2 | 3 | ✅ | a[3, 2] = **33** |

**실행 결과**
```
목적 (5×5)
       j=0  j=1  j=2  j=3  j=4
i=0  [   0    0    0    0    0 ]     ← 위 1줄: 빈 곳 (ty=1)
i=1  [   0    0    1    2    3 ]
i=2  [   0    0   11   12   13 ]
i=3  [   0    0   21   22   23 ]
i=4  [   0    0   31   32   33 ]
       └─ 왼쪽 2열: 빈 곳 (tx=2)

잘려 나간 원본: 오른쪽 2열 (4, 5, 14, 15, …), 아래 1줄 (41~45)
```
원본의 **1**이 (0, 0)에서 (1, 2)로, 오른쪽으로 2칸, 아래로 1칸 갔어요. ✅

### 4-3-b. 반대로 왼쪽 2, 위 1 이동: `translate(a, (-2, -1))`

역공식은 `x = j + 2`, `y = i + 1`이에요(음수를 빼면 더하기).

```
       j=0  j=1  j=2  j=3  j=4
i=0  [  13   14   15    0    0 ]
i=1  [  23   24   25    0    0 ]
i=2  [  33   34   35    0    0 ]
i=3  [  43   44   45    0    0 ]
i=4  [   0    0    0    0    0 ]     ← 아래 1줄: 빈 곳
                       └─ 오른쪽 2열: 빈 곳
```
목적 `(0, 0)`은 원본 `(y=1, x=2)` = **13**이에요. 이번엔 **왼쪽 위가 잘리고 오른쪽 아래가 비어요.** 빈 곳은 항상 **이동 방향의 반대편**에 생겨요.

## 4-4. `translate` 코드 해부

```python
def translate(img, pt):
    dst = np.zeros(img.shape, img.dtype)            # ① 원본과 같은 크기의 검은 캔버스
    for i in range(img.shape[0]):                   # ② 목적의 모든 행
        for j in range(img.shape[1]):               # ② 목적의 모든 열   → 역방향 사상
            x, y = np.subtract((j, i), pt)          # ③ 역공식
            if contain((y, x), img.shape):          # ④ 범위 검사
                dst[i, j] = img[y, x]               # ⑤ 원본 값 복사
    return dst
```

| 줄 | 하는 일 | 포인트 |
|---|---|---|
| ① | 결과 캔버스 | **원본과 같은 크기.** 창틀이 고정돼 있어서 잘림과 빈 곳이 생겨요 |
| ② | 목적을 돎 | 역방향 사상이에요 (Part 2와 같은 구조) |
| ③ | `(j, i) − (tx, ty)` | 아래 4-4-a에서 자세히 |
| ④ | 범위 밖이면 건너뜀 | 상황 ⓒ 처리 |
| ⑤ | 값 복사 | **보간 없음!** 이유는 4-6에서 |

### 4-4-a. ③ 한 줄에서 일어나는 순서 전환 (Part 0-2-e 복습)

```python
x, y = np.subtract((j, i), pt)
```
`pt = (30, 80)`, 목적 `(i=100, j=50)`일 때:

```
(j, i)              = (50, 100)        ← (x', y') 순서로 묶음. pt가 (tx, ty) 순서니까 맞춤
np.subtract(…, pt)  = (50−30, 100−80)
                    = (20, 20)
x, y                = 20, 20           ← 원본 좌표
```

그다음 줄들:
```
contain((y, x), img.shape)   ← (20, 20): shape (380, 300)과 맞추려고 (y, x) 순서
img[y, x]                    ← numpy 인덱싱이니 [y, x]
```

**한 화소를 처리하면서 순서를 세 번 바꿔요.** (x, y) → (y, x) → [y, x]. 헷갈리면 이렇게 기억하세요. **"짝이 (x, y)면 (x, y)로, 짝이 shape나 numpy면 (y, x)로."**

> 📝 `Common/interpolation.py`의 `translate`는 같은 일을 이렇게 풀어 써요. 이쪽이 더 읽기 쉬워요.
> ```python
> x = j - pt[0]      # 좌표는 x, y 순서
> y = i - pt[1]
> ```

> 📝 `np.subtract`의 결과는 `numpy.int64`라서 바로 인덱스로 쓸 수 있어요. 크기 변경 때처럼 `int()` 변환이 필요 없는 이유는 4-6에서 볼게요.

### 4-4-b. 메인 코드의 혼란스러운 창 제목

```python
dst1 = translate(image, (30, 80))                     # x로 30, y로 80
cv2.imshow("dst1: trans to (80, 30)", dst1)           # 제목은 (80, 30)??
```
호출은 `(x=30, y=80)`인데 창 제목은 `(80, 30)`이라 **(y, x) 순서**로 적혀 있어요. 틀린 건 아니지만 순서를 섞어 써서 헷갈려요. **실제로는 오른쪽으로 30, 아래로 80**이에요.

## 4-6. 정수 이동 vs 소수 이동: 보간은 언제 필요할까?

### 4-6-a. 정수 이동이면 보간이 필요 없어요

```
x = j − tx
   정수 − 정수 = 정수
```
`tx`, `ty`가 정수면 역공식 결과도 **항상 정수**예요. 원본의 **정확한 화소 위치**를 가리키니까 고를 필요도(최근접), 섞을 필요도(양선형) 없어요. 그래서 ⑤에서 그냥 `img[y, x]`를 복사해요.

**덤으로 정수 이동은 순방향으로 해도 구멍이 안 생겨요.** 원본 화소 하나가 목적 화소 하나에 **정확히 1:1로** 대응하기 때문이에요(겹침도 구멍도 없음). 그래도 역방향으로 짠 이유는 회전이나 어파인처럼 1:1이 깨지는 변환에도 **같은 틀을 그대로 쓰기 위해서**예요.

### 4-6-b. 소수 이동이면?

0.5칸만 옮기고 싶다면 `x = j − 0.5`가 돼서 다시 **소수 좌표**가 나와요. Part 2~3의 보간이 필요해요. 1×6 줄 `[0, 0, 100, 200, 0, 0]`을 `cv2.warpAffine`(4-7에서 설명)으로 옮긴 실제 결과예요.

| tx | 양선형 (`INTER_LINEAR`) | 최근접 이웃 (`INTER_NEAREST`) |
|---|---|---|
| 0 (원본) | `[0  0 100 200   0 0]` | `[0  0 100 200   0 0]` |
| 1 | `[0  0   0 100 200 0]` | `[0  0   0 100 200 0]` |
| **0.5** | `[0  0  50 150 100 0]` | `[0  0 100 200   0 0]` ← 안 움직임! |
| **0.25** | `[0  0  75 175  50 0]` | `[0  0 100 200   0 0]` ← 안 움직임! |

**tx = 0.5, 양선형을 손으로 검산** (`x = j − 0.5`)
```
j=2 → x=1.5 → (a[1] + a[2]) / 2 = (0 + 100) / 2   = 50     ✅
j=3 → x=2.5 → (a[2] + a[3]) / 2 = (100 + 200) / 2 = 150    ✅
j=4 → x=3.5 → (a[3] + a[4]) / 2 = (200 + 0) / 2   = 100    ✅
```

**관찰**
- **양선형**: 0.5칸 이동이 "값이 반씩 섞이는 것"으로 표현돼요. 대신 `[100, 200]`이라는 날카로운 모서리가 `[50, 150, 100]`으로 **뭉개져요(흐려짐).**
- **최근접 이웃**: 0.25칸, 0.5칸 이동이 반올림되어 **아예 사라졌어요.** 정밀하게 조금씩 옮기는 게 불가능해요.

> 💡 **교훈**: 소수 이동은 **"정확하지만 흐려지거나(양선형)" vs "선명하지만 부정확하거나(최근접)"** 중 하나를 골라야 해요. 공짜는 없어요.

> 🚗 **AVM 연결**: 서라운드뷰 탑뷰를 만들 때 카메라 영상의 각 화소를 탑뷰 캔버스로 옮기는 좌표(LUT)는 거의 다 **소수**예요. 그래서 매 프레임 보간이 일어나고, 4-6-b의 "흐려짐 vs 계단" 트레이드오프가 그대로 화질 문제로 나타나요. 주차선처럼 가늘고 촘촘한 무늬에서는 이 리샘플링이 **모아레**의 원인이 되기도 해요. 지금 배우는 보간이 실무 화질 이슈의 뿌리예요.

## 4-7. 더 빠른 방법 두 가지

`04` 코드는 원리를 보여 주려고 이중 for문을 썼어요. 실전에서는 이렇게 해요.

### 4-7-a. 방법 ①: numpy 슬라이싱 (정수 이동 전용)

평행 이동은 **"원본의 한 직사각형 조각을 목적의 다른 직사각형 자리에 통째로 복사"**하는 거예요. 화소 하나하나 물어볼 필요가 없어요.

```python
def translate_slice(img, pt):
    tx, ty = pt
    h, w = img.shape[:2]
    dst = np.zeros_like(img)
    dst[max(ty,0):min(h,h+ty), max(tx,0):min(w,w+tx)] = \
        img[max(-ty,0):min(h,h-ty), max(-tx,0):min(w,w-tx)]
    return dst
```

수식이 무서워 보이니까 **5×5, (tx=2, ty=1)**에 숫자를 넣어 볼게요.

| 부분 | 계산 | 결과 |
|---|---|---|
| dst 행 | `max(1,0) : min(5, 5+1)` | `1:5` |
| dst 열 | `max(2,0) : min(5, 5+2)` | `2:5` |
| img 행 | `max(−1,0) : min(5, 5−1)` | `0:4` |
| img 열 | `max(−2,0) : min(5, 5−2)` | `0:3` |

```
dst[1:5, 2:5] = img[0:4, 0:3]
     4행×3열        4행×3열     ← 크기가 같아야 복사 가능 ✅

원본 img                        목적 dst
┌──┬──┬──┬──┬──┐              ┌──┬──┬──┬──┬──┐
│▓▓│▓▓│▓▓│  │  │  y=0         │  │  │  │  │  │
│▓▓│▓▓│▓▓│  │  │       ──▶    │  │  │▓▓│▓▓│▓▓│  i=1
│▓▓│▓▓│▓▓│  │  │              │  │  │▓▓│▓▓│▓▓│
│▓▓│▓▓│▓▓│  │  │  y=3         │  │  │▓▓│▓▓│▓▓│
│  │  │  │  │  │              │  │  │▓▓│▓▓│▓▓│  i=4
└──┴──┴──┴──┴──┘              └──┴──┴──┴──┴──┘
 x=0~2                               j=2~4
```
`max`와 `min`은 이동량이 음수일 때와 양수일 때를 한 식으로 처리하려는 장치예요.

> **📚 복습: ROI 슬라이싱** (Chapter06 `03_OpenCV기초`)
> `img[y1:y2, x1:x2]`로 직사각형 영역을 잘라 쓰는 거, 기억나시죠? 이건 그 ROI를 **다른 자리에 붙여 넣는** 응용이에요.

### 4-7-b. 방법 ②: `cv2.warpAffine` (소수 이동도 OK)

```python
M = np.float32([[1, 0, tx],
                [0, 1, ty]])
dst = cv2.warpAffine(img, M, (w, h))     # dsize는 (w, h)! (Part 0-3)
```
2×3 행렬 `M`이 갑자기 나왔죠? 이 행렬로 좌표를 계산하면:
```
x' = 1·x + 0·y + tx  = x + tx
y' = 0·x + 1·y + ty  = y + ty        ← 4-1-b의 공식과 똑같음!
```
**왜 이런 행렬 모양이 되는지가 Part 6(동차 좌표)의 핵심**이에요. 지금은 "평행 이동도 행렬 하나로 표현된다" 정도만 기억해 두세요.

### 4-7-c. 세 방법 비교 (이 PC 실측, 380×300)

| 방법 | (30, 80) | (−70, −50) | `04` 결과와 같은가? |
|---|---|---|---|
| `04` 이중 for문 | 212.8 ms | 222.4 ms | (기준) |
| numpy 슬라이싱 | **0.075 ms** | **0.043 ms** | ✅ `array_equal = True` |
| `cv2.warpAffine` | 8.3 ms* | 0.22 ms | ✅ `array_equal = True` |

\* 첫 호출은 OpenCV 내부 초기화 때문에 느려요. 두 번째 호출부터는 0.2 ms 수준이에요.

**슬라이싱이 for문보다 약 3,000~5,000배 빨라요.** 계산이 아예 없는 "메모리 블록 복사"라서 그래요. 대신 **정수 이동만** 돼요. 소수 이동이나 회전과 이동을 섞는 경우에는 `warpAffine`을 써요.

## 📋 Part 4 한 장 요약

| 개념 | 한 줄 정리 |
|---|---|
| 공식 | 순방향 `x' = x + tx`, 역방향 `x = x' − tx` (y도 같음, **+ty는 아래로**) |
| 캔버스 | 원본과 같은 크기 → 이동 방향 쪽은 **잘리고**, 반대쪽은 **빈 곳(0)** |
| `contain((y, x), shape)` | 원본 밖이면 건너뜀. 안 하면 **음수 인덱스가 반대편을 읽는** 버그 |
| 순서 전환 | `(j, i) − pt` → `contain((y, x))` → `img[y, x]` |
| 보간 | 정수 이동은 불필요(1:1 대응). 소수 이동은 필요 (흐려짐 vs 부정확) |
| 실전 | 정수면 **슬라이싱**, 소수나 복합 변환이면 **`warpAffine` + `[[1,0,tx],[0,1,ty]]`** |

**다음 Part로 넘어가는 다리**: 평행 이동은 모든 화소가 **같은 방향으로 같은 거리**만큼 움직였어요. 그래서 1:1 대응이고 쉬웠어요. 회전은 다르게 **중심에서 멀수록 더 많이** 움직이고, 정수 좌표가 거의 항상 **소수**로 바뀌어요. Part 1~4에서 만든 도구(역방향 사상 + 양선형 보간 + `contain`)를 **한꺼번에 다 쓰는** 첫 변환이에요.
