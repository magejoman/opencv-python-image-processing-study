## 5-1. 삼각함수 최소 복습: cos과 sin은 "좌표"다

### 5-1-a. 단위원

반지름이 1인 원을 그리고, 오른쪽(+x 방향)에서 시작해 반시계 방향으로 각도 θ만큼 간 지점을 찍어요. 그 점의 좌표가 바로 **(cos θ, sin θ)**예요.

```
                    y ↑ (수학 좌표계: 위가 +)
                      │
              (0, 1)  ●  θ = 90°
                   ╱  │  ╲
                 ╱    │    ● (0.866, 0.5)   θ = 30°
               ╱      │  ╱ ┊
   (−1, 0) ●          ┼──────●──────→ x
               ╲      │      (1, 0)   θ = 0°
                 ╲    │    ╱
                   ╲  │  ╱
                      ●
                      (0, −1)  θ = 270°

    30° 지점:  x = cos 30° = 0.866  (오른쪽으로 얼마나)
               y = sin 30° = 0.5    (위로 얼마나)
```

**cos은 가로 성분, sin은 세로 성분**이에요. 외울 건 이것뿐이에요.

| θ | cos θ | sin θ | 위치 |
|---|---|---|---|
| 0° | 1 | 0 | 오른쪽 |
| 30° | 0.866 | 0.5 | |
| 45° | 0.707 | 0.707 | 대각선 |
| 60° | 0.5 | 0.866 | |
| 90° | 0 | 1 | 위 |

### 5-1-b. 반지름이 r이면 r배

반지름 r인 원 위에서 각도 φ인 점은 **(r·cos φ, r·sin φ)**예요. 이렇게 "거리 r과 각도 φ"로 점을 나타내는 걸 **극좌표**라고 해요. 다음 5-2의 유도에서 이걸 써요.

### 5-1-c. 도(°) → 라디안(rad)

`np.sin`, `np.cos`은 **라디안**만 받아요. 원 한 바퀴가 360° = 2π rad이니까 180° = π rad예요.

```
radian = degree / 180 × π          ← 코드: radian = (degree/180) * np.pi

30° → 30 / 180 × 3.14159 = 0.5236 rad
```

> ⚠️ **흔한 실수**: `np.sin(30)`은 sin 30°가 아니라 **sin 30 라디안 = −0.988**이에요. 0.5가 나올 줄 알았다면 단위를 안 바꾼 거예요. `np.radians(30)`이나 `np.deg2rad(30)`을 써도 돼요.

## 5-2. 📐 회전 공식 유도

### 5-2-a. 비유: 컴퍼스

회전은 **컴퍼스 바늘을 원점에 꽂고 연필을 돌리는 것**과 같아요.
- 원점까지의 **거리 r은 그대로**예요.
- **각도만 θ만큼** 늘어나요.

### 5-2-b. 유도

```
① 점 (x, y)를 극좌표로:          x = r·cos φ,         y = r·sin φ

② θ만큼 돌리면 각도만 φ+θ:       x' = r·cos(φ + θ),   y' = r·sin(φ + θ)

③ 덧셈정리로 풀기:
   x' = r·(cos φ·cos θ − sin φ·sin θ)
      = (r·cos φ)·cos θ − (r·sin φ)·sin θ
      =     x    ·cos θ −     y    ·sin θ        ← ①을 대입

   y' = r·(sin φ·cos θ + cos φ·sin θ)
      = (r·sin φ)·cos θ + (r·cos φ)·sin θ
      =     y    ·cos θ +     x    ·sin θ
```

> **📚 덧셈정리** (고등학교 수학)
> ```
> cos(a + b) = cos a·cos b − sin a·sin b
> sin(a + b) = sin a·cos b + cos a·sin b
> ```
> 외우기 힘들면 "cos은 **같은 것끼리** 곱하고 **빼기**, sin은 **섞어서** 곱하고 **더하기**"로 기억해요.

**최종 회전 공식**
```
x' = x·cos θ − y·sin θ
y' = x·sin θ + y·cos θ
```
r도 φ도 사라지고 **원래 좌표 (x, y)와 각도 θ만** 남았어요. 각 점의 극좌표를 따로 구할 필요가 없어요.

### 5-2-c. 숫자로 확인 (θ = 30°, cos = 0.8660, sin = 0.5)

| 점 (x, y) | x' = x·0.866 − y·0.5 | y' = x·0.5 + y·0.866 | 결과 | 거리 r (전 → 후) |
|---|---|---|---|---|
| (10, 0) | 8.660 − 0 | 5.000 + 0 | **(8.660, 5.000)** | 10 → 10 ✅ |
| (0, 10) | 0 − 5.000 | 0 + 8.660 | **(−5.000, 8.660)** | 10 → 10 ✅ |
| (10, 5) | 8.660 − 2.500 | 5.000 + 4.330 | **(6.160, 9.330)** | 11.18 → 11.18 ✅ |

`(10, 5)` 거리 검산: `√(6.160² + 9.330²) = √(37.95 + 87.05) = √125 = 11.18` ✅

**관찰 두 가지**
1. 거리가 그대로예요. 회전은 **모양과 크기를 보존**해요(Part 0-1-d 표).
2. 정수 좌표 `(10, 5)`가 `(6.160, 9.330)`이라는 **소수**가 됐어요. 평행 이동과 달리 **보간이 반드시 필요**해요.

## 5-3. 행렬로 쓰기, 그리고 역회전

### 5-3-a. 회전 행렬 R(θ)

공식 두 줄을 행렬 곱 하나로 묶을 수 있어요.

```
┌ x' ┐   ┌ cos θ   −sin θ ┐ ┌ x ┐
│    │ = │                │ │   │
└ y' ┘   └ sin θ    cos θ ┘ └ y ┘
              R(θ)
```

**행렬 곱 읽는 법**: 결과의 **첫째 줄 = 행렬의 첫째 행 · (x, y)**예요.
```
R(30°) = [[0.866, −0.5  ],
          [0.5,    0.866]]

R(30°) · (10, 5):
  첫째 줄: 0.866×10 + (−0.5)×5  = 8.660 − 2.5   = 6.160
  둘째 줄: 0.5  ×10 + 0.866 ×5  = 5.0   + 4.330 = 9.330      → (6.160, 9.330) ✅
```

### 5-3-b. 역회전 = R(−θ) = Rᵀ

**역방향 사상**(Part 2)을 하려면 "목적 → 원본"으로 가는 **역변환**이 필요해요. θ만큼 돌린 걸 되돌리려면 **−θ만큼 돌리면** 되죠.

```
cos(−θ) = cos θ       (가로 성분은 그대로)
sin(−θ) = −sin θ      (세로 성분은 뒤집힘)

R(−θ) = ┌  cos θ   sin θ ┐       ← R(θ)에서 sin의 부호만 바뀜
        └ −sin θ   cos θ ┘
```

실제 숫자를 보면 **R(−30°)는 R(30°)를 전치(행과 열 뒤집기)한 것**과 똑같아요.
```
R(30°)              R(30°)ᵀ              R(−30°)
[[ 0.866 −0.5  ]    [[ 0.866  0.5  ]     [[ 0.866  0.5  ]
 [ 0.5    0.866]]    [−0.5    0.866]]     [−0.5    0.866]]     ← 같음!

R(30°) · R(30°)ᵀ = [[1, 0],
                    [0, 1]]               ← 단위행렬 = "아무것도 안 함" ✅
```

> 💡 회전 행렬의 역행렬은 **그냥 전치**하면 돼요. 역행렬 계산이 공짜예요. 이런 행렬을 **직교 행렬**이라고 해요. Part 6에서 일반 어파인의 역행렬을 구할 때와 비교해 보세요.

### 5-3-c. `05` 코드 속 공식의 정체

```python
y = -j * sin + i * cos
x =  j * cos + i * sin
```
`(x', y') = (j, i)`로 놓고 정리하면:
```
x = cos θ · j + sin θ · i         ┌ x ┐   ┌  cos θ   sin θ ┐ ┌ j ┐
y = −sin θ · j + cos θ · i   →    └ y ┘ = └ −sin θ   cos θ ┘ └ i ┘
                                              R(−θ)  ✅
```
**목적 `(j, i)`에 R(−θ)를 곱해서 원본 위치를 찾는**, 역방향 사상이에요.

### 5-4-a. 같은 숫자, 다른 그림

`(10, 0)`을 R(30°)로 돌리면 `(8.660, 5.000)`이에요. **y가 0에서 5로 커졌어요.** 이걸 두 좌표계에 그려 볼게요.

```
   수학 좌표계 (y 위가 +)                   이미지 좌표계 (y 아래가 +)
         y ↑                                (0,0)──────────────→ x
           │      ● (8.66, 5)                 │╲
           │    ╱  ↖ 반시계                    │  ╲     ● (10, 0)
           │  ╱                               │    ╲   │
           │╱       ● (10, 0)                 │      ╲ ↓ 시계 방향
     ──────┼────────────→ x                   │        ● (8.66, 5)
           │                                  ↓ y
   y가 커짐 = 위로 감 = 반시계               y가 커짐 = 아래로 감 = 시계 방향
```

**공식은 똑같은데, y축 방향이 반대라서 화면에서는 반대로 돌아 보여요.** 수학 교과서의 "R(θ)는 반시계 회전"이라는 말이 이미지에서는 **"R(θ)는 시계 방향 회전"**이 돼요.

### 5-4-b. `05` 코드는 화면에서 시계 방향

5-3-c에서 봤듯이 `05`는 역방향으로 R(−θ)를 쓰니까, **순방향은 R(θ)**예요. 그래서 이미지에서는 **시계 방향**으로 돌아요.

**실제 실험**: 360×360 검은 이미지에서 중심 `(180, 180)`의 오른쪽 `(300, 180)`에 흰 점을 찍고 `rotate_pt(m, 20, center)`를 했어요.
```
점의 위치: (300, 180) → (292.8, 221.0)
                                 ↑ y가 커짐 = 아래로 내려감 = 시계 방향 ✅
```

### 5-4-c. OpenCV `getRotationMatrix2D`는 화면에서 반시계 방향

```python
M = cv2.getRotationMatrix2D((180, 180), 20, 1)
```
실제 출력은 이래요.
```
[[  0.9397   0.342  -50.7083]
 [ -0.342    0.9397  72.419 ]]
       ↑ 오른쪽 위가 +sin
```
왼쪽 2×2 부분이 `[[cos, +sin], [−sin, cos]]`예요. 5-3-b의 **R(−θ)** 모양이에요(오른쪽 열은 중심 처리용인데 Part 6에서 유도할게요). 같은 흰 점으로 실험하면:
```
cv2.warpAffine(m, M, ...):  (300, 180) → (292.8, 139.0)
                                                ↑ y가 작아짐 = 위로 = 반시계 방향
```
OpenCV 공식 문서에도 이렇게 적혀 있어요. *"양수 각도는 반시계 방향 회전 (좌표 원점은 왼쪽 위로 가정)"*. OpenCV는 일부러 부호를 뒤집어서 **사람이 보기에 "양수 = 반시계"**가 되도록 맞춰 둔 거예요.

### 5-4-d. 정리표

| | `05` 코드 (`rotate`, `rotate_pt`) | OpenCV `getRotationMatrix2D` | Pillow `Image.rotate` |
|---|---|---|---|
| 양수 각도의 화면 방향 | **시계 방향** ↻ | **반시계 방향** ↺ | 반시계 방향 ↺ |
| 순방향 행렬 | R(θ) = `[[c, −s], [s, c]]` | `[[c, s], [−s, c]]` | |

**그래서 `05`의 `rotate_pt(img, 20, c)`와 같은 결과를 OpenCV로 얻으려면 `getRotationMatrix2D(c, −20, 1)`이에요.** 실제로 비교하면:
```
평균 차이 0.755, 화소의 99.27%가 차이 1 이하
```
남은 차이는 Part 3에서 본 **버림 vs 반올림**, 그리고 이미지 **테두리 처리** 방식 때문이에요(최대 차이 194는 테두리에서 나와요). 속도는 OpenCV가 **0.2~0.4 ms**, `rotate_pt`는 **1,176 ms**예요.

> 💡 **실무 팁**: 남이 만든 회전 함수를 쓸 때는 **흰 점 하나 찍고 돌려 보는 테스트**를 꼭 하세요. 방향이 반대인 버그는 정사각형 대칭 이미지에서는 잘 안 보여요.

## 5-5. `rotate()`: 원점(왼쪽 위 모서리) 기준 회전

### 5-5-a. 코드 해부

```python
def rotate(img, degree):
    dst = np.zeros(img.shape[:2], img.dtype)                  # ① 같은 크기 캔버스
    radian = (degree/180) * np.pi                             # ② 도 → 라디안
    sin, cos = np.sin(radian), np.cos(radian)                 # ③ 미리 한 번만 계산
    for i in range(img.shape[0]):                             # ④ 목적을 돎 (역방향)
        for j in range(img.shape[1]):
            y = -j * sin + i * cos                            # ⑤ R(−θ)로 원본 위치
            x =  j * cos + i * sin
            if contain((y, x), img.shape):                    # ⑥ 범위 검사 (Part 4)
                dst[i, j] = bilinear_value(img, [x, y])       # ⑦ 양선형 보간 (Part 3)
    return dst
```

| 줄 | 포인트 |
|---|---|
| ③ | sin, cos을 **루프 밖에서 한 번만** 계산해요. 129,600번 반복할 때마다 다시 계산하면 낭비예요 |
| ⑤ | 5-3-c에서 본 R(−θ) |
| ⑥ | `contain`이 **0 이상**을 보장하니까, `bilinear_value` 안의 `np.int32` 버림이 내림과 같아져요(Part 3-5 ①의 음수 문제가 안 생겨요) |
| ⑦ | `bilinear_value(img, [x, y])` — **(x, y) 순서**예요 |

### 5-5-b. 화소 두 개 끝까지 따라가기 (θ = 30°)

**목적 `(i=200, j=100)`: 원본 안쪽**
```
⑤ y = −100 × 0.5   + 200 × 0.866 = −50 + 173.21 = 123.205
   x =  100 × 0.866 + 200 × 0.5   = 86.60 + 100  = 186.603
⑥ contain((123.205, 186.603), (360, 360)) → True
⑦ bilinear_value:
   x = 186, y = 123  →  img[123:125, 186:188] = [[36, 32],
                                                [25, 31]]
   α = 0.205, β = 0.603
   M1 = 36 + 0.205 × (25 − 36) = 33.74
   M2 = 32 + 0.205 × (31 − 32) = 31.79
   P  = 33.74 + 0.603 × (31.79 − 33.74) = 32.57
   dst[200, 100] = 32         (uint8 배열에 넣으면서 버림)
```

**목적 `(i=100, j=200)`: 원본 밖**
```
⑤ y = −200 × 0.5   + 100 × 0.866 = −100 + 86.60 = −13.40    ← 음수!
   x =  200 × 0.866 + 100 × 0.5   = 173.21 + 50  = 223.21
⑥ contain → False   →   dst[100, 200] = 0 (검정)
```

### 5-5-c. 결과 모양: 왼쪽 위 모서리를 축으로 휙

원본의 네 모서리가 어디로 가는지 보면(순방향 R(30°)):
```
(0, 0)     →  (0, 0)              ← 축이라 그대로
(360, 0)   →  (311.8, 180.0)      ← 오른쪽 위 모서리가 아래로 내려옴
(0, 360)   →  (−180.0, 311.8)     ← 왼쪽 아래 모서리가 캔버스 왼쪽 밖으로!
```

## 5-6. `rotate_pt()`: 중심 기준 회전

### 5-6-a. 아이디어: 이동 → 회전 → 되돌리기

회전 공식은 **원점을 축으로만** 돌릴 수 있어요. 그럼 중심 `(cx, cy)`를 축으로 돌리려면 이렇게 하면 돼요.

```
 ① 중심을 원점으로 옮긴다      ② 원점 기준으로 돌린다      ③ 다시 제자리로 옮긴다
    (−cx, −cy) 이동               R(θ)                        (+cx, +cy) 이동

  ┌──────────┐                    ╱╲                      ┌──────────┐
  │          │                  ╱    ╲                    │    ╱╲    │
  │    ●     │  →    ┌────┼────┐ → ╱   ●  ╲  →            │  ╱  ●  ╲ │
  │  (cx,cy) │       │    ●    │   ╲      ╱               │  ╲     ╱ │
  └──────────┘       │  (0,0)  │     ╲  ╱                 │    ╲╱    │
                     └────┼────┘      ╲╱                  └──────────┘
```

🧠 비유하면, 컴퍼스 바늘은 종이의 왼쪽 위 모서리에만 꽂을 수 있다는 규칙이 있을 때, **종이를 밀어서 그림 중심을 바늘 밑으로 가져오고 → 돌리고 → 다시 밀어 놓는** 거예요.

> 🔖 **"이동 → 회전 → 되돌리기"는 변환 3개를 이어 붙인 것**이에요. Part 7에서 이걸 **행렬 3개의 곱 하나**로 합치는 법을 배울 거예요.

### 5-6-b. 코드 해부 (역방향이니까 순서도 거꾸로 생각)

```python
def rotate_pt(img, degree, pt):
    ...
    for i in range(img.shape[0]):
        for j in range(img.shape[1]):
            jj, ii = np.subtract((j, i), pt)       # ① 목적 좌표에서 중심을 뺌 (원점으로)
            y = -jj * sin + ii * cos               # ② R(−θ)로 역회전
            x =  jj * cos + ii * sin
            x, y = np.add((x, y), pt)              # ③ 중심을 다시 더함 (제자리로)
            if contain((y, x), img.shape):
                dst[i, j] = bilinear_value(img, [x, y])
```

수식 한 줄로 쓰면:
```
x = (j − cx)·cos θ + (i − cy)·sin θ + cx
y = −(j − cx)·sin θ + (i − cy)·cos θ + cy
```

`center`는 Part 0-3-d에서 계산했던 그대로예요.
```
np.divmod((360, 360), 2)[0] = [180, 180]
```

### 5-6-c. 화소 하나 끝까지 따라가기 (θ = 20°, cos = 0.9397, sin = 0.3420)

**목적 `(i=100, j=300)`**
```
① jj, ii = (300 − 180, 100 − 180) = (120, −80)        ← 중심 기준 상대 좌표

② x = 120 × 0.9397 + (−80) × 0.3420 = 112.76 − 27.36 =   85.40
   y = −120 × 0.3420 + (−80) × 0.9397 = −41.04 − 75.18 = −116.22

③ x, y = (85.40 + 180, −116.22 + 180) = (265.40, 63.78)   ← 원본 위치

contain((63.78, 265.40), (360, 360)) → True

bilinear_value:
   img[63:65, 265:267] = [[59, 65],
                          [66, 74]]
   α = 0.782, β = 0.402
   M1 = 59 + 0.782 × (66 − 59) = 64.48
   M2 = 65 + 0.782 × (74 − 65) = 72.04
   P  = 64.48 + 0.402 × (72.04 − 64.48) = 67.51
   dst[100, 300] = 67
```

②의 중간값 `(85.40, −116.22)`는 **음수**예요. 그래도 괜찮아요. ③에서 중심을 더하면 다시 양수가 되니까요. 그래서 `contain` 검사는 반드시 **③ 다음에** 해야 해요.

## 5-7. `06.rotate2.py`: 마우스 3점으로 회전

### 5-7-a. 프로그램이 하는 일

1. 이미지를 클릭해서 **회전 중심**을 찍어요 (빨간 점).
2. 마우스를 **누른 곳**이 시작 방향이에요 (초록 점).
3. **드래그해서 뗀 곳**이 끝 방향이에요 (파란 점).
4. 중심에서 본 **시작 → 끝 각도**만큼 이미지를 돌려요.

### 5-7-b. 이벤트 흐름

> **📚 복습: 마우스 콜백** (Chapter06 `03_OpenCV기초`)
> `cv2.setMouseCallback("창이름", 함수)`로 등록하면, 그 창에서 마우스 이벤트가 생길 때마다 `함수(event, x, y, flags, param)`가 불려요. `x, y`는 **(x, y) 순서**의 화면 좌표예요.

```python
def onMouse(event, x, y, flags, param):
    if (event == cv2.EVENT_LBUTTONUP   and len(pts) == 0): draw_point(x, y, (0,0,255))   # 빨강
    if (event == cv2.EVENT_LBUTTONDOWN and len(pts) == 1): draw_point(x, y, (0,255,0))   # 초록
    if (event == cv2.EVENT_LBUTTONUP   and len(pts) == 2): draw_point(x, y, (255,0,0))   # 파랑
    if len(pts) == 3:
        ... 각도 계산 후 회전, pts 초기화
```

**시간 순서로 따라가기**
```
사용자 동작            이벤트           len(pts)   조건 일치?          결과
─────────────────────────────────────────────────────────────────────────
첫 클릭: 누름          LBUTTONDOWN      0          ✗ (UP이어야 함)    무시
첫 클릭: 뗌            LBUTTONUP        0          ✓ 1번째 줄          pts[0] = 중심 🔴
두 번째: 누름          LBUTTONDOWN      1          ✓ 2번째 줄          pts[1] = 시작 🟢
   (드래그 중)         MOUSEMOVE        2          ✗                  무시
두 번째: 뗌            LBUTTONUP        2          ✓ 3번째 줄          pts[2] = 끝 🔵
                                        3          ✓ len == 3          회전 실행!
```
**UP / DOWN / UP 조합의 의도**: 첫 번째는 "클릭(뗄 때 확정)"이고, 두 번째는 **"누르고 끌어서 놓기"(드래그)** 동작 하나로 시작점과 끝점을 함께 받으려는 거예요.

### 5-7-c. 각도 구하기: `atan2`

**"중심에서 이 점은 몇 도 방향인가?"** 를 구하는 함수가 `atan2`예요.

```python
def calc_angle(pt, org):
    dxy = np.subtract(pt, org).astype(float)        # 중심 → 점 벡터 (dx, dy)
    return cv2.fastAtan2(dxy[1], dxy[0])            # fastAtan2(dy, dx) → 도(°) 단위
```

5-1의 단위원을 거꾸로 쓰는 거예요. 단위원에서는 "각도 → (cos, sin)"이었고, atan2는 **"(dx, dy) → 각도"**예요.

```
                 (dx, dy) = (100, 10)
   중심 ●─────────────────────●
         ╲ θ = ?              
          ╲                   tan θ = dy / dx = 10 / 100
                              θ = atan2(10, 100) = 5.71°
```

**왜 그냥 `atan(dy/dx)`가 아니라 `atan2(dy, dx)`일까요?** `dy/dx`로 나눠 버리면 `(10, 100)`과 `(−10, −100)`이 같은 값 0.1이 돼서 **방향(사분면)이 사라져요.** `atan2`는 dx, dy를 **따로** 받아서 360° 전체를 구분해요. dx = 0이어도 나눗셈 에러가 없어요.

**`cv2.fastAtan2` 실측값** (결과가 항상 **0~360°**)

| dx | dy | `fastAtan2(dy, dx)` | `np.degrees(np.arctan2(dy, dx))` | 화면에서 |
|---|---|---|---|---|
| 100 | 10 | 5.71° | 5.71° | 오른쪽 약간 **아래** |
| 100 | −10 | **354.29°** | **−5.71°** | 오른쪽 약간 위 |
| −10 | 100 | 95.71° | 95.71° | 거의 **아래** |

- numpy의 `arctan2`는 −180~180°, OpenCV의 `fastAtan2`는 **0~360°**를 돌려줘요.
- 이름처럼 **빠른 대신 약 0.3° 오차**가 있어요(5.7098° vs 5.7106°).
- ⚠️ 여기서도 y가 아래로 커지니까, **각도가 커지는 방향은 화면에서 시계 방향**이에요(5-4와 같은 이유).

### 5-7-d. 회전각 = 끝 각도 − 시작 각도

```python
angle1 = calc_angle(pts[1], pts[0])     # 시작점 방향
angle2 = calc_angle(pts[2], pts[0])     # 끝점 방향
angle = angle2 - angle1
dst = rotate_pt(image, angle, pts[0])   # 클릭한 중심 기준으로 회전
```

**예시**: 중심 `(180, 180)`, 시작 `(280, 180)`(오른쪽), 끝 `(180, 280)`(아래)
```
angle1 = fastAtan2(0, 100)  =  0°
angle2 = fastAtan2(100, 0)  = 90°
angle  = 90 − 0 = 90°
rotate_pt(image, 90, (180,180))  →  시계 방향 90° 회전
```
오른쪽에 있던 내용이 **아래쪽으로** 가요. 마우스로 끈 방향(오른쪽 → 아래)과 정확히 같아요. ✅

**방향이 딱 맞는 이유**: `fastAtan2`도 `rotate_pt`도 **같은 이미지 좌표계(y 아래)**에서 계산하니까, "각도가 커지는 방향 = 회전 방향 = 시계 방향"으로 일관돼요. 만약 여기에 OpenCV `getRotationMatrix2D`를 그대로 썼다면 **드래그와 반대로** 돌았을 거예요.

**360°를 넘나드는 경우**: 시작이 350°, 끝이 10°면 `angle = −340°`예요. 이상해 보이지만 −340° 회전과 +20° 회전은 **같은 결과**예요(sin과 cos은 360°마다 반복). 그래서 문제없어요.

### 5-7-e. 소소한 관찰

- 회전 후 `tmp = np.copy(image)`, `pts = []`로 초기화해요. 그래서 다음 회전은 **원본에서 다시** 시작해요(누적되지 않아요).
- `calc_angle2` 함수는 정의만 있고 쓰이지 않아요. `calc_angle` 두 번 + 뺄셈과 같은 일을 하는 함수예요.
- 회전 한 번에 `rotate_pt`가 1초쯤 걸려서 클릭 후 잠깐 멈춘 것처럼 보여요.

> 🚗 **AVM 연결**: 서라운드뷰에서 앞·뒤·좌·우 카메라 영상을 탑뷰 캔버스에 붙일 때, 각 카메라 패치는 차량 기준으로 **0°, 180°, 90°, 270°**쯤 돌아간 상태로 놓여요. 실제 장착 오차(yaw)를 보정할 때도 "중심 기준 회전"이 기본 단위예요. 이때 **회전 방향 부호 규약**(5-4)이 라이브러리마다 다르다는 걸 모르면 보정이 반대로 들어가는 버그가 나요.

## 📋 Part 5 한 장 요약

| 개념 | 한 줄 정리 |
|---|---|
| cos, sin | 단위원 위 점의 **가로·세로 좌표**. `np.sin`은 **라디안** (`deg/180·π`) |
| 회전 공식 | `x' = x·cosθ − y·sinθ`, `y' = x·sinθ + y·cosθ` (덧셈정리로 유도) |
| 행렬 | `R(θ) = [[c, −s], [s, c]]`, 역회전 `R(−θ) = Rᵀ` |
| 역방향 사상 | 목적 `(j, i)`에 R(−θ)를 곱해 원본 위치 → `contain` → `bilinear_value` |
| ⚠️ 방향 | y가 아래라서 `05`는 **양수 = 시계**, OpenCV `getRotationMatrix2D`는 **양수 = 반시계** |
| 중심 기준 | **−중심 → 회전 → +중심**. `contain`은 마지막에 |
| `atan2(dy, dx)` | 벡터의 방향 각도. `fastAtan2`는 0~360°, 약 0.3° 오차 |
| `06` | 클릭(중심) + 드래그(시작 → 끝), `angle2 − angle1`만큼 `rotate_pt` |

**다음 Part로 넘어가는 다리**: 지금까지 크기 변경(곱셈), 평행 이동(덧셈), 회전(행렬 곱)을 **따로따로** 배웠어요. 그리고 중심 기준 회전처럼 이것들을 **섞어** 쓰기 시작했어요. 그런데 이동은 덧셈이라서 회전처럼 행렬 곱으로 쓸 수가 없었어요. **"이동까지 행렬 곱 하나로 쓸 수 있다면?"** 그 마법 같은 트릭이 Part 6의 **동차 좌표**예요. 그리고 그 결과로 나오는 2×3 행렬이 바로 5-4-c에서 정체를 미뤘던 `getRotationMatrix2D`의 **세 번째 열**의 비밀이에요.
