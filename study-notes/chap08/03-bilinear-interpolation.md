## 3-1. 1차원 선형 보간: 두 점 사이 값 구하기

### 3-1-a. 비유: 온도계 눈금

아침 6시에 10℃, 7시에 50℃였다고 해 볼게요(극단적인 날씨네요 😅). 6시 15분은 몇 도일까요?

```
온도
 50 ┤                        ● B (7시, 50℃)
    │                     ╱
    │                  ╱
    │               ╱
 20 ┤ · · · · · ●  ← 6시 15분이면 1시간의 25% 지점 → 20℃
    │        ╱  ┊
 10 ┤ A ●╱      ┊
    └───┴───────┴────────────┴──── 시간
       6:00   6:15          7:00
        t=0   t=0.25         t=1
```

두 점 사이를 **직선으로 이었다고 가정**하고 그 직선 위의 값을 읽는 거예요. 이게 **선형(linear) 보간**이에요.

### 3-1-b. 공식

```
P = A + t · (B − A)

  A   : 왼쪽(시작) 값
  B   : 오른쪽(끝) 값
  t   : A에서 얼마나 왔는가 (0 ~ 1)
  B−A : 전체 변화량
```

**말로 읽으면** "A에서 출발해서, 전체 변화량의 t만큼 더 간다"예요.

| t | 계산 | P | 의미 |
|---|---|---|---|
| 0 | 10 + 0 × 40 | 10 | A 그 자체 |
| 0.25 | 10 + 0.25 × 40 | **20** | A 쪽에 가까움 |
| 0.5 | 10 + 0.5 × 40 | 30 | 정확히 중간 = 평균 |
| 1 | 10 + 1 × 40 | 50 | B 그 자체 |

### 3-1-c. 같은 공식의 다른 모양: 가중 평균

식을 정리하면:
```
P = A + t·B − t·A = (1 − t)·A + t·B
```
**A에 (1−t)만큼, B에 t만큼 무게를 둔 평균**이에요. t = 0.25면 A를 75%, B를 25% 섞어요. **가까운 쪽에 더 큰 무게**가 가요. 이 모양이 3-4에서 다시 나와요.

### 3-1-d. Part 2의 그 질문에 답하기

Part 2에서 "0.667번 줄은 0번 줄이야, 1번 줄이야?"라고 물었죠. 실제 이미지의 x=60 열에서 위가 `57`, 아래가 `65`라면:

```
최근접 이웃 (int):   0번 줄 고름        → 57
양선형 (1차원):      57 + 0.667 × (65 − 57) = 57 + 5.33 = 62.3
```
둘 중 하나를 고르지 않고, **1번 줄에 더 가까우니까 65 쪽으로 더 기운 값**을 만들어요.

## 3-2. 2차원으로: 4화소 + 두 번의 1차원 보간

### 3-2-a. 소수 좌표를 둘러싼 4화소

원본 위치 `pt = (x, y)`가 소수면, 그 점은 반드시 **화소 4개로 만든 정사각형 안**에 있어요.

```
      x열              x+1열
y행    P1 ●───────────────────● P2         P1 = img[y,   x  ]  (왼쪽 위)
          │      β       │    │            P2 = img[y,   x+1]  (오른쪽 위)
          │◀────────────▶│    │            P3 = img[y+1, x  ]  (왼쪽 아래)
          │ α            │    │            P4 = img[y+1, x+1]  (오른쪽 아래)
          │ ▼            │    │
       M1 ◆──────────────●────◆ M2         α = pt.y − y   (세로로 얼마나 내려왔나, 0~1)
          │             pt    │            β = pt.x − x   (가로로 얼마나 왔나, 0~1)
          │                   │
y+1행  P3 ●───────────────────● P4
```

### 3-2-b. 계산 순서 (코드와 같은 순서)

```
1단계 (세로, 왼쪽 기둥):   M1 = P1 + α · (P3 − P1)    ← P1과 P3 사이 α 지점
1단계 (세로, 오른쪽 기둥): M2 = P2 + α · (P4 − P2)    ← P2와 P4 사이 α 지점
2단계 (가로):              P  = M1 + β · (M2 − M1)    ← M1과 M2 사이 β 지점
```

**1차원 선형 보간을 3번** 하는 게 전부예요. 세로로 2번 해서 `pt`와 같은 높이의 값 두 개(M1, M2)를 만들고, 그 둘을 가로로 한 번 더 보간해요. **두(bi) 방향으로 선형(linear)**이라서 **bi-linear(양선형)**이에요.

## 3-3. 손으로 끝까지 계산하기

### 3-3-a. 준비

작은 3×4 원본과 소수 좌표 `pt = (x=1.3, y=0.6)`로 해 볼게요.

```
       x=0  x=1  x=2  x=3
y=0  [  10   40   90   30 ]
y=1  [  60  120   20   70 ]
y=2  [  50   80  100   10 ]
```

### 3-3-b. 단계별 계산

**① 정수 부분: 왼쪽 위 화소 찾기**
```
x = int(1.3) = 1,   y = int(0.6) = 0
```

**② 4화소 꺼내기**
```
img[0:2, 1:3] = [[ 40,  90],        P1 = 40   P2 = 90
                 [120,  20]]   →    P3 = 120  P4 = 20
```

**③ 소수 부분: 거리 비율**
```
α = 0.6 − 0 = 0.6     (세로로 60% 내려옴 → 아래 줄에 더 가까움)
β = 1.3 − 1 = 0.3     (가로로 30% 옴 → 왼쪽 열에 더 가까움)
```

**④ 세로 보간 2번**
```
M1 = P1 + α(P3 − P1) = 40 + 0.6 × (120 − 40) = 40 + 0.6 × 80    = 40 + 48 = 88
M2 = P2 + α(P4 − P2) = 90 + 0.6 × ( 20 − 90) = 90 + 0.6 × (−70) = 90 − 42 = 48
```

**⑤ 가로 보간 1번**
```
P = M1 + β(M2 − M1) = 88 + 0.3 × (48 − 88) = 88 + 0.3 × (−40) = 88 − 12 = 76
```

**그림으로 정리**
```
         40 ●─────────────────● 90
            │                 │
            │ ↓ α=0.6         │ ↓ α=0.6
            │                 │
         88 ◆───●─────────────◆ 48
              ↑ β=0.3
             76  ← 최종 값
            │                 │
        120 ●─────────────────● 20
```

실제 `bilinear_value(a, (1.3, 0.6))`도 **76**을 돌려줬어요. ✅

### 3-3-c. 순서를 바꿔도 같을까? (가로 먼저)

```
위 줄 가로:   40 + 0.3 × (90 − 40)   = 40 + 15 = 55
아래 줄 가로: 120 + 0.3 × (20 − 120) = 120 − 30 = 90
세로:         55 + 0.6 × (90 − 55)   = 55 + 21 = 76   ✅ 똑같음!
```
**순서는 상관없어요.** 왜 같은지는 3-4에서 증명할게요.

## 3-4. 📐 넓이 가중 평균: 같은 계산의 다른 얼굴

### 3-4-a. 식 전개

3-1-c에서 `A + t(B − A) = (1−t)A + tB`였죠. 이걸 세 번 적용하면:

```
M1 = (1−α)·P1 + α·P3
M2 = (1−α)·P2 + α·P4
P  = (1−β)·M1 + β·M2

M1, M2를 대입:
P  = (1−β)·[(1−α)P1 + αP3] + β·[(1−α)P2 + αP4]

괄호를 풀면:
P  = (1−α)(1−β)·P1  +  (1−α)β·P2  +  α(1−β)·P3  +  αβ·P4
     └── w1 ──┘        └─ w2 ─┘       └─ w3 ─┘      └ w4 ┘
```

**4화소의 가중 평균**이에요. 이 식은 α와 β에 대해 대칭이라서 가로를 먼저 하든 세로를 먼저 하든 결과가 같아요. 3-3-c의 증명이에요.

### 3-4-b. 가중치 = 맞은편 사각형의 넓이

점 `pt`가 1×1 정사각형을 **4개의 작은 직사각형**으로 나눠요.

```
  P1 ●─────── β ───────┬──── 1−β ────● P2
     │                 │             │
   α │   넓이 αβ        │  넓이 α(1−β) │
     │   (→ P4의 무게)  │  (→ P3의 무게)│
     ├─────────────────●─────────────┤  ● = pt
     │                 │             │
 1−α │  넓이 (1−α)β     │ 넓이(1−α)(1−β)│
     │  (→ P2의 무게)   │  (→ P1의 무게)│
  P3 ●─────────────────┴─────────────● P4
```

**각 화소의 무게 = 그 화소의 대각선 맞은편에 있는 사각형의 넓이**예요.

**직관**: 점이 P1에 가까워질수록 P1의 **맞은편** 사각형(오른쪽 아래)이 커져요. 그래서 P1의 무게가 커져요. 점이 P1에 딱 붙으면 맞은편 사각형이 전체(넓이 1)가 되고 P = P1이 돼요.

### 3-4-c. 숫자로 검산 (α = 0.6, β = 0.3)

| 화소 | 값 | 가중치 공식 | 가중치 | 값 × 가중치 |
|---|---|---|---|---|
| P1 | 40 | (1−0.6)(1−0.3) = 0.4 × 0.7 | **0.28** | 11.2 |
| P2 | 90 | (1−0.6)(0.3) = 0.4 × 0.3 | **0.12** | 10.8 |
| P3 | 120 | (0.6)(1−0.3) = 0.6 × 0.7 | **0.42** | 50.4 |
| P4 | 20 | (0.6)(0.3) | **0.18** | 3.6 |
| 합계 | | | **1.00** | **76.0** ✅ |

- 가중치의 합은 **항상 1**이에요(0.28 + 0.12 + 0.42 + 0.18). 그래서 결과가 4화소의 **최솟값과 최댓값 사이**를 벗어나지 않아요. 이 성질이 3-5의 clip과 연결돼요.
- 점이 왼쪽 아래(P3) 쪽에 가까웠으니(α=0.6 아래로, β=0.3 왼쪽으로) P3의 무게 0.42가 가장 커요.

> 🧐 **"양선형"인데 전체가 직선(평면)은 아니에요.** 전개한 식에 `αβ`라는 곱하기 항이 있어서, 4점을 이은 면은 평면이 아니라 살짝 **휘어진 면(말안장 모양)**이에요. 가로나 세로로 자른 단면만 직선이에요.

## 3-5. `bilinear_value` 코드 해부

```python
def bilinear_value(img, pt):
    x, y = np.int32(pt)                                      # ①
    if x >= img.shape[1]-1: x = x - 1                        # ②
    if y >= img.shape[0]-1: y = y - 1                        # ②
    P1, P2, P3, P4 = np.float32(img[y:y+2, x:x+2].flat)      # ③
    alpha, beta = pt[1] - y,  pt[0] - x                      # ④
    M1 = P1 + alpha * (P3 - P1)                              # ⑤
    M2 = P2 + alpha * (P4 - P2)                              # ⑤
    P  = M1 + beta  * (M2 - M1)                              # ⑥
    return np.clip(P, 0, 255).astype(np.uint8)               # ⑦
```

### ① `x, y = np.int32(pt)`: 정수 부분 (⚠️ `pt`는 (x, y) 순서)
- `pt = (1.3, 0.6)`이면 `x = 1`, `y = 0`이에요.
- **주의**: `np.int32`는 내림(floor)이 아니라 **0 쪽으로 버림**이에요. `np.int32(-0.3) = 0`이지만 `np.floor(-0.3) = -1`이에요. 지금은 좌표가 항상 0 이상이라 괜찮지만, 회전처럼 음수 좌표가 나올 수 있는 곳(Part 5)에서는 `contain()`으로 미리 걸러 줘야 해요.

### ② 경계 처리: 오른쪽·아래 끝에서 한 칸 물러나기
왜 필요할까요? 원본이 4열(x = 0~3)인데 `x = 3`이면:
```
img[y:y+2, 3:5]  →  열 3 하나만 나옴 (열 4는 없음)
→ 값이 2개뿐이라 P1, P2, P3, P4 네 개로 못 나눔 → ValueError 💥
```
그래서 `x`가 마지막 열(`w−1`) 이상이면 한 칸 왼쪽으로 옮겨서 **항상 2×2 블록을 꺼낼 수 있게** 해요. 그러면 β는 1 이상이 돼요.

```
보통:      x ≤ pt.x < x+1    → β ∈ [0, 1)       ✅ 보간 (사이 값)
경계 보정: x를 하나 줄였으니 → β ≥ 1            ⚠️ 외삽 (바깥으로 연장)
```

**실제로 일어나요.** 350×400으로 키울 때 마지막 열 `j = 349`는 `x = 349 / 2.482 = 140.597`이에요. 원본 마지막 열이 140이니까 `x = 139`로 물러나고 **β = 1.597**이 돼요. P1–P2를 이은 직선을 P2 너머로 **연장(외삽)**해서 읽는 셈이에요.

### ③ 4화소 꺼내기: `.flat`의 순서와 `float32`
```
img[y:y+2, x:x+2]   →   [[P1, P2],
                         [P3, P4]]
.flat               →   P1, P2, P3, P4    ← 행 우선(왼→오, 위→아래) 순서
```
Part 0에서 본 "책 읽는 순서" 그대로예요.

**`np.float32`로 바꾸는 이유**가 중요해요.

> **📚 복습: uint8 넘침** (Chapter06 `03_OpenCV기초`)
> uint8은 0~255만 담아요. 범위를 벗어나면 한 바퀴 돌아요.
> ```
> np.uint8(40) − np.uint8(120)  =  176     ← −80이어야 하는데!
> ```
> ⑤의 `P3 − P1`, `P4 − P2`는 **음수가 자주 나와요**(3-3에서 `20 − 90 = −70`). float로 바꾸지 않으면 엉뚱한 값이 나와요.

### ④ 소수 부분
```
alpha = pt[1] − y  = 0.6 − 0 = 0.6     (세로, y 쪽)
beta  = pt[0] − x  = 1.3 − 1 = 0.3     (가로, x 쪽)
```
`pt[1]`이 y, `pt[0]`이 x예요. `pt`가 (x, y) 순서라서 그래요. **α는 세로, β는 가로**라는 걸 기억하세요.

### ⑤⑥ 3-2의 공식 그대로

### ⑦ `np.clip(P, 0, 255).astype(np.uint8)`: 범위 자르기 + 정수 변환
**clip이 필요한 이유는 ②의 외삽 때문이에요.** 3-4-c에서 "보간이면 결과가 4화소 범위 안"이라고 했는데, β ≥ 1인 외삽은 **범위를 벗어날 수 있어요.** 실제 예로 3×4 배열에서 `pt = (3.5, 0)`이면:
```
x = 3 → ②에서 2로 보정, β = 1.5, α = 0
P1 = 90, P2 = 30
P = 90 + 1.5 × (30 − 90) = 90 − 90 = 0        ← 범위 끝까지 감
pt = (3.9, 0)이었다면 → 90 + 1.9 × (−60) = −24  → clip → 0
```

**`.astype(np.uint8)`은 반올림이 아니라 버림이에요.** 실제 목적 화소 `(i=160, j=150)` 하나를 따라가 볼게요.
```
pt = (150/2.482, 160/2.667) = (60.4286, 60.0)
x=60, y=60  →  img[60:62, 60:62] = [[57, 54],
                                    [65, 57]]
α = 0.0,  β = 0.4286
M1 = 57 + 0 × (65 − 57) = 57
M2 = 54 + 0 × (57 − 54) = 54
P  = 57 + 0.4286 × (54 − 57) = 57 − 1.286 = 55.71
astype(uint8) → 55     (반올림이었다면 56)
```
이 1 차이도 3-7의 "OpenCV와 다른 이유" 중 하나예요.

> 📝 `Common/interpolation.py`의 `bilinear_value`는 마지막 `.astype(np.uint8)`이 없고 float로 돌려줘요. 이 함수를 쓰는 바깥 코드가 나중에 한꺼번에 uint8로 바꿔요. 동작은 같아요.

## 3-6. `scaling_bilinear` 해부: 이중 리스트 컴프리헨션

```python
def scaling_bilinear(img, size):
    ratioY, ratioX = np.divide(size[::-1], img.shape[:2])
    dst = [[ bilinear_value(img, (j/ratioX, i/ratioY))     # 안쪽: 한 화소 값
             for j in range(size[0])]                      # 안쪽 루프: 열 (가로 350)
           for i in range(size[1])]                        # 바깥 루프: 행 (세로 400)
    return np.array(dst, img.dtype)
```

### 3-6-a. 리스트 컴프리헨션을 for문으로 풀면
```python
dst = []
for i in range(size[1]):            # 목적의 행 0..399     ← 바깥 대괄호
    row = []
    for j in range(size[0]):        # 목적의 열 0..349     ← 안쪽 대괄호
        pt = (j / ratioX, i / ratioY)          # 역방향 사상! (x, y) 순서
        row.append(bilinear_value(img, pt))
    dst.append(row)
dst = np.array(dst, img.dtype)      # 400개 리스트(각 350개) → (400, 350) 배열
```
**읽는 법**: 리스트 컴프리헨션에서는 `for`가 **뒤에 쓰인 것이 바깥 루프**예요. 결과 모양은 **바깥 = 행, 안쪽 = 열**이에요.

### 3-6-b. Part 2와 같은 점, 다른 점

| | Part 2 `scaling_nearest` | Part 3 `scaling_bilinear` |
|---|---|---|
| 사상 | 역방향 (목적을 돎) | 역방향 (목적을 돎) |
| 역공식 | `i/ratioY`, `j/ratioX` | 같음 |
| 소수 처리 | `int()`로 하나 고름 | `bilinear_value`로 4개 섞음 |
| 구현 | meshgrid 벡터화 | **파이썬 이중 루프** (함수 호출 140,000번) |

### 3-6-c. 그래서 느려요

**이 PC에서 실제로 잰 시간** (150×141 → 400×350):

| 방법 | 시간 |
|---|---|
| 직접 만든 최근접 이웃 (벡터화) | 3.8 ms |
| **직접 만든 양선형 (루프)** | **1,135 ms** (1.1초!) |
| `cv2.resize(INTER_LINEAR)` | 4.4 ms |

OpenCV는 양선형인데도 직접 만든 루프 버전보다 **약 250배 빨라요.** Part 1에서 말한 "창구 접수 vs 트럭"에, OpenCV는 C++ 최적화와 SIMD(한 번에 여러 화소 계산)까지 더해져서 그래요. **직접 구현은 원리를 이해하는 용도, 실전은 OpenCV**라고 생각하면 돼요.

## 3-7. `cv2.resize`와 비교

### 3-7-a. 결과 눈으로 비교: 같은 줄을 두 방식으로

원본 행 60의 x = 60~63 `[57, 54, 81, 74]`를 키운 결과, 목적 행 160의 열 149~158이에요.

```
최근접 이웃: [57 57 57 54 54 81 81 81 74 74]      ← 값이 "툭툭" 바뀜 (계단)
양선형:      [56 55 54 60 71 80 77 75 72 70]      ← 54 → 60 → 71 → 80 매끄럽게 올라감

  값
  80 ┤             ┌──────┐                       ●
     │             │      └───┐               ●       ●  ●
  70 ┤             │          └──           ●              ●  ●
     │             │                                          
  60 ┤             │                      ●                   
     │ ──────┐     │               ● ● ●                     
  50 ┤       └─────┘                                         
       최근접 이웃 (계단)                  양선형 (경사로)
```
**계단이 경사로가 돼요.** Part 2의 깍두기가 사라지고 대신 **살짝 뿌옇게** 보여요. 섞으니까 날카로운 경계도 같이 부드러워지기 때문이에요.

### 3-7-b. 직접 만든 양선형 vs OpenCV 양선형: 왜 다를까?

실제로 두 결과를 화소별로 비교하면:
```
평균 차이 3.10,  최대 차이 67,  완전히 같은 화소 27%
```
꽤 달라요! 원인은 **화소 중심을 맞추는 방식**이에요(Part 2-4 ③ 기억나시죠?).

```
직접 만든 코드:   x = j / ratioX                       ← 화소의 "왼쪽 위 모서리" 기준
OpenCV:          x = (j + 0.5) / ratioX − 0.5          ← 화소의 "중심" 기준
```

```
목적 화소 j=0 (배율 2.5)
                    직접 코드: 0 / 2.5 = 0.0
                    OpenCV: (0 + 0.5) / 2.5 − 0.5 = −0.3 → 0으로 고정

목적 화소 j=5
                    직접 코드: 5 / 2.5 = 2.0
                    OpenCV: (5.5) / 2.5 − 0.5 = 1.7
                                                ↑ 0.3칸 차이
```

직접 만든 코드는 그림 전체가 **오른쪽 아래로 약 0.3~0.7 원본 화소만큼 밀려** 있어요. 경계(밝기가 확 바뀌는 곳) 근처에서는 이 작은 밀림이 큰 값 차이(최대 67)를 만들어요.

**검증**: 직접 코드를 OpenCV 방식 `(j+0.5)/ratio − 0.5`로 바꿔서 다시 비교하면:
```
평균 차이 0.368,  화소의 99.9%가 차이 1 이하
```
남은 1 차이는 3-5 ⑦의 **버림 vs 반올림**, 그리고 OpenCV 내부의 고정소수점 계산 때문이에요. 몇 군데 남은 큰 차이는 이미지 테두리에서 생겨요. 직접 코드는 테두리에서 외삽(②)하고 OpenCV는 테두리 값을 고정하는 차이예요.

> 📚 참고로 Pillow `Image.BILINEAR`와 OpenCV `INTER_LINEAR`는 같은 이미지에서 평균 차이 0.19, 최대 1이었어요. 둘 다 **화소 중심 방식**이라서 거의 같아요.

### 3-7-c. ⚠️ 이 파일의 진짜 버그: `dst4`는 최근접 이웃이 아니에요!

```python
dst3 = cv2.resize(image, size, 0, 0, cv2.INTER_LINEAR)
dst4 = cv2.resize(image, size, 0, 0, cv2.INTER_NEAREST)
```

`cv2.resize`의 인자 순서를 보면:
```
cv2.resize(src, dsize, dst, fx, fy, interpolation)
            ①     ②    ③   ④   ⑤       ⑥
```

코드를 이 순서에 맞춰 보면:
```
cv2.resize(image, size,  0,   0,  cv2.INTER_NEAREST)
            src   dsize  dst  fx  fy ← 여기!          interpolation ← 안 넣음 → 기본값 INTER_LINEAR
```
`INTER_NEAREST`가 **5번째 자리 `fy`**에 들어가 버렸어요. 보간 방법은 아무것도 지정하지 않은 셈이라 **기본값 `INTER_LINEAR`**가 쓰여요. (`dsize`를 줬으니 fx, fy는 무시돼서 에러도 안 나요.)

**실제 확인 결과**
```
dst4 == cv2.resize(..., interpolation=cv2.INTER_NEAREST)  →  False
dst4 == cv2.resize(..., interpolation=cv2.INTER_LINEAR)   →  True   ← 정체는 양선형
```
그래서 "OpenCV_Nearest" 창은 **양선형 결과**를 보여 줘요. dst3는 우연히 원하던 결과가 나온 거고요(기본값이 마침 LINEAR라서요).

**고치는 법**: 키워드 인자로 이름을 붙여 주세요.
```python
dst3 = cv2.resize(image, size, interpolation=cv2.INTER_LINEAR)
dst4 = cv2.resize(image, size, interpolation=cv2.INTER_NEAREST)
```
> 💡 **교훈**: OpenCV 함수는 중간에 `dst` 같은 선택 인자가 끼어 있는 경우가 많아요. 뒤쪽 인자는 **항상 키워드로** 넘기는 습관을 들이세요. 에러 없이 조용히 틀리는 버그가 Part 0의 `resize(img, img.shape)`처럼 제일 무서워요.

### 3-7-d. OpenCV 보간법 지도

| 플래그 | 참고하는 화소 | 특징 | 언제 쓰나 |
|---|---|---|---|
| `INTER_NEAREST` | 1개 | 가장 빠름, 계단 | 마스크, 라벨, 픽셀아트 |
| `INTER_LINEAR` | 2×2 = 4개 | 부드러움, 약간 흐림 (**기본값**) | 일반적인 확대, 실시간 처리 |
| `INTER_CUBIC` | 4×4 = 16개 | 3차 곡선으로 섞음, 더 선명 | 품질 중요한 확대 (Part 9의 `10` 파일에서 사용) |
| `INTER_AREA` | 덮이는 영역 전체 | **평균**을 냄 | **축소할 때 1순위** |
| `INTER_LANCZOS4` | 8×8 = 64개 | 가장 선명, 가장 느림 | 고품질 확대 |

**축소에서는 왜 LINEAR가 아니라 AREA일까?** LINEAR도 결국 **4화소만** 봐요. 1/4로 줄이면 원본 4×4 = 16화소가 목적 1화소로 모이는데, LINEAR는 그중 4개만 보고 나머지 12개는 무시해요. Part 1~2의 "정보 버림" 문제가 그대로 남아요. AREA는 16개를 **다 평균**해요.

실제로 150×141을 40×35로 줄였을 때, 같은 행의 값을 비교하면:
```
NEAREST: [238 233 231  62  66  63]     ← 밝다가 갑자기 어두움 (하나만 골라서)
LINEAR:  [243 228  84  99  96  77]
AREA:    [239 196 121  89  90  79]     ← 경계가 평균으로 자연스럽게 이어짐
```

이제 각 단계에서 무슨 일이 있었는지 설명할 수 있어요.

| 단계 | 일어난 일 | 배운 Part |
|---|---|---|
| `.resize((48, 27))` | 원본 화소 대부분이 **버려지거나 평균**됨. 세부 정보가 영원히 사라짐 | Part 1~2 축소의 정보 손실, 3-7-d |

**보간은 "없는 정보를 만들어 내는 마법"이 아니라, 있는 화소 사이를 그럴듯하게 이어 주는 추측일 뿐이에요.** 그래서 한 번 버린 정보는 돌아오지 않아요. 이걸 진짜로 "복원"하려는 게 딥러닝 초해상도(Super Resolution)인데, 그건 학습된 지식으로 디테일을 **새로 그려 넣는** 다른 차원의 방법이에요.
