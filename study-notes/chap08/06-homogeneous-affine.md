## 6-1. 문제 제기: 이동만 "따돌림"당한다

지금까지 배운 변환을 행렬로 써 볼게요.

| 변환 | 식 | 2×2 행렬 곱으로 쓸 수 있나? |
|---|---|---|
| 크기 변경 (Part 1~3) | `x' = sx·x`, `y' = sy·y` | ✅ `[[sx, 0], [0, sy]] · (x, y)` |
| 회전 (Part 5) | `x' = c·x − s·y`, `y' = s·x + c·y` | ✅ `[[c, −s], [s, c]] · (x, y)` |
| 평행 이동 (Part 4) | `x' = x + tx`, `y' = y + ty` | ❌ **곱셈이 아니라 덧셈** |

### 6-1-a. 한 줄 증명: 2×2 행렬로는 이동을 절대 못 만든다

어떤 2×2 행렬이든 **원점 (0, 0)에 곱하면 결과는 항상 (0, 0)**이에요.
```
┌ a  b ┐ ┌ 0 ┐   ┌ a·0 + b·0 ┐   ┌ 0 ┐
└ c  d ┘ └ 0 ┘ = └ c·0 + d·0 ┘ = └ 0 ┘      ← a, b, c, d가 뭐든
```
그런데 평행 이동은 원점을 `(tx, ty)`로 **옮겨야** 해요. 그래서 불가능해요. 증명 끝.

### 6-1-b. 왜 굳이 "행렬 하나"로 쓰고 싶을까?

Part 5의 중심 기준 회전을 떠올려 보세요. **빼기(이동) → 행렬 곱(회전) → 더하기(이동)** 세 단계를 화소마다 했어요. 이걸 **행렬 하나로** 쓸 수 있다면:

1. **합치기**: 변환 여러 개를 행렬 곱으로 미리 합쳐 두고, 화소마다는 **곱셈 한 번**만 하면 돼요 (Part 7).
2. **되돌리기**: 역변환이 그냥 **역행렬**이에요 (6-7).
3. **함수 하나**: OpenCV의 `warpAffine(img, M, size)` 하나로 이동, 회전, 크기, 기울이기를 전부 처리해요.

## 6-2. 해결사: 동차 좌표 `(x, y, 1)`

### 6-2-a. 트릭: 좌표 끝에 1을 붙인다

```
(x, y)   →   (x, y, 1)
```
이렇게 **항상 1인 세 번째 성분**을 붙인 걸 **동차 좌표(homogeneous coordinates)**라고 해요.

### 6-2-b. 그러면 2×3 행렬로 이동까지 된다

```
┌ x' ┐   ┌ a  b  c ┐ ┌ x ┐   ┌ a·x + b·y + c·1 ┐
│    │ = │         │ │ y │ = │                 │
└ y' ┘   └ d  e  f ┘ └ 1 ┘   └ d·x + e·y + f·1 ┘
                                         ↑
                           세 번째 열 × 1 = 그냥 "더하기"가 됨!
```

**세 번째 열(c, f)이 1과 곱해져서 덧셈 역할**을 해요. 이게 트릭의 전부예요.

🧠 **비유**: **곱셈만 할 줄 아는 계산기**에게 "+30"을 시키고 싶어요. 그러면 입력에 **항상 1을 하나 끼워 넣고**, 그 1에 30을 곱하게 하면 돼요. `30 × 1 = 30`이니까 결과적으로 30을 더한 셈이에요. 동차 좌표의 1은 **덧셈을 곱셈으로 위장시키는 손잡이**예요.

### 6-2-c. 숫자로 확인: 점 (10, 5)를 오른쪽 30, 아래 80 이동

```
T = ┌ 1  0  30 ┐        T · (10, 5, 1)
    └ 0  1  80 ┘
                       첫째 줄: 1·10 + 0·5 + 30·1 = 40
                       둘째 줄: 0·10 + 1·5 + 80·1 = 85      → (40, 85) ✅
```
실제 실행 결과도 `[40. 85.]`예요. Part 4-7-b에서 "일단 믿고 넘어가자"고 했던 `[[1, 0, tx], [0, 1, ty]]`의 정체가 이거예요.

### 6-2-d. 2×3 vs 3×3

2×3 행렬에 `[0, 0, 1]` 행을 하나 더 붙이면 3×3이 돼요.
```
┌ x' ┐   ┌ a  b  c ┐ ┌ x ┐
│ y' │ = │ d  e  f │ │ y │
└ 1  ┘   └ 0  0  1 ┘ └ 1 ┘    ← 결과의 세 번째도 0·x + 0·y + 1·1 = 1 그대로
```

| 형태 | 장점 | 쓰는 곳 |
|---|---|---|
| **2×3** | 군더더기 없음 | OpenCV `warpAffine`, `getAffineTransform`, `getRotationMatrix2D`가 주고받는 형태 |
| **3×3** | 결과도 `(x', y', 1)`이라 **또 곱할 수 있음**, 정사각 행렬이라 `np.linalg.inv`로 역행렬 가능 | 변환 합성 (Part 7), 원근 변환 (Part 9) |

> 🔖 **예고**: "동차"라는 이름은 `(x, y, 1)`과 `(2x, 2y, 2)`를 **같은 점**으로 보는 규칙에서 왔어요. 지금은 세 번째 성분이 항상 1이라서 신경 쓸 필요가 없어요. Part 9 원근 변환에서 세 번째 성분이 1이 아닌 값 w가 되고, **w로 나누는** 과정이 등장해요.

## 6-3. 변환별 2×3 행렬 카탈로그

변이 100인 정사각형 `(0,0) (100,0) (100,100) (0,100)`이 각 변환에서 어떻게 되는지 볼게요.

| 변환 | 2×3 행렬 | 식 | 정사각형 꼭짓점의 결과 |
|---|---|---|---|
| **이동** | `[[1, 0, tx], [0, 1, ty]]` | `x+tx, y+ty` | 모양 그대로 위치만 이동 |
| **크기** | `[[sx, 0, 0], [0, sy, 0]]` | `sx·x, sy·y` | sx=2, sy=1 → `(0,0) (200,0) (200,100) (0,100)` |
| **회전** (`05` 방식, 화면 시계) | `[[c, −s, 0], [s, c, 0]]` | Part 5 | 원점 기준으로 돌아감 |
| **회전** (OpenCV 방식, 화면 반시계) | `[[c, s, 0], [−s, c, 0]]` | | |
| **전단 (shear)** | `[[1, k, 0], [0, 1, 0]]` | `x + k·y, y` | k=0.5 → `(0,0) (100,0) (150,100) (50,100)` |
| **좌우 반사** | `[[−1, 0, w−1], [0, 1, 0]]` | `(w−1) − x, y` | w=320 → `(319,0) (219,0) (219,100) (319,100)` |

**전단(shear)** 은 처음 보는 거라 그림으로 볼게요. **아래로 갈수록(y가 클수록) 오른쪽으로 더 밀려요.**
```
     원본                      전단 k = 0.5
 (0,0)────(100,0)           (0,0)────(100,0)
   │         │                 ╲         ╲
   │         │      →           ╲         ╲
   │         │                   ╲         ╲
 (0,100)──(100,100)            (50,100)──(150,100)
                            y=0 줄은 안 밀리고, y=100 줄은 50만큼 밀림
```
🧠 비유: **카드 한 묶음**을 옆에서 슬쩍 밀면 위 카드는 그대로고 아래 카드일수록 더 밀리죠. 그 모양이에요. 이탤릭체 글씨가 전단 변환이에요.

**반사**에서 `w−1`을 더하는 이유는, `−x`만 하면 그림이 전부 음수 영역(캔버스 왼쪽 밖)으로 가 버리기 때문이에요. 반사한 뒤 **평행 이동으로 캔버스 안에 다시 넣는** 거예요. 실전에서는 `cv2.flip(img, 1)`을 쓰면 돼요.

## 6-4. 어파인 변환: 일반형과 성질

### 6-4-a. 일반형: 숫자 6개

```
x' = a·x + b·y + c                ┌ a  b │ c ┐     A = ┌ a  b ┐  (2×2: 회전·크기·전단·반사)
y' = d·x + e·y + f         →      └ d  e │ f ┘         └ d  e ┘
                                    A    │ t            t = (c, f) (이동)
```
**자유롭게 정할 수 있는 숫자가 6개**예요(자유도 6). 6-3의 모든 변환과 그 조합은 이 6개 숫자를 특정하게 고른 **특수한 경우**예요. 이렇게 "선형 변환 A + 이동 t"로 이루어진 변환을 **어파인(affine) 변환**이라고 해요.

### 6-4-b. 📐 핵심 성질 증명: 이동은 "차이"에서 사라진다

두 점 p, q를 변환하고 **그 차이(벡터)**를 보면:
```
p' − q' = (A·p + t) − (A·q + t) = A·(p − q)       ← t가 빠져서 사라짐!
```
**두 점 사이의 벡터는 A만 받고 이동 t의 영향은 받지 않아요.** 여기서 성질이 전부 나와요.

| 성질 | 왜 그런가 |
|---|---|
| **직선 → 직선** | 직선 위의 점 `p + k·v`는 `A·p + t + k·(A·v)`로 가요. 여전히 "한 점 + k × 방향"이라 직선이에요 |
| **평행 → 평행** | 평행한 두 선의 방향 벡터가 v와 m·v면, 변환 후 A·v와 m·A·v라서 여전히 평행해요 |
| **비율 보존** (중점 → 중점) | 선분 위 비율 k가 그대로 유지돼요 |
| ❌ 길이 | A가 늘이거나 줄일 수 있어요 |
| ❌ 각도 | A가 기울일 수 있어요 (전단) |

### 6-4-c. 숫자로 확인: `07`의 aff_mat으로 직사각형 변환하기

100×50 직사각형 `A(0,0) B(100,0) C(100,50) D(0,50)`을 6-5에서 구할 `aff_mat`으로 변환한 실제 결과예요.

```

B (100, 0)   → (210.26,   3.07)
C (100, 50)  → (179.91,  52.31)
D (0, 50)    → (111.66, −21.99)
```

| 확인 | 계산 | 결과 |
|---|---|---|
| 평행 ① | 벡터 AB vs DC | `(68.25, 74.30)` = `(68.25, 74.30)` ✅ 평행하고 길이도 같음 |
| 평행 ② | 벡터 AD vs BC | `(−30.35, 49.24)` = `(−30.35, 49.24)` ✅ |
| 중점 | AB의 중점 (50, 0) 변환 vs A', B'의 평균 | `(176.13, −34.08)` = `(176.13, −34.08)` ✅ |

## 6-5. `cv2.getAffineTransform`: 점 3쌍으로 행렬 구하기

### 6-5-a. 왜 점 3쌍인가

미지수는 a, b, c, d, e, f로 **6개**예요. 점 한 쌍 `(x, y) → (x', y')`은 **방정식 2개**(x'에 대해 하나, y'에 대해 하나)를 줘요. 그래서 **3쌍 = 방정식 6개**면 미지수 6개를 정확히 풀 수 있어요.

### 6-5-b. `07`의 숫자로 방정식 세우기

```
pt1 (원본)       pt2 (목적)
(30,  70)   →   (120,  20)
(20, 240)   →   ( 10, 180)
(300, 110)  →   (280, 260)
```

```
x' 방정식 (a, b, c를 구함)              y' 방정식 (d, e, f를 구함)
 30a +  70b + c = 120                    30d +  70e + f =  20
 20a + 240b + c =  10                    20d + 240e + f = 180
300a + 110b + c = 280                   300d + 110e + f = 260
```
**x' 방정식과 y' 방정식이 서로 독립**이라서 3×3 연립방정식 **두 개**로 나눠 풀 수 있어요. 둘의 계수 행렬은 똑같아요.

```
    ┌  30   70   1 ┐ ┌ a ┐   ┌ 120 ┐           ┌  30   70   1 ┐ ┌ d ┐   ┌  20 ┐
    │  20  240   1 │ │ b │ = │  10 │           │  20  240   1 │ │ e │ = │ 180 │
    └ 300  110   1 ┘ └ c ┘   └ 280 ┘           └ 300  110   1 ┘ └ f ┘   └ 260 ┘
          P                                          P
```

### 6-5-c. numpy로 직접 풀기

```python
P = np.array([[x, y, 1] for x, y in pt1])        # 계수 행렬
abc = np.linalg.solve(P, pt2[:, 0])              # x' 값들 [120, 10, 280]
def_ = np.linalg.solve(P, pt2[:, 1])             # y' 값들 [20, 180, 260]
```

**실제 결과**
```
abc = [ 0.6825  -0.6069  142.0086]
def = [ 0.7430   0.9849  -71.2311]

cv2.getAffineTransform(pt1, pt2) =
[[  0.6825  -0.6069  142.0086]        ← abc와 똑같음 ✅
 [  0.7430   0.9849  -71.2311]]       ← def와 똑같음 ✅
```
**`getAffineTransform`은 내부에서 이 연립방정식을 푸는 함수예요.** 신비로운 건 없어요.

### 6-5-d. 검산: pt1이 정말 pt2로 가나?

```
M · (30, 70, 1)   = 0.6825·30 − 0.6069·70 + 142.0086 = 20.47 − 42.48 + 142.01 = 120.00
                    0.7430·30 + 0.9849·70 − 71.2311  = 22.29 + 68.94 − 71.23  =  20.00   → (120, 20) ✅
M · (20, 240, 1)  → (10, 180)   ✅
M · (300, 110, 1) → (280, 260)  ✅
```

### 6-5-e. ⚠️ 세 점이 일직선이면?

계수 행렬 P의 행렬식(det)이 이번엔 −46,300이라 0이 아니어서 풀렸어요. 그런데 세 점이 `(0,0) (10,10) (20,20)`처럼 **한 줄 위에** 있으면 **det = 0**이 돼서 해가 하나로 정해지지 않아요.

🧠 **직관**: 어파인 변환은 **삼각형 → 삼각형** 대응이에요. 세 점이 한 줄이면 삼각형이 납작하게 찌그러진 거라, 그 줄 바깥 방향으로 어떻게 변환해야 할지 정보가 없어요. 그래서 **세 점은 넓게 퍼진 삼각형**이 되도록 고르는 게 좋아요(Part 8의 `09` 기본값 `(30,30) (450,30) (200,370)`이 그래요).

## 6-6. `cv2.getRotationMatrix2D` 해부: 세 번째 열의 비밀

Part 5-4-c에서 미뤘던 숙제예요.

### 6-6-a. 유도

중심 `(cx, cy)` 기준 회전 = **−중심 이동 → 회전 → +중심 이동** (Part 5-6). OpenCV 방식 회전 행렬 `[[α, β], [−β, α]]`(α = scale·cos θ, β = scale·sin θ)으로 쓰면:

```
x' = α·(x − cx) + β·(y − cy) + cx
y' = −β·(x − cx) + α·(y − cy) + cy

괄호를 풀고 x, y, 상수항끼리 모으면:
x' = α·x + β·y + [ (1 − α)·cx − β·cy ]
y' = −β·x + α·y + [ β·cx + (1 − α)·cy ]
                   └──── 세 번째 열 ────┘

         ┌  α   β   (1−α)·cx − β·cy ┐
M  =     │                          │
         └ −β   α   β·cx + (1−α)·cy ┘
```
OpenCV 공식 문서에 적힌 식과 정확히 같아요. **세 번째 열은 "중심을 원점으로 보냈다가 다시 데려오는" 두 번의 이동이 합쳐진 결과**예요.

### 6-6-b. `07`의 숫자로 검산: center = (200, 200), 30°, scale 1

```
α = cos 30° = 0.8660,   β = sin 30° = 0.5

(1 − α)·cx − β·cy = 0.1340 × 200 − 0.5 × 200 = 26.79 − 100 = −73.21
β·cx + (1 − α)·cy = 0.5 × 200 + 0.1340 × 200 = 100 + 26.79 = 126.79
```
실제 `getRotationMatrix2D((200, 200), 30, 1)` 출력:
```
[[  0.866    0.5    -73.2051]
 [ -0.5      0.866  126.7949]]     ✅
```
**중심이 제자리에 있는지 확인**: `M · (200, 200, 1) = (200, 200)` ✅ 회전축은 안 움직여야 하니까 맞아요.

Part 5-4-c에서 봤던 `(180, 180), 20°` 행렬의 `−50.71, 72.42`도 같은 식으로 나와요.
```
(1 − 0.9397)·180 − 0.3420·180 = 10.85 − 61.56 = −50.71 ✅
0.3420·180 + (1 − 0.9397)·180 = 61.56 + 10.85 =  72.42 ✅
```

## 6-7. `cv2.invertAffineTransform`: 역행렬

### 6-7-a. 왜 필요한가

`aff_mat`은 **원본 → 목적**(순방향)이에요. 그런데 우리는 Part 2부터 줄곧 **역방향 사상**(목적 → 원본)을 써요. 그래서 역변환이 필요해요. 크기 변경에서는 나눗셈, 회전에서는 −θ였는데, 일반 어파인에서는 **역행렬**이에요.

### 6-7-b. 📐 유도

```
순방향:  p' = A·p + t
         p' − t = A·p
         A⁻¹·(p' − t) = p
역방향:  p = A⁻¹·p' − A⁻¹·t

역행렬 (2×3):  [ A⁻¹  │  −A⁻¹·t ]
```

2×2 역행렬은 공식이 있어요.
```
A = ┌ a  b ┐        A⁻¹ = 1 / (ad − bc) · ┌  d  −b ┐
    └ d' e ┘                               └ −d'  a ┘     (det = ad − bc ≠ 0 이어야 함)
```

### 6-7-c. 숫자로

```
A = [[0.6825, −0.6069],          det A = 1.1231
     [0.7430,  0.9849]]

A⁻¹ = [[ 0.8769, 0.5404],
       [−0.6615, 0.6077]]

−A⁻¹·t = (−86.04, 137.23)

cv2.invertAffineTransform(aff_mat) =
[[  0.8769   0.5404  -86.0385]
 [ -0.6615   0.6077  137.2308]]     ✅ 손 계산과 같음
```

**3×3으로 바꿔서 `np.linalg.inv`를 써도 같아요.**
```
np.linalg.inv([[0.6825, −0.6069, 142.0086],
               [0.7430,  0.9849, −71.2311],
               [0,       0,        1     ]])
= [[  0.8769   0.5404  -86.0385]
   [ -0.6615   0.6077  137.2308]
   [  0.       0.       1.     ]]     ✅ (6-2-d에서 말한 3×3의 장점)
```

**검산: pt2를 넣으면 pt1이 나오나?**
```
inv · (120, 20, 1)  = (30, 70)   ✅
inv · (10, 180, 1)  = (20, 240)  ✅
inv · (280, 260, 1) = (300, 110) ✅
```

> 💡 **det A = 1.1231의 의미**: 2×2 행렬의 행렬식은 **넓이가 몇 배가 되는지**를 나타내요. 이 변환은 넓이를 약 1.12배로 만들어요. det이 0이면 넓이가 0이 된다는 뜻이라(평면이 선으로 짜부라짐) 되돌릴 수 없고, 그래서 역행렬도 없어요. 6-5-e의 "세 점이 일직선이면 안 된다"와 같은 이야기예요.

## 6-8. `affine_transform` vs `cv2.warpAffine`

### 6-8-a. 직접 구현 해부

```python
def affine_transform(img, mat):
    rows, cols = img.shape[:2]                                          # 330, 320
    inv_mat = cv2.invertAffineTransform(mat)                            # ① 역행렬 (6-7)
    pts = [np.dot(inv_mat, (j, i, 1)) for i in range(rows) for j in range(cols)]   # ②
    dst = [bilinear_value(img, p) if contain(p, size) else 0 for p in pts]          # ③
    dst = np.reshape(dst, (rows, cols)).astype('uint8')                 # ④
    return dst
```

| 줄 | 하는 일 | 포인트 |
|---|---|---|
| ① | 역행렬 | 역방향 사상용 |
| ② | 목적의 **모든 (j, i)**를 동차 좌표 `(j, i, 1)`로 만들어 역행렬을 곱함 → 원본 `(x, y)` 105,600개 목록 | `np.dot(2×3, 3)` = 길이 2 벡터. **(x, y) 순서** |
| ③ | 범위 안이면 양선형 보간, 밖이면 0 | `contain(p, size)`: p는 (x, y), size는 (w, h) → **짝이 맞음** ✅ |
| ④ | 1차원 목록을 (330, 320)으로 접고 uint8로 | `Common`의 `bilinear_value`는 float를 돌려줘서 여기서 변환 |

> 📝 Part 4에서 `contain`은 `(y, x)`와 `shape`의 짝으로 썼는데, 여기서는 `(x, y)`와 `size`의 짝으로 써요. **짝만 맞으면** 둘 다 맞아요. 다만 이 함수는 함수 밖의 **전역 변수 `size`**를 몰래 쓰고 있어서, 다른 파일로 옮기면 깨져요. `Common/interpolation.py` 버전은 `img.shape[::-1]`로 고쳐져 있어요.

### 6-8-b. 화소 세 개 끝까지 따라가기

**① 목적 (i=20, j=120): pt2[0]의 자리**
```
inv · (120, 20, 1) = (29.999999999999986, 70.0)    ← 30이 아니라 29.99999…!
bilinear_value:
   x = int(29.99999…) = 29,  y = 70
   β = 0.99999…  →  img[70, 29] = 72 를 0.00000…%, img[70, 30] = 100 을 99.99999…% 섞음
   P = 99.9999999999996
astype('uint8') → 99            ← 원본 img[70, 30] = 100인데 99가 됨!
```
소수 오차(Part 1-4) + 버림(Part 3-5 ⑦)이 겹쳐서 **1이 깎였어요.** 반올림(`np.round`)을 한 번 넣으면 해결돼요. OpenCV 결과와 1씩 차이 나는 이유 중 하나예요.

**② 목적 (i=100, j=200): 평범한 안쪽 화소**
```
inv · (200, 100, 1) = (143.38, 65.69)
img[65:67, 143:145] = [[203, 200],
                       [202, 200]]
양선형 → 201.42 → 201
```

**③ 목적 (i=5, j=5): 바깥**
```
inv · (5, 5, 1) = (−78.95, 136.96)   → x가 음수 → contain False → 0 (검정)
```

### 6-8-c. `cv2.warpAffine`은 순방향 행렬을 받는다

```python
dst3 = cv2.warpAffine(image, aff_mat, size, ...)     # aff_mat = 순방향 (pt1 → pt2)
```
직접 구현에서는 우리가 `invertAffineTransform`을 불렀는데, `warpAffine`은 **순방향 행렬을 받아서 내부에서 알아서 역행렬을 구해** 역방향 사상을 해요. 이미 역행렬을 가지고 있다면 `flags=cv2.INTER_LINEAR | cv2.WARP_INVERSE_MAP`으로 넘길 수 있어요.

**실측 비교**

| | 직접 구현 | `cv2.warpAffine` |
|---|---|---|
| 시간 | 718 ms | **3.7 ms** |
| 결과 차이 | 평균 0.838, 화소의 **99.48%가 차이 1 이하** (테두리에서 최대 218) | |

### 6-8-d. ⚠️ Part 3과 똑같은 위치 인자 버그

```python
dst3 = cv2.warpAffine(image, aff_mat, size, cv2.INTER_LINEAR)
```
`warpAffine`의 인자 순서는 이래요.
```
cv2.warpAffine(src, M, dsize, dst, flags, borderMode, borderValue)
                ①   ②   ③     ④     ⑤
```
네 번째 자리는 `flags`가 아니라 **`dst`**예요! `cv2.INTER_LINEAR`(= 정수 1)가 dst 자리에 들어가서 **무시되고**, flags는 기본값 `INTER_LINEAR`가 쓰여요. 기본값이 마침 원하던 값이라 티가 안 났을 뿐이에요.

**증명 실험**
```
warpAffine(img, M, size, cv2.INTER_NEAREST)        == LINEAR 결과?  → True   ← 무시됨!
warpAffine(img, M, size, flags=cv2.INTER_NEAREST)  == LINEAR 결과?  → False  ← 제대로 적용
```
**고치는 법**: `cv2.warpAffine(image, aff_mat, size, flags=cv2.INTER_LINEAR)`. Part 3의 교훈 그대로, **뒤쪽 인자는 키워드로** 넘기세요.

### 6-8-e. `borderValue=255`

```python
dst4 = cv2.warpAffine(image, rot_mat, size, cv2.INTER_LINEAR, borderValue=255)
```
원본 밖(상황 ⓒ)을 **0 대신 255(흰색)**로 채워요. 실제로 dst4의 16.9%가 흰색이에요. 이건 키워드로 넘겨서 제대로 적용됐어요. 직접 구현의 `else 0`에 해당하는 부분이에요.

### 6-8-f. dst2와 dst4의 회전 방향

`rot_mat`은 OpenCV 방식이라 30°가 **화면 반시계 방향**이에요. 직접 구현 `affine_transform(image, rot_mat)`도 **같은 행렬**을 쓰니까 똑같이 반시계예요. Part 5의 `05`와 방향이 다른 이유는 **함수가 달라서가 아니라 행렬의 부호가 달라서**예요. 행렬을 손에 쥐면 방향 혼란이 사라져요.

### 6-8-g. 빨간 원으로 눈으로 검증

```python
for i in range(len(pt1)):
    cv2.circle(image, tuple(pt1[i].astype(int)), 3, (0, 0, 255), 2)   # 원본에 pt1
    cv2.circle(dst1 , tuple(pt2[i].astype(int)), 3, (0, 0, 255), 2)   # 결과에 pt2
```
원본에서 pt1이 찍힌 **무늬**가, 결과에서 pt2 원 아래에 그대로 와 있으면 성공이에요. 실제 값으로도 `dst1[180, 10] = 165`, `img[240, 20] = 165`로 같아요(pt1[1] `(20, 240)` → pt2[1] `(10, 180)`).

> 🚗 **AVM 연결**: "대응점 몇 쌍 → 연립방정식 → 변환 행렬"은 **캘리브레이션의 기본 패턴**이에요. 바닥에 놓인 체커보드나 마커의 **화면 좌표**와 **실제 바닥 좌표** 쌍을 모아 행렬을 푸는 거예요. 다만 카메라로 비스듬히 본 바닥은 평행선이 소실점으로 모여서 어파인(평행 유지)으로는 부족해요. 그래서 실무 탑뷰는 Part 9의 **원근 변환(호모그래피)**을 써요. 오늘 푼 6원 연립방정식이 Part 9에서 8원 연립방정식으로 커질 뿐이에요.

|---|---|
