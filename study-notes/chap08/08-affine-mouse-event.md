## Part 7 확인 질문 정답

| 질문 | 정답 |
|---|---|
| Q1 | **`T · C · R · O`**예요. 오른쪽부터 O(중심을 원점으로) → R(회전) → C(제자리로) → **T(마지막에 화면 기준 이동)** 순서로 적용돼요. T와 C는 둘 다 이동이라 서로 바꿔도 되니까 `C · T · R · O`도 같은 결과예요. T가 R보다 **왼쪽**에만 있으면 돼요. |
| Q2 | 균일 2배는 **`S·R = R·S`** ✅예요. `S = 2·I`(단위행렬의 2배)는 어떤 행렬과도 순서를 바꿀 수 있어요. 가로만 2배면 **다르게** 나와요. `S·R = [[2c, −2s], [s, c]]`, `R·S = [[2c, −s], [2s, c]]`예요. 늘린 다음 돌리느냐, 돌린 다음 늘리느냐에 따라 늘어나는 방향이 달라요. |
| Q3 | `M⁻¹ = O⁻¹ · R⁻¹ · C⁻¹`이에요(순서 뒤집기). **`C⁻¹ = O`, `O⁻¹ = C`**예요(+중심을 되돌리면 −중심). 그래서 `M⁻¹ = C · R(−θ) · O`, 즉 **같은 중심으로 반대 방향 회전**이에요. 직관과 딱 맞아요. |

## 📄 전체 코드 (짧아서 통째로)

```python
import numpy as np, cv2

def contain_pts(p, p1, p2):                         # p가 사각형 [p1, p2) 안에 있나   → 8-3
    return p1[0] <= p[0] < p2[0] and p1[1] <= p[1] < p2[1]

def draw_rect(title, img, pts):                     # 점마다 24×24 초록 핸들 그리기   → 8-2
    rois = [(p - small, small * 2) for p in pts]
    for (x,y), (w,h) in np.int32(rois):
        cv2.rectangle(img, (x,y,w,h), (0, 255, 0), 2)
    cv2.imshow(title, img)

def affine(img):                                    # 행렬 풀기 + 변환 + 다시 그리기   → 8-7
    aff_mat = cv2.getAffineTransform(pts1, pts2)
    dst = cv2.warpAffine(img, aff_mat, image.shape[1::-1], cv2.INTER_LINEAR)
    draw_rect("image", np.copy(image), pts1)
    draw_rect('dst', dst, pts2)

def onMouse(event, x, y, flags, param):             # 잡기 / 끌기 / 놓기             → 8-4
    global check
    if event == cv2.EVENT_LBUTTONDOWN:
        for i, p in enumerate(pts1):
            p1, p2 = p - small, p + small
            if contain_pts((x, y), p1, p2): check = i
    if event == cv2.EVENT_LBUTTONUP: check = -1
    if check >= 0:
        pts1[check] = (x, y)
        affine(np.copy(image))

image = cv2.imread('images/affine1.jpg')           # 컬러 (400, 480, 3)
small = np.array((12, 12))                          # 핸들 반쪽 크기
check = -1                                          # 지금 잡고 있는 핸들 번호 (-1 = 없음)
pts1 = np.float32([(30, 30), (450, 30), (200, 370)])    # 원본 창의 점 (움직임)
pts2 = np.float32([(30, 30), (450, 30), (200, 370)])    # 결과 창의 점 (고정)

draw_rect('image', np.copy(image), pts1)
draw_rect('dst', np.copy(image), pts2)
cv2.setMouseCallback("image", onMouse, 0)          # 마우스는 "image" 창에서만 받음
cv2.waitKey(0)
```

## 8-1. 프로그램 구조: 움직이는 점과 고정된 점

### 8-1-a. 두 창, 두 점 세트

```
     "image" 창 (원본)                         "dst" 창 (결과)
 ┌──────────────────────────┐            ┌──────────────────────────┐
 │ ▣ pts1[0]      pts1[1] ▣ │            │ □ pts2[0]      pts2[1] □ │
 │  (30,30)       (450,30)  │            │  (30,30)       (450,30)  │
 │                          │  ──────▶   │                          │
 │                          │  aff_mat   │                          │
 │          ▣ pts1[2]       │            │          □ pts2[2]       │
 │           (200,370)      │            │           (200,370)      │
 └──────────────────────────┘            └──────────────────────────┘
    ▣ 마우스로 끌 수 있음                      □ 항상 고정
```

- **pts1**: 원본 창의 핸들 3개. **마우스로 끌어요.**
- **pts2**: 결과 창의 점 3개. **절대 안 움직여요.**
- 매번 `getAffineTransform(pts1, pts2)`로 **"pts1 → pts2"** 행렬을 새로 풀어요.

### 8-1-b. 처음에는 "아무것도 안 하는" 변환

처음에는 pts1과 pts2가 똑같아서, 풀리는 행렬은:
```
cv2.getAffineTransform(pts2, pts2) = [[1, 0, 0],
                                      [0, 1, 0]]      ← 단위행렬 (Part 7-3-a의 np.eye)
```
그래서 결과 창은 원본과 똑같아요.

### 8-1-c. `image.shape[1::-1]` 복습

`affine1.jpg`는 컬러라서 shape가 `(400, 480, 3)`이에요. `warpAffine`에는 `(w, h)`를 줘야 하니까 `[1::-1]`로 `(480, 400)`을 만들어요. Part 0-3-c 그대로예요. (`[::-1]`을 썼다면 `(3, 480, 400)`이 돼서 에러가 났을 거예요.)

## 8-2. 핸들 그리기: `draw_rect`

### 8-2-a. 점 → 24×24 사각형

```python
small = np.array((12, 12))
rois = [(p - small, small * 2) for p in pts]       # (왼쪽 위 꼭짓점, 크기)
```

| 점 p | `p − small` (왼쪽 위) | `small × 2` (w, h) | 사각형 |
|---|---|---|---|
| (30, 30) | (18, 18) | (24, 24) | x 18~42, y 18~42 |
| (450, 30) | (438, 18) | (24, 24) | x 438~462, y 18~42 |
| (200, 370) | (188, 358) | (24, 24) | x 188~212, y 358~382 |

점이 사각형의 **정중앙**에 오도록 12씩 빼고, 크기는 24예요.

### 8-2-b. `np.int32(rois)`와 언패킹

`rois`는 "(배열, 배열) 튜플"의 리스트예요. `np.int32(rois)`로 한꺼번에 정수 배열로 바꾸면 shape가 `(3, 2, 2)`가 돼요.
```
[[[ 18  18]   [ 24  24]]     ← 핸들 0: (x, y), (w, h)
 [[438  18]   [ 24  24]]     ← 핸들 1
 [[188 358]   [ 24  24]]]    ← 핸들 2
```
`for (x,y), (w,h) in ...`는 이걸 한 줄씩 꺼내서 **두 겹으로 풀어요.** 그리고 `cv2.rectangle(img, (x, y, w, h), ...)`처럼 **(x, y, w, h) 튜플 하나**로 사각형을 그려요. 두 꼭짓점 `(x1, y1), (x2, y2)`을 넘기는 방식 말고도 이렇게 rect 형식으로 넘길 수 있어요.

> 📝 `cv2.rectangle`은 정수 좌표만 받아서 `np.int32`가 필요해요. `pts1`은 float32거든요. `getAffineTransform`이 **float32만** 받기 때문이에요.

## 8-4. 잡기 → 끌기 → 놓기: `onMouse`의 상태 머신

### 8-4-a. 상태 변수 `check`

**"지금 몇 번 핸들을 잡고 있나"**를 기억하는 변수 하나로 드래그를 구현해요.

```
            LBUTTONDOWN (핸들 위)
   ┌──────────────────────────────────┐
   │                                  ▼
┌──────────┐                   ┌──────────────┐
│ check=-1 │                   │ check = i    │──┐ MOUSEMOVE마다
│ (빈손)   │                   │ (i번 잡는 중) │◀─┘ pts1[i] = (x, y), 다시 그림
└──────────┘                   └──────────────┘
   ▲                                  │
   └──────────────────────────────────┘
              LBUTTONUP
```

### 8-4-b. 시간 순서로 따라가기 (핸들 0을 (30, 30)에서 (80, 30)으로 끌기)

| # | 사용자 동작 | event | 처리 | check | pts1[0] | 다시 그림? |
|---|---|---|---|---|---|---|
| 1 | 마우스를 핸들 위로 | MOUSEMOVE | 아무 조건 해당 없음 | −1 | (30, 30) | ✗ |
| 2 | (35, 32)에서 **누름** | LBUTTONDOWN | 핸들 0 사각형 안 → `check = 0` | **0** | → **(35, 32)** | ✅ |
| 3 | (50, 31)로 이동 | MOUSEMOVE | `check >= 0` → 갱신 | 0 | (50, 31) | ✅ |
| 4 | (80, 30)으로 이동 | MOUSEMOVE | 갱신 | 0 | (80, 30) | ✅ |
| 5 | **뗌** | LBUTTONUP | `check = -1` → 아래 if 통과 못 함 | **−1** | (80, 30) 유지 | ✗ |
| 6 | 마우스 이동 | MOUSEMOVE | `check < 0` | −1 | (80, 30) | ✗ |

**관찰 포인트**
- **2번에서 바로 갱신돼요.** 누른 순간 핸들 중심이 마우스 위치로 "찰칵" 붙어요(핸들 중앙에서 5화소 떨어진 곳을 잡았으면 5화소 튀어요).
- **5번(뗄 때)은 갱신이 없어요.** `check = -1`이 먼저 실행돼서 바로 아래 `if check >= 0`이 거짓이 되거든요. 4번까지의 위치가 최종이에요.
- **MOUSEMOVE는 버튼을 안 눌러도 계속 와요.** 그래서 `check`로 "지금 잡고 있을 때만" 반응하게 걸러요.

### 8-4-c. 작은 디테일 두 가지

**① `global check`는 필요하고 `global pts1`은 필요 없는 이유**
> **📚 파이썬 변수 범위**
> 함수 안에서 `check = i`처럼 **이름에 새 값을 대입**하면, 파이썬은 그걸 "함수 안의 새 지역 변수"로 봐요. 바깥 변수를 바꾸려면 `global`이 필요해요.
> `pts1[check] = (x, y)`는 이름에 대입하는 게 아니라 **바깥 배열의 내용물을 고치는** 거라서 `global`이 없어도 돼요.

**② 핸들이 겹치면?** `for` 루프에 `break`가 없어서, 클릭한 곳에 핸들이 둘 겹쳐 있으면 **번호가 큰 쪽**이 잡혀요(나중에 검사한 게 덮어쓰니까요).

## 8-5. 직관 뒤집기: 핸들을 오른쪽으로 끌면 그림은 왼쪽으로?

### 8-5-a. 실제 행렬 (핸들 0을 (80, 30)으로 끈 상태)

```
pts1 = [(80, 30), (450, 30), (200, 370)]      ← 0번만 바뀜
pts2 = [(30, 30), (450, 30), (200, 370)]      ← 고정

aff_mat = [[1.1351  0.0994  −63.79]
           [0       1         0   ]]
```

**점들이 어디로 가나**
| 원본 점 | → 결과 위치 | 의미 |
|---|---|---|
| (80, 30) | **(30, 30)** | 핸들이 가리키는 원본 점이 고정 자리 pts2[0]로 감 |
| (450, 30) | (450, 30) | 핸들 1은 그대로 |
| (200, 370) | (200, 370) | 핸들 2도 그대로 |
| (30, 30) | (−26.76, 30) | 원래 왼쪽 위에 있던 내용은 **캔버스 왼쪽 밖으로** |
| (240, 200) | (228.51, 200) | 그림 가운데도 11.5화소 **왼쪽으로** |

핸들을 **오른쪽**으로 50 끌었는데, 결과 그림의 왼쪽 위 부분은 **왼쪽**으로 50 당겨졌어요.

### 8-5-b. 왜 그럴까: 핸들의 진짜 의미

이 프로그램에서 원본 창의 핸들은 **"원본의 이 점을 결과의 고정 핀(pts2) 자리에 꽂아라"**라는 뜻이에요.

🧠 **비유: 벽에 박힌 못과 포스터.** 결과 창에는 **못 3개(pts2)**가 박혀 있어요. 원본 창의 핸들은 "포스터의 **어느 지점**을 그 못에 걸까"를 고르는 거예요. 포스터에서 더 오른쪽 지점을 못에 걸면, 포스터 전체는 **왼쪽으로** 당겨지죠.

```
원본 (포스터)                          결과 (벽)
 ┌──────────────┐                       📌(30,30)
 │ ·    ▣       │  ▣ = (80,30)를 골라   ┌──────────────
 │ (30,30)      │  ───────────────▶    ▣ 포스터의 (80,30)이 못에 걸림
 │              │                     │  → (30,30)~(80,30) 사이 내용은 왼쪽 밖으로 밀려남
```

이 방식은 Part 10의 **문서 스캐너**와 같은 발상이에요. 원본 사진에서 **"펴고 싶은 영역의 꼭짓점"을 고르면**, 그 점들이 결과의 **반듯한 고정 위치**로 가요. 그래서 이 UI가 오히려 자연스러워요.

## 8-6. 손으로 느끼는 어파인의 한계

### 8-6-a. 아무리 끌어도 평행사변형

핸들 2를 `(200, 370) → (300, 370)`으로 오른쪽으로 끌면:
```
aff_mat = [[1  −0.2941  8.82]
           [0   1       0   ]]          ← 6-3의 전단(shear) 행렬 모양!
           x' = x − 0.2941·y + 8.82,  y' = y
```
핸들 0, 1이 같은 높이(y = 30)에 고정돼 있고 핸들 2만 옆으로 움직였으니 **순수한 전단**이 돼요.

**원본 이미지 네 모서리가 가는 곳**
```
A (0, 0)      → (8.82, 0)
B (479, 0)    → (487.82, 0)
C (479, 399)  → (370.47, 399)
D (0, 399)    → (−108.53, 399)

AB = (479, 0)          = DC = (479, 0)          ✅ 평행
AD = (−117.35, 399)    = BC = (−117.35, 399)    ✅ 평행  → 평행사변형
```

### 8-6-b. 네 번째 꼭짓점은 "자동으로 정해진다"

어파인은 점 **3개**로 결정돼요. 그래서 네 번째 꼭짓점은 내 마음대로 못 정하고, 평행사변형 규칙으로 **자동** 계산돼요.
```
D' = A' + C' − B'
   = (8.82, 0) + (370.47, 399) − (487.82, 0)
   = (−108.53, 399)   ✅ 위 결과와 같음
```

```
 원하는 것 (사다리꼴)             어파인이 할 수 있는 것
      ┌────┐                         ┌─────────┐
     ╱      ╲                       ╱         ╱
    ╱        ╲                     ╱         ╱
   └──────────┘                   └─────────┘
   위아래 폭이 다름                 마주 보는 변이 항상 평행 + 길이 같음
   → ❌ 불가능                      → 3점이 정해지면 4번째는 자동
```
사진 속에서 비스듬히 찍힌 문서나 도로는 **사다리꼴**로 보여요. 그걸 반듯하게 펴려면 **네 점을 각각 자유롭게** 정할 수 있는 변환이 필요해요. 그게 Part 9의 원근 변환이에요.

### 8-6-c. 세 점을 일직선으로 만들면?

핸들 세 개를 `(30, 30) (200, 200) (370, 370)`처럼 **한 줄**에 놓으면(Part 6-5-e의 det = 0 상황):
```
cv2.getAffineTransform(일직선 3점, pts2) = [[0, 0, 0],
                                           [0, 0, 0]]      ← 에러 없이 0 행렬!
```
`warpAffine`이 이 0 행렬의 역을 구하면 역시 0 행렬이 돼서, **결과의 모든 화소가 원본의 (0, 0) 한 점**을 가리켜요. 실제로 결과 전체가 원본 `img[0, 0]`의 색 `(144, 156, 150)` **한 가지로** 칠해져요.

**거의 일직선**(`(370, 370)` 대신 `(371, 370)`)이면:
```
[[−670.0   672.47  −44.12]
 [ 340.0  −340.0    30.0 ]]       ← 계수가 수백 단위로 폭발
```
그림이 엄청나게 늘어나서 줄무늬처럼 보여요. **세 점을 넓게 퍼뜨려야 안정적**이라는 Part 6의 조언을 손으로 확인할 수 있어요.

## 8-7. 실시간이 가능한 이유

마우스를 끄는 동안 MOUSEMOVE 이벤트가 **초당 수십 번** 와요. 그때마다 `affine()`이 행렬을 풀고 이미지 전체를 변환해요.

| 작업 | 시간 (480×400 컬러) |
|---|---|
| `cv2.getAffineTransform` (3×3 연립방정식 2개) | 거의 0 |
| `cv2.warpAffine` | **약 0.37 ms** |
| Part 6의 직접 구현 `affine_transform` (흑백 320×330 기준) | 약 718 ms |

직접 구현이었다면 **한 번 움직일 때마다 1초 가까이 멈췄을** 거예요. OpenCV라서 끊김 없이 따라와요. Part 1~6에서 직접 만든 함수들은 **원리 이해용**이고, 인터랙티브 도구는 OpenCV로 만드는 이유예요.

> 🐛 여기도 `cv2.warpAffine(img, aff_mat, size, cv2.INTER_LINEAR)`로 플래그를 **네 번째 위치(`dst` 자리)**에 넣었어요(Part 6-8-d와 같은 패턴). 기본값이 마침 LINEAR라 결과는 같지만, 고친다면 `flags=cv2.INTER_LINEAR`예요.

> 🚗 **AVM 연결**: 탑뷰 캘리브레이션 도구에서 흔히 쓰는 UI가 바로 이거예요. 카메라 영상 위의 **핸들을 바닥 마커에 맞춰 끌면**, 그 점들이 탑뷰의 **고정된 실제 좌표**로 가도록 행렬이 실시간으로 다시 계산돼요. 다만 실무에서는 점 4개 이상과 원근 변환을 써요(Part 10이 정확히 그 구조예요).

|---|---|
| 구조 | 원본 창 pts1(끌기) → 결과 창 pts2(고정), 이벤트마다 `getAffineTransform(pts1, pts2)` + `warpAffine` |

| 핸들의 의미 | "원본의 **이 점**을 고정 핀에 꽂아라" → 오른쪽으로 끌면 그림은 왼쪽으로 |
