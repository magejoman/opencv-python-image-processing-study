## ① 왜 복소수가 필요할까?

0-1 ⑦에서 이 식을 봤어요.
```
A·sin(θ + φ) = (A·cos φ)·sin θ + (A·sin φ)·cos θ
```
그래서 DFT는 주파수 하나마다 **숫자 2개**(cos 몫, sin 몫)를 구해야 해요. 주파수가 1000개면 숫자 2000개예요.

이 두 숫자를 따로따로 들고 다니면 불편해요. 그래서 **숫자 2개를 하나로 묶은 자료형**을 써요. 그게 복소수예요.

🧠 **비유: 좌표 한 쌍**
- 지도 위 위치는 (가로, 세로) 두 숫자로 말해요.
- 복소수도 똑같이 **(가로, 세로)** 두 숫자예요. 다만 계산 규칙이 특별해서 **곱하면 회전**이 돼요. 이 성질 덕분에 0-1의 관람차를 수식 하나로 다룰 수 있어요.

> "허수(imaginary)"라는 이름 때문에 상상 속 숫자처럼 느껴지지만, 여기서는 그냥 **세로 방향 숫자**라고 생각하면 돼요.

## ② 생김새: `a + bj`와 복소평면

### ②-1 구성
```
z = a + b j
    │   │
    │   └─ 허수부 (imag) = 세로 좌표
    └───── 실수부 (real) = 가로 좌표
```
- 수학책은 `i`를 쓰지만 공학과 **파이썬은 `j`**를 써요(전기공학에서 i는 전류라서).
- 파이썬에서는 `3+4j` 또는 `complex(3, 4)`로 써요. 둘은 같아요.

### ②-2 🎨 복소평면에 그리면 (`z = 3 + 4j`)
```
          허수축 (세로, j)
             ↑
           4 ┤           ● z = 3+4j
             │          ╱
           3 ┤        ╱
             │      ╱   ← 길이 5
           2 ┤    ╱
             │  ╱
           1 ┤╱ θ=53.13°
   ──────────┼────┬────┬────┬────→ 실수축 (가로)
             0    1    2    3
```
복소수 하나 = **원점에서 (3, 4)까지 가는 화살표**예요.

### ②-3 파이썬에서 꺼내 보기 (실제 실행 결과)
```python
z = 3 + 4j
z.real   # 3.0   ← 가로
z.imag   # 4.0   ← 세로
```

## ③ 크기와 각도: 화살표를 다르게 표현하기

같은 화살표를 **"(가로, 세로)"** 대신 **"(길이, 방향)"**으로도 말할 수 있어요.

### ③-1 직교형 → 극형식 (z = 3 + 4j)
| 구하는 것 | 식 | 중간 계산 | 결과 |
|---|---|---|---|
| 크기 \|z\| | √(a² + b²) | √(3² + 4²) = √(9 + 16) = √25 | **5** |
| 각도 θ | atan2(b, a) | atan2(4, 3) | **53.13°** |

### ③-2 극형식 → 직교형 (5∠53.13°를 다시 되돌리기)
| 구하는 것 | 식 | 결과 (실측) |
|---|---|---|
| 가로 a | r · cos θ = 5 · cos 53.13° | 3.0000 |
| 세로 b | r · sin θ = 5 · sin 53.13° | 4.0000 |

그래서 **`z = r·(cos θ + j·sin θ)`**예요. 이 식이 0-4 오일러 공식의 출발점이니 기억해 두세요.

> 💡 **0-1의 관람차와 같은 그림이에요.** 반지름 r인 관람차에서 각도 θ에 있는 사람의 위치는 가로 = r·cos θ, 세로(높이) = r·sin θ였죠. **복소수 = 관람차 위 사람의 위치**예요.

### ③-3 🐞 함정: `atan(b/a)` 말고 `atan2(b, a)`를 써야 해요
🧪 **실측 결과**

| z | 진짜 방향 | `atan(b/a)` | `atan2(b,a)` / `np.angle` |
|---|---|---:|---:|
| 3+4j | 1사분면 (오른쪽 위) | 53.13° ✅ | 53.13° ✅ |
| −3+4j | 2사분면 (왼쪽 위) | **−53.13° ❌** | 126.87° ✅ |
| −3−4j | 3사분면 (왼쪽 아래) | **53.13° ❌** | −126.87° ✅ |
| 3−4j | 4사분면 (오른쪽 아래) | −53.13° ✅ | −53.13° ✅ |

`b/a`로 나누는 순간 a와 b 각각의 부호 정보가 사라져요(−4/−3 = 4/3). 그래서 `atan2`는 a, b를 따로 받아요. numpy에서는 `np.angle(z)`가 이 일을 해요.

## ④ 덧셈 = 화살표 잇기

규칙은 **가로끼리, 세로끼리 더하기**예요.
```
(3 + 4j) + (1 − 2j)
= (3 + 1) + (4 − 2)j
= 4 + 2j                     ← 실측: (4+2j)
```
🎨
```
  4 ┤         ● (3,4)
    │        ╱ ╲
  3 ┤      ╱     ╲  ← 두 번째 화살표 (1,−2)를 끝에 이어 붙임
    │    ╱         ╲
  2 ┤  ╱             ● (4,2) = 합
    │╱          ......
  1 ┤   ......
  ──┼────┬────┬────┬────┬──→
    0    1    2    3    4
```
첫 화살표 끝에 두 번째 화살표를 이어 붙이면, 원점에서 최종 끝점까지가 합이에요. 여기까지는 보통의 2D 벡터와 같아요.

> **DFT 미리보기:** DFT는 `Σ`(전부 더하기)예요. 화살표 N개를 줄줄이 이어 붙여서 **최종적으로 어디에 도착하는지** 보는 거예요(Part 2).

## ⑤ j를 곱하면 = 90° 회전

여기서부터 복소수가 보통 벡터와 달라져요.

### ⑤-1 규칙은 딱 하나: **j² = −1**
"제곱해서 −1이 되는 수"라고 하면 이상하게 들려요. 회전으로 보면 자연스러워요.
- j를 한 번 곱하면 **90° 회전**
- j를 두 번 곱하면(j²) **180° 회전**이고, 180° 회전은 **방향 뒤집기 = −1을 곱한 것**과 같아요.

🔢 **1에 j를 계속 곱해 보기 (실측)**
| 연산 | 결과 | 화살표 방향 |
|---|---|---|
| 1 | 1 | → 오른쪽 (0°) |
| 1 × j | j | ↑ 위 (90°) |
| j × j = j² | −1 | ← 왼쪽 (180°) |
| j³ | −j | ↓ 아래 (270°) |
| j⁴ | 1 | → 오른쪽 (360°, 제자리) |

```
                 j (90°)
                 ↑
                 │
   −1 (180°) ←───┼───→ 1 (0°)        j를 곱할 때마다 반시계로 90°씩
                 │
                 ↓
                −j (270°)
```

### ⑤-2 🔢 아무 복소수에나 j를 곱해 보기: (3 + 4j) × j
```
(3 + 4j) × j
= 3j + 4j²             ← 분배법칙
= 3j + 4·(−1)          ← j² = −1
= −4 + 3j              ← 실측: (-4+3j)
```
| | 직교형 | 크기 | 각도 |
|---|---|---:|---:|
| 원래 z | 3 + 4j | 5 | 53.13° |
| z × j | −4 + 3j | **5 (그대로)** | **143.13° (+90°)** |

길이는 그대로고 **각도만 정확히 90° 늘었어요.** j 곱하기는 순수한 90° 회전이에요.

---

## ⑥ 일반 곱셈 = 크기는 곱하고, 각도는 더한다

### ⑥-1 🔢 (3 + 4j) × (1 + 1j) 전개
```
(3 + 4j)(1 + 1j)
= 3·1 + 3·1j + 4j·1 + 4j·1j
= 3   + 3j   + 4j   + 4j²
= 3   + 7j   + 4·(−1)
= −1 + 7j                       ← 실측: (-1+7j)
```

### ⑥-2 극형식으로 확인
| | 크기 | 각도 |
|---|---:|---:|
| z = 3+4j | 5 | 53.13° |
| w = 1+1j | √2 = 1.4142 | 45° |
| **예상**: 크기는 곱, 각도는 합 | 5 × 1.4142 = **7.0711** | 53.13 + 45 = **98.13°** |
| **실측**: −1+7j | √(1+49) = √50 = **7.0711** ✅ | atan2(7, −1) = **98.13°** ✅ |

> 💡 **복소수 곱셈의 정체:** `z × w` = "z 화살표를 **w의 각도만큼 돌리고**, **w의 크기만큼 늘린다**."
> ⑤의 j는 크기 1, 각도 90°짜리 복소수였어요. 그래서 "늘리기 없이 90°만 회전"이 된 거예요.

## ⑦ 크기 1짜리 복소수를 곱하면 = 순수 회전

⑥에서 w의 크기가 **정확히 1**이면 늘리기 효과가 사라지고 **회전만** 남아요. 크기 1인 복소수는 ③-2의 식에서 r=1을 넣은 것이니까:
```
회전자(30°) = cos 30° + j·sin 30° = 0.8660 + 0.5000j      (크기 = 1)
```
🔢 **(3 + 4j)를 30° 돌려 보기 (실측)**
```
(3 + 4j) × (0.8660 + 0.5j)
= 3·0.8660 + 3·0.5j + 4j·0.8660 + 4j·0.5j
= 2.5981   + 1.5j   + 3.4641j   + 2j²
= 2.5981 − 2      + (1.5 + 3.4641)j
= 0.5981 + 4.9641j
```
| | 크기 | 각도 |
|---|---:|---:|
| 원래 | 5 | 53.13° |
| 30° 회전 후 | **5.0** ✅ | **83.13°** ✅ (+30°) |

### ⑦-1 크기 1인 복소수 = 원 위의 점 = 관람차
크기 1인 복소수들은 모두 **반지름 1인 원** 위에 있어요. 이건 0-1의 관람차 그 자체예요.
```
cos θ + j·sin θ    ←  "관람차에서 각도 θ에 있는 사람의 위치"
                       가로 = cos θ, 세로(높이) = sin θ
```
여기에 **시간에 따라 각도가 커지는 θ = 2π·f·t**를 넣으면 **빙글빙글 도는 점**이 돼요. 이 식을 짧게 쓰는 방법이 다음 스텝(0-4)의 **오일러 공식 `e^{jθ}`**예요.

## ⑧ 켤레 복소수 = 위아래 거울

### ⑧-1 정의
허수부 부호만 뒤집은 거예요: `z = a + bj`이면 켤레 `z* = a − bj`예요.
```
  4 ┤      ● z = 3+4j      (각도 +53.13°)
    │    ╱
    │  ╱
  ──┼──────────→  ← 실수축이 거울
    │  ╲
    │    ╲
 −4 ┤      ● z* = 3−4j     (각도 −53.13°)
```
크기는 같고, **각도 부호만 반대**예요. 관람차로 치면 같은 속도로 **반대 방향(시계 방향)**에 있는 점이에요.

### ⑧-2 유용한 성질 (실측)
```python
z = 3 + 4j
z.conjugate()          # (3-4j)
z * z.conjugate()      # (25+0j)  =  |z|² = 5²
```
중간 계산: `(3+4j)(3−4j) = 9 − 12j + 12j − 16j² = 9 + 16 = 25`

> **Part 2-4 미리보기:** 실수 신호의 DFT 결과는 `G[N−k] = G[k]*` (켤레)예요. 03번 그래프에서 50Hz 피크의 거울상이 950Hz에 생기는 이유가 바로 이 켤레 관계예요. 0-2 ⑦-2의 "주파수 축 접기"와도 같은 이야기예요.

## ⑨ 코드 연결: chap09에 나오는 복소수 문법

### ⑨-1 [Common/dft2d.py:3-5](../../Common/dft2d.py#L3-L5)의 `exp()` 함수
```python
def exp(knN):
    th = -2 * math.pi * knN
    return complex(math.cos(th), math.sin(th))   # 복소수 클래스
```
| 줄 | 하는 일 | 0-3에서 배운 것 |
|---|---|---|
| `th = -2π·knN` | 각도 계산. **음수**라서 **시계 방향** | ⑧ 켤레 방향 |
| `complex(cos th, sin th)` | 크기 1인 복소수, 즉 원 위의 점 | ⑦ 회전자 |

🧪 **실제 값**
| knN | th | 결과 (real, imag) | 크기 | 화살표 방향 |
|---:|---:|---|---:|---|
| 0 | 0° | (1.0, 0.0) | 1 | → |
| 0.125 | −45° | (0.7071, −0.7071) | 1 | ↘ |
| 0.25 | −90° | (0.0, −1.0) | 1 | ↓ |
| 0.5 | −180° | (−1.0, 0.0) | 1 | ← |
| 0.75 | −270° | (0.0, 1.0) | 1 | ↑ |

knN이 커질수록 점이 **시계 방향**으로 원을 돌아요. DFT의 `Σ g[n]·exp(k·n/N)`은 "신호값 g[n]만큼 늘린, 시계 방향으로 도는 화살표들을 전부 이어 붙이기"예요(⑥ 곱셈 + ④ 덧셈). Part 2에서 자세히 다룰게요.

### ⑨-2 numpy 복소수 배열 (실측)
```python
a = np.array([3+4j, 1-2j, -1+0j])
a.real               # [ 3.  1. -1.]
a.imag               # [ 4. -2.  0.]
np.abs(a)            # [5.     2.2361  1.    ]          ← 크기 √(a²+b²)
np.angle(a, deg=True)# [ 53.13 -63.43 180.  ]          ← atan2
np.conj(a)           # [3.-4.j  1.+2.j  -1.-0.j]
```

### ⑨-3 OpenCV는 복소수를 "2채널"로 저장해요
OpenCV에는 복소수 자료형이 없어요. 그래서 `cv2.dft`는 결과를 **채널 2개짜리 float32 배열**로 줘요.
```
numpy 방식:  shape (H, W)     dtype complex      각 칸에 3+4j
OpenCV 방식: shape (H, W, 2)  dtype float32      [:,:,0] = 3 (real), [:,:,1] = 4 (imag)
```
그래서 [Common/dft2d.py:17-21](../../Common/dft2d.py#L17-L21)의 `calc_spectrum`은 경우를 나눠서 크기를 구해요.
```python
if complex.ndim == 2: dst = abs(complex)                          # numpy 복소 배열
else: dst = cv2.magnitude(complex[:,:,0], complex[:,:,1])          # OpenCV 2채널
```
🧪 같은 세 숫자를 2채널로 넣고 `cv2.magnitude`를 돌리면 `[5.0, 2.236068, 1.0]`이 나와서 `np.abs`와 같아요. 둘 다 **√(실수² + 허수²)**를 계산해요.

> 📚 **복습 (Chapter06):** 컬러 이미지가 `(H, W, 3)`처럼 채널 3개(BGR)를 가졌던 거 기억나죠? 여기서는 같은 구조에 B, G, R 대신 **real, imag** 두 채널이 들어있다고 보면 돼요. 05번 코드가 `cv2.dft 방법 변환 행렬 크기`를 출력할 때 `(240, 240, 2)`가 나오는 이유예요(Part 4-6).

## ⑩ 신호와 연결: 복소수 하나 = 진폭 + 위상

이제 ①의 약속을 지킬 차례예요. 맛보기로 DFT를 미리 돌려 볼게요(계산 원리는 Part 2에서 다뤄요).

### ⑩-1 🧪 실험: N=8, 진폭 A=0.6, 위상 φ=30°인 코사인
```python
g = 0.6 * np.cos(2*np.pi*1*n/8 + 30°)     # n = 0..7
g = [ 0.5196  0.1553 -0.3   -0.5796 -0.5196 -0.1553  0.3    0.5796]
G = np.fft.fft(g)
G = [0, 2.0785+1.2j, 0, 0, 0, 0, 0, 2.0785-1.2j]
```
**G[1] = 2.0785 + 1.2j**를 ③의 방법으로 극형식으로 바꾸면:

| | 계산 | 결과 | 의미 |
|---|---|---:|---|
| 크기 | √(2.0785² + 1.2²) | 2.4 | |
| 크기 × 2 / N | 2.4 × 2 / 8 | **0.6** | = **진폭 A** ✅ |
| 각도 | atan2(1.2, 2.0785) | **30°** | = **위상 φ** ✅ |

그리고 **G[7] = 2.0785 − 1.2j = G[1]의 켤레**예요(⑧).

> 💡 **chap09 전체를 관통하는 사실:** DFT 결과의 복소수 하나에 **"그 주파수가 얼마나 큰가(크기)"**와 **"어디서 출발했나(각도)"**가 한꺼번에 담겨 있어요. 스펙트럼 이미지(Part 3)는 이 중 **크기만** 그린 그림이에요.

### ⑩-2 sin이면? (sin = 90° 늦게 출발한 cos)
`0.6·sin(...)`으로 바꾸면 G[1] = **−2.4j** (실측), 각도 **−90°**예요. 크기 2.4는 같아요.

### ⑩-3 03번 코드 미리보기
03번의 `0.6·sin(2π·50·t)` (N=1000)을 실제로 FFT하면:
```
G[50]  = −300j      크기 300 = 1000 × 0.6 / 2,  각도 −90° (sin이니까)
G[950] = +300j      ← G[50]의 켤레 (거울상)
G[50] × dt = −0.3j  → 크기 0.3     ← 03번 그래프에 찍히는 피크 높이!
```
0-2 ⑧에서 "03번 그래프 피크가 0.6이 아니라 0.3"이라고 했던 이유는, 진폭이 **G[50]과 G[950] 두 칸에 반씩** 나뉘어 담기기 때문이에요(Part 2-6).

## ⑪ 정리 + 셀프 체크

### 한 장 요약
| 개념 | 식 | 그림으로 | chap09 코드 |
|---|---|---|---|
| 복소수 | a + bj | 화살표 (가로 a, 세로 b) | `complex(a, b)`, `3+4j` |
| 실수부/허수부 | a / b | 가로 / 세로 | `.real`, `.imag`, `[:,:,0]`, `[:,:,1]` |
| 크기 | √(a²+b²) | 화살표 길이 | `abs()`, `np.abs`, `cv2.magnitude` |
| 각도 | atan2(b, a) | 화살표 방향 | `np.angle` |
| 극형식 | r(cos θ + j sin θ) | 길이 + 방향 | |
| 덧셈 | 가로끼리, 세로끼리 | 화살표 잇기 | DFT의 `sum` |
| 곱셈 | 크기 ×, 각도 + | 회전 + 늘리기 | DFT의 `g[n] * exp(...)` |
| j² = −1 | | 90° + 90° = 180° = 뒤집기 | |
| 크기 1인 복소수 | cos θ + j sin θ | 원 위의 점 = 관람차 | `exp()` 함수 |
| 켤레 | a − bj | 위아래 거울 | 스펙트럼 대칭 |

**꼭 가져갈 3문장**
1. **복소수 = 2D 화살표 = 숫자 두 개(cos 몫, sin 몫)를 한 그릇에 담은 것**
2. **곱셈 = 회전 + 늘리기.** 크기 1짜리를 곱하면 순수 회전이에요.
3. **DFT 결과 복소수 하나의 크기는 진폭, 각도는 위상이에요.** 스펙트럼 이미지는 크기만 그린 거예요.

### 셀프 체크
1. `z = −6 + 8j`의 크기는?
2. `(2 + 3j) × j`는? (전개 과정도 써 보세요)
3. 크기 2, 각도 30°인 복소수와 크기 3, 각도 60°인 복소수를 곱하면 크기와 각도는?
4. `(1 + 2j)`의 켤레와, `z × z*`의 값은?
5. `cv2.dft` 결과 `dft3`가 shape `(240, 240, 2)`예요. (10, 20) 위치의 크기를 구하는 코드는?
6. `math.atan(4 / −3)`이 `−3 + 4j`의 각도로 틀린 이유는?

<br>

**정답 ↓**
1. √(36 + 64) = √100 = **10**
2. 2j + 3j² = 2j − 3 = **−3 + 2j** (90° 회전)
3. 크기 2 × 3 = **6**, 각도 30° + 60° = **90°** → 6j
4. 켤레 **1 − 2j**, z × z* = 1 + 4 = **5** (= |z|²)
5. `cv2.magnitude(dft3[:,:,0], dft3[:,:,1])[10, 20]` 또는 `np.sqrt(dft3[10,20,0]**2 + dft3[10,20,1]**2)`
6. 4 / −3 = −1.333은 −4 / 3과 같아서 부호 정보가 사라져요. 그래서 4사분면(−53.13°)으로 계산돼요. 진짜는 2사분면 126.87°라서 `math.atan2(4, -3)`을 써야 해요.
