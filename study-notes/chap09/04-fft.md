## 4-2. 핵심 아이디어: 짝수/홀수로 반씩 쪼개기

### 4-2-1 출발점
```
G[k] = Σ_{n=0}^{N−1} g[n] · W^{kn}        단, W = e^{−j2π/N} (한 칸 회전자)
```

### 4-2-2 단계 ①: n을 짝수(2m)와 홀수(2m+1)로 나누기
```
G[k] = Σ_m g[2m]·W^{k·2m}  +  Σ_m g[2m+1]·W^{k·(2m+1)}
       └─── 짝수 샘플들 ───┘   └────── 홀수 샘플들 ──────┘
```

### 4-2-3 단계 ②: 홀수 쪽에서 W^k를 앞으로 빼기
```
W^{k(2m+1)} = W^{2km} · W^k        (지수법칙, 0-4 ②)

G[k] = Σ_m g[2m]·W^{2km}  +  W^k · Σ_m g[2m+1]·W^{2km}
```

### 4-2-4 단계 ③: W²는 "길이 N/2짜리 DFT의 회전자"예요
W² = e^{−j2π·2/N} = e^{−j2π/(N/2)}. 즉 **두 칸씩 건너뛰며 도는 회전자 = 길이 N/2 DFT의 회전자**예요. 그래서:
```
E[k] = 짝수 샘플 [g0, g2, g4, …]의 (N/2)점 DFT
O[k] = 홀수 샘플 [g1, g3, g5, …]의 (N/2)점 DFT

G[k] = E[k] + W^k · O[k]
```

### 4-2-5 단계 ④: 뒤쪽 절반은 공짜 (핵심 중의 핵심)
- E와 O는 길이 N/2짜리라서 **주기가 N/2**예요: E[k + N/2] = E[k], O[k + N/2] = O[k]
- 회전자는 반 바퀴 더 돌면 부호가 뒤집혀요: W^{k+N/2} = W^k · W^{N/2} = W^k · (**−1**) (0-4 ①: e^{−jπ} = −1)

그래서:
```
G[k]       = E[k] + W^k · O[k]
G[k + N/2] = E[k] − W^k · O[k]        ← 같은 재료, 부호만 반대!
             (k = 0 ~ N/2 − 1)
```
**곱셈 `W^k · O[k]` 한 번으로 출력 두 개**를 만들어요. 이 "더하기/빼기 한 쌍"을 그림으로 그리면 나비 모양이라서 **butterfly**라고 불러요.

🧠 **비유: 시험 채점 나누기**
1000장을 혼자 채점하는 대신, 반으로 나눠 두 사람에게 맡기고, 각자 또 반으로 나눠 맡기고… 마지막에 결과를 **합치는 비용만** 들어요. 합치는 비용이 단계마다 N이고 단계 수가 log₂N이라서 총 N·log₂N이에요.

| 단계 수 | 각 단계 비용 | 총 비용 |
|---|---|---|
| log₂N번 반으로 쪼개짐 (N=8이면 3단계) | butterfly N/2개 (곱셈 N/2번) | **(N/2)·log₂N 곱셈** |

## 4-3. `pairing` 재귀 트리 (N = 8)

### 4-3-1 코드 ([Common/fft2d.py:20-28](../../Common/fft2d.py#L20-L28))
```python
def pairing(g, N, dir, start=0, stride=1):
    if N == 1: return [g[start]]                     # ① 길이 1이면 DFT = 자기 자신
    L = N // 2                                        # 반
    sd = stride * 2                                   # 간격 2배 → 한 칸씩 건너뜀
    part1 = pairing(g, L, dir, start, sd)             # ② 짝수 쪽 (start부터)
    part2 = pairing(g, L, dir, start + stride, sd)    # ③ 홀수 쪽 (start+stride부터)
    pair = part1 + part2                              # ④ 리스트 이어 붙이기 [E..., O...]
    butterfly(pair, L, N, dir)                        # ⑤ 합치기
    return pair
```
배열을 실제로 복사해서 나누지 않고 **(start, stride)** 두 숫자로 "어느 원소를 쓸지"만 가리켜요. `start + stride·i`번째 원소가 i번째 원소예요.

### 4-3-2 🔢 호출 추적표 (실제 실행 기록)
```
N=8 start=0 stride=1  [g0 g1 g2 g3 g4 g5 g6 g7]
├─ N=4 start=0 stride=2  [g0 g2 g4 g6]             ← 짝수
│  ├─ N=2 start=0 stride=4  [g0 g4]
│  │  ├─ N=1 start=0 stride=8  [g0]
│  │  └─ N=1 start=4 stride=8  [g4]
│  └─ N=2 start=2 stride=4  [g2 g6]
│     ├─ N=1 start=2 stride=8  [g2]
│     └─ N=1 start=6 stride=8  [g6]
└─ N=4 start=1 stride=2  [g1 g3 g5 g7]             ← 홀수
   ├─ N=2 start=1 stride=4  [g1 g5]
   │  ├─ N=1 start=1 stride=8  [g1]
   │  └─ N=1 start=5 stride=8  [g5]
   └─ N=2 start=3 stride=4  [g3 g7]
      ├─ N=1 start=3 stride=8  [g3]
      └─ N=1 start=7 stride=8  [g7]
```
**맨 아래 잎의 순서:** g0, g4, g2, g6, g1, g5, g3, g7

이 순서를 2진수로 쓰면 재미있는 규칙이 보여요.
| 원래 번호 | 2진수 | 비트 뒤집기 | 잎 순서에서 위치 |
|---:|---|---|---:|
| 0 | 000 | 000 | 0 |
| 4 | 100 | 001 | 1 |
| 2 | 010 | 010 | 2 |
| 6 | 110 | 011 | 3 |
| 1 | 001 | 100 | 4 |

**비트 역순(bit-reversal)**이에요. 그냥 신기한 성질이니까 외울 필요는 없어요. 실제 고속 FFT 라이브러리는 이 성질로 재귀 없이 반복문으로 구현해요.

## 4-4. butterfly: N = 4 숫자로 끝까지

### 4-4-1 코드 ([Common/fft2d.py:14-18](../../Common/fft2d.py#L14-L18))
```python
def butterfly(pair, L, N, dir):
    for k in range(L):
        Geven, Godd = pair[k], pair[k + L]                   # E[k], O[k]
        pair[k]     = Geven + Godd * exp(dir * k / N)       # G[k]       = E + W^k·O
        pair[k + L] = Geven - Godd * exp(dir * k / N)       # G[k+N/2]   = E − W^k·O
```
- `exp(dir*k/N)`: dir = 1이면 e^{−j2πk/N} = **W^k** (FFT), dir = −1이면 반대 방향 (IFFT)
- 리스트 `pair`를 **그 자리에서(in-place)** 덮어써요. 앞 절반이 E, 뒤 절반이 O였다가 → G의 앞 절반, 뒤 절반으로 바뀌어요.

### 4-4-2 🎨 나비 모양
```
  E[k] ──────●────────────●──── G[k]       = E[k] + W^k·O[k]
              ╲          ╱
               ╲        ╱
                ╲  ╱  (+)
                 ╳
                ╱  ╲  (−)
               ╱        ╲
  O[k] ─×W^k─●────────────●──── G[k+N/2]   = E[k] − W^k·O[k]
```

### 4-4-3 🔢 g = [1, 2, 3, 4] 전 과정 (2-2와 같은 신호)
**① 맨 아래 (N = 1):** 잎은 자기 자신 → [1], [3], [2], [4] (순서: g0, g2, g1, g3)

**② N = 2 짝수 쪽 [g0, g2] = [1, 3]:** L = 1, k = 0, W⁰ = 1
```
pair = [1, 3]
pair[0] = 1 + 3·1 = 4
pair[1] = 1 − 3·1 = −2          → E = [4, −2]
```
**③ N = 2 홀수 쪽 [g1, g3] = [2, 4]:**
```
pair[0] = 2 + 4 = 6
pair[1] = 2 − 4 = −2            → O = [6, −2]
```
**④ N = 4 합치기:** pair = E + O = [4, −2, 6, −2], L = 2

| k | E[k] | O[k] | W^k (N=4) | W^k·O[k] | pair[k] = E + W·O | pair[k+2] = E − W·O |
|---:|---:|---:|---|---|---|---|
| 0 | 4 | 6 | W⁰ = 1 | 6 | 4 + 6 = **10** | 4 − 6 = **−2** |
| 1 | −2 | −2 | W¹ = e^{−jπ/2} = **−j** | (−2)(−j) = **2j** | −2 + 2j | −2 − 2j |

**결과:** `[10, −2+2j, −2, −2−2j]`

🧪 실측 `fft([1,2,3,4])` = `[10, −2+2j, −2, −2−2j]`이고, **2-2 DFT 손계산과 완전히 같아요.** ✅ `ifft`로 되돌리면 `[1, 2, 3, 4]`예요.

**곱셈 횟수 비교:** DFT 손계산(2-2)은 16번, FFT는 W를 곱하는 곳 4번(N=2에서 2번, N=4에서 2번)이에요. W⁰ = 1, W¹ = −j는 사실상 곱셈도 아니라서 더 적어요.

🧪 N = 8 (`[1, 2, …, 8]`)도 `fft`와 `np.fft.fft`가 `[36, −4+9.66j, −4+4j, −4+1.66j, −4, …]`로 일치해요.

### 4-4-4 IFFT ([Common/fft2d.py:33-35](../../Common/fft2d.py#L33-L35))
```python
def ifft(g):
    fft = pairing(g, len(g), -1)        # dir = −1: 반대로 돌리기
    return [v / len(g) for v in fft]    # 1/N
```
2-7의 IDFT 규칙(**부호 반대 + 1/N**)과 똑같아요. 같은 함수에 dir만 바꿔서 재활용해요.

> 📌 여기서도 `fft = pairing(...)`이 바깥의 `fft` 함수 이름을 지역변수로 가려요. 함수 안이라 바깥에 영향은 없지만 읽기 헷갈리는 이름이에요.

## 4-5. zeropadding: 왜 2의 거듭제곱이어야 할까?

### 4-5-1 반으로 계속 쪼개야 하니까
`pairing`은 `L = N // 2`로 쪼개요. N이 2의 거듭제곱이 아니면 중간에 **홀수 길이**가 나와요.

🧪 N = 6을 넣어 보면: 6 → 3 → (3//2 = 1)로 쪼개지면서 원소 하나가 사라지고, butterfly가 없는 칸을 찾다가 **`IndexError: list index out of range`**가 나요(실측).

### 4-5-2 코드 ([Common/fft2d.py:5-12](../../Common/fft2d.py#L5-L12))
```python
def zeropadding(img):
    h, w = img.shape[:2]
    m = 1 << int(np.ceil(np.log2(h)))    # h 이상인 가장 작은 2의 거듭제곱
    n = 1 << int(np.ceil(np.log2(w)))
    dst = np.zeros((m, n), img.dtype)    # 0으로 채운 큰 판
    dst[0:h, 0:w] = img[:]               # 왼쪽 위에 원본 복사
    return dst
```
🔢 **h = 240일 때 단계별 계산**
| 단계 | 계산 | 값 |
|---|---|---|
| `np.log2(240)` | 2^? = 240 | 7.9069 |
| `np.ceil(...)` | 올림 | 8 |
| `1 << 8` | 1을 왼쪽으로 8비트 밀기 = 2⁸ | **256** |

🧪 결과 `pad.shape = (256, 256)`. 원본 경계 부근 값을 보면 `pad[239, 235:245] = [27, 40, 35, 44, 51, 0, 0, 0, 0, 0]`이에요. 240열부터 0(검정)이에요.
```
┌──────────────────────┬──┐
│                      │  │
│  원본 240×240        │0 │  ← 오른쪽 16열 검정
│                      │  │
├──────────────────────┴──┤
│        0 (검정)          │  ← 아래 16행 검정
└─────────────────────────┘
          256×256
```

### 4-5-3 ⚠️ 패딩은 스펙트럼을 바꿔요
- 크기가 달라지니까 **주파수 칸 간격(df = 1/256)이 달라져요.** 같은 이미지라도 칸 위치가 240짜리와 일치하지 않아요.
- 원본과 검정 영역 사이에 **인공적인 에지**가 생겨요. 그래서 스펙트럼의 **가로·세로 십자선이 훨씬 진해져요**(3-6의 "십자 = 테두리").
- 🧪 실제로 두 스펙트럼을 나란히 그려 보니, 패딩한 쪽(user `fft2`)의 십자선이 np/cv2(패딩 없음)보다 **훨씬 밝고 날카로웠어요.**
- 역변환한 뒤 **240×240만 잘라내면** 원본은 정확히 돌아와요(4-6). 정보 손실은 없고, 스펙트럼 모양만 달라져요.

## 4-6. 세 구현 비교 ([05.2d_fft.py:42-56](../../chap09/05.2d_fft.py#L42-L56))

```python
dft1 = fft2(image)                                                # ① 직접 구현
dft2 = np.fft.fft2(image)                                         # ② numpy
dft3 = cv2.dft(np.float32(image), flags = cv2.DFT_COMPLEX_OUTPUT) # ③ OpenCV
```

### 4-6-1 🧪 결과 비교 (실측)
| | ① user `fft2` | ② `np.fft.fft2` | ③ `cv2.dft` |
|---|---|---|---|
| **shape** | **(256, 256)** | (240, 240) | (240, 240, **2**) |
| dtype | complex128 | complex128 | float32 |
| 복소수 저장 | 복소수 자료형 | 복소수 자료형 | `[...,0]` = 실수, `[...,1]` = 허수 (0-3 ⑨-3) |
| 크기 제약 | **2의 거듭제곱만** → 패딩 | 아무 크기 | 아무 크기 (2, 3, 5의 곱이면 특히 빠름) |
| DC 값 | 7,513,396 | 7,513,396 | [7,513,396, 0] |
| 시간 | 0.449초 | **1.03 ms** | 3.47 ms |
| 입력 | uint8 그대로 OK | uint8 그대로 OK | **float32 필수** |

**값은 같은가요?**
- ① vs `np.fft.fft2(패딩한 이미지)`: 최대 차이 5.2e−10 → **같아요.**
- ② vs ③: 최대 차이 0.046, 상대 오차 **6e−9** → ③이 float32(유효숫자 약 7자리)라서 생긴 반올림 차이일 뿐이에요.

### 4-6-2 `cv2.dft`의 주의점 세 가지
**① 입력은 float32여야 해요.** uint8을 그대로 넣으면(실측):
```
error: (-215:Assertion failed) type == CV_32FC1 || type == CV_32FC2 || ...
```
그래서 코드에 `np.float32(image)`가 있어요.

**② `DFT_COMPLEX_OUTPUT`이 없으면** 결과가 OpenCV 고유의 압축 형식(CCS, 실수 입력의 거울 대칭을 이용해 절반만 저장)으로 나와요. 다루기 어려우니까 항상 이 플래그를 붙이세요.

**③ 2·3·5의 곱이면 빨라요.** 🧪 `cv2.getOptimalDFTSize`:
| 입력 | 추천 크기 | 이유 |
|---:|---:|---|
| 240 | 240 | 2⁴·3·5 → 그대로 OK |
| 241 | 243 | 소수라서 3⁵로 늘림 |
| 1280 | 1280 | 2⁸·5 |
| 944 | 960 | 944 = 2⁴·59라서 2⁶·3·5로 늘림 |

numpy와 OpenCV는 2의 거듭제곱이 아니어도 3, 5 같은 **다른 소인수로도 쪼개는** FFT를 써서 패딩이 필요 없어요. 05번의 직접 구현은 가장 단순한 **radix-2**(반씩 쪼개기)라서 2의 거듭제곱만 돼요. 🚗 AVM 카메라 1280×944 같은 해상도라면 944 → 960으로 맞추는 게 유리하다는 뜻이에요.

### 4-6-3 역변환 세 가지
```python
idft1 = ifft2(dft1).real                              # (256, 256)
idft2 = np.fft.ifft2(dft2).real                       # (240, 240)
idft3 = cv2.idft(dft3, flags=cv2.DFT_SCALE)[:,:,0]    # (240, 240)
```
🧪 **원본과의 최대 오차:** ① 8.5e−14 (240×240 부분) / ② 8.5e−14 / ③ 6.1e−5 (float32)

**`cv2.DFT_SCALE`을 빼먹으면?** 🧪 `cv2.idft(dft3)[0,0,0]` = **5,644,800**인데 원본 `im[0,0]` = 98이에요. 정확히 **57,600배(= 240 × 240 = N)** 커요. OpenCV는 IDFT의 1/N을 **기본으로 안 해요.** 2-7에서 IDFT = "부호 반대 + 1/N"이었죠. 1/N을 해 달라는 게 `DFT_SCALE` 플래그예요.

**`[:,:,0]`은?** 결과도 2채널(실수, 허수)이라서 **실수부만** 꺼내요. 허수부는 계산 오차 수준(≈ 0)이에요. numpy의 `.real`과 같은 역할이에요.

## 4-8. 정리 + 셀프 체크

### 한 장 요약
| 개념 | 내용 |
|---|---|
| FFT | DFT와 **결과 동일**, 계산만 (N/2)·log₂N |
| 분할 | G[k] = E[k] + W^k·O[k], G[k+N/2] = E[k] − W^k·O[k] (E = 짝수 샘플 DFT, O = 홀수 샘플 DFT) |
| 왜 공짜 절반 | E, O의 주기 N/2 + W^{N/2} = −1 |
| `pairing` | (start, stride)로 짝/홀 가리키며 재귀. 잎 순서 = 비트 역순 |
| `butterfly` | 곱셈 1번으로 출력 2개. dir = 1 FFT, −1 IFFT |
| `zeropadding` | 240 → 256 (`1 << ceil(log2)`). 스펙트럼 십자선 진해짐. 역변환 후 잘라내기 |
| radix-2 한계 | N = 6이면 IndexError |
| np.fft | 아무 크기, complex 배열 |
| cv2.dft | float32 입력, `DFT_COMPLEX_OUTPUT` → (H, W, 2), 2·3·5 곱 크기가 빠름 |
| cv2.idft | **`DFT_SCALE` 필수** (없으면 N배), `[:,:,0]` = 실수부 |
| 실측 속도 (240²) | 순수 DFT 25.7초 → 순수 FFT 0.45초 → np 1ms |

**꼭 가져갈 3문장**
1. **FFT는 짝수/홀수로 반씩 쪼개고, butterfly로 "곱셈 하나에 결과 둘"을 만들어 N²을 N·log N으로 줄인다. 결과는 DFT와 똑같다.**
2. **05번 직접 구현은 2의 거듭제곱만 되어서 240을 256으로 0 패딩하고, 그래서 결과 크기와 스펙트럼 모양이 다르다.**
3. **`cv2.dft`는 float32 + 2채널(실수, 허수)이고, `cv2.idft`에는 `DFT_SCALE`을 붙여야 원래 밝기로 돌아온다.**

### 셀프 체크
1. N = 16의 FFT는 몇 단계(재귀 깊이)이고, 단계마다 butterfly는 몇 개일까?
2. G[k + N/2] = E[k] − W^k·O[k]에서 "−"가 나오는 이유를 한 줄로 설명해 보세요.
3. g = [2, 0, 2, 0]을 4-4-3처럼 FFT로 손계산해 보세요.
4. 300×300 이미지를 05번 `zeropadding`에 넣으면 몇×몇이 될까?
5. `cv2.idft(dft3)[:,:,0]`을 그대로 `convertScaleAbs`해서 화면에 띄우면 어떻게 보일까?
6. N = 10을 05번 `fft`에 넣으면 왜 실패할까? numpy는 왜 괜찮을까?

<br>

**정답 ↓**
1. log₂16 = **4단계**, 단계마다 N/2 = **8개** butterfly (총 32번)
2. W^{k+N/2} = W^k · e^{−jπ} = **W^k · (−1)**, 반 바퀴 더 돌면 방향이 반대예요.
3. 짝수 [g0, g2] = [2, 2] → E = [4, 0] / 홀수 [g1, g3] = [0, 0] → O = [0, 0] / k=0: 4 + 0 = **4**, 4 − 0 = **4** / k=1: 0 + (−j)·0 = **0**, **0** → **[4, 0, 4, 0]** (DC 4, 나이퀴스트 k=2에 4: "2칸마다 반복" 무늬)
4. log₂300 = 8.23 → 올림 9 → 2⁹ = **512×512** (원본보다 거의 3배 큰 판이에요)
5. 값이 57,600배 커서 거의 모든 픽셀이 255로 포화되어 **하얗게** 보여요(값이 0인 곳만 검정).
6. 10 → 5 → 5//2 = 2로 쪼개면서 원소가 빠져 IndexError가 나요. numpy는 10 = 2 × 5처럼 **다른 소인수로도 쪼개는** FFT(mixed-radix)를 써서 괜찮아요.
