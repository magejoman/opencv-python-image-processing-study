## 18-7. 🧱 한글 조각 합치기: `np.sort(axis=0)` 트릭 (45~51번째 줄)

### 18-7-a. 🍕 개념

> 🍕 비유: 종이 조각 여러 장을 **한 봉투에 다 넣으려면** 봉투가 얼마나 커야 할까요? 봉투의 **왼쪽 위**는 조각들 중 **가장 왼쪽(x0 최솟값)이자 가장 위(y0 최솟값)**, **오른쪽 아래**는 **가장 오른쪽(x1 최댓값)이자 가장 아래(y1 최댓값)**여야 해요.

수식으로 쓰면 이렇습니다.
```
합친 상자 = ( min(x0들), min(y0들) ) ~ ( max(x1들), max(y1들) )
```

### 18-7-b. 코드

```python
45     if text_rois:
47         pts= np.sort(text_rois, axis=0)        # ⚠️ 주석은 "y 방향 정렬"이지만 실제로는 "열마다 따로 정렬"
48         x0, y0 = pts[ 0, 0:2]                  # 첫 행 = 각 열의 최솟값
49         x1, y1 = pts[-1, 2:]                   # 마지막 행 = 각 열의 최댓값
50         w, h = x1-x0, y1-y0
51         num_rois.append((x0, y0, w, h))        # 숫자 목록 맨 끝에 붙임
```

`np.sort(..., axis=0)`는 **행을 통째로 정렬하는 게 아니라, 열 4개를 각각 따로** 정렬합니다. 그래서 정렬한 뒤의 첫 행에는 각 열의 최솟값이, 마지막 행에는 각 열의 최댓값이 모여요.

**🔢 1번 차 실측:**
```
정렬 전                     np.sort(axis=0) 후
ㅜ [48, 16, 65, 27]          [48,  3, 64, 14]   ← x0, y0만 보면 열별 최솟값 (48, 3)
ㄷ [48,  3, 64, 14]          [48, 16, 65, 27]   ← x1, y1만 보면 열별 최댓값 (65, 27)

x0, y0 = 48, 3      x1, y1 = 65, 27      w, h = 17, 24
→ num_rois에 (48, 3, 17, 24) 추가
```

여기서는 결과가 **행 두 개를 위아래로 바꾼 것과 똑같아 보입니다.** 그래서 주석에 "y 방향 정렬"이라고 쓴 것 같아요. 그런데 **열이 섞이는 경우**를 보면 차이가 드러납니다.

**🔢 장난감 예시 '서' = ㅅ + ㅓ:**
```
정렬 전                       np.sort(axis=0) 후
ㅅ [48, 6, 60, 26]             [48, 2, 60, 26]   ← 48은 ㅅ에서, 2는 ㅓ에서 왔음! 행이 섞임
ㅓ [58, 2, 66, 28]             [58, 6, 66, 28]

pts[0, 0:2]  = (48, 2)   = (가장 왼쪽 x, 가장 위 y)    ✓
pts[-1, 2:]  = (66, 28)  = (가장 오른쪽 x, 가장 아래 y) ✓
→ 합친 상자 (48, 2, 18, 26)
```

```
   x: 48      58  60   66
 y 2 ┼─────────┬────────┐  ← ㅓ의 위쪽 끝 (y=2)
     │  ㅅ     │  ㅓ     │
     │         │        │
 26  ┼─────────┼──┘     │  ← ㅅ의 아래쪽 끝
 28  └─────────┴────────┘  ← ㅓ의 아래쪽 끝 (y=28)
     └─── 합친 상자: 봉투 하나 ───┘
```

행이 섞여도 결과는 정확합니다. 사실 "열마다 최솟값과 최댓값"이라는 목적에 딱 맞는 트릭이에요. 다만 읽기 쉽게 쓰면 이렇게 됩니다.
```python
x0, y0 = pts[:, :2].min(axis=0)
x1, y1 = pts[:, 2:].max(axis=0)
```

## 20-3. 🧪 실험: K를 바꾸면? (15대 × seed 5개 = 7글자를 읽어낸 68번)

| K | 한글 정답 | 7글자 전체 정답 |
|---|---|---|
| **1** | **57 / 68** | **51** |
| 3 | 42 / 68 | 38 |
| 5 | 44 / 68 | 39 |
| 7 | 46 / 68 | 41 |
| 10 (원래) | 49 / 68 | 44 ← L8의 "44/75"와 같은 숫자 |

**K = 1이 가장 좋았습니다.** 7번, 9번, 13번 차가 각각 `33서7336`, `43무1023`, `59저0678`로 한글이 맞게 나왔어요.

**그런데 L9의 학습표 실험(글꼴 하나 빼고 맞히기)에서는 반대로 K = 1이 K = 10보다 약 5%p 낮았죠.** 왜 반대일까요?

> 🍕 비유: **쌍둥이 vs 동네 사람들**
> - L9 실험은 질문 글자의 **자기 글꼴을 빼고** 물어봤어요. 쌍둥이가 없으니 동네 사람 10명의 의견을 모으는 게 나았죠.
> - 진짜 번호판 글꼴은 학습표 20개 글꼴 중 **아주 닮은 쌍둥이가 하나** 있는 것으로 보여요. 9번 차 '무'의 1등 거리(2,188)와 2등(2,952)의 큰 차이가 그 증거예요. 그런데 K = 10이면 쌍둥이 말 한 표에 **남의 글꼴 9표**가 섞이고, 그 9표에서는 L9에서 본 '저→사', '자→사' 같은 혼동이 다수를 차지해요.

⚠️ **정직한 주의사항:**
1. 차가 15대뿐이고, 11번과 13번은 같은 번호판이에요. 표본이 아주 작습니다.
2. **이 15대 성적을 보고 K를 고르면 L8 Q3에서 배운 "시험지 미리 보기(데이터 누수)"가 됩니다.** 제대로 하려면 K를 고를 **별도의 번호판 사진**이 필요해요.
3. 동점 문제를 줄이는 더 근본적인 방법은 **홀수 K**나 **거리 가중 투표**(가까운 이웃일수록 큰 표)예요. OpenCV `KNearest`에는 가중 투표가 없어서, `neighborResponses`와 `dist`를 받아 직접 계산해야 해요.

**🧪 고쳐 보기:** 두 상자의 **x 범위가 거의 같으면**(9~23과 8~24) 같은 글자로 보고 합칩니다.
```python
def merge_x(rois):                                  # x 순서로 정렬한 뒤, 겹치면 합치기
    rois = sorted(rois, key=lambda r: r[0]); out = []
    for x, y, w, h in rois:
        if out:
            X, Y, W, H = out[-1]
            ov = min(X+W, x+w) - max(X, x)          # x 방향으로 겹치는 길이
            if ov > 0.7 * min(W, w):                # 좁은 쪽 폭의 70% 이상 겹치면 같은 글자
                x0, y0 = min(X, x), min(Y, y); x1, y1 = max(X+W, x+w), max(Y+H, y+h)
                out[-1] = (x0, y0, x1-x0, y1-y0); continue
        out.append((x, y, w, h))
    return out
```
```
결과: 8개 → 7개   (8, 0, 16, 27) = 합쳐진 '5' ✓
숫자: 5 9 _ 0 6 7 8  ✓ (전부 정답)
한글: K=10 → '사' ✗,   K=1 → '서' ✗   (정답 '저')
```
**분리 문제는 해결**됐지만, 이 사진의 '저'는 K = 1로도 못 맞혔어요. 같은 번호판인 13번 차에서는 K = 1로 맞혔는데, 사진마다 획이 조금씩 다르게 나오기 때문입니다. L9에서 학습표 안의 **'저' 정확도가 0%**였던 것과 연결돼요.

(참고: 세로 3×1 커널로 닫힘(close) 연산도 해봤는데 **효과가 없었어요.** 끊긴 틈이 세로가 아니라 가로 방향이라서 그래요.)

## 20-5. 남은 오답 원인 정리

| 원인 | 사례 | 해결 아이디어 |
|---|---|---|
| 동점이면 번호가 작은 라벨이 이김 | 9번 무→두, 7번 9→7 | 홀수 K, 거리 가중 투표 |
| K가 커서 정답이 군중에 묻힘 | 7번 서→사, 13번 저→사 | K = 1 (단, 별도 데이터로 결정) |

> 🚗 **AVM 연결:** 이 코드의 `dx, dy = 6, 3`, `45 < x < 80`, 면적 60/150은 모두 **"번호판이 항상 똑같은 크기와 위치로 반듯하게 잘려 온다"**는 가정 위에 서 있어요. 탑뷰에서 주차선이나 정지선 ROI를 픽셀 좌표로 박아 두는 것도 똑같은 가정이죠. 카메라 장착 공차, 차체 기울기, 캘리브레이션이 틀어지면 이런 고정 숫자가 가장 먼저 깨집니다. 그래서 실무에서는 **비율이나 검출 결과를 기준으로 상대적인 위치**를 쓰는 편이 안전해요.
