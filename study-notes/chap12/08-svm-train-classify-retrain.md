# PART 1. 학습 코드: [04.train_plate_data.py](../../chap12/04.train_plate_data.py)

## 14-1. SVM 객체 만들기 (3~11번째 줄)

```python
 3 def SVM_create(type, max_iter, epsilon):
 4     svm = cv2.ml.SVM_create()                     # 빈 SVM 객체
 6     svm.setType(cv2.ml.SVM_C_SVC)                 # "C를 쓰는 분류" (L7의 소프트 마진)
 7     svm.setKernel(cv2.ml.SVM_LINEAR)              # 직선(초평면) 커널
 8     svm.setGamma(1)                               # ⚠️ LINEAR에서는 쓰이지 않음
 9     svm.setC(1)                                   # 위반 벌금 C = 1
10     svm.setTermCriteria((type, max_iter, epsilon))
11     return svm
```

| 설정 | 값 | L7과의 연결 |
|---|---|---|
| Type | `SVM_C_SVC` | 13-5의 C 파라미터를 쓰는 분류 |
| Kernel | `SVM_LINEAR` | 13-6. 4,032차원이라 직선이면 충분 |
| Gamma | 1 | RBF용. **효과 없음** |
| C | 1 | 13-5. 적당히 관대함 |

⚠️ 함수 인자 이름 `type`은 파이썬 내장 함수 `type()`을 가립니다. 이 함수 안에서는 `type(x)`를 쓸 수 없어요. 동작에는 문제없지만 나쁜 습관입니다.

### 🧱 `TermCriteria`: 언제 학습을 멈출까

SVM 학습은 답을 **조금씩 고쳐 나가는 반복 계산**이라서 "언제 그만둘지"를 정해 줘야 합니다.

```python
svm.setTermCriteria((type, max_iter, epsilon))
#                     │     │         └ 한 번 고쳤을 때 변화가 이것보다 작으면 멈춤
#                     │     └ 최대 반복 횟수
#                     └ 어떤 조건을 쓸지 (비트 플래그)

32번째 줄 호출:  SVM_create(cv2.TERM_CRITERIA_MAX_ITER, 1000, 1e-6)
```

| 상수 | 값 | 뜻 |
|---|---|---|
| `TERM_CRITERIA_MAX_ITER` (= `COUNT`) | 1 | 반복 횟수 조건만 사용 |
| `TERM_CRITERIA_EPS` | 2 | 변화량 조건만 사용 |
| 둘을 더한 3 | 3 | 둘 중 **먼저 만족하는 쪽**에서 멈춤 |

교재는 `MAX_ITER`(1)만 넘겼으니까 **1000번 반복하면 멈추고, `1e-6`은 무시됩니다.** L6의 floodFill `flags`처럼 비트를 더해서 조건을 조합하는 방식이에요.

## 14-3. 🔢 모양 바꾸기: (140, 28, 144) → (140, 4032) float32 (26번째 줄)

```python
26 trainData = np.reshape(trainData, (nsample, -1)).astype("float32")
```

```
trainData (읽은 직후):  길이 140짜리 리스트, 원소 하나 = (28, 144) uint8 배열
                         ┌─────────┐ ┌─────────┐       ┌─────────┐
                         │ 28×144  │ │ 28×144  │  …    │ 28×144  │
                         └─────────┘ └─────────┘       └─────────┘
          │ np.reshape(…, (140, -1))       -1 = "나머지는 알아서 계산" → 28×144 = 4032
          ▼
(140, 4032) uint8        한 행 = 사진 한 장 = 4,032차원 점 하나 (L7의 12-2)
          │ .astype("float32")
          ▼
(140, 4032) float32      140 × 4032 × 4바이트 = 2,257,920바이트 ≈ 2.2 MB
```

**왜 float32로 바꾸나?** OpenCV의 `ml` 모듈은 학습 데이터로 **32비트 실수(CV_32F)만** 받습니다. uint8 그대로 넣으면 에러가 나요.

## 15-2. 🔢 불러오고, 펴고, 예측하기 (13~16번째 줄)

자동차 2번(2차 후보 2개: 진짜 번호판 + 왼쪽 아래 어두운 부분)으로 실제 값을 따라가 볼게요.

```python
13 svm = cv2.ml.SVM_load("SVMTrain.xml")       # ⚠️ 저장할 땐 SVMtrain, 읽을 땐 SVMTrain (Windows만 OK)
14 rows = np.reshape(candidate_imgs, (len(candidate_imgs), -1))
#   → (2, 4032) uint8
15 _, results = svm.predict(rows.astype("float32"))
16 correct = np.where(results == 1)[0]
```

**`predict`의 반환값 (실측):**
```
retval  = 0.0
results = [[1.],          ← 0번 후보: 번호판 ✓
           [0.]]          ← 1번 후보: 아님
          모양 (2, 1), float32
```

⚠️ 0번 결과가 1인데 `retval`은 **0.0**입니다. 여러 장을 한꺼번에 넣으면 `retval`은 믿을 만한 값이 아니에요. 그래서 코드가 `_`로 버리고 `results`만 씁니다. 잘한 부분이에요.

**`np.where`가 번호를 골라내는 과정:**
```
results == 1              → [[ True],
                             [False]]          (2, 1) 불리언 배열
np.where(results == 1)    → (array([0]), array([0]))
                              └ True인 칸의 행 번호 ┘ └ 열 번호 ┘   ← 2차원이라 튜플 2개
np.where(…)[0]            → array([0])         ← 행 번호만 = "번호판인 후보의 번호"
```

**콘솔 출력:**
```
분류 결과:  [1. 0.]
번호판 영상 인덱스: [0]
번호판 검출완료
```

# PART 3. 🧪 재학습 실험: 번호판 사진을 직접 만들어 보자

## 16-1. 문제와 아이디어

04번은 "번호판(1)" 사진이 없어서 실행할 수 없습니다. 그런데 우리 손에는 이미 **15장 자동차에서 똑바로 잘라낸 번호판 15장**이 있죠 (L6에서 버그를 고친 덕분이에요). 이걸로 학습 데이터를 만들어 봅시다.

**문제:** 15장은 너무 적어요. 4,032차원 공간에 점 15개로는 "번호판 무리"의 모양을 제대로 알 수 없습니다.

## 16-2. 🧱 데이터 증강 (augmentation)

> 🍕 비유: 친구 얼굴 사진이 한 장뿐이어도, 조금 밝게, 조금 어둡게, 조금 오른쪽으로, 조금 크게 찍힌 모습을 떠올려 볼 수 있죠. 실제 환경에서 **생길 법한 변화**를 일부러 만들어서 예시를 불리는 게 증강입니다.

번호판 한 장당 **30가지 변형**을 만들었어요.

| 변형 | 범위 | 실제 환경에서는 |
|---|---|---|
| 위치 이동 | 가로 ±3px, 세로 ±2px | floodFill이 사각형을 조금 다르게 잡음 |
| 크기 | 0.94 ~ 1.06배 | 후보 사각형이 조금 크거나 작음 |
| 밝기 | ×0.75 ~ 1.25, ±20 | 낮/밤, 그늘, 반사 |

```
번호판 15장 × 30 = 450장 (라벨 1)
"아님":  교재 제공 70장
       + 2차 후보 중 가짜 2개(2번 차, 4번 차) × 30
       + floodFill이 걸러낸 1차 후보 가짜들 × 10
```

## 16-3. 🧱 공정한 시험: Leave-One-Car-Out

> 🍕 비유: 시험 문제를 미리 보고 공부하면 100점이 나와도 실력이 아니죠. **0번 차로 시험을 볼 때는 0번 차의 사진(과 그 변형 30장)을 공부에서 빼야** 공정합니다.

그래서 **모델을 15번** 따로 학습시켰어요.
```
모델 #0: 1~14번 차로 학습  →  0번 차로 시험
모델 #1: 0, 2~14번 차로 학습  →  1번 차로 시험
…
모델 #14: 0~13번 차로 학습  →  14번 차로 시험
(각 모델: 학습 사진 610~660장, 그중 번호판 420장)
```

```python
# 핵심 코드 (요약)
s = cv2.ml.SVM_create()
s.setType(cv2.ml.SVM_C_SVC); s.setKernel(cv2.ml.SVM_LINEAR); s.setC(1)
s.setTermCriteria((cv2.TERM_CRITERIA_MAX_ITER, 1000, 1e-6))
s.train(np.reshape(X, (len(X), -1)).astype('float32'), cv2.ml.ROW_SAMPLE,
        np.int32(y).reshape(-1, 1))
```
04번과 **완전히 같은 설정**이에요. 데이터만 바꿨습니다.

## 16-5. ⚠️ 이 실험의 한계 (정직하게)

1. **15장은 여전히 아주 적다:** 모두 비슷한 카메라와 거리, 낮 시간 사진입니다. 밤 사진, 비 오는 날, 다른 각도에서는 장담할 수 없어요.
2. **11번과 13번은 같은 차**(`59저 0678`)입니다. 11번을 시험할 때 13번이 학습에 들어가 있으니 완벽히 공정하지는 않아요.
3. **증강 ≠ 새 데이터:** 같은 번호판을 흔든 것일 뿐, 새로운 글자 배치나 새 번호판 종류를 가르쳐 주지는 못합니다.
4. **실제 서비스라면** 수천~수만 장의 다양한 번호판이 필요합니다. 요즘은 이 단계를 딥러닝 검출기(YOLO 등)가 대신해요 (L11에서 비교).

## ⑥ ⚠️ 함정 모음

1. **학습 데이터 절반이 없음:** 04번은 지금 저장소에서 실행할 수 없습니다.
2. **`setGamma(1)`, `epsilon=1e-6`:** 둘 다 설정만 있고 **효과는 없어요.**
3. **함수 인자 이름 `type`:** 내장 함수를 가립니다.
4. **float32 / int32 형식:** 학습 데이터는 float32, 분류 라벨은 int32 (N, 1)이어야 합니다.
5. **`predict`의 retval:** 여러 장을 넣으면 의미 없는 값입니다. `results`를 쓰세요.
6. **후보 0개 → `reshape` 에러:** 07번과 08번 모두 해당돼요.
7. **`SVMtrain.xml` vs `SVMTrain.xml`:** 대소문자를 구분하는 OS에서는 파일을 못 찾습니다.
8. **판정값이 0 근처:** 정답이어도 아슬아슬한 판정은 작은 흔들림에 뒤집힙니다. 정확도뿐 아니라 **여유(마진)**도 봐야 해요.
