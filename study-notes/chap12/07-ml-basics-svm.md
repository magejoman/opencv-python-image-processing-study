## 🔑 L6 확인 문제 정답

**Q1.** `flags = 8 + (128 << 8) + MASK_ONLY`
- ① 하위 8비트가 8 → **8-연결**
- ② 8~15비트가 128 → 마스크에 **128**로 기록 (그래도 `threshold(fill, 120)`은 128 > 120이라 흰색으로 남아요)
- ③ FIXED_RANGE 비트가 없음 → **FLOATING** (바로 옆 이웃과 비교)

**Q2.** θ = 90°이니까 α = 0, β = 1입니다.
```
M = [[ 0, 1, (1−0)×100 − 1×100 ],   = [[ 0, 1,   0 ],
     [−1, 0, 1×100 + (1−0)×100 ]]      [−1, 0, 200 ]]

(150, 100) → x' = 0×150 + 1×100 + 0   = 100
             y' = −1×150 + 0×100 + 200 = 50     → (100, 50)
```
중심의 **오른쪽**에 있던 점이 중심의 **위쪽**(y가 작아짐)으로 갔어요. 화면에서 "오른쪽 → 위"는 **반시계 방향**이 맞습니다.

**Q3.** w < h이니까 두 코드 모두 w와 h를 바꿉니다.
- 원래 코드: 85 + 90 = **175°** 회전 → 거꾸로 뒤집힌 번호판
- 고친 코드: 85 − 90 = **−5°** 회전 → **똑바로 선 번호판**

# PART 1. 머신러닝 기초

## 12-1. 규칙으로 쓰기 vs 예시로 배우기

### 12-1-a. "번호판이란?"을 if문으로 써 보면

지금까지는 전부 **사람이 규칙을 썼습니다.** "반지름이 25보다 크면 동전", "종횡비가 2~6.5면 번호판 후보"처럼요. 그럼 "이 144×28 사진이 번호판인가?"도 규칙으로 써 볼까요?

```
if 바탕이 밝은가
   and 어두운 덩어리가 7개쯤 있는가
   and 덩어리들이 가로로 일정 간격인가
   and 양 끝에 볼트 구멍이 있는가
   and 위아래 테두리가 있는가
   and … (조명이 어두우면? 흙탕물이 튀었으면? 기울어졌으면? 반사가 심하면?)
```

예외가 끝없이 생겨요. 사람이 모든 경우를 미리 생각해 둘 수는 없습니다.

### 12-1-b. 🍕 다른 방법: 예시를 보여주고 스스로 규칙을 찾게 하기

> 🍕 비유: 아이에게 "강아지란 다리가 넷이고 털이 있고 꼬리가 있고…"라고 규칙을 가르치지 않죠. 강아지 사진 여러 장과 "이건 강아지 아님"인 사진 여러 장을 보여주면, 아이가 **스스로 구분하는 감**을 익힙니다. 이게 **지도 학습(supervised learning)**이에요.

| 용어 | 뜻 | 이 프로젝트에서는 |
|---|---|---|
| 샘플 (sample) | 예시 하나 | 144×28 사진 한 장 |
| 특징 (feature) | 샘플을 설명하는 숫자들 | 픽셀 밝기 4,032개 |
| 라벨 (label) | 정답 | 1 = 번호판, 0 = 아님 |
| 모델 (model) | 특징 → 라벨을 맞히는 함수 | SVM |
| 학습 (train) | 예시로 모델 안의 숫자를 정하기 | `svm.train(…)` → `SVMtrain.xml` |
| 예측 (predict) | 새 샘플의 라벨 맞히기 | `svm.predict(…)` |

## 12-2. 🧱 특징 벡터: 사진 → 숫자 한 줄 → 공간의 점

### 12-2-a. 사진을 한 줄로 펴기

```
2×3 장난감 사진               한 줄로 펴기 (reshape)
┌────┬────┬────┐
│ 10 │ 20 │ 30 │      →      [10, 20, 30, 40, 50, 60]
├────┼────┼────┤              └ 1행 ┘ └ 2행 ┘

└────┴────┴────┘
```

번호판 후보는 28행 × 144열이니까 **28 × 144 = 4,032개** 숫자가 됩니다. 07번 코드의 이 줄이 그 일을 해요.
```python
rows = np.reshape(candidate_imgs, (len(candidate_imgs), -1))   # (N, 28, 144) → (N, 4032)
```

**🔢 실제 값 (자동차 0번 후보들의 처음 10개 숫자):**

```
번호판     [174 168 171 172 171 172 174 174 175 174 …]   ← 흰 바탕 (왼쪽 위 모서리)
헤드라이트 [190 182 173 167 158 148 135 124 115 113 …]
미러       [ 22  60 115 144 143 131 120 116 116 119 …]
```

### 12-2-b. 🖼️ "4,032차원 공간의 점"이 무슨 뜻인가

4,032차원은 상상이 안 되니 **사진이 픽셀 2개짜리라고 상상해 봅시다.** 그러면 사진 한 장 = 숫자 2개 = **평면 위의 점 하나**예요.

```
 픽셀2 밝기
 255 ┤                          ● ● ●       ← "번호판" 사진들은
     │                        ●  ● ●          이 근처에 모이고
     │                          ●
     │
     │       ○                              ← "번호판 아님" 사진들은
     │    ○    ○  ○                           여기저기 흩어짐
     │  ○   ○
   0 ┼──────────────────────────────── 픽셀1 밝기
     0                                 255
```

비슷한 사진은 **가까운 점**이 됩니다 (픽셀 값이 비슷하니까요). 그러면 "번호판 판별"은 **"두 무리를 가르는 선을 긋는 문제"**로 바뀌어요. 차원이 4,032로 늘어도 원리는 똑같습니다. 선이 "4,031차원짜리 평평한 칸막이(초평면)"가 될 뿐이에요.

# PART 2. SVM의 원리

## 13-1. 장난감 문제: 점 8개를 가르는 선

2D 평면에 점 8개가 있습니다. ○는 라벨 0, ●는 라벨 1이에요.

```
 y
 5 ┤                   ●(5,5)
 4 ┤           ●(3,4)  ●(4,4)
 3 ┤                   ●(4,3)
 2 ┤ ○(0,2) ○(1,2)
 1 ┤        ○(1,1) ○(2,1)
 0 ┼──┬──┬──┬──┬──┬──┬── x
   0  1  2  3  4  5  6
```

두 무리를 가르는 선은 **무수히 많습니다.**
```
 선 A:  x + y = 3.5   ← ○ 쪽에 바짝 붙음
 선 B:  x + y = 5     ← 딱 가운데
 선 C:  x + y = 6.5   ← ● 쪽에 바짝 붙음
```
셋 다 학습 데이터 8개는 완벽하게 가릅니다. **어느 선이 가장 좋을까요?**

## 13-2. 🍕 마진과 서포트 벡터: "가장 넓은 도로"

> 🍕 비유: 두 마을(○ 마을, ● 마을) 사이에 **도로**를 깐다고 해 봐요. 도로 위에는 집이 있으면 안 됩니다. SVM의 규칙은 하나예요. **"도로 폭을 최대한 넓게."**
>
> 도로의 **중앙선**이 판정선이고, 도로 **폭의 절반**을 **마진(margin)**이라고 부릅니다. 도로 가장자리에 딱 닿는 집들이 도로 위치를 결정하는데, 이 집들을 **서포트 벡터(support vector)**라고 해요. 도로를 "받치고(support)" 있으니까요.

```
 y
 5 ┤  ╲         ╲         ╲    ●
 4 ┤   ╲      ●  ╲      ●  ╲●         ← 오른쪽 가장자리 x+y=7 에 ●(4,3), ●(3,4) 가 닿음
 3 ┤    ╲         ╲         ●
 2 ┤ ○   ○         ╲         ╲
 1 ┤    ╲○   ○      ╲         ╲       ← 왼쪽 가장자리 x+y=3 에 ○(1,2), ○(2,1) 이 닿음
 0 ┼─────╲──────────╲──────────╲──── x
         x+y=3     x+y=5       x+y=7
        (가장자리)  (중앙선)    (가장자리)
         └────── 도로 ──────────┘
```

- **선 B**(x+y = 5)는 양쪽 가장 가까운 점까지의 거리가 같고 최대입니다 → **SVM의 답**
- 선 A나 C는 한쪽 마을에 바짝 붙어 있어요. 새 점이 조금만 흔들려도 틀리기 쉽습니다.
- **서포트 벡터 4개:** ○(1,2), ○(2,1), ●(4,3), ●(3,4)
- 나머지 점 ○(0,2), ○(1,1), ●(4,4), ●(5,5)는 **없어도 답이 똑같아요.** 경계에서 멀리 떨어진 "쉬운 예시"는 판정선에 영향을 주지 않습니다.

## 13-3. 🧮 수학으로 쓰기

### 13-3-a. 판정 함수

```
f(x) = w · x + b          w = 가중치 벡터 (방향),  b = 절편 (위치)

f(x) > 0  →  ● (라벨 1)
f(x) < 0  →  ○ (라벨 0)
f(x) = 0  →  판정선 (중앙선)
f(x) = ±1 →  도로 가장자리
```

`w · x`는 **내적**이에요. 2D에서는 w₁x₁ + w₂x₂, 4,032D에서는 w₁x₁ + w₂x₂ + … + w₄₀₃₂x₄₀₃₂. 한 줄로 말하면 **"픽셀마다 가중치를 곱해서 전부 더한 점수"**입니다. L3 동전의 `ws` 가중치 점수와 같은 모양이죠. 차이는 그때는 사람이 `ws`를 정했고, 이번에는 **데이터가 w를 정한다**는 거예요.

### 13-3-b. 도로 폭 = 2 / ‖w‖

가장자리 두 선 f = +1과 f = −1 사이의 거리는 **2 / ‖w‖**입니다 (‖w‖ = w의 길이). 그래서:

```
"도로 폭을 최대로"  =  "‖w‖를 최소로"

  최소화:  ½ ‖w‖²
  조건:    모든 학습 점 i 에 대해  yᵢ · f(xᵢ) ≥ 1     (yᵢ = +1 또는 −1)
           → "모든 집은 자기 마을 쪽 도로 가장자리 밖에 있어야 한다"
```

### 13-3-c. ✍️ 장난감 문제를 손으로 풀기

대칭이니까 w = (a, a) 꼴로 두고, 서포트 벡터가 가장자리에 **딱 닿는다**는 조건을 씁니다.
```
●(4,3) 이 f = +1 위에:   4a + 3a + b = +1   →   7a + b = +1
○(1,2) 이 f = −1 위에:   1a + 2a + b = −1   →   3a + b = −1
                                               ──────────────
                                    빼면:      4a = 2  →  a = 0.5
                                               b = −1 − 1.5 = −2.5

w = (0.5, 0.5),  b = −2.5,   f(x, y) = 0.5x + 0.5y − 2.5
판정선 f = 0  ⇔  x + y = 5   ✓
도로 폭 = 2 / ‖w‖ = 2 / √(0.25 + 0.25) = 2 / 0.7071 = 2.828
          (확인: 선 x+y=3 과 x+y=7 사이 거리 = 4/√2 = 2.828 ✓)
```

**8개 점 전부 조건 검사:**
| 점 | 라벨 y | f(x) = 0.5x + 0.5y − 2.5 | y·f ≥ 1 ? | 위치 |
|---|---|---|---|---|
| ○(1,2) | −1 | −1.0 | 1.0 ✓ | 가장자리 (SV) |
| ○(2,1) | −1 | −1.0 | 1.0 ✓ | 가장자리 (SV) |
| ○(1,1) | −1 | −1.5 | 1.5 ✓ | 바깥 |
| ○(0,2) | −1 | −1.5 | 1.5 ✓ | 바깥 |
| ●(4,3) | +1 | +1.0 | 1.0 ✓ | 가장자리 (SV) |
| ●(3,4) | +1 | +1.0 | 1.0 ✓ | 가장자리 (SV) |
| ●(4,4) | +1 | +1.5 | 1.5 ✓ | 바깥 |
| ●(5,5) | +1 | +2.5 | 2.5 ✓ | 바깥 |

## 13-4. 🔢 OpenCV로 실제 학습시켜 확인

같은 점 8개로 `cv2.ml.SVM`(선형, C = 100)을 학습시켰습니다.

```
getUncompressedSupportVectors() → [[1,2], [2,1], [4,3], [3,4]]     ✓ 손계산과 같음
getSupportVectors()             → [[−0.5, −0.5]]                    ← 선형 SVM은 w 하나로 "압축"해서 저장
getDecisionFunction(0)          → rho = −2.5,  alpha = [1.0]
```

⚠️ **부호 주의:** OpenCV의 판정값은 `d(x) = w_cv · x − rho`입니다.
```
d(x) = (−0.5)x + (−0.5)y − (−2.5) = −0.5x − 0.5y + 2.5 = −f(x)
→ d > 0 이면 첫 번째 라벨(0),  d < 0 이면 두 번째 라벨(1)
```
손계산 f와 **부호만 반대**이고 같은 선이에요. OpenCV 내부 규칙일 뿐입니다.

**새 점 예측 (실측):**
| 새 점 | x + y | d(x) (RAW_OUTPUT) | 예측 | 해석 |
|---|---|---|---|---|
| (0, 0) | 0 | +2.5 | 0 | ○ 쪽 깊숙이 |
| (2, 2) | 4 | +0.5 | 0 | ○ 쪽, **도로 위** (\|d\| < 1) |
| (2.5, 2.5) | 5 | ≈ 0.0000000004 | 0 | **중앙선 바로 위** (동전 던지기) |
| (3, 3) | 6 | −0.5 | 1 | ● 쪽, 도로 위 |
| (4, 3) | 7 | −1.0 | 1 | ● 쪽 가장자리 |
| (6, 6) | 12 | −3.5 | 1 | ● 쪽 깊숙이 |

**|d|가 클수록 "확신"이 큽니다.** 중앙선에서 멀수록 확실한 판정이에요.

## 13-5. C 파라미터: 도로 폭 vs 규칙 위반

### 13-5-a. 문제 상황

현실의 데이터에는 **이상한 점**(라벨 실수, 애매한 사진)이 섞여 있습니다. 장난감에 ○(3,3)을 하나 추가해 볼게요. ● 마을 바로 앞에 있는 ○입니다.

```
 4 ┤           ●   ●
 3 ┤        ○(3,3) ●      ← 이 녀석 때문에 도로를 넓게 깔 수가 없음
 2 ┤ ○   ○
 1 ┤     ○   ○
```

**선택지는 두 가지예요.**
- (가) 이 ○ 하나를 **무시하고**(틀려도 되니까) 넓은 도로를 유지한다
- (나) 이 ○까지 맞히려고 도로를 **아주 좁게** 깐다

> 🍕 **C = "규칙 위반 벌금"**
> - C가 **작으면** 벌금이 싸서 몇 집이 도로를 침범해도 넓은 도로를 깝니다 → (가)
> - C가 **크면** 벌금이 비싸서 모든 집을 지키려고 좁은 도로를 깝니다 → (나)
> 이렇게 위반을 허용하는 걸 **소프트 마진**이라고 해요.

### 13-5-b. 🔢 실측

| C | 판정선 | 도로 폭 2/‖w‖ | 학습 정확도 (9개 중) | ○(3,3) 판정 | 성격 |
|---|---|---|---|---|---|
| 0.01 | (너무 느슨) | **15.7** | 56% | 0 | 너무 관대 → 아무것도 제대로 못 가름 (과소적합) |
| 0.1 | | 3.54 | 89% | **1 (틀림)** | |
| 1 | x + y = 5 | 2.83 | 89% | **1 (틀림)** | ○(3,3)을 "예외"로 보고 무시 |
| 100 | **x + y = 6.5** | **0.71** | **100%** | 0 (맞힘) | 전부 맞히려고 도로를 ● 쪽으로 바짝 붙임 |

C = 100의 선 x + y = 6.5는 ● 마을에 바짝 붙어 있어요. 학습 데이터는 100% 맞히지만, 새로운 ●가 조금만 왼쪽에 와도 틀립니다. **학습 점수가 높다고 좋은 모델은 아니에요** (과적합). 교재 코드는 **C = 1**을 씁니다.

## 13-6. 커널: 직선으로 안 될 때

### 13-6-a. 문제

점들이 **원 안(●)과 원 밖(○)**으로 나뉘면 직선 하나로는 절대 못 가릅니다.

```
 ○   ○    ○    ○
   ○   ● ● ●   ○
 ○   ● ● ● ●     ○       어떤 직선을 그어도 원을 못 가름
   ○   ● ● ●   ○
 ○   ○    ○    ○
```

### 13-6-b. 🍕 커널 트릭: 차원을 하나 올려서 보기

> 🍕 비유: 평평한 탁자 위에 동그랗게 놓인 구슬(●)과 바깥 구슬(○)이 있어요. 탁자 가운데를 **아래에서 손가락으로 쭉 밀어 올리면** ●들이 위로 솟고 ○들은 아래에 남습니다. 이제 **수평한 판 하나**로 위아래를 가를 수 있죠.

수학으로는 z = x² + y²라는 **새 축**을 만드는 겁니다. 원 안의 점은 z가 작고 밖의 점은 z가 커서, 3D에서는 평면 z = r²로 가를 수 있어요. **RBF 커널**은 이런 변환을 (사실상 무한 차원으로) 자동으로 해 줍니다.

**🔢 실측 (원 안 25.5%, 원 밖 74.5%인 점 200개):**
| 커널 | 정확도 |
|---|---|
| LINEAR | 74.5% ← "전부 ○"라고 찍은 것과 같은 수준 |
| RBF (γ = 0.5) | **99.0%** |

### 13-6-c. 그런데 번호판은 왜 LINEAR?

차원이 **4,032**나 되면 샘플 140개 정도는 대부분 **직선(초평면)만으로도 충분히 갈라집니다.** 차원이 높을수록 공간이 넓어서 점들 사이에 칸막이를 넣을 틈이 많거든요. 선형은 빠르고 과적합 위험도 적어요.

⚠️ 그래서 04번의 `svm.setGamma(1)`은 **아무 효과가 없습니다.** γ(gamma)는 RBF 같은 커널의 파라미터라서 LINEAR에서는 쓰이지 않아요.

## 13-8. 🖼️ w를 다시 28×144 그림으로 펴 보기

w는 픽셀마다 하나씩 있는 가중치니까, **사진 모양으로 되돌려 볼 수 있습니다.** 14×48로 줄여서 크기가 큰 쪽 절반만 표시했어요.

판정값 `d = w·x − rho`에서:
- `+` : 여기가 **밝으면** d가 커짐 → **"번호판 아님(0)"** 쪽 증거
- `−` : 여기가 **밝으면** d가 작아짐 → **"번호판(1)"** 쪽 증거

```
...........+...............--.................-.
.---....--.......-.--...-..--...............---.
.---.++...+++++++............++++++++++++++.---.
.---.++...+....++++..--.......++..........+----.
-----++.--.....++++..---....-...-...++....+----+
-----+++--+.+.+++++.----...+..+...-.++....+----+
.-.-.++.--+...+++++..---.++....+.--.+..+..+----+
.-..-.+.-....-.++++..---..+..-.+.--...-+.++....+
--......-.+.....+++.-----.++--.+.-....-.+++....+
.---.++.-.+++...+.+.-----..+...+.-...+-..++---.+
----.+++--++++..+..-----+.....+++...++--+++----+
----.++.--.....---------.......+.-..+.--...----+
.-.-..........---------...--------------..---..+
+.+++++++..+++++...++...........++....++.....++.
 └┬┘  └─글자 자리─┘  └┬┘  └──글자 자리 ────┘ └─┬┘
 왼쪽 끝 여백         가운데 빈칸               오른쪽 끝 여백
 ("−": 밝아야 번호판)  ("−")                    ("−")
```

대략적인 해석은 이렇습니다.
- **`−` 영역 = 번호판이라면 늘 흰 바탕인 곳:** 왼쪽 끝 여백, 앞 글자와 뒤 숫자 사이의 빈칸(가운데), 오른쪽 끝 여백, 아래쪽 여백. 여기가 밝으면 "번호판답다".
- **`+` 영역 = 번호판이라면 검은 글자가 있는 곳과 바깥 테두리:** 여기까지 밝으면 "글자가 없네? 번호판이 아니구나".

SVM이 **"번호판의 밝고 어두운 배치 패턴"**을 스스로 찾아낸 거예요. 아무도 "가운데에 빈칸이 있다"고 가르쳐 주지 않았는데요.

> 🔍 **L6 뒤집힘 버그와의 연결:** w는 **"똑바로 선 번호판"의 배치**를 외우고 있습니다. 180° 뒤집힌 번호판은 여백과 글자 자리가 서로 엇갈려서 이 패턴과 맞지 않아요. 그래서 SVM이 "번호판 아님"이라고 거절했던 겁니다 (L0 성적표의 "SVM 거절" 대부분).

## 13-9. 🔢 자동차 0번 후보들의 실제 판정값

| 후보 | 판정값 d = w·x − rho | 예측 | 해석 |
|---|---|---|---|
| 번호판 (2차 후보) | **−0.188** | **1 (번호판)** ✓ | 중앙선 근처, **도로 위**(\|d\| < 1). 아슬아슬하게 통과 |
| 헤드라이트 (1차 후보 그대로) | +1.301 | 0 | 도로 밖, 확실한 "아님" |
| 미러 (1차 후보 그대로) | +1.258 | 0 | 도로 밖, 확실한 "아님" |
| 학습용 "아님" 70장 | **+1.000 ~ +1.731** | 70장 모두 0 | 최솟값 0.99999 ≈ 1 → 여러 장이 **도로 가장자리**에 딱 붙어 있음 (= 서포트 벡터) |

두 가지를 눈여겨보세요.
1. 헤드라이트와 미러는 L6의 floodFill이 이미 떨어뜨렸지만, **SVM에게 줬어도 거절**당했을 겁니다. 깔때기에 **이중 안전장치**가 있는 셈이에요.
2. 진짜 번호판의 d가 **−0.188**로 0에 꽤 가깝습니다. 자신 있는 판정이 아니에요. 학습 때 본 번호판 사진들과 조명이나 크기가 조금 다르면 쉽게 0으로 넘어갈 수 있습니다. L6 성적표에서 시드에 따라 "SVM 거절"이 나왔다 안 나왔다 한 이유 중 하나예요.

## ⑥ ⚠️ 함정 모음

1. **OpenCV 판정값의 부호:** `d = w·x − rho`이고 **양수면 첫 번째 라벨(0)**입니다. 교과서의 f(x) = w·x + b와 부호가 반대예요.
2. **`setGamma(1)`은 LINEAR에서 무의미:** 코드에 있지만 아무 일도 안 합니다.
3. **픽셀 위치에 민감하다:** w는 "이 자리는 밝아야 해"를 외운 것이라, 번호판이 **뒤집히거나 밀리거나 크기가 다르면** 판정이 무너집니다. L6의 회전·잘라내기·144×28 고정이 그래서 중요해요.
4. **원본 밝기(0~255)를 그대로 넣는다:** 조명이 전체적으로 어두운 사진은 모든 숫자가 작아져서 판정값이 흔들립니다. 보통은 정규화(평균 빼기 등)를 해요.
5. **샘플 140개 vs 차원 4,032개:** 숫자(가중치)가 샘플보다 훨씬 많아서 학습 데이터를 "외워 버릴" 위험이 큽니다.
6. **학습 데이터의 절반이 없다:** "번호판(1)" 예시 000~069가 저장소에 없어서 재학습할 수 없어요 (L8에서 대안을 봅니다).
