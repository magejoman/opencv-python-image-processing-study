# PART 1. 색 분포 재기 (`calc_histo_hue`)

## 4-1. HSV로 바꾸기

### 4-1-a. 📚 복습 박스: HSV

> Chapter06 배경교체·손감지에서 `inRange`로 "특정 색만 골라내기"를 할 때 HSV를 썼죠. HSV는 색을 세 가지 질문으로 나눕니다.
> - **H (Hue, 색상):** 무슨 색이야? 빨강, 노랑, 초록, 파랑…
> - **S (Saturation, 채도):** 얼마나 진해? 0 = 회색·흰색, 높을수록 선명
> - **V (Value, 명도):** 얼마나 밝아? 0 = 검정
>
> BGR은 세 숫자가 섞여서 "무슨 색인지"가 한 숫자로 드러나지 않습니다. HSV에서는 **H 하나만 보면 색**을 알 수 있어요. 조명이 밝든 어둡든(V가 변해도) H는 비교적 그대로라서 색 판별에 유리합니다.

### 4-1-b. 🖼️ 색상환과 OpenCV의 H 범위

원래 Hue는 0~360°의 각도입니다. 그런데 uint8은 255까지만 담을 수 있으니까 OpenCV는 **각도를 2로 나눠 0~179**로 저장해요.

```
OpenCV H:   0      15      30      60      90      120     150     179
각도:       0°     30°     60°     120°    180°    240°    300°    358°
색:        빨강 → 주황 → 노랑 → 초록 → 청록 → 파랑 → 보라 → (다시 빨강)
```

**실측 확인:**
| BGR | 색 | OpenCV HSV |
|---|---|---|
| (0, 0, 255) | 순수 빨강 | H=**0**, S=255, V=255 |
| (0, 128, 255) | 주황 | H=**15**, S=255, V=255 |
| (255, 0, 0) | 순수 파랑 | H=**120**, S=255, V=255 |
| (0, 0, 0) | **검정** | H=**0**, S=0, V=0 |
| (255, 255, 255) | **흰색** | H=**0**, S=0, V=255 |

⚠️ 검정과 흰색은 "무슨 색이냐"는 질문에 답할 수 없는 색입니다(S = 0). 그래서 OpenCV는 **그냥 H = 0으로 적어요.** 순수 빨강과 같은 값이죠. 4-5의 함정으로 이어집니다.

### 4-1-c. 🧮 변환 공식과 실제 픽셀 손계산

```
V   = max(R, G, B)
mn  = min(R, G, B),   d = V − mn
S   = d / V × 255                      (V = 0 이면 S = 0)
H°  = 60 × (G − B) / d                 (V가 R일 때)
      120 + 60 × (B − R) / d           (V가 G일 때)
      240 + 60 × (R − G) / d           (V가 B일 때)
H   = H° / 2                           ← OpenCV 저장값
```

**① 은색 500원 L의 중심 픽셀: BGR = (255, 230, 210)** → R=210, G=230, B=255
```
V = 255 (B가 최대),  mn = 210,  d = 45
S = 45 / 255 × 255 = 45
H° = 240 + 60 × (210 − 230) / 45 = 240 − 26.67 = 213.3°   → 파랑 쪽!
H = 213.3 / 2 = 106.7 → 107        실측 HSV: [107, 45, 255] ✓
```

**② 구리색 10원 C의 중심 픽셀: BGR = (126, 145, 138)** → R=138, G=145, B=126
```
V = 145 (G가 최대),  mn = 126,  d = 19
S = 19 / 145 × 255 = 33.4 → 33
H° = 120 + 60 × (126 − 138) / 19 = 120 − 37.9 = 82.1°     → 노랑~연두 쪽
H = 41                              실측 HSV: [41, 33, 145] ✓
```

> 🤔 **잠깐, 은색이 왜 파랑이지?** 은색 동전은 원래 거의 무채색입니다. 그런데 이 사진을 찍은 카메라의 **화이트밸런스가 살짝 차갑게** 잡혀서, 은색 동전 전체의 평균이 B 244.8 > G 222.6 > R 204.3으로 **푸르스름하게** 찍혔어요. 구리색 10원은 평균 B 122.9 < G 138.5 > R 133.8로 **누르스름한 올리브색**이고요. 교재 코드는 이 "은색 = 푸르스름" 현상을 그대로 이용합니다. 그래서 조명이 바뀌면 깨질 수 있어요(5-5).

## 4-2. 🧱 히스토그램: 투표함 32개

### 4-2-a. 🍕 개념

> 🍕 비유: 투표함이 32개 놓여 있고, 각 함에는 "H 0~5.6", "H 5.6~11.3" … 이런 이름표가 붙어 있습니다. 동전 패치의 픽셀 하나하나가 **자기 H값에 맞는 함에 표를 한 장씩** 넣어요. 다 넣은 뒤 함마다 표를 세면 그게 히스토그램입니다.

```
칸 하나의 폭 = 180 / 32 = 5.625
칸 번호 = floor(H / 5.625)

칸  0: H 0.0 ~ 5.6     ← 빨강 + 검정 + 흰색이 전부 여기!
칸  6: H 33.8 ~ 39.4   ← 노랑~연두 (구리색 10원)
칸 19: H 106.9 ~ 112.5 ← 파랑 (은색 동전)
```

### 4-2-b. 🔢 장난감: 픽셀 8개의 H값을 직접 투표

```
H값:   0   0   41   38   107   110   107   0
칸:   0   0    7    6    19    19    19    0        (41/5.625 = 7.3 → 7,  107/5.625 = 19.02 → 19)

결과:  칸0 = 3표,  칸6 = 1표,  칸7 = 1표,  칸19 = 3표,  나머지 = 0표
```

## 4-5. ⚠️ 칸 0의 정체: 동전이 아닌 픽셀들

L2 복선에서 말한 문제가 숫자로 확인됐습니다.

```
은색 L 패치 25,281픽셀 =
    16,472  마스크 밖 검정 (0,0,0)  → H=0 → 칸 0     65.2%
  +  8,809  실제 동전 픽셀           → 칸 15~27
```

마스크로 지운 검정 영역이 **동전의 색이 아닌데도** 칸 0에 표를 던지고 있어요. `calcHist`의 마스크 자리가 `None`이라서 생기는 일입니다.

하얗게 날아간 R은 더 심합니다. 동전 픽셀 중 **59.1%가 S = 0**(순백)이라 이것들도 H = 0으로 칸 0에 들어가요. 65.2% + 동전 픽셀 일부 = **85.8%**가 칸 0입니다.

> 이게 문제가 될까요? 칸 0의 가중치가 0이라 **분자**에는 영향이 없어요. 하지만 **분모**에는 들어갑니다. 결과는 5-3, 5-5에서 확인할게요.

## 5-3. 🧮 점수 계산

### 5-3-a. 공식과 비유

```
             Σ ( hᵢ × wᵢ )        칸마다 (표 수 × 그 칸 점수)를 다 더함
   s  =  ─────────────────
               Σ hᵢ               전체 표 수 (= 패치 픽셀 수)
```

> 🍕 비유: 다트 게임이에요. 픽셀 하나하나가 자기 H 칸에 다트를 던지고, 칸마다 점수판(`ws`)이 있습니다. 파랑 한가운데는 8점, 나머지는 0점. **s는 "픽셀 한 개당 평균 점수"**예요. 푸르스름한 픽셀이 많을수록 s가 커집니다.

### 5-3-b. 🔢 은색 L을 손으로 계산

| 표 hᵢ | 1 | 950 | 822 | 2447 | 4175 | 268 | 51 | 30 | 15 | 31 | 16 |
| 점수 wᵢ | 3 | 4 | 5 | 6 | **8** | 6 | 5 | 4 | 3 | 2 | 1 |
| hᵢ × wᵢ | 3 | 3,800 | 4,110 | 14,682 | **33,400** | 1,608 | 255 | 120 | 45 | 62 | 16 |

```
분자 = 3 + 3,800 + 4,110 + 14,682 + 33,400 + 1,608 + 255 + 120 + 45 + 62 + 16 = 58,101
분모 = 25,281 (검정 16,472 포함!)
s    = 58,101 / 25,281 = 2.298       실측: 2.298 ✓
```

### 5-3-d. 💻 numpy가 20개를 한 번에 계산하는 방법 (모양 따라가기)

```python
sim = np.multiply(hists, ws)
```
```
hists: 길이 32짜리 배열 20개의 리스트 → numpy가 (20, 32) 행렬로 취급
ws:    길이 32 리스트                 → (32,)

브로드캐스팅: ws 한 줄을 20줄로 "복사한 것처럼" 맞춰서 칸끼리 곱함
   ┌ h_A0  h_A1  …  h_A31 ┐     ┌ w0 w1 … w31 ┐     ┌ h_A0·w0  …  h_A31·w31 ┐
   │ h_B0  h_B1  …  h_B31 │  ×  │ w0 w1 … w31 │  =  │ h_B0·w0  …  h_B31·w31 │
   │  …                   │     │  …  (복사)   │     │  …                    │
   └ h_T0  h_T1  …  h_T31 ┘     └ w0 w1 … w31 ┘     └ h_T0·w0  …  h_T31·w31 ┘
            (20, 32)                (32,)→(20,32)              (20, 32)
```
```python
similaritys = np.sum(sim, axis=1) / np.sum(hists, axis=1)
#             └ 각 행을 가로로 합산 (20,)  └ 각 행의 총 표 수 (20,)   → 칸끼리 나눔 (20,)
```

`axis=1`은 "열 방향(가로)으로 접어서 합친다"는 뜻입니다. 행 20개가 남아요.

## 5-5. R과 T는 왜 구리 그룹으로 갔나? 그리고 고치는 방법

### 5-5-a. 원인 해부

```
R의 분모 25,281 =  16,472 (마스크 검정)  +  5,219 (순백 S=0 → 칸 0)  +  3,590 (나머지)
R의 분자 12,201 =  나머지 3,590픽셀에서만 나온 점수

→ 패치의 85.8%가 0점짜리 칸 0에 표를 던짐 → 평균 점수가 0.483으로 주저앉음
```

빛 반사로 **색 정보 자체가 사라진** 동전입니다. "파랑이 아니다"가 아니라 "색을 알 수 없다"가 정답인데, 이 방법은 "모름"을 "0점"으로 처리해 버려요.

### 5-5-b. 실험: 칸 0을 빼고 다시 계산하면?

분모에서 칸 0의 표를 빼 봤습니다. 즉 **색이 있는 픽셀만으로 평균**을 내는 거예요.

| | 원래 s | 칸 0 제외 s |
|---|---|---|
| 구리 8개 | 0.014 ~ 0.123 | 0.040 ~ **0.353** |
| 은색 10개 | 2.003 ~ 2.768 | **5.81** ~ 7.96 |
| R (하양) | 0.483 → 그룹 0 ✗ | **3.399** → 은색 쪽 ✓ |
| T (하양) | 0.216 → 그룹 0 ✗ | **2.237** → 은색 쪽 ✓ |

칸 0만 빼도 R과 T가 올바르게 은색 쪽으로 넘어갑니다. 코드로는 두 가지 방법이 있어요.
```python
# 방법 1: calcHist에 원형 마스크를 넘겨서 검정 영역은 아예 투표 못 하게
hist = cv2.calcHist([hsv], [0], mask_1ch, [32], [0, 180])
# 방법 2: 분모에서 칸 0을 빼기
similaritys = np.sum(sim, axis=1) / (np.sum(hists, axis=1) - hists[:, 0])
```

(방법 2를 쓰면 기준값 1.2도 다시 정해야 합니다. 점수 범위 자체가 바뀌니까요.)

### 5-5-c. 그래도 결과가 맞았던 이유

R과 T는 그룹이 틀렸지만 **반지름 53**이 워낙 커서 L4의 반지름 표에서 결국 500원이 됩니다. 운이 좋았던 거예요. 만약 하얗게 날아간 동전이 **반지름 42짜리 50원**이었다면 그룹 0(구리)으로 가서 **10원**으로 잘못 세졌을 겁니다.

### 5-5-d. 이 방법의 근본적 한계

- **조명 의존:** "은색 = 푸르스름"은 이 사진의 화이트밸런스 덕분입니다. 따뜻한 노란 조명에서 찍으면 은색 동전의 H가 파랑 근처에 오지 않아서 `ws`가 무용지물이 돼요.
- **손으로 정한 숫자:** `ws`의 모양(칸 13~25, 최고점 칸 19)과 기준 1.2는 사람이 이 사진들을 보고 맞춘 값입니다 (L0의 매직 넘버 표).

## ⑥ ⚠️ 함정 모음

1. **검정과 흰색의 H는 0:** 순수 빨강과 구분되지 않습니다. 마스크 밖 검정이 칸 0에 65%나 쌓여요.
2. **`calcHist`의 마스크 자리가 `None`:** 원형 마스크를 넘겼다면 1번 문제가 없었습니다.

4. **하얗게 날아간 동전 → 그룹 오분류:** R과 T는 반지름 덕분에 결과만 우연히 맞았습니다.
