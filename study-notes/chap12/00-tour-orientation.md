## 0-1. 완성품부터 보기

레고를 조립하기 전에 상자 표지의 완성 사진부터 보는 단계입니다.

### 0-1-a. 프로젝트 A: 동전 → 금액

**입력:** `images/coin/70.png` (720×960 컬러). 검은 천 위에 동전 20개가 흩어진 사진입니다.

아래는 전처리를 마친 흑백 이진 영상을 64×24 글자 크기로 줄여 그린 그림이에요.
- `#` = 흰색(255) = 동전
- `.` = 검정(0) = 배경
- 알파벳 = 프로그램이 찾아낸 동전 20개의 중심. 찾은 순서대로 A~T를 붙였습니다.

```
................................................................
................................#####...........................
...............................###T###..#####...................
................###....#####...#######..##S##...................
...............##Q###.###R###.....#.......#.....................
...............#####...######...............###.................
...................................####...###P###...............
..............####................###O##..#######...............
.......####..###N##..######..#####.####.....###.................
......##K##..######.###L###..##M##.....####.....................
......#####..........######....#......###J##....................
.................................####..#####.######.............
..........####...####...######..##H###.......##I###.............
.........##F###.##E###..###G##..######..##.....##...............
.......#######...####.....###.....##..###D##....................
.....##C###...................####....######....................
.....######.######...........###B##.............................
............###A##............#####.............................
..............##................................................
```

> 💡 재미있는 점: **A가 맨 아래, T가 맨 위**에 있어요. OpenCV가 덩어리를 아래쪽부터 찾아서 그렇습니다. 이 순서가 왜 생기는지는 L2에서 봅니다.

**프로그램이 내린 판정 (20개 전부):**

| 판정 | 동전 기호 | 반지름(px) | 색 그룹 |
|---|---|---|---|
| 10원 | C E F K M O Q S (8개) | 44~45 | 0 (노란빛·구리빛) |
| 100원 | A B D G I J N (7개) | 46~47 | 1 (은빛) |
| 500원 | H L P (3개) | 52~53 | 1 (은빛) |
| 500원 | R T (2개) | 53 | **0** ← 조명 반사로 **하얗게 날아간** 동전 |

**최종 계산:**
```
 10원 × 8 =    80
 50원 × 0 =     0
100원 × 7 =   700
500원 × 5 = 2,500
──────────────────
       합계 3,280원   ← 콘솔에 "Total coin: 3,280 Won" 출력
```

> 🔎 **R과 T를 눈여겨보세요.** 빛 반사 때문에 색 정보가 사라져서 "구리색 그룹(0)"으로 **잘못** 분류됐어요. 그런데도 반지름이 53으로 커서 결국 500원으로 판정됩니다. 이 코드가 **색과 크기라는 두 단서를 함께 쓰는 이유**가 여기서 살짝 보입니다. 3,280원이 정말 정답인지는 L4에서 동전을 하나씩 눈으로 대조해 확인합니다.

다른 사진도 돌려봤어요: 15번 → 2,360원, 0번 → 2,590원, 5번 → 2,460원.

### 0-1-b. 프로젝트 B: 자동차 → 번호판 문자열

**입력:** `images/car/00.jpg` (350×500). 은색 승용차 정면 사진입니다.

**중간 단계 미리보기:** 세로 에지 검출과 닫힘 연산을 거친 영상을 64×22 글자로 그렸어요. `#`은 흰 덩어리, 숫자 0·1·2는 **1차 번호판 후보**의 중심입니다.

```
................................................................
......................................................2.........
....................................................##....#.....
................................................................
(…중략…)
##..............................................................
####.............................................##.............
#............................................##1#####...........
................................#...........###.................
................................................................
..................######################........................
..................##########0###########........................   ← 이게 번호판!
..................................................###...........
```

| 1차 후보 | 중심 (x, y) | 크기 w×h | 각도 | 정체 |
|---|---|---|---|---|
| 0 | (224, 271) | 171×32 | 2.0° | **번호판** (가로가 세로의 5.3배) |
| 1 | (373, 184) | 33×96 | 68.4° | 오른쪽 헤드라이트 부근 |
| 2 | (428, 45) | 136×41 | 24.2° | 오른쪽 위 사이드미러 부근 |

다음 단계(floodFill로 다시 다듬기)를 거치면 후보가 1개로 줄고, SVM이 그 1개를 "번호판 맞음(1)"으로 판정합니다. 이어서 k-NN이 글자 7개를 읽으면 콘솔에 이렇게 찍혀요.

```
정렬 인덱스: [5 4 6 3 2 1 0]
숫자 분류 결과: [2 4 8 3 9 6 7]
문자 분류 결과: 25
분류 결과:  6 9 두 3 8 4 2
```

- **실제 번호판: `69두 3842` → 정답 ✅**
- 숫자 배열이 뒤죽박죽인 이유: 글자를 **찾은 순서**가 오른쪽→왼쪽이기 때문입니다. "정렬 인덱스"로 왼쪽→오른쪽 순서로 다시 줄을 세워요.
- "문자 분류 결과: 25"는 한글 40자 목록의 25번째 글자인 **'두'**를 뜻합니다.

이 부분은 L10에서 한 줄씩 해부합니다.

### 0-2-e. 🧱 `from xxx import *`가 실제로 가져오는 것

[01.find_coins.py](../../chap12/01.find_coins.py)를 보면 **`import cv2`가 어디에도 없는데** `cv2.circle(...)`이 동작합니다. 이유를 단계별로 볼게요.

```python
# header/coin_preprocess.py 의 첫 줄
import numpy as np, cv2           # ← 이 모듈 안에 np, cv2 라는 "이름"이 생김

def preprocessing(coin_no): ...   # ← preprocessing 이라는 이름
def find_coins(image): ...        # ← find_coins 라는 이름
```

```python
# 01.find_coins.py
from coin_preprocess import *
# "coin_preprocess 안의 이름 중 _로 시작하지 않는 것을 전부 내 쪽으로 복사해 와라"
# 결과적으로 01번 안에 생기는 이름: np, cv2, preprocessing, find_coins
```

```
coin_preprocess 모듈              01.find_coins.py
┌──────────────────┐   import *   ┌──────────────────┐
│ np               │ ───────────▶ │ np               │
│ cv2              │ ───────────▶ │ cv2   ← 그래서 cv2.circle 가능
│ preprocessing    │ ───────────▶ │ preprocessing    │
│ find_coins       │ ───────────▶ │ find_coins       │
└──────────────────┘              └──────────────────┘
```

⚠️ 편하긴 하지만 위험도 있습니다. `coin_preprocess`와 `plate_preprocess`에는 **똑같은 이름의 함수 `preprocessing`**이 있어요. 둘을 같이 `import *` 하면 **나중에 가져온 쪽이 앞의 것을 덮어씁니다.** 이 장에서는 두 모듈을 같이 import하는 파일이 없어서 문제가 생기지 않을 뿐이에요.

```
                                            Common ✓ (pip install -e . 로 등록돼 있음)
```

## 0-4. 고전 영상처리 파이프라인 사고방식

### 0-4-a. 🍕 비유: 깔때기 (공항 보안검색대)

공항에서 수천 명을 한 번에 정밀 검사하지는 않죠. **싸고 빠른 검사로 대부분을 걸러내고, 남은 소수만 비싸고 정밀하게** 봅니다. Chapter 12의 두 프로젝트가 정확히 이 구조예요. 실제 숫자로 보겠습니다.

```
[프로젝트 A: 동전 70번]
  691,200 픽셀 (720×960)
     │  전처리: 흑백 → 블러 → 이진화 → 열림           (L1)
     ▼
  흰 덩어리 20개      (findContours)                  (L2)
     │  반지름 > 25 인 것만 남김
     ▼
  동전 20개           (이 사진에선 걸러진 게 0개)
     │  동전마다 오려내기 → Hue 히스토그램 32칸       (L2~L3)
     ▼
  색 점수 20개  →  그룹0: 10개 / 그룹1: 10개          (L3)
     │  (그룹, 반지름) → 표 조회                       (L4)
     ▼
  10원 8 · 50원 0 · 100원 7 · 500원 5  →  3,280원


[프로젝트 B: 자동차 0번]
  175,000 픽셀 (350×500)
     │  전처리: 흑백 → 블러 → Sobel → 이진화 → 닫힘   (L5)
     ▼
  흰 덩어리 20개
     │  회전 사각형 + 넓이·종횡비 검사                 (L5)
     ▼
  1차 후보 3개
     │  floodFill로 다시 칠하고 다시 검사              (L6)
     ▼
  2차 후보 1개
     │  기울기 펴기 → 잘라내기 → 144×28 고정 크기      (L6)
     ▼
  후보 영상 1장  = 숫자 4,032개 한 줄
     │  SVM: "번호판이야?" → 1 (예)                    (L7~L8)
     ▼
  번호판 1장
     │  글자 조각 나누기                               (L10)
     ▼
  글자 7개  = 각각 숫자 1,600개 한 줄
     │  k-NN: 숫자 6개 + 한글 1개 읽기                 (L9~L10)
     ▼
  "69두 3842"
```

### 0-4-b. 두 프로젝트의 공통 4단계

| 단계 | 하는 일 | 동전 | 번호판 |
|---|---|---|---|
| ① 전처리 | 필요 없는 정보를 버리고 원하는 걸 **흰 덩어리**로 만들기 | 블러, 이진화, 열림 | 블러, Sobel, 이진화, 닫힘 |
| ② 후보 찾기 | 덩어리를 **도형**으로 바꾸기 | 최소 외접 **원** | 최소 면적 **회전 사각형** |
| ③ 검증·정제 | 가짜 걸러내기, 모양 다듬기 | 반지름 > 25 | 넓이·종횡비, floodFill, **SVM** |
| ④ 분류 | 무엇인지 결정 | 색 점수 + 반지름 표 | **k-NN** 글자 인식 |

### 0-4-c. "사람이 정한 숫자" vs "데이터가 정한 숫자"

이 장의 코드에는 사람이 사진을 보면서 손으로 맞춘 숫자, 이른바 **매직 넘버**가 아주 많습니다.

| 숫자 | 위치 | 의미 | 레슨 |
|---|---|---|---|
| `25` | find_coins | 이보다 작은 원은 버림 | L2 |
| `ws` 32개, `1.2` | grouping | 색 가중치와 은색 판정 기준 | L3 |
| `g` 표 (반지름 26/36/44/47/50) | classify_coins | 반지름 → 동전 종류 | L4 |
| `120`, `5×13`, `×3` | plate preprocessing | 이진화 기준, 닫힘 커널, 반복 횟수 | L5 |
| `3000~12000`, `2.0~6.5` | verify_aspect_size | 번호판 넓이와 종횡비 | L5 |
| `±25`, `±15`, `20개` | color_candidate_img | floodFill 색 허용치, 시드 범위, 시드 개수 | L6 |
| `45<x<80`, `w/h<2.5`, `60`, `150` | find_objects | 한글 위치, 글자 모양 조건 | L10 |

반대로 **데이터가 정한 숫자**는 두 군데뿐입니다.
- SVM의 가중치 4,032개: 학습 사진 140장에서 계산된 값
- k-NN이 외워 둔 글자 샘플: 숫자 200개 + 한글 800개

> 🍕 **딥러닝과 비교:** 고전 방식은 "180도 오븐에서 12분" 같은 **레시피를 사람이 한 줄씩 다 정하는** 요리입니다. 딥러닝은 완성된 요리 사진 수만 장을 보여주고 **레시피 자체를 기계가 배우게** 하는 방식이고요. Chapter 12는 레시피를 사람이 정하고, **마지막 맛 판정(번호판인가? 무슨 글자인가?)만** 학습에 맡긴 중간 형태입니다. 사람이 정한 숫자는 그 사진들에 딱 맞춰져 있어서 사진이 조금만 달라져도 쉽게 깨집니다. 0-1-c 성적표가 그 증거예요.

## ⑥ ⚠️ 함정 모음 (L0에서 발견한 것)

5. **04번은 실행 불가:** "번호판 맞음" 학습 사진(000~069)이 없습니다. 이미 학습된 xml이 있으니 07·08번은 문제없어요.
6. **실행할 때마다 결과가 조금씩 다름:** floodFill 단계가 **난수**로 시작점 20개를 뽑기 때문입니다. 같은 사진을 시드만 바꿔 8번 돌려보니 2차 후보 사각형이 0번 차는 4가지, 2번과 12번 차는 7가지로 나왔어요. 1번 차가 어떤 때는 통과하고 어떤 때는 거절되는 이유입니다.
7. **번호판이 180° 뒤집힘:** 실패의 주범입니다 (0-1-c). 원인 분석과 수정은 L6에서 합니다.
