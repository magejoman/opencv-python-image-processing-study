## 4-1. 히스토그램이란? 값별 인원수 세기

### Step A. 비유: 반 시험 점수 분포

30명 반의 시험 점수를 구간별로 세면 이렇게 돼요.

```
점수 구간     인원
 0~19  │ ██          2명
20~39  │ ████        4명
40~59  │ ████████    8명
60~79  │ ██████████ 10명
80~100 │ ██████      6명
```

이걸 보면 **"누가 몇 점인지"는 몰라도 반 전체의 실력 분포**가 한눈에 보여요. 이미지도 같아요.

> **이미지 히스토그램 = "밝기 0~255 각각(또는 구간마다) 화소가 몇 개 있나"를 센 표**

화소의 **위치 정보는 완전히 버려요.** 화소를 섞어 놓아도 히스토그램은 같아요. 대신 **밝기 분포**라는 전체 성격을 숫자 몇 개로 요약해요.

### Step B. 4×4 미니 이미지로 직접 세기

```
mini = [[ 10,  12, 200, 201],
        [ 11,  13, 205, 250],
        [100, 101, 102, 255],
        [  0,   9,   8,   7]]       화소 16개
```

**구간 4개 (폭 64)**로 세면:

| 구간(bin) | 값 범위 | 해당 화소 | 개수 |
|---|---|---|---:|
| 0 | 0 ~ 63 | 10, 12, 11, 13, 0, 9, 8, 7 | **8** |
| 1 | 64 ~ 127 | 100, 101, 102 | **3** |
| 2 | 128 ~ 191 | (없음) | **0** |
| 3 | 192 ~ 255 | 200, 201, 205, 250, 255 | **5** |
| | | 합계 | 16 ✔ |

실측 `cv2.calcHist` 결과도 `[8, 3, 0, 5]`로 같아요.

**구간 32개 (폭 8)**로 세면, 0이 아닌 구간만 추려서 실측 `{0: 2, 1: 6, 12: 3, 25: 3, 31: 2}`가 나와요.

- bin 0 (0~7): 0, 7 → 2개
- bin 1 (8~15): 10, 12, 11, 13, 9, 8 → 6개
- bin 12 (96~103): 100, 101, 102 → 3개
- bin 25 (200~207): 200, 201, 205 → 3개
- bin 31 (248~255): 250, 255 → 2개

**구간을 넓게 잡으면 대략적인 모양이, 좁게 잡으면 세밀한 모양이 보여요.**

## 4-2. 계급(bin): 값을 구간 번호로 바꾸기

### Step A. 공식

Part 2의 **양자화**가 그대로 다시 나와요.

$$\text{bin 번호} = \left\lfloor \frac{x}{\text{gap}} \right\rfloor, \qquad \text{gap} = \frac{\text{범위}}{\text{bin 개수}} = \frac{256}{32} = 8$$

| x | x / 8 | int(...) = bin | 이 bin의 범위 |
|---:|---:|---:|---|
| 0 | 0.0 | 0 | 0~7 |
| 7 | 0.875 | 0 | 0~7 |
| 8 | 1.0 | 1 | 8~15 |
| 187 | 23.375 | 23 | 184~191 |
| 189 | 23.625 | 23 | 184~191 |
| 255 | 31.875 | **31** | 248~255 (마지막 칸) |

### Step B. 범위가 왜 `[0, 256]`일까? (255가 아니라)

범위는 **[시작, 끝)**, 즉 끝값을 포함하지 않는 구간이에요. 슬라이싱 `a:b`와 같은 규칙이에요.

- `[0, 256]` → 0 ≤ x < 256 → 0~255 전부 포함 ✅. gap = 256/32 = 8로 깔끔하게 나눠져요.
- `[0, 255]`로 쓰면 → 255가 빠지고, gap도 255/32 = 7.97…로 지저분해져요.

## 4-3. 히스토그램 계산: 세 가지 방법

### Step A. 직접 구현 ([07.calc_histogram.py:3-9](../../chap06/07.calc_histogram.py#L3-L9))

```python
def calc_histo(image, hsize, ranges=[0, 256]):
    hist = np.zeros((hsize, 1), np.float32)   # ① 개수를 셀 빈 칸 32개 (32행 1열)
    gap = ranges[1] / hsize                   # ② 256 / 32 = 8.0
    for i in (image/gap).flat:                # ③ 모든 화소를 8로 나눈 값을 하나씩
        hist[int(i)] += 1                     # ④ 그 bin 칸의 개수 +1
    return hist
```

하나씩 볼게요.

**① `np.zeros((hsize, 1), np.float32)`**: 왜 굳이 **32행 1열**, 그리고 **실수형**일까요? 개수는 정수인데도요. **OpenCV의 `calcHist`가 돌려주는 형식과 똑같이 맞추려고** 그래요 (실측: `(32, 1) float32`). 그래야 나중에 결과를 비교하거나 OpenCV 함수에 그대로 넘길 수 있어요.

**③ `(image / gap).flat`**:
- `image / gap`: 브로드캐스팅으로 모든 화소를 8로 나눠요. `/`는 실수 나눗셈이라 결과는 **float64**예요.
  - 실측: 0행의 처음 4화소 `[187 189 185 182]` → `[23.375 23.625 23.125 22.75]`
- `.flat`: 2차원 배열을 **1줄로 펼쳐서 하나씩 꺼내 주는** 반복자예요. 이중 for문 대신 한 줄로 전체를 돌 수 있어요. 순서는 행 우선(Part 1에서 본 그 순서)이에요.

**④ `hist[int(i)] += 1`**: 투표함에 한 표씩 넣는 거예요.

처음 4화소를 추적하면 이래요.

```
화소 187 → 23.375 → int → 23 → hist[23] : 0 → 1
화소 189 → 23.625 → int → 23 → hist[23] : 1 → 2
화소 185 → 23.125 → int → 23 → hist[23] : 2 → 3
화소 182 → 22.75  → int → 22 → hist[22] : 0 → 1
... 72,000번 반복 (pixel.jpg = 300 × 240)
```

### Step B. OpenCV와 numpy ([08.calc_histogram_opencv.py:17-22](../../chap06/08.calc_histogram_opencv.py#L17-L22))

```python
hist2 = cv2.calcHist([image], [0], None, hsize, ranges)
hist3, bins = np.histogram(image, ranges_gap)
```

**`cv2.calcHist`의 인자 다섯 개**를 해부해 볼게요. 전부 **리스트로 감싸는** 이유는 이 함수가 원래 **여러 이미지, 여러 채널, 다차원 히스토그램**까지 다루는 범용 함수라서예요.

| 인자 | 이 코드의 값 | 뜻 |
|---|---|---|
| images | `[image]` | 이미지 **목록**. 하나뿐이어도 리스트로 감싸요 |
| channels | `[0]` | 몇 번 채널을 셀까. 흑백은 채널이 하나라 0이에요. 컬러 BGR이면 0 = B, 1 = G, 2 = R |
| mask | `None` | 셀 영역을 제한하는 마스크. None이면 전체를 세요 (4-6에서 다시 나와요) |
| histSize | `[32]` | bin 개수 |
| ranges | `[0, 256]` | 값의 범위 [시작, 끝) |

**`np.histogram`은 bin "개수"가 아니라 "경계값 목록"을 받아요.**

```python
gap = 256 / 32                                  # 8.0
ranges_gap = np.arange(0, 256 + 1, gap)         # [0, 8, 16, ..., 248, 256] → 33개
```

```
경계:  0    8    16   24  ...  248   256
       ├────┼────┼────┼── ... ──┼─────┤
bin:     0    1    2      ...     31          경계 33개 → 칸 32개
```

울타리 기둥 33개 사이에 칸이 32개 생기는 것과 같아요. 그래서 `+1`을 해서 256까지 포함시켜요.

## 4-4. 히스토그램 그리기 (`09.draw_histogram.py`)

숫자 32개를 **막대그래프 이미지**로 만드는 함수예요. 네 단계로 나눠 볼게요.

```python
def draw_histo(hist, shape=(200, 256)):
    hist_img = np.full(shape, 255, np.uint8)                 # ① 흰 도화지
    cv2.normalize(hist, hist, 0, shape[0], cv2.NORM_MINMAX)  # ② 높이 맞추기
    gap = hist_img.shape[1] / hist.shape[0]                  # ③ 막대 하나의 폭
    for i, h in enumerate(hist.flat):
        x = int(round(i * gap))
        w = int(round(gap))
        cv2.rectangle(hist_img, (x, 0, w, int(h)), 0, cv2.FILLED)  # ③ 검은 막대
    return cv2.flip(hist_img, 0)                             # ④ 위아래 뒤집기
```

### Step ①: 흰 도화지

`np.full((200, 256), 255, np.uint8)`은 높이 200, 너비 256이고 **전부 255(흰색)**인 이미지예요. `np.zeros`의 "아무 값으로나 채우기" 버전이에요.

### Step ②: 정규화(normalize), 막대 높이를 0~200에 맞추기

실측 `draw_hist.jpg` 히스토그램의 최댓값은 **5250**이에요. 도화지 높이는 200픽셀밖에 안 되니까, 숫자 그대로 그리면 막대가 화면을 뚫고 나가요. 그래서 **가장 작은 값은 0, 가장 큰 값은 200**이 되도록 비율대로 줄여요.

$$h' = \frac{h - \min}{\max - \min} \times (200 - 0) + 0$$

실측값(min = 32, max = 5250)으로 대입해 볼게요.

| bin | 원래 개수 h | 계산 | 정규화된 높이 |
|---:|---:|---|---:|
| 0 | 32 (최소) | (32 − 32) / 5218 × 200 | **0.0** |
| 3 | 2947 | (2947 − 32) / 5218 × 200 = 2915 / 5218 × 200 | **111.7** |
| 22 | 5250 (최대) | (5250 − 32) / 5218 × 200 | **200.0** |
| 31 | 59 | (59 − 32) / 5218 × 200 | **1.0** |

세 가지 주의할 점이 있어요.

1. **최솟값은 0이 돼요.** bin 0은 실제로 32개가 있는데 막대가 아예 안 보여요. `NORM_MINMAX`는 "비율"이 아니라 "**최소와 최대 사이에서의 위치**"를 보여주기 때문이에요. (32개와 0개를 구분해야 한다면 `h / max × 200`처럼 최솟값을 빼지 않는 방식을 써야 해요.)
2. **`cv2.normalize(hist, hist, ...)`는 입력을 덮어써요.** 첫 번째가 입력, 두 번째가 출력인데 같은 변수를 넣었으니 원본 개수가 사라지고 0~200 값으로 바뀌어요. 함수 밖의 `hist`도 같이 바뀌어요 (Part 1의 "같은 데이터 공유"). 그래서 그린 뒤에 히스토그램 개수를 다시 쓰려면 미리 `.copy()`해 두어야 해요.
3. 사소한 것: bin 22는 출력하면 200.0인데 `int()`로 바꾸면 **199**예요. float32의 계산 오차로 실제 값이 199.99998…이라서, 버림하면 199가 돼요 (Part 3의 버림 문제와 같아요).

### Step ③: 막대 그리기

- `gap = 256 / 32 = 8.0` → 막대 하나의 폭이 **8픽셀**이에요.
- bin i의 막대는 x = i × 8에서 시작해요. 예: bin 3 → x = 24, 폭 8, 높이 111.
- `cv2.rectangle(img, (x, 0, w, h), 0, cv2.FILLED)`: (x, y, 폭, 높이) 사각형을 **검정(0)**으로 **꽉 채워서(FILLED)** 그려요.

실제로 작은 도화지에 `(0, 0, 3, 2)` 사각형을 그려서 확인해 봤어요.

```
cv2.rectangle(a, (0,0,3,2), 0, FILLED)        높이 0: (0,0,3,0)
[[  0   0   0 255 255 ...]   ← y=0            [[255 255 255 ...]   아무것도 안 그려짐
 [  0   0   0 255 255 ...]   ← y=1             [255 255 255 ...]
 [255 255 255 255 255 ...]                     ...
```

(x, y, w, h)는 x ~ x+w−1, y ~ y+h−1 칸을 칠해요. 높이가 0이면 아무것도 그리지 않아요.

### Step ④: 왜 마지막에 `flip`할까?

이미지 좌표계는 **y가 아래로 증가**해요. 그래서 y = 0부터 높이 h만큼 그리면 막대가 **천장에 매달린 고드름**처럼 돼요.

```
flip 전 (y=0이 위쪽)              cv2.flip(img, 0) 후 (상하 반전)
y=0 ┌───────────────┐           ┌───────────────┐
    │ █  ██ █  █ ██ │           │       █       │
    │ █  ██    █  █ │           │ █  █  █    █  │
    │    █        █ │    ──►    │ █  ██    █  █ │
    │       █       │           │ █  ██ █  █ ██ │
y=199└───────────────┘           └───────────────┘
   고드름 모양                       정상 막대그래프
```

`cv2.flip`의 두 번째 인자는 **0 = 상하 반전**, 1 = 좌우 반전, −1 = 둘 다예요.

> 📚 **reference 연결**: reference 02번에서 `arr[::-1]`(상하)과 `arr[:, ::-1]`(좌우)로 뒤집었었죠. `cv2.flip(img, 0)`은 `img[::-1]`과 같은 결과예요.

### Step ⑤: ⚠️ Common 버전과의 차이

[Common/histogram.py:10](../../Common/histogram.py#L10)는 `enumerate(hist.flat)`이 아니라 **`enumerate(hist)`**를 써요. hist가 (32, 1)이라서 h가 숫자가 아니라 **길이 1짜리 배열**이 되고, `int(h)`를 할 때 이런 경고가 나와요 (실측).

```
DeprecationWarning: Conversion of an array with ndim > 0 to a scalar is deprecated,
and will error in future.
```

지금은 경고만 나오지만 **앞으로 나올 NumPy 버전에서는 에러가 될 예정**이에요. 09번처럼 `.flat`을 쓰면 h가 진짜 숫자라서 문제가 없어요. (Part 5의 11, 12번이 Common 버전을 쓰니까 거기서 이 경고가 보일 수 있어요.)

### Step ⑥: 결과 읽기 (`draw_hist.jpg`)

`draw_hist.jpg`는 성화가 걸린 대리석 벽과 왼쪽의 짙은 나무 문이 있는 사진이에요.

```
   |                      █
   |    ██             █  ██
   |    ██             █████
   |    ███           ███████ █
   |   ████           ██████████
   |   █████         ███████████
   |   ███████       ████████████
   |   █████████  ████████████████
   |   ███████████████████████████
   |  █████████████████████████████
   +--------------------------------
    0       ↑              ↑       255
         어두운 봉우리     밝은 봉우리
        (bin 3~6, 24~55)  (bin 18~27, 144~223)
         나무 문, 그림자     대리석 벽
```

봉우리가 **두 개**예요. 이런 모양을 **쌍봉(bimodal)** 히스토그램이라고 해요. "어두운 물체 + 밝은 배경"이 뚜렷하게 나뉜 사진에서 자주 나와요. 두 봉우리 사이 골짜기(bin 10~15, 80~127)에 기준선을 그으면 문과 벽을 나눌 수 있어요. 이게 Part 7 **이진화**의 아이디어예요.

## 4-5. 히스토그램으로 사진 진단하기

히스토그램만 보고 사진을 보지 않아도 상태를 알 수 있어요.

```
① 어두운 사진            ② 밝은 사진             ③ 저대비 (뿌연 사진)      ④ 고대비
 █                                  █              ██                    █              █
```

## 4-6. 색상(Hue) 히스토그램 (`10.hue_histogram.py`)

### Step A. 📚 복습: HSV와 Hue

reference 05번(배경 교체)에서 초록 배경을 잡으려고 색 범위를 다뤘었죠. BGR로 "초록"의 범위를 정하려면 B, G, R 세 값을 동시에 조절해야 해서 까다로워요. HSV는 색을 이렇게 나눠서 표현해요.

| 채널 | 뜻 | OpenCV 범위 |
|---|---|---|
| **H**ue (색상) | **무슨 색인가.** 색상환의 각도 | **0~179** (원래 0~360°인데 uint8에 넣으려고 반으로 나눔) |
| **S**aturation (채도) | 얼마나 **선명한가.** 0이면 회색 | 0~255 |
| **V**alue (명도) | 얼마나 **밝은가** | 0~255 |

실측으로 순수한 색들을 HSV로 바꿔 봤어요.

| 색 | BGR | → HSV | H × 2 = 실제 각도 |
|---|---|---|---|
| 빨강 | (0, 0, 255) | (**0**, 255, 255) | 0° |
| 노랑 | (0, 255, 255) | (**30**, 255, 255) | 60° |
| 초록 | (0, 255, 0) | (**60**, 255, 255) | 120° |
| 청록 | (255, 255, 0) | (**90**, 255, 255) | 180° |
| 파랑 | (255, 0, 0) | (**120**, 255, 255) | 240° |
| 자홍 | (255, 0, 255) | (**150**, 255, 255) | 300° |
| 회색 | (128, 128, 128) | (0, **0**, 128) | 정의 불가 → 0 |
| 흰색 | (255, 255, 255) | (0, **0**, 255) | 정의 불가 → 0 |

```
      H 색상환 (OpenCV 값)
              30 노랑
         ╱──────────╲
   0/180 빨강        60 초록
        │              │
  150 자홍            90 청록
         ╲──────────╱
             120 파랑
```

**회색과 흰색은 H가 0으로 나와요.** 색이 없으니까 "무슨 색인가"를 정할 수 없고, OpenCV는 그냥 0을 넣어요. 이게 아래 Step E의 함정이에요. (HSV 공식 자체는 Part 6에서 자세히 다뤄요.)

### Step B. Hue 채널만 세기

```python
hsv_img = cv2.cvtColor(image, cv2.COLOR_BGR2HSV)
hue_hist = cv2.calcHist([hsv_img], [0], None, [18], [0, 180])
```

- 이번에는 3채널 이미지예요. `[0]`은 **H 채널**만 세라는 뜻이에요.
- 범위 `[0, 180]`, bin 18개 → gap = 10. bin 하나가 H 10칸(실제 각도 20°)이에요.

### Step C. 팔레트 만들기: 막대를 그 색으로 칠하려면

```python
def make_palette(rows):                                # rows = 18
    hue = np.arange(0, rows) / rows * 180              # ① [0, 10, 20, ..., 170]
    hsv = [[(h, 255, 255)] for h in hue]               # ② 각 hue의 가장 선명하고 밝은 색
    hsv = np.array(hsv, np.uint8)                      # ③ shape (18, 1, 3)
    return cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)        # ④ HSV → BGR
```

**① hue 목록**: `np.arange(18)` = [0, 1, …, 17] → / 18 × 180 → **[0, 10, 20, …, 170]** (실측). 각 bin의 시작 색상이에요.

**② `(h, 255, 255)`**: 채도와 명도를 최대로 해서 그 색상의 **가장 순수한 색**을 만들어요.

**③ 왜 `[[(h,255,255)] for ...]`처럼 괄호를 두 겹으로 쌀까?** `cvtColor`는 **이미지**만 받아요. 그래서 색 18개를 **18행 × 1열짜리 작은 이미지**로 만든 거예요.

```
shape (18, 1, 3) = 세로 18칸, 가로 1칸, 채널 3개인 "이미지"

  행 0: [(  0, 255, 255)]     → 빨강
  행 1: [( 10, 255, 255)]     → 주황
  ...
  행17: [(170, 255, 255)]     → 붉은 자홍
```

**④ BGR로 변환**: 실측 결과예요.

| 행 i | hue | BGR (팔레트 색) |
|---:|---:|---|
| 0 | 0 | (0, 0, 255) 빨강 |
| 3 | 30 | (0, 255, 255) 노랑 |
| 6 | 60 | (0, 255, 0) 초록 |
| 9 | 90 | (255, 255, 0) 청록 |
| 12 | 120 | (255, 0, 0) 파랑 |
| 15 | 150 | (255, 0, 255) 자홍 |

> [Common/histogram.py:18](../../Common/histogram.py#L18)의 `make_palate`(오타가 그대로 함수 이름이 됨)는 `round(i * 180 / rows)`로 계산해요. bin이 18개일 때는 나눗셈이 딱 떨어져서 결과가 같아요.

### Step D. 막대를 색으로 칠하기

```python
color = tuple(map(int, hsv_palate[i][0]))   # 예: array([0,0,255], uint8) → (0, 0, 255)
cv2.rectangle(hist_img, (x, 0, w, int(h)), color, cv2.FILLED)
```

- `hsv_palate[i][0]`: i번째 행, 0번째 열의 BGR 3개 → `array([0, 0, 255], dtype=uint8)`
- `map(int, ...)` → `tuple(...)`: OpenCV 그리기 함수의 색 인자는 **파이썬 int 튜플**이어야 안전해요. numpy uint8 배열을 그대로 넣으면 버전에 따라 에러가 나요.
- 도화지가 `(200, 360, 3)`이라서 gap = 360 / 18 = **20픽셀**, 3채널이라 컬러 막대가 가능해요.

### Step E. 결과 읽기와 ⚠️ 회색의 함정

`hue_hist.jpg`는 돌바닥 길 위에 놓인 **파란 유리 수거함** 사진이에요. 실측 히스토그램은 이래요.

```
[11527 32780 10939 5821 822 722 292 2427 1439 7224 35324 3625 2839 252 729 207 1820 1211]

   |          █              ← bin 10 (H 100~109): 35324  파랑
   | █        █              ← bin 1  (H 10~19):  32780  주황??
   | █        █
   | █        █
   | █        █
   |██        █
   |███      ██
   |████   █ ████
   +------------------
    빨 노  초  청 파  자
```

- **bin 10 (파랑)**: 수거함이에요. 이 화소들의 채도 중앙값은 **209**로 아주 선명한 파랑이에요. ✅
- **bin 1 (주황)**: 사진에 주황색 물체는 거의 없는데 두 번째로 커요. 이 화소들을 조사해 보니 **47%가 채도 30 미만, 74%가 채도 60 미만**이에요 (중앙값 31). 정체는 **갈색빛이 살짝 도는 돌바닥과 담장**이에요. 거의 회색인데 아주 약간의 붉은 기 때문에 주황 bin으로 분류된 거예요.
- **bin 0 (빨강)**도 11,527개인데, 그중 7,942개가 채도 30 미만이에요. Step A의 표대로 **회색과 흰색은 H = 0**이 되기 때문이에요.

실측으로 전체 화소의 **39%가 채도 30 미만(거의 무채색)**이에요.

> 💡 **교훈: 채도가 낮은 화소의 Hue는 믿을 수 없어요.** 회색에 가까울수록 색상이 의미가 없어지는데, 히스토그램에는 그래도 한 표씩 들어가요.

**해결책이 바로 `calcHist`의 세 번째 인자 `mask`예요.**

```python
mask = cv2.inRange(hsv_img, (0, 60, 30), (180, 255, 255))   # 채도 60 이상, 명도 30 이상만
hue_hist = cv2.calcHist([hsv_img], [0], mask, [18], [0, 180])
```

`mask`가 0이 아닌 위치의 화소만 세요. 이렇게 하면 회색 돌바닥이 빠지고 **진짜 색이 있는 화소**만 남아요.

> 📚 **reference 연결**: `cv2.inRange`는 reference 05번에서 초록 배경을 잡을 때 썼던 바로 그 함수예요. 범위 안이면 255, 밖이면 0인 마스크를 만들어요.
