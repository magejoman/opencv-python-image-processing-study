chap06의 18개 파일과 `reference/Chapter06` 노트북 7개를 다 읽고 세운 계획이에요.

## 0. 큰 그림: 이 챕터는 결국 한 문장이에요

> **"화소 하나의 값 `x`를 받아서 새 값 `y`를 돌려주는 함수 `y = f(x)`를 어떻게 설계하느냐"**

밝게 하기, 대비 조절, 스트레칭, 평활화, 이진화, CMY 변환은 이름만 다르고, 전부 **0~255를 0~255로 보내는 함수**예요. 그래서 설명할 때마다 이 함수를 아래 같은 **변환 곡선 그래프**로 그려서 비교할 거예요.

```
출력 y
255 ┤            ╱        ← 이 곡선 하나가 "알고리즘" 전체
    │          ╱
    │        ╱
  0 ┼──────╱───────── 입력 x
    0             255
```

챕터의 흐름은 이래요.

```
[1] 화소에 접근하기 ──► [2] 화소값 들여다보기 ──► [3] 산술로 바꾸기
                                                      │
[6] 색 표현 바꾸기 ◄── [5] 분포 고치기 ◄── [4] 분포 보기(히스토그램)
        │
        ▼
[7] 기준선으로 판정하기(이진화)
```

---

## 0-1. 이미 아는 것과 새로 배울 것

| 이미 아는 것 (reference/Chapter06) | chap06에서 새로 배울 것 |
|---|---|
| 이미지 = numpy 배열 `(H, W, C)`, `uint8` | `uint8` **오버플로**: saturation과 modulo의 차이 |
| `arr[y, x]` 접근, 슬라이싱, `clip` | **룩업 테이블(LUT)**, 루프와 벡터 연산의 속도 차이 |
| BGR 순서, `imread`/`imshow` | `cv2.add`/`subtract`/`addWeighted`/`scaleAdd` |
| 알파 합성 `αA + (1-α)B` | **명암 대비**의 수학 (`y = a·x + b`) |
| 휘도 공식 `Y = 0.299R + 0.587G + 0.114B` | **히스토그램** 계산, 그리기, 정규화 |
| 트랙바, 마우스 콜백 | **히스토그램 스트레칭, 평활화** (누적분포 CDF) |
| `inRange` 마스크 | **컬러 공간**: CMY(K), HSI/HSV, YCrCb, YUV, Lab |
| GaussianBlur (맛보기) | **이진화(threshold)** 종류와 색상 기반 분할 |

이미 아는 내용은 짧게 짚고(📚 복습), 시간은 오른쪽 열에 씁니다.

## Part 1. 화소에 접근하는 5가지 방법과 속도
📁 `01.mat_access.py`, `02.image_access.py`

| 단계 | 내용 | 설명 기법 |
|---|---|---|
| 1-1 | `mat[i, j]`와 `mat.item(i, j)`의 차이: 둘 다 값을 꺼내지만 반환 타입이 달라요 | 2×5 행렬을 처리 전/후 표로 출력 |
| 1-2 | 반전 `255 - x`를 다섯 가지 방법으로 구현 | 같은 3×3 예시 이미지로 다섯 번 계산 |
| 1-3 | ⭐ **룩업 테이블(LUT)** 원리: "계산을 미리 해 둔 정답표" | 비유: 구구단 표 / ASCII 그림: `lut[image]`가 인덱싱되는 과정 |
| 1-4 | 왜 이중 for문은 느리고 벡터 연산은 빠른가 (Python 인터프리터 vs C 루프) | 비유: 택배를 한 개씩 나르기 vs 트럭 한 번 / 실제 ms 측정값 |
| 1-5 | 함정: NumPy 2.0에서 `itemset()`이 제거됨 | 코드 줄 짚기 |

> 🔑 LUT은 Part 5(스트레칭, 평활화)에서 핵심 도구로 다시 나와요.

## Part 2. 화소값 = 밝기라는 숫자
📁 `03.grayscale_image.py`, `03.pixel_value.py`

| 단계 | 내용 | 설명 기법 |
|---|---|---|
| 2-1 | `j // 2`(부드러운 그라데이션)와 `j // 20 * 10`(계단) 비교 | 열 번호 j에 대한 값 표 직접 계산 |
| 2-2 | 정수 나눗셈 `//`이 "계단"을 만드는 이유 = **양자화(quantization)** | 계단 ASCII 그래프 |
| 2-3 | ROI 숫자 덤프: 좌표 `(x, y)`와 행렬 인덱스 `[y, x]`의 순서 헷갈림 | 15×10 숫자 표에서 경계(edge)가 숫자로 보이는 모습 |

## Part 3. 산술 연산: 밝기, 합성, 대비
📁 `04.bright_dark.py`, `05.image_synthesis.py`, `06.contrast.py`

| 단계 | 내용 | 설명 기법 |
|---|---|---|
| 3-1 | ⭐ `uint8`은 0~255밖에 못 담아요. 그럼 `250 + 10`은? | 비유: 자동차 주행거리계 vs 물컵 |
| 3-2 | `cv2.add`(saturation)와 `image + 100`(modulo) | 값 하나씩 추적 / 변환 곡선 2개 비교 |
| 3-3 | 영상 합성: `add`, 비율 곱셈 후 `clip`, `addWeighted` | 픽셀 하나로 세 방법 계산 비교 |
| 3-4 | 수학: 대비 = 기울기, 밝기 = 절편 → `y = a·x + b` | 직선 그래프 4개 |
| 3-5 | `scaleAdd`와 `addWeighted(…, gamma)`의 시그니처 해부 | 인자를 수식 기호에 매핑 |
| 3-6 | **평균 기준 대비**: 왜 `avg`를 더하거나 빼는가 | 시소 비유 + 수치 예시 |
| 3-7 | 06이 `dst.jpg`를 저장 → Part 5의 11번 입력 | 파일 의존성 표시 |
