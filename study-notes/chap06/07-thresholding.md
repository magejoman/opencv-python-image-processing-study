## 7-1. 이진화란?

### Step A. 비유: 시험 커트라인

> "60점 **초과**면 합격(1), 아니면 불합격(0)"

점수가 61점이든 100점이든 결과는 똑같이 "합격"이에요. 세밀한 정보를 버리고 **예/아니오 하나만** 남겨요.

이미지에서는 이렇게 돼요.

> "밝기가 임계값(threshold) **초과**면 255(흰색), 아니면 0(검정)"

### Step B. 변환 곡선: 계단 딱 하나

```
 y
255┤              ┌──────────────
   │              │
   │              │      ← 기준선에서 수직으로 점프
   │              │
  0┼──────────────┘──────────── x
   0           임계값          255
```

Part 2의 양자화 계단이 26개였다면, 이진화는 **계단이 2개**인 극단적인 양자화예요. 모든 화소 연산이 `y = f(x)`라는 Part 0의 관점에서 보면 가장 단순한 f예요.

### Step C. 왜 쓸까

이진 이미지(0과 255만 있는 이미지)는 **"여기가 관심 영역이다"를 표시하는 마스크**가 돼요.
- 물체와 배경 분리 (reference 05번 배경 교체의 마스크)
- 문서 스캔에서 글자만 뽑기 (OCR 전처리)
- 다음 챕터들의 윤곽선 찾기, 모폴로지 연산의 입력

## 7-2. `cv2.threshold`와 다섯 가지 타입

### Step A. 함수 모양

```python
retval, dst = cv2.threshold(src, thresh, maxval, type)
#   ↑      ↑                  ↑       ↑       ↑
# 쓴 임계값 결과 이미지         임계값  "흰색" 값 방식
```

- 반환값이 **튜플 두 개**예요 (실측: `<class 'tuple'>`). 그래서 18번 코드는 `cv2.threshold(...)[1]`로 결과 이미지만 꺼내요.
- `retval`은 보통 넣은 thresh 그대로예요 (실측 128.0). 7-3 Step E의 **오츠(Otsu)** 방식에서는 OpenCV가 **자동으로 고른 값**이 여기 들어와요.

### Step B. 다섯 가지 타입 실측 (thresh = 128, maxval = 255)

| 입력 x | 0 | 50 | 100 | 127 | **128** | 129 | 150 | 200 | 250 |
|---|---|---|---|---|---|---|---|---|---|
| **BINARY** | 0 | 0 | 0 | 0 | **0** | 255 | 255 | 255 | 255 |
| **BINARY_INV** | 255 | 255 | 255 | 255 | **255** | 0 | 0 | 0 | 0 |
| **TRUNC** | 0 | 50 | 100 | 127 | 128 | 128 | 128 | 128 | 128 |
| **TOZERO** | 0 | 0 | 0 | 0 | **0** | 129 | 150 | 200 | 250 |
| **TOZERO_INV** | 0 | 50 | 100 | 127 | **128** | 0 | 0 | 0 | 0 |

⚠️ **x = 128(임계값과 같은 값)**을 보세요. BINARY에서 **0**이에요. 조건이 **`x > thresh`(초과)**이지 이상이 아니에요. 7-4에서 이 경계가 결과를 바꿔요.

### Step C. 변환 곡선 다섯 개

```
BINARY               BINARY_INV           TRUNC
255┤      ┌────      255┤──────┐          255┤
   │      │             │      │             │
   │      │             │      │          128┤      ┌────── ← 천장
  0┼──────┘────        0┼──────└────         │    ╱
   0     128              0     128         0┼──╱──────────
                                              0     128
 "넘으면 흰색"        "넘으면 검정"          "넘는 부분을 잘라냄"

TOZERO               TOZERO_INV
255┤          ╱      255┤
   │        ╱           │
   │      │╱         128┤     ╱│
  0┼──────┘────        0┼───╱──└────
   0     128              0     128
 "기준 이하는 0,        "기준 초과는 0,
  나머지는 원래 값"       나머지는 원래 값"
```

### Step D. 이름 외우는 법

| 이름 | 뜻 | 한 줄 요약 |
|---|---|---|
| BINARY | 이진 | 넘으면 maxval, 아니면 0 |
| **_INV** | inverse (반대) | 결과를 뒤집기 |
| TRUNC | truncate (자르기) | 머리를 thresh에서 잘라 **천장** 만들기 |
| TOZERO | to zero (0으로) | 기준 **이하**를 0으로 지우고 나머지는 **원래 값 유지** |
| TOZERO_INV | | 기준 **초과**를 0으로 지우고 나머지는 원래 값 유지 |

TRUNC, TOZERO, TOZERO_INV는 결과가 0/255만 있는 게 아니라서 엄밀히는 "이진화"가 아니에요. 그런데 **조합하면 강력해요.** 7-4의 범위 이진화가 TOZERO_INV와 BINARY를 조합한 거예요.

## 7-3. `18.thresholding.py`: 트랙바로 임계값 조절

### Step A. 코드 전체

```python
def onThreshold(value):                                          # ③ 콜백
    result = cv2.threshold(image, value, 255, cv2.THRESH_BINARY)[1]
    cv2.imshow("result", result)

image = cv2.imread("images/color_space.jpg", cv2.IMREAD_GRAYSCALE)   # 컬러 사진을 흑백으로

cv2.namedWindow("result")                                        # ① 창 먼저
cv2.createTrackbar("threshold", "result", 128, 255, onThreshold) # ② 트랙바 붙이기
onThreshold(128)                                                 # ④ 첫 화면 직접 그리기
cv2.imshow("image", image)
cv2.waitKey(0)
```

### Step B. 순서가 중요한 이유

```
① namedWindow("result")       창이 있어야 트랙바를 붙일 곳이 생겨요
          │
② createTrackbar(...)          "result" 창에 0~255 슬라이더, 시작 위치 128
          │                     ⚠️ 만들 때는 콜백이 호출되지 않아요
③ (콜백 등록만 된 상태)
          │
④ onThreshold(128) 직접 호출   그래서 처음 화면을 수동으로 한 번 그려요
          │                     (이 줄이 없으면 슬라이더를 건드리기 전까지 창이 비어 있어요)
⑤ waitKey(0)                   이벤트 대기. 이 동안 슬라이더를 움직이면
          │
          └──► OpenCV가 onThreshold(새 값)을 자동 호출 → 다시 이진화 → 창 갱신
```

콜백의 `value`에는 **슬라이더의 현재 위치(정수)**가 들어와요. 그래서 코드가 `value`를 그대로 임계값으로 써요.

임계값을 올릴수록 "흰색 합격선"이 높아져서 흰 영역이 줄어요.

retval, dst = cv2.threshold(img, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)

## 7-4. `17.hue_threshold.py`: 색상 범위로 이진화

### Step A. 왜 밝기가 아니라 Hue일까: 조명에 강해요

같은 빨간 물체가 햇빛과 그늘에 걸쳐 있다고 해 볼게요 (실측).

| 상황 | BGR | HSV (H, S, V) |
|---|---|---|
| 햇빛 받은 빨강 | (40, 40, 220) | (**0**, **209**, 220) |
| 그늘진 빨강 | (20, 20, 110) | (**0**, **209**, 110) |
| 아주 어두운 빨강 | (8, 8, 45) | (**0**, **210**, 45) |

- BGR로는 햇빛과 그늘의 거리가 **113.6**이나 돼요. 전혀 다른 색처럼 보여요.
- HSV로는 **H와 S가 그대로**이고 **V(밝기)만** 바뀌어요.

조명은 주로 **밝기**를 바꾸니까, 밝기를 따로 떼어 놓은 HSV에서 **H로 고르면 그림자에 덜 흔들려요.** reference 05번 배경 교체에서 초록 배경을 HSV로 잡는 이유가 이거예요.

### Step B. 준비: `np.copy`는 왜 했을까

```python
HSV_img = cv2.cvtColor(BGR_img, cv2.COLOR_BGR2HSV)
hue = np.copy(HSV_img[:,:,0])                       # H 채널만 복사
th = [50, 100]                                      # 범위 [하한, 상한]
```

`HSV_img[:,:,0]`은 Part 2에서 배운 **뷰(view)**예요. 그런데 이번에는 메모리에 **듬성듬성** 놓인 뷰예요.

```
HSV_img 메모리:  [H S V][H S V][H S V][H S V] ...
H 채널 뷰:        ↑      ↑      ↑      ↑         ← 3칸마다 하나씩 건너뛰며 봄
                                                    (C_CONTIGUOUS = False, 실측)
np.copy 후:      [H][H][H][H] ...                ← 빈틈없이 연속 (C_CONTIGUOUS = True)
```

뷰에 직접 결과를 쓰게 하면 이런 에러가 나요 (실측).

```
cv2.threshold(v, 50, 255, cv2.THRESH_BINARY, v)   # v = HSV_img[:,:,0] 뷰
→ error: (-5:Bad argument) ... Layout of the output array is incompatible ...
```

OpenCV는 **출력 배열이 메모리에 연속으로** 있어야 해요. 그래서 `np.copy`로 연속된 새 배열을 만들어요. 덤으로 원본 `HSV_img`가 바뀌지도 않아요.

### Step C. ⭐ 두 단계 트릭: threshold 두 번으로 범위 잡기

`cv2.threshold`는 기준선이 **하나**뿐이에요. "50~100 사이"처럼 **범위**를 고르려면 기준선이 두 개 필요해요. 그래서 7-2의 타입 두 개를 조합해요.

```python
_, result = cv2.threshold(hue, th[1], 255, cv2.THRESH_TOZERO_INV)   # 1단계: 상한 위를 지움
cv2.threshold(result, th[0], 255, cv2.THRESH_BINARY, result)        # 2단계: 하한 위만 흰색
```

실제 값으로 추적해 볼게요 (th = [50, 100]).

| 입력 H | 0 | 49 | **50** | 51 | 75 | 99 | **100** | 101 | 150 | 179 |
|---|---|---|---|---|---|---|---|---|---|---|
| ① TOZERO_INV @100 (100 초과 → 0) | 0 | 49 | 50 | 51 | 75 | 99 | 100 | **0** | **0** | **0** |
| ② BINARY @50 (50 초과 → 255) | 0 | 0 | **0** | 255 | 255 | 255 | **255** | 0 | 0 | 0 |

```
1단계: 너무 큰 값(상한 초과)을 0으로 떨어뜨림 → 이제 "작은 값들"만 남음
   0 ─────────── 50 ─────────── 100 ───────── 179
   [  원래 값 유지                  ][ 전부 0 ]

2단계: 하한을 넘는 것만 255
   [   0     ][     255         ][   0 (1단계에서 이미 0)  ]
              ↑                ↑
          50 초과          100 이하
```

두 번째 줄의 **5번째 인자 `result`**는 "결과를 이 배열에 바로 써 달라"는 뜻이에요 (새 배열을 만들지 않고 덮어쓰기). Step B의 연속 메모리 조건이 여기서 필요해요.

### Step D. ⚠️ 경계값 문제: 세 구현의 범위가 다 달라요

코드 주석에는 세 가지 구현이 있어요. 표의 **50과 100**을 보세요.

| 구현 | 조건 | 50 | 100 | 수학 기호 |
|---|---|---|---|---|
| for문 (주석) | `th[0] <= hue < th[1]` | **255** | **0** | **[50, 100)** |
| `np.logical_and` (주석) | `hue >= th[0]` and `hue < th[1]` | **255** | **0** | **[50, 100)** |
| threshold 두 번 (실제 사용) | `> 50` and `≤ 100` | **0** | **255** | **(50, 100]** |
| `cv2.inRange` (reference 05) | `>= 50` and `<= 100` | **255** | **255** | **[50, 100]** |

`threshold`는 7-2에서 본 대로 **초과(>)**로 판정해서 경계가 한 칸씩 밀려요. 실측으로 `color_space.jpg` 전체를 비교하면 for문과 threshold 결과가 **1,020화소** 달라요. H가 정확히 50인 44개와 정확히 100인 976개예요.

눈으로는 큰 차이가 없지만, **"주석의 for문과 실제 코드가 같은 결과를 낸다"는 건 사실이 아니에요.** 정확한 범위가 중요하면 `cv2.inRange`처럼 경계가 명확한 함수를 쓰고, 문서에 범위를 적어 두는 게 좋아요.

속도(실측, 최솟값)는 Part 1의 결론과 같아요.

| 구현 | 시간 |
|---|---:|
| for문 | 8.74 ms |
| `np.logical_and` | 0.07 ms |
| threshold 두 번 | 0.01 ms |
| `cv2.inRange` | 0.01 ms |

### Step E. 트랙바 두 개, 콜백 하나

```python
def onThreshold(value):
    th[0] = cv2.getTrackbarPos("Hue_th1", "result")    # 하한 슬라이더 위치를 직접 읽음
    th[1] = cv2.getTrackbarPos("Hue_th2", "result")    # 상한 슬라이더 위치를 직접 읽음
    ...

cv2.createTrackbar("Hue_th1", "result", th[0], 180, onThreshold)   # 최댓값 180 (H 범위)
cv2.createTrackbar("Hue_th2", "result", th[1], 180, onThreshold)
```

- 두 트랙바가 **같은 콜백**을 불러요. 콜백은 `value`만 받아서는 **어느 슬라이더가 움직였는지 몰라요.** 그래서 `value`를 무시하고 `getTrackbarPos`로 **두 슬라이더를 모두** 다시 읽어요.
- 최댓값이 **180**인 건 OpenCV H가 0~179라서예요 (Part 6).
- `th`는 리스트라서 함수 안에서 `th[0] = ...`처럼 **내용물을 바꿀 수 있어요** (`global` 선언 없이). Part 1의 "같은 객체를 공유한다"와 같은 원리예요.
- 하한을 상한보다 크게 놓으면 (예: th1 = 120, th2 = 60) 조건을 만족하는 화소가 없어서 **전부 검정**이에요.

### Step F. 기본값 [50, 100]은 실제로 뭘 잡을까? (실측)

H 50~100은 실제 각도로 **100°~200°**, 즉 **초록~청록** 범위예요. 그런데 결과를 보면 의외예요.

- 이 사진의 초록 식물은 **H 30~50**(노란빛 도는 올리브색)에 있어서 기본 범위에 거의 안 걸려요.
- 기본 범위에 걸린 건 **채도 13짜리 거의 회색인 하늘**이에요. Part 4에서 "채도가 낮은 화소의 Hue는 믿을 수 없다"고 했던 함정이 그대로 나타났어요.

### Step G. 💡 실전 개선: H에 S 조건을 더하기

reference 05번의 `cv2.inRange`는 **3채널 범위를 한 번에** 받을 수 있어요.

```python
mask = cv2.inRange(hsv_img, (H하한, S하한, V하한), (H상한, S상한, V상한))
```
