## 8-6. XML 해부: 약한 분류기 = 작은 결정 나무

### (가) 전체 구조 (실측)

```
 haarcascade_frontalface_alt2.xml
 ├─ <stages>  게이트 20개
 │    ├─ 게이트 1:  stageThreshold 0.3507,  weakClassifiers 3개
 │    ├─ 게이트 2:  stageThreshold 3.4722,  weakClassifiers 9개
 │    ├─ …
 │    └─ 게이트 20: stageThreshold 53.7556, weakClassifiers 109개
 │                                         ─────────────────────
 │                                         합계 1,047개
 └─ <features> 특징 2,094개   (= 1,047 × 2. 나무마다 질문 2개)
```

### (나) 1번 게이트의 첫 번째 약한 분류기 (XML 그대로)

```xml
<internalNodes>
  0 1 0 4.3272329494357109e-03  -1 -2 1 1.3076160103082657e-02
</internalNodes>
<leafValues>
  3.8381900638341904e-02  8.9652568101882935e-01  2.6293140649795532e-01
</leafValues>
```

`internalNodes`는 **숫자 4개씩 한 묶음 = 질문 하나**입니다.

```
 [ 왼쪽, 오른쪽, 특징번호, 문턱값 ]
   질문 #0:  0,  1, 0, 0.004327   → "0번 특징 < 0.004327 ?"  예→왼쪽(0)  아니오→오른쪽(1)
   질문 #1: -1, -2, 1, 0.013076   → "1번 특징 < 0.013076 ?"  예→왼쪽(-1) 아니오→오른쪽(-2)
```

다음 칸 번호를 읽는 규칙:
- **양수**면 그 번호의 **다음 질문**으로 갑니다.
- **0 이하**면 거기서 끝납니다. **나뭇잎 번호 = −(그 값)**입니다. 0→잎 0, −1→잎 1, −2→잎 2.

그림으로 그리면:

```
                  질문 #0: 0번 특징 < 0.004327 ?
                    (눈 밑 − 눈 줄)
                 예 ╱                ╲ 아니오
                   ╱                  ╲
          🍃 잎 0 = 0.0384       질문 #1: 1번 특징 < 0.013076 ?
          "얼굴 같지 않음"          (세로 띠 아래 − 위)
                                 예 ╱          ╲ 아니오
                                   ╱            ╲
                         🍃 잎 1 = 0.8965     🍃 잎 2 = 0.2629
                         "얼굴 같음!"         "조금 애매"
```

🧠 **비유: 스무고개를 딱 두 번만 하는 감별사.** 이 감별사 한 명은 "아마 얼굴" 정도의 의견만 냅니다. 혼자서는 믿을 수 없지만, 정답률이 동전 던지기(50%)보다는 확실히 높습니다. 그래서 **약한 분류기(weak classifier)**라고 부릅니다.

나뭇잎 값은 "얼굴일 것 같은 정도"를 나타내는 **점수**입니다. 게이트 안의 모든 감별사 점수를 **더해서** 문턱값과 비교합니다(8-8).

> 파일 머리말의 설명 `Tree-based 20x20 gentle adaboost`가 바로 이 구조를 말합니다. **나무(tree) 모양** 약한 분류기를 **Gentle AdaBoost**로 학습했다는 뜻입니다. 질문이 하나뿐인 버전은 "그루터기(stump)"라고 부르고, `haarcascade_frontalface_default.xml`이 그런 방식입니다.

## 8-7. 비교 전에: 특징값 정규화

### (가) 왜 필요한가

8-A에서 얼굴의 0번 특징 원시값이 +1,431이었습니다. 그런데 같은 얼굴을 **조명만 절반으로** 찍으면 모든 픽셀이 절반이 되고 특징값도 약 +715가 됩니다. 문턱값 하나로는 두 경우를 같이 판정할 수 없습니다.

그래서 OpenCV는 특징값을 **창의 밝기 퍼짐(표준편차)**으로 나눕니다. 조명이 절반이 되면 표준편차도 절반이 되므로, 나눈 값은 **그대로**입니다.

### (나) 📐 실제 공식

```
 area = 18 × 18 = 324                 ← 20×20 창에서 테두리 1픽셀씩 뺀 안쪽
 Σx  = 안쪽 18×18의 픽셀 합            ← 적분 영상에서 조회 4번
 Σx² = 안쪽 18×18의 픽셀 제곱의 합     ← 제곱 적분 영상에서 조회 4번 (8-A 예고)

 nf  = √( area·Σx² − (Σx)² )   = area × 표준편차

 정규화된 특징값 = (Σ 가중치 × 사각형 합) / nf
```

`√(area·Σx² − (Σx)²) / area`는 분산 공식 `√(E[x²] − E[x]²)`을 정리한 것이라 결국 표준편차입니다. **창마다 조회 8번**으로 표준편차를 얻습니다.

## 8-8. 🔢 1번 게이트 손계산

1번 게이트는 나무 3그루이고 문턱값은 **0.3507**입니다. 위 표의 정규화값으로 각 나무를 따라 내려갑니다.

### (가) face 창

**나무 1** `[0,1, 특징0, 0.004327] [-1,-2, 특징1, 0.013076]`  잎 (0.0384, 0.8965, 0.2629)
```

 특징1 = −0.01360 < 0.013076 ? 예     → 왼쪽(−1) → 🍃 잎 1 = 0.8965
```

**나무 2** `[0,1, 특징2, 0.000524] [-1,-2, 특징3, 0.004457]`  잎 (0.1022, 0.1238, 0.6910)
```
 특징2 = 0.01865 < 0.000524 ?  아니오 → 질문 #1
 특징3 = 0.14188 < 0.004457 ?  아니오 → 오른쪽(−2) → 🍃 잎 2 = 0.6910
```

**나무 3** `[1,0, 특징4, −0.000927] [-1,-2, 특징5, 0.000340]`  잎 (0.1954, 0.2101, 0.8259)
(이 나무는 첫 질문의 왼쪽이 1, 오른쪽이 0입니다. **"예"일 때 다음 질문으로** 갑니다.)
```

 특징5 = 0.12189 < 0.000340 ?   아니오 → 오른쪽(−2) → 🍃 잎 2 = 0.8259
```

```
 게이트 1 점수 = 0.8965 + 0.6910 + 0.8259 = 2.4134
 2.4134 ≥ 0.3507  →  ✅ 통과 (여유 있게)
```

### (나) bg 창 (왼쪽 위 배경)


## 8-9. AdaBoost: 수만 개 특징 중에서 감별사를 어떻게 골랐나

학습은 OpenCV 개발자가 수천 장의 얼굴 사진과 얼굴이 아닌 사진으로 **미리** 해 둔 것이고, 우리는 결과물(XML)만 씁니다. 원리는 이렇습니다.

### (가) 🧠 비유: 오답 노트로 과외 선생님 뽑기

```
 1. 모든 학습 사진(얼굴 ✔ / 얼굴 아님 ✘)에 같은 중요도를 준다
 2. 78,460개 후보 특징 × 가능한 문턱값 중에서
    "중요도를 반영한 오답률"이 가장 낮은 감별사 하나를 뽑는다
 3. 그 감별사가 틀린 사진의 중요도를 올린다   ← 오답 노트
    (맞힌 사진의 중요도는 내린다)
 4. 2로 돌아가 다음 감별사를 뽑는다
    → 다음 감별사는 앞사람이 틀린 사진을 맞히는 쪽으로 뽑힌다
```

이렇게 뽑힌 감별사들은 **서로의 약점을 보완**합니다. 각자는 약해도 점수를 합치면 강한 분류기가 됩니다. "부스팅(boosting)"은 약한 것을 끌어올린다는 뜻이고, "Ada(Adaptive)"는 중요도를 매번 조정한다는 뜻입니다.

Gentle AdaBoost는 감별사가 "예/아니오" 대신 **실수 점수**(나뭇잎 값 0.0384, 0.8965 …)를 내도록 한 변형입니다. 확신의 정도를 점수로 표현합니다.

### (나) 그래서 1번 게이트의 특징들이 무엇을 보는가

| 나무 | 첫 질문 | 두 번째 질문 |
|---|---|---|
| 1 | 0번: 눈 밑이 눈 줄보다 밝은가 | 1번: 얼굴 가운데 세로 띠 위아래 차이 |
| 2 | 2번: 오른쪽 눈 아래 1픽셀 폭 세로 띠 | 3번: **미간·콧대가 양쪽 눈보다 밝은가** |
| 3 | 4번: 왼쪽 눈 쪽 1픽셀 폭 세로 띠 | 5번: 코 높이 가로 띠가 위아래보다 밝은가 |

학습 알고리즘은 "눈"이나 "코"라는 개념을 모릅니다. 그런데 오답률만 따져서 고른 결과가 **사람이 얼굴을 볼 때 쓰는 단서와 거의 같습니다.** 이 점이 Viola–Jones 방식이 유명해진 이유 중 하나입니다.

- 게이트가 뒤로 갈수록 나무가 많아지고(3 → 109) 문턱값도 올라갑니다. 뒤쪽 게이트일수록 **진짜 얼굴과 얼굴 비슷한 것을 가르는 어려운 문제**를 맡습니다.

### (나) 🔢 깔때기: 창 350개가 어떻게 걸러지나

47×68 이미지 전체를 OpenCV와 같은 간격(2픽셀)으로 훑으면 20×20 창이 **350개**입니다. 각 게이트에 도달한 창의 수를 세었습니다.

### (다) 📐 왜 게이트를 20개나 두나: 확률 계산

학습할 때 흔히 이런 목표를 각 게이트에 줍니다.

| 게이트 하나의 목표 | 값 |
|---|---|
| 진짜 얼굴을 통과시키는 비율 (검출률) | 99.9% |
| 얼굴 아닌 것을 통과시키는 비율 (오검출률) | 50% |

20개를 직렬로 이으면 모두 곱해집니다.

```
 전체 검출률   = 0.999²⁰ ≈ 0.980   → 얼굴 100개 중 98개는 끝까지 통과
 전체 오검출률 = 0.5²⁰   ≈ 0.00000095 → 얼굴 아닌 창 100만 개 중 약 1개만 통과
```

게이트 하나하나는 "얼굴 아닌 것 중 절반만 걸러내는" **허술한 검사**입니다. 그런데 20번 연속으로 통과해야 한다는 조건이 붙으면 **아주 엄격한 검사**가 됩니다. 반대로 진짜 얼굴은 매번 99.9%로 통과하니 거의 잃지 않습니다.

## 📝 확인 퀴즈

1. `internalNodes`가 `1 0 4 -9.27e-04 …`인 나무에서 특징 4의 값이 **+0.001**이면 어느 잎으로 가나요?
2. 어떤 창의 모든 픽셀을 2배 밝게 만들면(포화 없이) 정규화된 특징값은 어떻게 되나요?
3. 1번 게이트에서 가능한 **최저 점수**는? (각 나무의 가장 작은 잎을 더해 보세요.) 그 점수면 통과하나요?
4. 게이트 하나의 오검출률이 50%가 아니라 70%라면, 20개 게이트를 지난 뒤의 오검출률은?
5. 게이트 순서를 거꾸로(109그루짜리를 맨 앞에) 바꾸면 결과(최종 얼굴 판정)와 속도는 각각 어떻게 될까요?

<br>

**정답**
1. −0.000927보다 작지 않으므로 오른쪽 = **0** → 잎 0 = **0.1954** (질문 1개로 끝)
2. **그대로**입니다. 특징 원시값도 2배, nf(표준편차)도 2배라서 나누면 같습니다. 이게 정규화의 목적입니다.
3. 0.0384 + 0.1022 + 0.1954 = **0.3360** < 0.3507 → **탈락**. 세 나무 모두 "얼굴 같지 않음"이면 떨어집니다.
4. 0.7²⁰ ≈ **0.0008** (1만 개 중 약 8개). 50%일 때보다 약 800배 많은 오검출입니다.
5. 모든 게이트를 통과해야 하므로 **최종 판정은 같습니다**. 하지만 거의 모든 창이 맨 앞의 109그루를 계산해야 하므로 **훨씬 느려집니다.** 가벼운 게이트를 앞에 두는 순서가 속도의 비결입니다.
