## 🖼️ Step 1. 도화지를 깔고 아이콘 메뉴 12개 배치하기

📄 대상 코드: [01.place_icons.py](../../chap11/01.place_icons.py), [paint_utils.py:3-16](../../chap11/header/paint_utils.py#L3-L16)

🎯 **목표:** 아래 20줄짜리 코드가 픽셀 단위로 무엇을 하는지, 모든 중간값을 따라가며 설명할 수 있게 되기

```python
def place_icons(image, size):
    icon_name = ["rect", "circle", "eclipe", "line", "brush", "eraser",
                 "open", "save", "plus", "minus", "clear", "color"]
    icons = [(i%2, i//2, 1, 1) for i in range(len(icon_name))]   # ① 칸 번호표
    icons = np.multiply(icons, size*2)                           # ② 픽셀 좌표로 변환

    for roi, name in zip(icons, icon_name):                      # ③ 하나씩
        icon = cv2.imread('images/icon/%s.jpg' % name, cv2.IMREAD_COLOR)
        if icon is None: continue
        x, y, w, h = roi
        image[y:y+h, x:x+w] = cv2.resize(icon, size)             # ④ 붙이기
    return list(icons)                                           # ⑤ 위치 정보 반환

image = np.full((500, 800, 3), 255, np.uint8)                    # ⓪ 도화지
icons = place_icons(image, (60, 60))
cv2.imshow("PaintCV", image)
cv2.waitKey(0)
```

전체 흐름은 이렇습니다.

```
⓪ 흰 도화지 ──▶ ① 칸 번호표 12개 ──▶ ② 픽셀 사각형 12개 ──▶ ③ 아이콘 파일 읽기 ──▶ ④ 60×60으로 줄여 붙이기 ──▶ ⑤ 사각형 목록 반환
```

이걸 sub-step 6개로 나눠서 봅니다.

### 1-1. 도화지 만들기 (+ 📚 좌표계 복습)

```python
image = np.full((500, 800, 3), 255, np.uint8)
```

| 부분 | 의미 |
|---|---|
| `np.full(모양, 값, 타입)` | "이 모양의 배열을 만들고 모든 칸을 이 값으로 채워라" |
| `(500, 800, 3)` | **(높이 H, 너비 W, 채널 C)**. 세로 500줄, 가로 800칸, 칸마다 B·G·R 3개 |
| `255` | B=G=R=255, 즉 **흰색** |
| `np.uint8` | 0~255 정수 1바이트 |

실측 결과:
```
image.shape  = (500, 800, 3)
image.dtype  = uint8
image.nbytes = 1,200,000   ← 500 × 800 × 3 = 120만 바이트 ≈ 1.2MB
```

> ### 📚 복습: 좌표를 부르는 두 가지 방식 (chap11 내내 나옵니다)
>
> ```
>          x →  0    1    2   ...                   799
>    y  0    ┌──────────────────────────────────────┐
>    ↓  1    │  ●(x=2, y=1)                          │
>       2    │                                      │
>       ⋮    │                                      │
>     499    └──────────────────────────────────────┘
> ```
>
> | 누가 | 순서 | 점 ●를 부르는 법 |
> |---|---|---|
> | **numpy 인덱싱** | `[행, 열]` = `[y, x]` | `image[1, 2]` |
> | **OpenCV 함수 인자** | `(x, y)` | `cv2.circle(image, (2, 1), …)` |
> | **OpenCV 크기 인자** (`resize`의 dsize 등) | `(w, h)` | `cv2.resize(img, (800, 500))` |
>
> 이유: numpy는 수학의 행렬처럼 "몇 번째 줄의 몇 번째 칸"으로 생각하고, OpenCV 함수는 그래프 좌표처럼 "가로 먼저, 세로 나중"으로 생각합니다.

이 챕터의 거의 모든 사각형은 **`(x, y, w, h)`** 4개짜리 튜플로 표현됩니다. "왼쪽 위 꼭짓점이 (x, y)이고 가로 w, 세로 h인 사각형"이라는 뜻입니다. 이걸 numpy로 잘라낼 때는 **순서가 뒤집힙니다.**

```
 (x, y, w, h) = (60, 300, 60, 60)  의 사각형

      x=60        x+w=120
 y=300 ┌──────────┐
       │          │   numpy 로 잘라내기:
       │          │   image[ y : y+h ,  x : x+w ]
       │          │        = image[300:360, 60:120]
y+h=360└──────────┘          ↑ 세로 먼저   ↑ 가로 나중
```

### 1-2. 칸 번호표 만들기: `(i%2, i//2, 1, 1)`

```python
icons = [(i%2, i//2, 1, 1) for i in range(len(icon_name))]
```

`len(icon_name)`은 12이고, `range(12)`는 0, 1, 2, …, 11입니다. 각 i마다 4개짜리 튜플을 하나씩 만듭니다.

🧠 **비유: 한 줄에 2석짜리 극장.** 좌석 번호 i만 알면 몇 번째 줄의 왼쪽 자리인지 오른쪽 자리인지 계산할 수 있습니다.
- `i % 2` = i를 2로 나눈 **나머지**. 0이면 왼쪽 열, 1이면 오른쪽 열 → **열(column) 번호**
- `i // 2` = i를 2로 나눈 **몫**. 앞에서부터 몇 번째 줄인지 → **줄(row) 번호**
- 예: `7 % 2 = 1`, `7 // 2 = 3` → 7번은 "3번 줄의 오른쪽 자리"

마지막 `1, 1`은 "가로 1칸, 세로 1칸 크기"라는 뜻입니다. 지금은 단위가 "칸"이고, 다음 단계에서 픽셀로 바꿉니다.

🔢 **12개 전부 계산:**

| i | 이름 | i%2 (열) | i//2 (줄) | 결과 튜플 |
|---|---|---|---|---|
| 0 | rect | 0 | 0 | `(0, 0, 1, 1)` |
| 1 | circle | 1 | 0 | `(1, 0, 1, 1)` |
| 2 | eclipe | 0 | 1 | `(0, 1, 1, 1)` |
| 3 | line | 1 | 1 | `(1, 1, 1, 1)` |
| 4 | brush | 0 | 2 | `(0, 2, 1, 1)` |
| 5 | eraser | 1 | 2 | `(1, 2, 1, 1)` |
| 6 | open | 0 | 3 | `(0, 3, 1, 1)` |
| 7 | save | 1 | 3 | `(1, 3, 1, 1)` |
| 8 | plus | 0 | 4 | `(0, 4, 1, 1)` |
| 9 | minus | 1 | 4 | `(1, 4, 1, 1)` |
| 10 | clear | 0 | 5 | `(0, 5, 1, 1)` |
| 11 | color | 1 | 5 | `(1, 5, 1, 1)` |

칸 번호로 그리면 이렇게 됩니다. 번호가 왼쪽→오른쪽, 그다음 아래 줄 순서로 진행합니다.

```
          열0      열1
 줄0   [  0  ] [  1  ]
 줄1   [  2  ] [  3  ]
 줄2   [  4  ] [  5  ]
 줄3   [  6  ] [  7  ]
 줄4   [  8  ] [  9  ]
 줄5   [ 10  ] [ 11  ]
```

### 1-3. 칸 번호를 픽셀 좌표로: `np.multiply(icons, size*2)` ⭐ Step 1에서 가장 영리한 줄

```python
icons = np.multiply(icons, size*2)     # size = (60, 60)
```

이 한 줄에 두 가지 일이 겹쳐 있어서 나눠서 봅니다.

#### (가) `size*2`: ⚠️ 곱셈이 아니라 반복입니다

파이썬 **튜플에 정수를 곱하면** 숫자에 곱해지는 게 아니라 **튜플이 이어 붙습니다.**

| 식 | 결과 | 이유 |
|---|---|---|
| `(60, 60) * 2` | **`(60, 60, 60, 60)`** | 튜플 반복 (실측) |
| `np.array((60, 60)) * 2` | `[120, 120]` | numpy 배열이면 진짜 곱셈 |
| `[1, 2] * 3` | `[1, 2, 1, 2, 1, 2]` | 리스트도 반복 |

`size`는 `(w, h)`이므로 `size*2 = (w, h, w, h)`입니다. 이 순서가 다음 단계에서 딱 맞아떨어집니다.

#### (나) `np.multiply`와 브로드캐스팅

`np.multiply(A, B)`는 **같은 위치끼리 곱합니다.** 그런데 두 입력의 모양이 다릅니다.

```
A = icons (튜플 12개짜리 리스트) → numpy가 자동 변환 → shape (12, 4)
B = (60, 60, 60, 60)                                → shape (4,)
```

모양이 달라도 numpy는 **B 한 줄을 12번 복사한 것처럼** 취급해서 곱해 줍니다. 이걸 **브로드캐스팅**이라고 합니다.

```
   A (12×4)            B (4,) → 12줄로 늘린 것처럼       결과 (12×4)
 [0, 0, 1, 1]          [60, 60, 60, 60]              [ 0,   0, 60, 60]
 [1, 0, 1, 1]          [60, 60, 60, 60]              [60,   0, 60, 60]
 [0, 1, 1, 1]    ×     [60, 60, 60, 60]       =      [ 0,  60, 60, 60]
     ⋮                       ⋮                             ⋮
 [1, 5, 1, 1]          [60, 60, 60, 60]              [60, 300, 60, 60]
```

각 줄 안에서 일어나는 계산은 이렇습니다.

```
 ( 열 ,  줄 , 1 , 1 )
 ×  w     h   w   h
 ─────────────────────
 ( 열·w, 줄·h,  w,  h )  =  ( x , y , w , h )   ← 정확히 ROI 형식!
```

🔢 **실측 결과 전체** (dtype = int64):

| i | 이름 | 칸 번호 | → **(x, y, w, h)** | 차지하는 픽셀 범위 |
|---|---|---|---|---|
| 0 | rect | (0,0,1,1) | **(0, 0, 60, 60)** | x 0~59, y 0~59 |
| 1 | circle | (1,0,1,1) | **(60, 0, 60, 60)** | x 60~119, y 0~59 |
| 2 | eclipe | (0,1,1,1) | **(0, 60, 60, 60)** | x 0~59, y 60~119 |
| 3 | line | (1,1,1,1) | **(60, 60, 60, 60)** | x 60~119, y 60~119 |
| 4 | brush | (0,2,1,1) | **(0, 120, 60, 60)** | x 0~59, y 120~179 |
| 5 | eraser | (1,2,1,1) | **(60, 120, 60, 60)** | x 60~119, y 120~179 |
| 6 | open | (0,3,1,1) | **(0, 180, 60, 60)** | x 0~59, y 180~239 |
| 7 | save | (1,3,1,1) | **(60, 180, 60, 60)** | x 60~119, y 180~239 |
| 8 | plus | (0,4,1,1) | **(0, 240, 60, 60)** | x 0~59, y 240~299 |
| 9 | minus | (1,4,1,1) | **(60, 240, 60, 60)** | x 60~119, y 240~299 |
| 10 | clear | (0,5,1,1) | **(0, 300, 60, 60)** | x 0~59, y 300~359 |
| 11 | color | (1,5,1,1) | **(60, 300, 60, 60)** | x 60~119, y 300~359 |

#### (다) 그냥 60을 곱하면 안 되나?

정사각형일 때는 됩니다(`np.multiply(icons, 60)`도 같은 결과). 하지만 `size*2` 방식은 **아이콘이 정사각형이 아닐 때도** 맞게 동작합니다. 직접 실험한 결과입니다.

```python
size = (60, 40)          # 가로 60, 세로 40 직사각형 아이콘
size*2 → (60, 40, 60, 40)
np.multiply(첫 4개, size*2) →
 [[ 0  0 60 40]          # x는 60씩, y는 40씩 증가 ✅
  [60  0 60 40]
  [ 0 40 60 40]
  [60 40 60 40]]
```

`*2`를 빼고 `np.multiply(icons, (60, 60))`로 쓰면 이렇게 됩니다.
```
ERR: operands could not be broadcast together with shapes (12,4) (2,)
```
(12, 4)와 (2,)는 끝자리 4와 2가 안 맞아서 브로드캐스팅이 안 됩니다. 그래서 `*2`로 길이를 4로 맞춘 겁니다.

### 1-4. 아이콘을 하나씩 읽어서 붙이기

```python
for roi, name in zip(icons, icon_name):
    icon = cv2.imread('images/icon/%s.jpg' % name, cv2.IMREAD_COLOR)
    if icon is None: continue
    x, y, w, h = roi
    image[y:y+h, x:x+w] = cv2.resize(icon, size)
```

#### (가) `zip`: 두 목록을 지퍼처럼 짝짓기

```
icons     :  [0,0,60,60]   [60,0,60,60]   [0,60,60,60]   …  [60,300,60,60]
               │              │              │                 │
icon_name :  "rect"        "circle"       "eclipe"       …   "color"
               ↓              ↓              ↓                 ↓
 1회차 roi=[0,0,60,60], name="rect"
 2회차 roi=[60,0,60,60], name="circle"
 …  (12회 반복)
```

#### (나) 파일 경로 만들기와 읽기

`'images/icon/%s.jpg' % name`에서 `%s` 자리에 name이 들어갑니다. name이 `"rect"`면 `'images/icon/rect.jpg'`가 됩니다.

실측해 보니 **아이콘 원본 12장은 전부 `(70, 70, 3)`**, 즉 70×70 컬러 이미지입니다.

#### (다) `x, y, w, h = roi`: 언패킹

`roi`는 `array([60, 300, 60, 60])` 같은 numpy 1차원 배열입니다. 왼쪽에 변수 4개를 쓰면 순서대로 하나씩 들어갑니다. 이때 들어가는 값의 타입은 파이썬 int가 아니라 `numpy.int64`입니다(실측). 슬라이싱에는 아무 문제가 없습니다.

#### (라) 왜 `cv2.resize`가 꼭 필요한가

원본은 70×70인데 자리는 60×60입니다. resize 없이 바로 붙여 보면 이렇게 됩니다(실측).

```
ERR: could not broadcast input array from shape (70,70,3) into shape (60,60,3)
```

numpy는 **크기가 정확히 같아야** 붙여 줍니다. 그래서 `cv2.resize(icon, size)`로 70×70을 60×60으로 줄입니다(약 0.857배). 여기서 `size`는 **(w, h)** 순서입니다(1-1 복습 표 참고). 지금은 정사각형이라 순서가 바뀌어도 티가 안 나지만, 원칙은 기억해 두세요.

#### (마) 붙이기: 큰 배열의 일부를 덮어쓰기

`image[y:y+h, x:x+w]`는 **원본의 일부를 가리키는 창문(view)**입니다. 복사본이 아닙니다. 실측으로 `np.shares_memory(image, image[0:60, 0:60]) → True`가 나왔습니다. 그래서 여기에 대입하면 **원본 image가 직접 바뀝니다.**

🧠 **비유:** 큰 게시판(image)에서 "가로 60~120, 세로 300~360 구역"에 테이프로 테두리를 치고, 그 구역에 포스터를 붙이는 겁니다. 포스터를 붙이면 게시판 자체가 바뀝니다.

🔢 **12회 반복을 전부 추적:**

| 회차 | name | roi (x,y,w,h) | 실행되는 대입문 | 원본 → 붙는 크기 |
|---|---|---|---|---|
| 1 | rect | (0,0,60,60) | `image[0:60, 0:60] = …` | 70×70 → 60×60 |
| 2 | circle | (60,0,60,60) | `image[0:60, 60:120] = …` | 〃 |
| 3 | eclipe | (0,60,60,60) | `image[60:120, 0:60] = …` | 〃 |
| 4 | line | (60,60,60,60) | `image[60:120, 60:120] = …` | 〃 |
| 5 | brush | (0,120,60,60) | `image[120:180, 0:60] = …` | 〃 |
| 6 | eraser | (60,120,60,60) | `image[120:180, 60:120] = …` | 〃 |
| 7 | open | (0,180,60,60) | `image[180:240, 0:60] = …` | 〃 |
| 8 | save | (60,180,60,60) | `image[180:240, 60:120] = …` | 〃 |
| 9 | plus | (0,240,60,60) | `image[240:300, 0:60] = …` | 〃 |
| 10 | minus | (60,240,60,60) | `image[240:300, 60:120] = …` | 〃 |
| 11 | clear | (0,300,60,60) | `image[300:360, 0:60] = …` | 〃 |
| 12 | color | (60,300,60,60) | `image[300:360, 60:120] = …` | 〃 |

대입문을 보면 **세로 범위(y)가 앞**, **가로 범위(x)가 뒤**에 옵니다. 1-1에서 말한 순서 뒤집기가 여기서 실제로 일어납니다.

### 1-5. `return list(icons)`: 왜 굳이 list로 바꿔서 돌려주나?

`icons`는 지금 (12, 4) numpy 배열입니다. 그런데 **numpy 배열에는 `.append()`가 없습니다.**
다음 Step 2에서 팔레트와 색상 바의 사각형을 `icons.append(...)`로 덧붙여야 하므로, 미리 **파이썬 리스트**로 바꿔 둡니다.

```
list(icons) = [array([ 0,  0, 60, 60]),      ← 원소 하나하나는 여전히 numpy 1차원 배열
               array([60,  0, 60, 60]),
               ...
               array([60, 300, 60, 60])]      ← 12개
```

Step 2에서 이 리스트 뒤에 튜플 2개가 붙습니다(12번 팔레트, 13번 색상 바). 그러면 **리스트 인덱스 0~13이 그대로 명령 번호**가 됩니다. [paint_init.py](../../chap11/header/paint_init.py)의 `DRAW_RECTANGLE = 0`, …, `COLOR = 11`, `PALETTE = 12`, `HUE_IDX = 13`이 바로 이 인덱스입니다. 이 설계는 Step 2-5에서 자세히 봅니다.
