# 👀 Step 9. 눈 검출과 좌표 변환

📄 대상 코드: [06.detect_face.py](../../chap11/06.detect_face.py) 전체

🎯 **목표:** 얼굴 안에서 찾은 눈 박스 `(82, 30, 45, 45)`를 전체 사진 좌표 `(278, 123)`으로 바꾸는 과정을 설명하고, "얼굴 안에서만 찾기"와 "minNeighbors=7"이 왜 필요한지 **60장 실험 결과**로 보이기

```python
face_cascade = cv2.CascadeClassifier("haarcascade_frontalface_alt2.xml")
eye_cascade  = cv2.CascadeClassifier("haarcascade_eye.xml")
image, gray = preprocessing(34)                                      # Step 7
faces = face_cascade.detectMultiScale(gray, 1.1, 2, 0, (100, 100))   # Step 8
if faces.any():                                                      # ⚠️ 9-6
    x, y, w, h = faces[0]
    face_image = image[y:y + h, x:x + w]                             # 9-2
    eyes = eye_cascade.detectMultiScale(face_image, 1.15, 7, 0, (25, 20))   # 9-3
    if len(eyes) == 2:
        for ex, ey, ew, eh in eyes:
            center = (x + ex + ew // 2, y + ey + eh // 2)            # 9-4 ⭐
            cv2.circle(image, center, 10, (0, 255, 0), 2)
    else:
        print("눈 미검출")
    cv2.rectangle(image, faces[0], (255, 0, 0), 2)                   # 9-5
    cv2.imshow("image", image)
else: print("얼굴 미검출")
```

sub-step 6개로 나눠서 봅니다. 숫자는 전부 실측입니다.

## 9-1. 왜 얼굴 안에서만 눈을 찾나: 60장 실험

같은 눈 검출기, 같은 인자 `(1.15, 7, 0, (25, 20))`로 **사진 전체**에서 찾는 경우와 **얼굴 박스 안**에서만 찾는 경우를 비교했습니다.

### (가) 34.jpg 한 장

| | 검사 창 수 | 실측 시간 | 찾은 눈 (전체 좌표) |
|---|---|---|---|
| 사진 전체 (500×349) | 176,274 | 5.2 ms | (257, 102, 44, 44), (198, 120, 40, 40) |
| 얼굴 안 (158×158) | **15,815** | **2.7 ms** | (256, 101, 45, 45), (199, 118, 41, 41) |

34.jpg에서는 두 방법 모두 눈 두 개를 맞게 찾았습니다. 차이는 속도뿐입니다(창 수 약 11분의 1).

### (나) 60장 전체 (minNeighbors = 7)

| 찾은 눈 개수 | 사진 전체에서 찾기 | **얼굴 안에서 찾기** |
|---|---|---|
| 1개 | 1장 | 0장 |
| **2개** | **45장** | **60장** ✅ |
| 3개 | 11장 | 0장 |
| 4개 | 1장 | 0장 |
| 5개 | 1장 | 0장 |
| 11개 | 1장 | 0장 |
| 얼굴 박스 **밖**에서 나온 가짜 눈 | **19개** | 0개 (구조상 불가능) |

사진 전체에서 찾으면 60장 중 **15장**이 "눈이 정확히 2개"라는 조건을 통과하지 못합니다. 콧구멍, 단추, 귀걸이, 배경 무늬처럼 "어두운 동그라미 주변이 밝은" 패턴이 눈으로 잡히기 때문입니다.

### (다) 이유 세 가지 정리

| 이유 | 설명 |
|---|---|
| ① 속도 | 검사할 영역이 작아져 창 수가 약 1/11 |
| ② 오검출 감소 | 눈이 있을 수 없는 곳(배경, 옷)은 아예 보지 않음. 60장에서 가짜 19개 → 0개 |
| ③ 소속 | 단체 사진이라면 "이 눈이 어느 얼굴의 눈인가"가 저절로 정해짐 |

🧠 **비유: 잃어버린 열쇠 찾기.** 온 집을 뒤지는 대신 "가방 안에 있다"는 걸 알면 가방만 뒤집니다. 더 빨리 찾고, 다른 열쇠와 헷갈릴 일도 줄어듭니다. **큰 것을 먼저 찾고, 그 안에서 작은 것을 찾는** 이 순서를 **coarse-to-fine(거친 것에서 세밀한 것으로)** 전략이라고 부릅니다.

> 🚗 **AVM 연결:** 주차선 검출에서도 같은 전략을 씁니다. 탑뷰 전체에서 바로 선 끝점을 찾지 않고, 먼저 "주차 칸이 있을 법한 영역"을 잡은 뒤 그 안에서 모서리를 정밀하게 찾습니다.

## 9-2. `face_image = image[y:y+h, x:x+w]`: 얼굴 잘라내기

```
 x, y, w, h = faces[0] = 174, 71, 158, 158
 face_image = image[71:229, 174:332]
```

실측:
```
 face_image.shape                     = (158, 158, 3)
 np.shares_memory(face_image, image)  = True       ← 복사가 아니라 view (Step 5와 같은 원리)
 type(x)                              = numpy.int32
```

### (가) 컬러 영상을 넣어도 되나?

얼굴 검출은 평활화한 흑백 `gray`에 했는데, 눈 검출은 **컬러 원본** `image`에서 자른 `face_image`에 합니다. `detectMultiScale`은 3채널 영상을 받으면 **내부에서 흑백으로 바꿔서** 씁니다. 실측으로 확인했습니다.

| 입력 | 결과 |
|---|---|
| 컬러 자른 것 `face_image` | (82, 30, 45, 45), (25, 47, 41, 41) |
| 같은 것을 직접 흑백으로 바꾼 것 | (82, 30, 45, 45), (25, 47, 41, 41) ← **완전히 같음** |
| 평활화된 `gray`에서 자른 것 | (84, 33, 41, 41), (26, 49, 39, 39) ← 조금 다름 |

얼굴은 평활화된 영상에서, 눈은 평활화 안 된 영상에서 찾는 셈이라 **일관성은 없습니다.** 이 데이터셋에서는 문제가 안 됐지만(아래 60/60), 어두운 사진이라면 눈 검출에도 평활화된 `gray[y:y+h, x:x+w]`를 쓰는 편이 Step 7의 실험 결과로 볼 때 더 안전합니다.

### (나) view라서 생기는 주의점

`face_image`는 image와 메모리를 공유합니다. 그래서 코드가 **눈 검출을 끝낸 뒤에** 원과 사각형을 그리는 순서가 중요합니다. 만약 얼굴 사각형을 먼저 그리고 눈을 찾으면, 파란 테두리 선이 `face_image` 안에도 그려진 상태로 검출하게 됩니다.

## 9-3. 눈 검출 인자 `(1.15, 7, 0, (25, 20))`

`haarcascade_eye.xml`도 얼굴 검출기와 **같은 구조**입니다(실측: 20×20 창, 게이트 24개, 특징 1,066개). Step 8에서 배운 것이 그대로 적용됩니다.

| 인자 | 얼굴 검출 | 눈 검출 | 차이의 이유 |
|---|---|---|---|
| scaleFactor | 1.1 | **1.15** | 얼굴 안의 눈 크기는 범위가 좁아서 단계를 성기게 해도 됨 (13단계) |
| minNeighbors | 2 | **7** | 아래 (가) 참고 |
| minSize | (100, 100) | **(25, 20)** | 아래 (나) 참고 |

### (가) 🔢 minNeighbors를 바꿔 가며 (34.jpg 얼굴 안)

| minNeighbors | 찾은 개수 | 결과 |
|---|---|---|
| 0 | **215** | 묶기 전 원시 후보 전부 |
| 1 | 3 | 눈 2개 + **(54, 104, 43, 43)** ← 얼굴 아래쪽(코·입 근처) 가짜 |
| 2 ~ 15 | 2 | (82, 30, 45, 45), (25, 47, 41, 41) |

34.jpg 한 장만 보면 2 이상이면 다 되는 것 같습니다. 60장 전체로 보면 다릅니다.

| minNeighbors | 눈이 정확히 2개인 사진 | 3개가 나온 사진 |
|---|---|---|
| 3 | 51장 | **9장** |
| **7** | **60장** | 0장 |

코드는 `if len(eyes) == 2:`로 **딱 2개일 때만** 진행합니다. minNeighbors=3이면 9장이 "눈을 찾았는데도 3개라서" **"눈 미검출"**로 처리됩니다. 7은 이 데이터셋에서 60장 모두 정확히 2개가 나오도록 맞춘 값입니다.

> ⚠️ 이 7은 **이 60장에 맞춘 값**입니다. 다른 사진(작은 얼굴, 안경, 어두운 조명)에서는 7이 너무 엄격해서 진짜 눈까지 버릴 수 있습니다. 파라미터는 데이터에 맞춰 조정하는 것이지 정답이 있는 게 아닙니다.

### (나) minSize (25, 20)의 실제 의미

눈 검출기의 기본 창은 **20×20 정사각형**이라 피라미드의 창도 항상 정사각형입니다(20, 23, 26, 30, …). 가로 25 이상, 세로 20 이상을 둘 다 만족하는 첫 창은 **26×26**입니다. 그래서 `(25, 20)`은 사실상 "26픽셀보다 작은 눈은 안 찾는다"는 뜻입니다.

34.jpg에서 얼굴 폭 158에 대해 눈 폭이 41~45, 즉 **얼굴 폭의 약 26~28%**입니다. 얼굴 박스가 최소 100이면 눈은 약 26 이상일 테니, 둘이 대략 맞물립니다.

## 9-4. ⭐ 좌표 변환: 얼굴 안 좌표 → 사진 전체 좌표

### (가) 문제

`eye_cascade.detectMultiScale(face_image, …)`가 돌려준 `(82, 30, 45, 45)`는 **face_image 기준** 좌표입니다. face_image의 (0, 0)은 사진 전체의 (174, 71)입니다. 이 숫자를 그대로 `image`에 쓰면 눈이 아니라 사진 왼쪽 위 엉뚱한 곳에 원이 그려집니다.

🧠 **비유: 건물 안 좌표.** "3층 복도 끝에서 왼쪽으로 5m"는 건물 안에서만 통하는 주소입니다. 지도에 표시하려면 **건물의 위치를 더해야** 합니다.

```
 사진 전체 (image) 좌표계
 (0,0) ─────────────────────────────────────▶ x
   │
   │            (174, 71) = face_image의 (0,0)
   │              ┌────────────────────────┐
   │              │ (0,0) ──────────▶ x'    │
   │              │   │      ┌──────┐       │
   │              │   │      │ 👁 ● │← (82,30) 박스, 중심 (104, 52)   ← face_image 좌표
   │              │   │      └──────┘       │
   │              │   ▼ y'                  │
   │              └────────────────────────┘
   ▼ y                         ● = 전체 좌표로는 (174+104, 71+52) = (278, 123)
```

### (나) 🔢 두 눈 전부 계산

```python
center = (x + ex + ew // 2,  y + ey + eh // 2)
```

| 단계 | 눈 A | 눈 B |
|---|---|---|
| 검출 결과 (ex, ey, ew, eh) | (82, 30, 45, 45) | (25, 47, 41, 41) |
| 반 크기 (ew//2, eh//2) | (22, 22) ← 45//2 = 22 (버림) | (20, 20) ← 41//2 = 20 |
| **얼굴 안** 중심 (ex+ew//2, ey+eh//2) | (104, 52) | (45, 67) |
| + 얼굴 위치 (x, y) | + (174, 71) | + (174, 71) |
| **사진 전체** 중심 | **(278, 123)** | **(219, 138)** |

`//`는 **정수 나눗셈**(몫만 남김)입니다. 45 / 2 = 22.5인데 OpenCV 그리기 함수는 정수 좌표를 받으므로 22로 맞춥니다.

### (다) 이 숫자들에서 보이는 두 가지

**① 순서:** 검출 결과에서 **화면 오른쪽 눈(x=82)이 먼저**, 왼쪽 눈(x=25)이 나중에 나왔습니다. 이 순서는 보장되지 않습니다. Step 10에서는 x좌표로 정렬한 뒤 계산합니다.

**② 높이 차이:** 두 눈 중심의 y가 123과 138로 **15픽셀 차이**가 납니다. 34.jpg 속 얼굴이 기울어져 있다는 뜻입니다. 다음 Step 10에서 이 기울기를 각도로 계산해서 바로잡습니다.

```
 사진 전체에서 두 눈 위치
        x=219        x=278
  y=123   ·            ●  ← 눈 A
  y=138   ●            ·  ← 눈 B
          └─── 59 ───┘
          높이 차 15픽셀 → 얼굴이 기울어짐
```

### (라) 같은 원리, 다른 장소

Step 5의 `canvas[r, c] ≡ image[r, c + 120]`과 **완전히 같은 원리**입니다. view로 잘라낸 부분 영상에서 얻은 좌표는 **잘라낸 위치(offset)를 더해야** 원본 좌표가 됩니다. 영상 처리 코드에서 아주 흔한 계산이고, 이걸 빠뜨려서 박스가 엉뚱한 곳에 그려지는 버그도 아주 흔합니다.

## 9-5. 결과 그리기

```python
cv2.circle(image, center, 10, (0, 255, 0), 2)        # 눈 중심에 반지름 10 초록 원
cv2.rectangle(image, faces[0], (255, 0, 0), 2)       # 얼굴에 파란 사각형
```

### (가) `cv2.rectangle`에 박스를 통째로 넘기는 문법

`cv2.rectangle`은 두 가지 방식으로 부를 수 있습니다.

| 방식 | 코드 | 34.jpg에서 |
|---|---|---|
| 두 꼭짓점 | `cv2.rectangle(img, (x, y), (x+w, y+h), 색, 두께)` | (174, 71) ~ (332, 229) |
| **박스 하나** (x, y, w, h) | `cv2.rectangle(img, (x, y, w, h), 색, 두께)` | `faces[0]` = [174, 71, 158, 158] |

06은 두 번째 방식을 씁니다. `faces[0]`이 numpy int32 배열이어도 실측으로 잘 그려졌습니다. Step 8-C 실험 코드에서도 같은 문법을 썼습니다.

### (나) 좌표에 numpy 정수가 섞여도 되나?

`center`는 실측으로 `(np.int32(278), np.int32(123))`입니다. 점 좌표 인자는 numpy 정수도 받아 줍니다(실측 OK). Step 3-5에서 본 것처럼 **색 인자만 파이썬 int 튜플**이어야 합니다. 07, 08에서는 `faces[0].tolist()`로 아예 파이썬 int로 바꿔서 이런 걱정을 없앱니다.

## 9-6. ⚠️ 이 코드의 함정

### (가) 얼굴을 못 찾으면 `else`에 도달하기 전에 죽습니다

실측: 얼굴이 없는 검은 이미지로 검출하면
```
 detectMultiScale 반환값: ()                  ← numpy 배열이 아니라 빈 '튜플'
 ().any()  → AttributeError: 'tuple' object has no attribute 'any'
```

얼굴을 찾으면 numpy 배열(`.any()` 있음)을, 못 찾으면 빈 튜플(`.any()` 없음)을 돌려주기 때문입니다. 그래서 [06.detect_face.py:30](../../chap11/06.detect_face.py#L30)의 `print("얼굴 미검출")`은 **실행될 수 없습니다.** 프로그램이 그 전에 에러로 끝납니다.

```diff
- if faces.any():
+ if len(faces) > 0:          # 튜플이든 배열이든 둘 다 len()은 됨
```

`.any()`는 원래 "0이 아닌 원소가 하나라도 있나"라는 뜻이라 "검출 결과가 있나"를 묻는 데 맞는 함수도 아닙니다. 07, 08도 같은 코드라 같은 문제가 있습니다. 09는 60장이 모두 얼굴 검출에 성공해서(Step 7 실험) 우연히 터지지 않았습니다.

### (나) `faces[0]`이 가장 큰 얼굴이라는 보장이 없습니다

여러 얼굴이 잡히면 `faces[0]`은 그냥 **첫 번째로 나온 무리**입니다. Step 7에서 평활화 없이 돌렸을 때 02.jpg, 37.jpg에서 가짜 박스가 `faces[0]` 자리에 왔던 것을 기억하세요. 가장 큰 얼굴을 고르려면:
```python
x, y, w, h = max(faces, key=lambda r: r[2] * r[3])    # 넓이(w×h)가 가장 큰 박스
```

### (다) `len(eyes) == 2`는 양쪽으로 엄격합니다

눈이 1개(한쪽이 머리카락이나 안경에 가림)여도, 3개(가짜 하나 추가)여도 실패입니다. 9-3의 표처럼 minNeighbors에 아주 민감합니다. 더 튼튼하게 하려면 3개 이상일 때 "얼굴 위쪽 절반에 있고, 크기가 비슷한 두 개"를 고르는 규칙을 추가할 수 있습니다.

### (라) 사소한 것

[06.detect_face.py:15](../../chap11/06.detect_face.py#L15) 끝의 `;`는 C 언어 습관입니다. 파이썬에서는 아무 의미 없이 무시됩니다.

## 🖼️ Step 9 한 장 요약

```
 gray (평활화) ── 얼굴 검출 ──▶ faces[0] = (174, 71, 158, 158)
                                    │
 image (컬러) ── [71:229, 174:332] ──▶ face_image (view, 158×158)
```
