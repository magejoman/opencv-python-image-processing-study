## C-2. 두 번 이상 나온 함정 5가지

### ① 4번째 위치 인자는 `dst`다

| 어디서 | 코드 | 결과 |
|---|---|---|
| Step 5 | `cv2.add(a, b, dst)` | dst 자리 = 결과를 담을 배열 |
| Step 10 | `cv2.warpAffine(img, M, size, cv2.INTER_CUBIC)` | INTER_CUBIC(=2)이 dst 자리로 감 → **실제로는 LINEAR** (실측 픽셀 하나까지 같음) |

**규칙:** 선택 인자는 `flags=`, `interpolation=`처럼 **키워드로** 넘깁니다.

### ② 함수가 원본을 직접 바꾼다

| 어디서 | 내용 |
|---|---|
| Step 4·5 | 고무줄 미리보기는 `np.copy` 위에 그려야 원본이 안 더러워짐 |
| Step 9 | `face_image`는 view → 그리기 순서가 중요 |
| Step 12 | `draw_ellipse(base_mask, …)`가 base_mask를 바꿈 → **코드가 그 부작용에 기댐**. 복사로 "고치면" 피부 마스크 0픽셀 → sim1 = 1.0 |

**규칙:** OpenCV 그리기 함수는 전부 제자리 수정입니다. 원본이 필요하면 먼저 복사합니다.

### ③ numpy 타입과 파이썬 타입

| 어디서 | 상황 | 결과 |
|---|---|---|
| Step 3 | 색 인자에 numpy 정수 | 에러 → `tuple(map(int, pixel))` |
| Step 9 | 점 좌표에 numpy 정수 | OK |
| Step 10 | `cv2.fastAtan2(np.int32, …)` | TypeError → `.astype(float)` |
| Step 11 | 튜플 + 튜플 | 이어 붙이기 → `np.array`로 바꿔야 좌표 덧셈 |
| Step 9 | 검출 실패 시 `()` 튜플 반환 | `.any()` AttributeError → `len()` 사용 |

### ④ 에러 없이 틀린 답

가장 위험한 종류입니다. 이번 장에서만 네 번 나왔습니다.

| 어디서 | 원인 | 겉으로 보이는 것 |
|---|---|---|
| Step 10 | INTER_CUBIC이 dst로 감 | 아무것도 안 보임 (차이 최대 25) |
| Step 11 | ROI y < 0 → 음수 인덱스 → 빈 배열 | 경고 한 줄 + 유사도 1.0 |
| Step 12 | 마스크 부작용 제거 | 경고 한 줄 + 유사도 1.0 |
| Step 12 | 3D 히스토그램 → 64채널 해석 | 아무것도 안 보임 (0.4982 대신 0.4448) |

**규칙:** 중간값(shape, 픽셀 수, 합)을 찍어 보고, 경고(`RuntimeWarning`)를 무시하지 않습니다.

### ⑤ 파이썬 배열 모양을 OpenCV가 어떻게 해석하나

"마지막 축이 작으면 채널"이라는 규칙 하나가 두 번 나왔습니다.

| 어디서 | 배열 | OpenCV가 보는 것 |
|---|---|---|
| Step 10 | 눈 좌표 (2, 2) | 2×2 흑백 → transform 에러 / (1, 2, 2)로 바꾸면 2채널 점 2개 |
| Step 12 | 히스토그램 (64, 64, 64) | 64×64 행렬, 64채널 → CORREL의 N = 4,096 |

## C-5. 🚗 AVM과 연결된 것 모음

| 이 장의 기술 | AVM에서 |
|---|---|
| coarse-to-fine (얼굴 → 눈) | 주차 칸 후보 영역 → 모서리 정밀 검출 |
| 부분 영상 좌표 + offset | 카메라별 ROI 좌표 ↔ 탑뷰 전체 좌표 |
| `atan2` 각도 | 주차선 방향, 차량 heading (수직선에서 `atan` 금지) |
| `warpAffine` 역방향 매핑 + 보간 | **탑뷰 LUT + `cv2.remap`**의 기본 원리 |
| 검출 크기에 비례한 ROI | 입구 폭에 비례한 주차 칸 안쪽 ROI |
| 마스크 + 히스토그램 비교 | 카메라 간 겹침 영역 밝기 보정, 빈 칸 판단 |
| 같은 데이터로 기준값 조정 = 과대평가 | 다른 주행 기록(밤·비·지하)으로 검증해야 함 |

## C-6. 📝 종합 퀴즈

1. PaintCV에서 마우스 콜백은 언제 실행되나요? `while` 루프에 `waitKey`가 없으면 어떻게 되나요?
2. 캔버스 `canvas = image[:, 120:]`에 그린 선이 화면 `image`에도 나타나는 이유는?
3. Haar cascade가 창 하나를 평균 35개 나무만 보고 넘어갈 수 있는 이유는?
4. minNeighbors를 0으로 하면 34.jpg 얼굴 검출에서 무엇이 나오나요?
5. 얼굴 박스 (100, 50, 200, 200), 눈 박스 (40, 60, 50, 50)이면 눈 중심의 전체 좌표는?
6. 두 눈이 (100, 200), (180, 180)일 때 `getRotationMatrix2D`에 넣는 각도와 사진이 도는 방향은?
7. 이 장에서 "에러 없이 유사도 1.0"이 나오는 경로 두 가지는?
8. `cv2.compareHist`에 (64, 64, 64) 히스토그램을 넣으면 왜 교과서 피어슨 값과 다른가요? 고치면 무엇도 같이 바꿔야 하나요?
9. 60장 중 39번이 틀린 이유는? 이걸 줄이려면 색 공간을 어떻게 바꾸는 게 좋을까요?
10. "58/60 = 96.7%"를 그대로 믿으면 안 되는 이유 두 가지는?

<br>

**정답**
1. `cv2.waitKey()` 안에서 OS 이벤트를 처리할 때 호출됩니다. `waitKey`가 없으면 이벤트가 처리되지 않아 콜백이 불리지 않고 창도 갱신되지 않습니다(Step 3).
2. `image[:, 120:]`는 복사가 아니라 **view**라서 같은 메모리를 가리킵니다. `canvas[r, c] ≡ image[r, c + 120]`입니다(Step 5).
3. Cascade 앞쪽 게이트가 대부분의 창을 몇 개 나무만으로 탈락시키기 때문입니다. 1,047개 중 평균 34.8개만 계산했습니다(Step 8-B, 8-C).
4. 묶기 전 원시 후보가 전부 나옵니다. 34.jpg 얼굴 주변에서만 41개였습니다(Step 8-C).
5. (100 + 40 + 25, 50 + 60 + 25) = **(165, 135)** (Step 9).
6. dx = 80, dy = −20 → `fastAtan2` = **345.96°**. 화면에서 **시계 방향 14.04°** 회전 (Step 10).
7. ① ROI가 사진 밖 → 빈 배열 → NaN (Step 11), ② 마스크 부작용 제거 → 피부 마스크 0픽셀 → NaN (Step 12). 둘 다 CORREL의 "분모가 0이면 1" 분기로 빠집니다.
8. 파이썬 바인딩이 마지막 축 64를 채널로 해석해서 평균을 낼 때 N = 4,096을 씁니다. `.ravel()`로 고치면 값이 올라가므로 **Step 13의 기준값(0.2, 0.25, 0.1)도 다시 맞춰야** 합니다.
9. 같은 머리카락이 아래쪽만 그림자로 약 2배 어두워서 BGR 64칸 히스토그램의 다른 칸에 들어갔습니다. 밝기(V, Y)를 빼고 **색상(H-S)이나 Cr-Cb만으로** 히스토그램을 만들면 그림자에 덜 예민해집니다.
10. ① 기준값을 정한 바로 그 60장으로 채점했고 중복 사진도 3쌍입니다. ② 데이터가 "여성 = 긴 머리, 남성 = 짧은 머리"로 골라져 있어 가정이 틀리는 사진이 없습니다.
