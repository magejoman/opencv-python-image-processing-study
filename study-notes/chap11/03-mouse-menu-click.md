# 🖱️ Step 3. 마우스로 메뉴 클릭 처리하기

📄 대상 코드: [03.event_platte.py](../../chap11/03.event_platte.py)

🎯 **목표:** 마우스를 한 번 클릭했을 때 OpenCV 내부에서 함수가 어떤 순서로 불리고, 어떤 변수가 어떤 값으로 바뀌는지 처음부터 끝까지 따라갈 수 있게 되기

이번에는 GUI 창을 띄우지 않고 `onMouse`에 **가짜 클릭 이벤트를 직접 넣어서** 변수 값을 찍어 봤습니다. 아래 표의 값은 전부 그렇게 얻은 실측값입니다.

전체 코드:

```python
def onMouse(event, x, y, flags, param):           # ← OpenCV가 대신 불러주는 함수
    global pt1, pt2, mouse_mode, draw_mode

    if event == cv2.EVENT_LBUTTONUP:              # [A] 왼쪽 버튼을 뗐을 때
        pt2 = (x, y)
        mouse_mode = 1
        for i, (x0, y0, w, h) in enumerate(icons):
            if x0 <= x < x0+w and y0 <= y < y0+h:     # 이 사각형 안을 클릭했나?
                if i < 6:                             # 그리기 도구
                    mouse_mode = 0
                    draw_mode = i
                else:                                 # 일반 명령
                    command(i)
                return

    elif event == cv2.EVENT_LBUTTONDOWN:          # [B] 왼쪽 버튼을 눌렀을 때
        pt1 = (x, y)
        mouse_mode = 2

    if mouse_mode >= 2:                           # [C] 누른 상태 / 드래그 (Step 4 주제)
        mouse_mode = 0 if x < 125 else 3
        pt2 = (x, y)

def command(mode):
    global icons, image, Color, hue
    if mode == PALETTE:                           # 팔레트 클릭
        pixel = image[pt2[::-1]]
        x, y, w, h = icons[COLOR]
        image[y:y + h - 1, x:x + w - 1] = pixel
        Color = tuple(map(int, pixel))
    elif mode == HUE_IDX:                         # 무지개 바 클릭
        create_colorPlatte(image, pt2[0], icons[PALETTE])
    cv2.imshow("PaintCV", image)

# … (Step 2의 화면 준비) …
cv2.imshow("PaintCV", image)
cv2.setMouseCallback("PaintCV", onMouse)          # "이 창에서 마우스 일이 생기면 onMouse를 불러줘"
cv2.waitKey(0)
```

## 3-1. 📚 콜백 복습: "내가 부르는 함수"와 "남이 불러주는 함수"

> ### 📚 복습: `setMouseCallback`
> ```python
> cv2.setMouseCallback("창 이름", 함수)
> ```
> "이 창에서 마우스로 무슨 일이 생기면, 이 함수를 `함수(event, x, y, flags, param)` 형태로 불러줘"라고 **등록만** 하는 것입니다. 이 줄이 실행될 때 함수가 바로 불리지는 않습니다.

🧠 **비유: 초인종.**
- 보통 함수: 내가 친구 집에 가서 문을 두드리는 것. **내가 부를 때** 실행됩니다.
- 콜백 함수: 우리 집 초인종에 "누가 누르면 나한테 알려줘"라고 연결해 두는 것. **손님(사용자의 마우스)이 누를 때** 실행됩니다.

### 실제로 누가, 언제 부르나

중요한 사실이 하나 있습니다. **콜백은 `cv2.waitKey()`가 실행되는 동안에만 불립니다.** `waitKey`는 키 입력만 기다리는 게 아니라 **창의 이벤트(마우스, 다시 그리기 등)를 처리하는 엔진**이기도 합니다.

```
 시간 ──────────────────────────────────────────────────────────────▶

 파이썬 코드:  imshow  setMouseCallback  waitKey(0) ═══════════════════════ (ESC 등 키 입력까지 계속)
                                             ║
 사용자:                                     ║  🖱️누름        🖱️뗌
                                             ║    │            │
 OpenCV 내부:                                ╠═▶ onMouse(1,…)  ╠═▶ onMouse(4,…) ─▶ command(12)
                                             ║                 ║
```

`waitKey(0)` 대신 무거운 계산을 하고 있으면 그동안은 클릭해도 반응이 없습니다.

### 콜백이 받는 5개 인자

| 인자 | 의미 | 이 코드에서 쓰나? |
|---|---|---|
| `event` | 어떤 일이 일어났나 (정수 코드) | ✅ |
| `x, y` | 마우스 위치. **OpenCV 순서 (x, y)** | ✅ |
| `flags` | 그 순간 눌려 있는 버튼이나 키 (Ctrl, Shift 등) | ❌ |
| `param` | 등록할 때 넘긴 추가 데이터 | ❌ |

event 코드 실측값:

| 상수 | 값 | 언제 |
|---|---|---|
| `EVENT_MOUSEMOVE` | 0 | 마우스가 움직일 때마다 (아주 자주) |
| `EVENT_LBUTTONDOWN` | **1** | 왼쪽 버튼 누름 |
| `EVENT_RBUTTONDOWN` | 2 | 오른쪽 버튼 누름 |
| `EVENT_LBUTTONUP` | **4** | 왼쪽 버튼 뗌 |

클릭 한 번은 이벤트 하나가 아니라 **누름(1) → 뗌(4) 두 번의 호출**입니다. 그 사이에 마우스를 조금이라도 움직이면 MOUSEMOVE(0)도 끼어듭니다.

## 3-2. `onMouse`의 뼈대: 블록 세 개

```
 onMouse 호출됨
     │
     ├─ event == 4 (뗌)?  ──▶ [A] 메뉴 판정 + 명령 실행        ← 이번 Step의 주인공
     │
     ├─ event == 1 (누름)? ──▶ [B] 시작점 pt1 기록, mode=2
     │
     └─ (이벤트 종류 상관없이) mode ≥ 2 ? ──▶ [C] 메뉴 위인지 확인, pt2 갱신   ← Step 4의 주인공
```

**메뉴 클릭은 "뗄 때(UP)" 처리합니다.** 실제 프로그램 버튼도 대부분 이렇게 동작합니다. 누른 채로 버튼 밖으로 끌고 나가서 떼면 취소되는 것과 같은 원리입니다.

## 3-3. 🔢 Hit-test: 어느 사각형을 눌렀나?

```python
for i, (x0, y0, w, h) in enumerate(icons):
    if x0 <= x < x0+w and y0 <= y < y0+h:
```

### (가) `enumerate`와 언패킹을 한 줄에

`enumerate(icons)`는 `(번호, 원소)` 쌍을 하나씩 내줍니다. `for i, (x0, y0, w, h) in ...`는 그 쌍을 받아서 원소를 또 4개로 풉니다.

```
 1회차: i=0,  (x0,y0,w,h) = (0,   0, 60, 60)
 2회차: i=1,  (x0,y0,w,h) = (60,  0, 60, 60)
  ⋮
 13회차: i=12, (x0,y0,w,h) = (0, 362, 120, 120)   ← 팔레트
 14회차: i=13, (x0,y0,w,h) = (0, 484, 120, 15)    ← 무지개 바
```

### (나) 🔢 팔레트 (90, 380)을 클릭했을 때 루프 추적

조건은 `x0 ≤ 90 < x0+w` **그리고** `y0 ≤ 380 < y0+h`입니다.

| i | 사각형 | x 범위 검사 | y 범위 검사 | 결과 |
|---|---|---|---|---|
| 0 | (0,0,60,60) | 0≤90<60 ❌ | (검사 안 함) | 통과 |
| 1 | (60,0,60,60) | 60≤90<120 ✅ | 0≤380<60 ❌ | 통과 |
| 2 | (0,60,60,60) | 0≤90<60 ❌ | — | 통과 |
| 3 | (60,60,60,60) | ✅ | 60≤380<120 ❌ | 통과 |
| ⋮ | ⋮ | ⋮ | ⋮ | ⋮ |
| 11 | (60,300,60,60) | ✅ | 300≤380<360 ❌ | 통과 |
| **12** | **(0,362,120,120)** | **0≤90<120 ✅** | **362≤380<482 ✅** | **🎯 적중 → `command(12)` → return** |
| 13 | — | — | — | (return 했으므로 검사 안 함) |

`and`는 앞쪽이 거짓이면 뒤쪽을 아예 보지 않습니다(단락 평가). 그래서 표에 "검사 안 함"이 있습니다.

### (다) 왜 `<=`와 `<`를 섞어 쓰나: 반만 열린 구간

`x0 <= x < x0+w`는 **시작은 포함하고 끝은 포함하지 않는** 구간입니다. 0번 아이콘은 x 0~59, 1번은 60~119로, 경계가 **겹치지도 비지도 않게** 딱 맞물립니다.

```
 x:  …  57  58  59 │ 60  61  62 …
        ── 0번 ──── │ ──── 1번 ──
                    ↑ x=60 은 1번에만 속함
```

경계 (60, 0)을 클릭한 실측 결과: **`draw_mode = 1`(원)**. 0번은 `0≤60<60` ❌, 1번은 `60≤60<120` ✅입니다.

만약 양쪽을 다 `<=`로 쓰면 x=60이 0번과 1번 둘 다에 속하게 되고, 루프가 먼저 만나는 0번이 선택됩니다. 1픽셀짜리 오차지만, 이런 경계 처리를 일관되게 하는 습관이 중요합니다. numpy 슬라이싱 `image[y:y+h, x:x+w]`도 같은 "시작 포함, 끝 미포함" 규칙이라 서로 정확히 일치합니다.

### (라) 어디에도 안 걸리는 곳

| 클릭 위치 | 결과 | 이유 |
|---|---|---|
| (120, 400) | 적중 없음 | 팔레트는 x 0~119. 120은 바깥 |
| (50, 361) | 적중 없음 | y 360~361은 Step 2의 "흰 틈" |
| (500, 250) | 적중 없음 | 그림 영역 |

적중이 없으면 루프가 끝까지 돌고 `return`을 만나지 않습니다. 그러면 함수 끝까지 내려가서 `mouse_mode = 1`이 남습니다. 이 값은 Step 4에서 "도형을 확정해서 그려라"라는 신호로 쓰입니다.

## 3-5. 🔢 팔레트 클릭: `command(PALETTE)` 한 줄씩

```python
pixel = image[pt2[::-1]]                  # ①
x, y, w, h = icons[COLOR]                 # ②
image[y:y + h - 1, x:x + w - 1] = pixel   # ③
Color = tuple(map(int, pixel))            # ④
```

### ① `image[pt2[::-1]]`: 좌표 뒤집기 트릭 ⭐

`pt2`는 OpenCV 순서 `(x, y) = (90, 380)`입니다. numpy로 픽셀을 꺼내려면 `[y, x]` 순서가 필요합니다(Step 1-1 복습).

```
 pt2         = (90, 380)        ← (x, y)
 pt2[::-1]   = (380, 90)        ← [::-1] 은 "처음부터 끝까지, 거꾸로" → (y, x)
 image[(380, 90)]  ≡  image[380, 90]    ← numpy에서 튜플 하나로 인덱싱 = 쉼표 인덱싱
```

실측:
```
 image[(380, 90)] → array([ 53,  53, 214], dtype=uint8)
 image[380, 90] 과 같은가? → True
```

### 🔢 그 픽셀이 왜 (53, 53, 214)인가: Step 2 공식으로 검산

팔레트 ROI는 `(0, 362, ...)`이므로 팔레트 **안에서의** 좌표는 이렇습니다.
```
 i (행) = 380 − 362 = 18
 j (열) =  90 −   0 = 90
```

| 단계 | 계산 | 값 |
|---|---|---|
| H | hue 0 × 1.5 | 0 (빨강) |
| S | 90 × 2.125 = 191.25 → 버림 | **191** |
| V | (119 − 18) × 2.125 = 214.6 → 버림 | **214** |
| 최대 채널 (R) | = V | 214 |
| 최소 채널 (B, G) | 214 × (1 − 191/255) = 53.7 | 53 |
| **BGR** | | **(53, 53, 214)** ✅ 실측과 일치 |

### ② ③ 색상 아이콘을 그 색으로 칠하기

```
 icons[COLOR] = icons[11] = (60, 300, 60, 60)
 image[300 : 300+60-1,  60 : 60+60-1] = pixel
     = image[300:359, 60:119] = (53, 53, 214)
```

`(59, 59, 3)` 영역에 길이 3짜리 `pixel`을 넣으면 브로드캐스팅으로 **모든 칸이 같은 색**이 됩니다.

**왜 `-1`인가?** 마지막 행(y=359)과 마지막 열(x=119) 한 줄을 남기기 위해서입니다. 실측해 보면 칠한 뒤에도 (y=359, x=119)는 원래 아이콘의 `[0, 0, 0]` 그대로이고, 바로 안쪽 (358, 118)은 새 색 `[53, 53, 214]`입니다. 아이콘 테두리선 일부를 보존하려는 의도로 보입니다(위쪽과 왼쪽 테두리는 덮이니 완벽하지는 않습니다).

```
 x=60                    119
 y=300 ┌──────────────────┐
       │██████████████████│
       │██ (53,53,214) ███│   ← 새 색으로 칠해짐
       │██████████████████│
   359 └──────────────────┘   ← 맨 아래 줄과 맨 오른쪽 열은 원래 색 유지
```

### ④ `tuple(map(int, pixel))`: 왜 이렇게 번거롭게 바꾸나

`pixel`은 numpy uint8 배열입니다. 나중에(Step 4) `cv2.rectangle(..., color=Color, ...)`에 색으로 넘길 건데, **OpenCV 그리기 함수는 numpy 배열이나 numpy 정수를 색으로 받지 않습니다.** 세 가지 형태로 직접 실험했습니다.

| `Color`로 넘긴 것 | `cv2.rectangle` 결과 |
|---|---|
| `image[380, 90]` (ndarray uint8) | ❌ `(-5:Bad argument) in function 'rectangle'` |
| `tuple(image[380, 90])` (np.uint8 3개짜리 튜플) | ❌ 같은 에러 |
| `tuple(map(int, image[380, 90]))` → `(53, 53, 214)` | ✅ OK |

`map(int, pixel)`은 pixel의 원소 하나하나에 파이썬 `int()`를 적용합니다. 그 결과를 `tuple()`로 묶으면 **순수 파이썬 정수 튜플**이 됩니다. [04.draw_command.py:8](../../chap11/04.draw_command.py#L8)도 같은 일을 하고 있습니다. 주석 처리된 `pixel.astype('int')` 방식은 numpy int64가 남아서 안 됩니다.

> 💡 **view 연결 고리:** 실측으로 `np.shares_memory(pixel, image) → True`였습니다. `pixel`은 image 안의 그 3바이트를 **가리키는** view입니다. 그래서 나중에 팔레트가 다시 그려지면 `pixel` 값도 같이 바뀝니다. `int`로 변환해서 **복사**해 두는 ④는 이 점에서도 안전합니다.

`pt2[0]`은 **클릭한 x좌표**입니다. 무지개 바에서는 x가 곧 색상이었습니다(Step 2-3).

### 🔢 클릭 세 번의 타임라인 (실측)

| 순서 | 클릭 | 적중 | 일어난 일 | 팔레트 (380,90) 픽셀 | Color |

```
 ① 빨강 팔레트            ② 바 x=60 클릭            ③ 청록 팔레트
  ┌────────────┐          🔴🟡🟢🩵🔵🟣              ┌────────────┐

## 3-7. `global`: 언제 필요하고 언제 필요 없나

파이썬 규칙은 하나입니다. **함수 안에서 이름에 `=`로 새 값을 대입하면, 따로 말하지 않는 한 그 이름은 지역 변수가 됩니다.**

| 함수 안 코드 | 하는 일 | `global` 필요? |
|---|---|---|
| `pt2 = (x, y)` | 이름에 새 값 **대입** | ✅ 필요 (없으면 함수 안 지역 변수가 생겼다 사라짐) |
| `Color = tuple(...)` | 대입 | ✅ 필요 |
| `image[300:359, 60:119] = pixel` | 이름은 그대로, **배열 내용만 수정** | ❌ 불필요 |
| `pixel = image[pt2[::-1]]` | `pt2`를 **읽기만** 함 | ❌ 불필요 (`pixel`은 원래 지역 변수) |

그래서 `command`의 `global icons, image, Color, hue` 중에서 **실제로 필요한 건 `Color` 하나**입니다. 나머지는 없어도 동작합니다. 교재 코드가 "안전하게 다 적어 둔" 것입니다.

🧠 **비유:** 집 공용 화이트보드(전역변수)에 적힌 글을 **읽는 건** 누구나 그냥 할 수 있습니다. 화이트보드 내용을 **통째로 새로 쓰려면** "공용 보드에 쓰는 거야"라고 밝혀야 합니다(`global`). 그렇지 않으면 파이썬은 내 방에 개인 메모지를 하나 새로 만듭니다.

> 💡 **세부 사항:** `pt1`, `mouse_mode` 등은 [paint_init.py:20-22](../../chap11/header/paint_init.py#L20-L22)에서 정의됐습니다. 그런데 `from paint_init import *`는 그 값을 **03 파일 쪽으로 복사해 온 것**입니다. `global mouse_mode`가 바꾸는 건 03 파일의 `mouse_mode`이고, `paint_init.mouse_mode`는 0 그대로 남습니다. 지금은 모든 코드가 03 파일 안에서만 읽고 쓰니까 문제가 없습니다.

## 3-8. 🔍 03과 04의 미묘한 차이: 줄 순서

03의 `[A]` 블록은 **루프 전에** `pt2 = (x, y)`, `mouse_mode = 1`을 먼저 실행합니다. 그래서 팔레트나 무지개 바를 클릭한 뒤에는 `return`해도 `mouse_mode = 1`이 **남습니다.** 실측에서도 클릭 ①②③ 후 전부 `mouse_mode = 1`이었습니다.

03에는 그리기 루프가 없으니 아무 문제가 없습니다. 하지만 Step 4에서 "`mouse_mode == 1`이면 도형을 그려라"라는 루프가 생기면, **색을 고르려고 팔레트를 클릭했는데 도형이 그려지는** 버그가 됩니다.

그래서 [04.draw_command.py:20-31](../../chap11/04.draw_command.py#L20-L31)에서는 순서가 이렇게 바뀝니다.

```diff
  if event == cv2.EVENT_LBUTTONUP:
-     pt2 = (x, y)
-     mouse_mode = 1
      for i, (x0, y0, w, h) in enumerate(icons):
          if ...:                       # 메뉴를 클릭했으면
              ...
              return                    # ← 여기서 빠져나가므로 아래 두 줄이 실행 안 됨
+     pt2 = (x, y)                      # 메뉴가 아닐 때만
+     mouse_mode = 1                    # "도형 확정" 신호
```

`return`의 역할도 함께 바뀝니다. 03에서는 "찾았으니 그만 검사"였는데, 04에서는 **"메뉴 클릭이면 그리기 신호를 보내지 마"라는 문지기**가 됩니다.

> 이렇게 되면 04에서 `command()`가 쓰는 `pt2`는 "뗀 위치"가 아니라 [C] 블록이 기록한 **"누른 위치"**가 됩니다. 메뉴는 보통 제자리에서 클릭하니 사실상 같은 값입니다. Step 4에서 다시 봅니다.
