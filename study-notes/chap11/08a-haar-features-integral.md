## 8-1. 큰 그림: 검출기가 푸는 문제

얼굴 검출기는 사실 **딱 한 가지 질문**만 반복합니다.

> **"이 20×20 픽셀 창 안에 정면 얼굴이 꽉 차 있나? (예/아니오)"**

`haarcascade_frontalface_alt2.xml`을 열어 보면 맨 앞에 이렇게 적혀 있습니다(실측).
```xml
<featureType>HAAR</featureType>
<height>20</height>
<width>20</width>
<stageNum>20</stageNum>
```
기본 창 크기는 **20×20**이고 판정 단계(stage)가 **20개**입니다.

이 질문을 사진의 **모든 위치, 모든 크기**의 창에 대해 던집니다. 34.jpg 한 장에서만 수만 번입니다(8-C에서 직접 셉니다). 그래서 이 검출기 설계의 모든 부분이 **"한 번의 판정을 얼마나 빨리 끝내느냐"**에 맞춰져 있습니다.

🧠 **비유: 공항 보안 검색대가 여러 겹 있는 구조.**
- 1번 게이트(아주 간단한 검사 3개): 대부분의 창(벽, 하늘, 옷)이 여기서 **바로 탈락**합니다.
- 통과한 소수만 2번 게이트(검사 9개)로 갑니다.
- … 20번 게이트까지 **모두 통과해야** "얼굴"로 인정됩니다.

이 비유의 부품을 하나씩 만들어 갑니다.

```
 오늘 (8-A)                          8-B                          8-C
 ┌──────────────┐  여러 개 모아   ┌──────────────┐  모든 위치·   ┌──────────────────┐
 │ 특징 하나     │ ─────────────▶ │ 게이트(stage) │ ─────────────▶ │ 사진 전체 훑기    │
 │ = 밝기 차이   │  AdaBoost      │ 20개 직렬     │  크기에 대해   │ detectMultiScale │
 │ + 적분 영상   │                │ = Cascade     │                │                  │
 └──────────────┘                 └──────────────┘                └──────────────────┘
```

## 8-2. Haar-like 특징이란?

### (가) 정의: 흰 영역 합 − 검은 영역 합

창 안에 **흰 사각형과 검은 사각형을 맞대어 놓고**, 각 영역의 픽셀 합을 구해 빼는 것입니다.

```
 특징값 = (흰 영역 픽셀의 합) − (검은 영역 픽셀의 합)
```

결과는 **숫자 하나**입니다. 이 숫자가 크면 "흰 쪽이 확실히 더 밝다", 0 근처면 "차이 없음", 음수면 "오히려 반대"라는 뜻입니다.

이름은 1909년 수학자 알프레드 하르(Alfréd Haar)가 만든 **Haar 웨이블릿**에서 왔습니다. "+1인 부분과 −1인 부분이 붙어 있는 사각형 파형"이라는 모양이 같습니다.

### (나) 기본 모양들

```
  ① 경계(edge)          ② 선(line)               ③ 대각(four-rect)
  ┌────┬────┐           ┌───┬───┬───┐            ┌────┬────┐
  │ ░░ │ ██ │           │ ░ │ █ │ ░ │            │ ░░ │ ██ │
  │ ░░ │ ██ │           │ ░ │ █ │ ░ │            ├────┼────┤
  └────┴────┘           └───┴───┴───┘            │ ██ │ ░░ │
  세로 경계 (좌우 비교)  가운데 줄 vs 양옆         └────┴────┘
                                                  대각선끼리 비교
  ┌────────┐            ┌────────┐
  │ ██████ │            │ ░░░░░░ │
  ├────────┤            │ ██████ │
  │ ░░░░░░ │            │ ░░░░░░ │
  └────────┘            └────────┘
  가로 경계 (위아래 비교) 가운데 띠 vs 위아래

  ░ = 흰 영역 (+)    █ = 검은 영역 (−)
```

얼굴에 대입하면 이런 "상식"을 표현할 수 있습니다.

| 특징 모양 | 얼굴에서 잡는 패턴 |
|---|---|
| 가로 경계 (위 어둡고 아래 밝음) | **눈 줄은 그 아래 볼·코 줄보다 어둡다** |
| 세로 선 (가운데 밝고 양옆 어두움) | **콧대는 양쪽 눈보다 밝다** |
| 가로 선 | 입술 줄은 위아래 피부보다 어둡다 |

### (다) 🔢 6×6 장난감 패치로 손계산

가로 경계 특징(아래 3줄 합 − 위 3줄 합)을 세 가지 패치에 적용합니다.

**패치 1: 눈 줄과 볼처럼 생긴 것** (위는 어둡고 아래는 밝음)
```
 [ 45  50  40  42  55  48 ]  ┐
 [ 52  38  35  40  44  50 ]  │ 위 3줄 (검은 영역) 합 = 875
 [ 60  55  50  52  58  61 ]  ┘
 [180 185 190 188 182 179 ]  ┐
 [195 190 200 198 192 188 ]  │ 아래 3줄 (흰 영역) 합 = 3403
 [185 192 188 195 190 186 ]  ┘
                         특징값 = 3403 − 875 = +2528  ← 크게 양수
```

| 패치 | 위 3줄 합 | 아래 3줄 합 | 특징값 | 해석 |
|---|---|---|---|---|
| 1. 눈+볼 모양 | 875 | 3403 | **+2528** | "위가 확실히 어둡다" ✅ |
| 2. 거의 평평한 회색 (118~122) | 2160 | 2160 | **0** | "차이 없음" |
| 3. 패치 1을 위아래로 뒤집은 것 | 3403 | 875 | **−2528** | "오히려 위가 밝다" |

특징 하나는 **"이 위치에 이런 밝기 차이가 있다/없다"**만 말해 줍니다. 혼자서는 아주 약한 단서입니다. 이 약한 단서 수천 개를 조합하는 게 8-B의 내용입니다.

## 8-3. 🔢 진짜 특징 하나 해부: XML의 0번 특징

`haarcascade_frontalface_alt2.xml`의 `<features>` 목록 맨 첫 항목입니다(7460행 부근, 실제 내용 그대로).

```xml
<_>
  <rects>
    <_>  2 7 16 4 -1.</_>      ← 사각형 A: x=2, y=7, w=16, h=4, 가중치 −1
    <_>  2 9 16 2  2.</_>      ← 사각형 B: x=2, y=9, w=16, h=2, 가중치 +2
  </rects>
</_>
```

### (가) "−1과 +2" 표기의 정체

흰 영역과 검은 영역을 따로 적지 않고 **겹치는 사각형 두 개에 가중치를 주는** 방식으로 저장합니다.

```
 A = 7~10행 (4줄)   가중치 −1
 B = 9~10행 (2줄)   가중치 +2      (B는 A의 아래쪽 절반)

 특징값 = −1·합(A) + 2·합(B)
        = −[합(7~8행) + 합(9~10행)] + 2·합(9~10행)
        =  합(9~10행) − 합(7~8행)
        =  (아래 2줄) − (위 2줄)
```

결국 **"9~10행이 7~8행보다 얼마나 밝은가"**라는 가로 경계 특징입니다. 8-2 장난감 예제와 같은 모양입니다.

### (나) 20×20 창 위에 그려 보면

 행 7   · · █ █ █ █ █ █ █ █ █ █ █ █ █ █ █ █ · ·   ┐ 검은 영역 (위 2줄)

## 8-4. 문제: 특징이 너무 많고, 합이 너무 비쌉니다

### (가) 20×20 창 하나에 가능한 특징 개수

기본 5종(가로·세로 경계, 가로·세로 선, 대각 4칸)을 **모든 위치, 모든 크기**로 놓아 보면 몇 개일까요? 직접 세었습니다.

| 모양 (최소 크기) | 20×20 창 안의 개수 |
|---|---|
| 가로 경계 (2×1) | 21,000 |
| 세로 경계 (1×2) | 21,000 |
| 가로 선 (3×1) | 13,230 |
| 세로 선 (1×3) | 13,230 |
| 대각 (2×2) | 10,000 |
| **합계** | **78,460** |

(검산: 원 논문의 24×24 창으로 같은 계산을 하면 **162,336**이 나오는데, 널리 알려진 값과 일치합니다.)

이 중 학습이 실제로 골라 XML에 넣은 특징은 `<rects>` 개수를 세어 보면 **2,094개**입니다. 고르는 방법은 8-B에서 다룹니다.

### (나) 합을 매번 직접 더하면?

34.jpg 얼굴은 158×158 크기에서 찾았습니다. 20×20 기준 특징을 그 크기로 키우면 7.9배가 됩니다. 0번 특징의 사각형 A(16×4)는 **126×32 = 4,032픽셀**이 됩니다.

```
 사각형 합 하나        = 4,032번 덧셈
 × 특징 수천 개
 × 창 수만 개
 × 사진 60장
 = 도저히 실시간 불가능
```

이걸 해결하는 아이디어가 **적분 영상**입니다. Viola–Jones 논문(2001)을 유명하게 만든 핵심 트릭입니다.

## 8-5. 🆕 적분 영상 (Integral Image)

### (가) 정의

**적분 영상의 (y, x) 칸 = 원본에서 (0, 0)부터 (y, x)까지, 왼쪽 위 사각형 안 모든 픽셀의 합**

🧠 **비유: 가계부의 누적 잔액.** 날마다 쓴 돈을 적어 두면 "3일~7일에 쓴 돈"을 구하려고 5일치를 다시 더할 필요가 없습니다. `7일까지 누적 − 2일까지 누적` 한 번이면 됩니다. 적분 영상은 이 누적합을 **2차원으로** 확장한 것입니다.

### (나) 🔢 5×5 예제로 전체 계산

원본 M:
```
       x=0  1  2  3  4
 y=0  [  3  1  4  1  5 ]
 y=1  [  9  2  6  5  3 ]
 y=2  [  5  8  9  7  9 ]
 y=3  [  3  2  3  8  4 ]
 y=4  [  6  2  6  4  3 ]
```

적분 영상 ii (실측):
```
       x=0   1   2   3   4
 y=0  [  3   4   8   9  14 ]
 y=1  [ 12  15  25  31  39 ]
 y=2  [ 17  28  47  60  77 ]
 y=3  [ 20  33  55  76  97 ]
 y=4  [ 26  41  69  94 118 ]   ← 오른쪽 아래 118 = 원본 전체 합
```

**한 칸씩 채우는 점화식**: 이미 구한 왼쪽, 위, 왼쪽 위 칸을 재활용합니다.

```
 ii(y, x) = M(y, x) + ii(y−1, x) + ii(y, x−1) − ii(y−1, x−1)
            지금 칸    위쪽 누적     왼쪽 누적      두 번 더해진 겹친 부분 빼기
```

🔢 ii(2, 2) 계산:
```
 M(2,2) = 9,  ii(1,2) = 25,  ii(2,1) = 28,  ii(1,1) = 15
 ii(2,2) = 9 + 25 + 28 − 15 = 47 ✅
```

```
 ┌───────────┬───┐
 │ ii(1,1)=15 │   │   ← 위쪽 누적 ii(1,2)=25는 이 두 칸 영역
 │  (겹침)   │   │
 ├───────────┼───┤
 │           │ 9 │   ← 지금 칸
 └───────────┴───┘
  ↑ 왼쪽 누적 ii(2,1)=28은 이 세로 두 칸 영역
  겹침(15)이 위쪽과 왼쪽에 두 번 들어갔으므로 한 번 뺌
```

픽셀마다 덧셈 3번이면 되므로 **사진 한 장에 한 번만** 만들어 두면 됩니다(34.jpg라면 174,500칸).

### (다) 📐 아무 사각형의 합을 4번 조회로

사각형 (x=1, y=1, w=3, h=2)의 합을 구해 봅니다. 원본의 이 부분입니다.
```
 [ 2  6  5 ]
 [ 8  9  7 ]     직접 더하면 2+6+5+8+9+7 = 37
```

꼭짓점 네 곳의 누적합만 있으면 됩니다.

```
          x                x+w
     ┌────┬─────────────────┐
     │ ①  │       ②         │
   y ├────A─────────────────B
     │    │                 │
     │ ③  │   ④ 구하려는     │
     │    │     사각형       │
 y+h ├────C─────────────────D

 D = ①+②+③+④      B = ①+②      C = ①+③      A = ①

 ④ = D − B − C + A
     (전체에서 위쪽 빼고, 왼쪽 빼고, 두 번 빠진 ①을 한 번 더하기)
```

OpenCV의 `cv2.integral`은 **맨 위와 맨 왼쪽에 0으로 된 줄을 하나씩 덧붙인** (h+1)×(w+1) 배열을 돌려줍니다. 실측: 5×5 입력 → **(6, 6)**, dtype int32
```
 [[  0   0   0   0   0   0]
  [  0   3   4   8   9  14]
  [  0  12  15  25  31  39]
  [  0  17  28  47  60  77]
  [  0  20  33  55  76  97]
  [  0  26  41  69  94 118]]
```

0 줄 덕분에 사각형이 그림 맨 가장자리(x=0이나 y=0)에서 시작해도 "왼쪽 위 칸이 없는" 예외 처리가 필요 없습니다. 이 배열 P에서는 **꼭짓점 좌표를 그대로** 쓰면 됩니다.

```
 A = P[y,   x  ] = P[1, 1] =  3
 B = P[y,   x+w] = P[1, 4] =  9
 C = P[y+h, x  ] = P[3, 1] = 17
 D = P[y+h, x+w] = P[3, 4] = 60

 D − B − C + A = 60 − 9 − 17 + 3 = 37 ✅ (직접 더한 값과 같음)
```

### (라) 이게 왜 결정적인가

| 사각형 크기 | 직접 더하기 | 적분 영상 |
|---|---|---|
| 3×2 | 6번 | **4번 조회** |
| 16×4 (0번 특징 A, 20×20 창) | 64번 | **4번 조회** |
| 126×32 (34.jpg 얼굴 크기) | 4,032번 | **4번 조회** |

**사각형이 아무리 커도 비용이 일정합니다.** 사각형 2개짜리 특징은 조회 8번, 3개짜리는 12번으로 끝납니다.

🔢 34.jpg 얼굴 창의 0번 특징(8-3 다)도 실제로 `cv2.integral`로 계산한 결과와 직접 더한 결과가 똑같이 **+1,431**이었습니다.

> 💡 **예고:** OpenCV는 적분 영상을 하나 더 만듭니다. **픽셀 값의 제곱**의 적분 영상(`cv2.integral2`가 둘 다 돌려줌)입니다. 창 안의 Σx와 Σx²를 각각 4번 조회로 얻으면 창의 **표준편차**를 바로 구할 수 있습니다. 8-3 (라)의 💡에서 말한 "표준편차로 나누는 정규화"가 창마다 공짜에 가깝게 되는 이유입니다. 8-B에서 실제로 계산합니다.

## 🧪 직접 해 볼 실험

```python
import cv2, numpy as np
M = np.array([[3,1,4,1,5],[9,2,6,5,3],[5,8,9,7,9],[3,2,3,8,4],[6,2,6,4,3]], np.uint8)
P = cv2.integral(M)
print(P)
def rect_sum(x, y, w, h):
    return P[y+h, x+w] - P[y, x+w] - P[y+h, x] + P[y, x]
print(rect_sum(1, 1, 3, 2), M[1:3, 1:4].sum())     # 둘 다 37
print(rect_sum(0, 0, 5, 5), M.sum())               # 둘 다 118 (가장자리도 OK)
```
1. `rect_sum(2, 0, 3, 4)`를 손으로 먼저 계산한 뒤 코드로 확인해 보세요.
2. `s, sq = cv2.integral2(M)`로 제곱 적분 영상 `sq`의 마지막 칸이 `(M.astype(int)**2).sum()`과 같은지 확인해 보세요.

5. 사각형 합을 직접 더하지 않고 적분 영상으로 구할 때, 창 크기가 2배가 되면 계산량은 몇 배가 되나요?

<br>

**정답**
1. M(3,1) = 2, ii(2,1) = 28, ii(3,0) = 20, ii(2,0) = 17 → 2 + 28 + 20 − 17 = **33** ✅ (표와 일치)
2. A = P[2,2] = 15, B = P[2,4] = 31, C = P[4,2] = 33, D = P[4,4] = 76 → 76 − 31 − 33 + 15 = **27**. 검산: 9 + 7 + 3 + 8 = 27 ✅
3. A = 8~10열, **4~17행**(14줄), B = 같은 열, **11~17행**(아래쪽 7줄). 값 = 합(11~17행) − 합(4~10행). **세로 띠의 아랫부분 − 윗부분**입니다. 얼굴 가운데 세로 띠(이마~코 쪽 vs 코 아래~입)를 비교합니다.
4. A = 4~15열 (12칸 폭), B = 8~11열 (가운데 4칸 = A의 가운데 1/3). −합(A) + 3·합(B) = 2·합(가운데) − 합(양옆). 즉 **가운데 띠 vs 양옆 띠**를 비교하는 "선(line)" 특징입니다. 가운데 영역이 양옆 영역의 절반 넓이라서 가중치를 3으로 맞춰 넓이를 균형 잡았습니다. 눈 높이(2~9행)에서 미간·콧대(가운데)가 양쪽 눈(양옆)보다 밝은지를 봅니다.
5. **1배** (변하지 않음). 꼭짓점 조회 4번은 크기와 무관합니다.
