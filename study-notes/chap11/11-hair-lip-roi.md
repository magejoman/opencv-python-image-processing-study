# 📦 Step 11. 머리·입술 영역 잡기 (`detect_object`, `define_roi`)

📄 대상 코드: [haar_utils.py:28-50](../../chap11/header/haar_utils.py#L28-L50), 호출하는 곳 [07.detect_hair_lip.py:19-23](../../chap11/07.detect_hair_lip.py#L19-L23)

🎯 **목표:** 얼굴 중심 (253, 150)과 얼굴 크기 158, 이 숫자 3개만으로 **박스 4개**의 좌표를 소수점까지 계산합니다. 그리고 "입술은 중심에서 0.3h 아래"라는 비율이 실제로 맞는지 60장으로 확인합니다.

```python
def define_roi(pt, size):
    return np.ravel([pt, size]).astype(int)

def detect_object(center, face):
    w, h = face[2:4]
    center = np.array(center)
    gap1 = np.multiply((w,h), (0.45, 0.65))     # 11-2
    gap2 = np.multiply((w,h), (0.20, 0.1))

    pt1 = center - gap1                           # 11-3
    pt2 = center + gap1
    hair = define_roi(pt1, pt2-pt1)               # 11-4

    size = np.multiply(hair[2:4], (1, 0.4))       # 11-5
    hair1 = define_roi(pt1, size)
    hair2 = define_roi(pt2-size, size)

    lip_center = center + (0, h * 0.3)            # 11-6
    lip1 = lip_center - gap2
    lip2 = lip_center + gap2
    lip = define_roi(lip1, lip2-lip1)

    return [hair1, hair2, lip, hair]
```

sub-step 8개로 나눕니다. 숫자는 전부 실측입니다.

## 11-1. 박스 4개로 무엇을 하려는가

이 장의 최종 목표는 **성별 분류**입니다(Step 13). 아이디어는 아주 단순한 두 가지 가정입니다.

| 가정 | 비교할 두 영역 | 쓰는 박스 |
|---|---|---|
| ① **머리가 길면** 턱 옆까지 머리카락이 내려온다 → 윗머리와 턱 옆의 색이 비슷하다 | 윗머리 vs 귀밑머리 | `hair1` vs `hair2` |
| ② 입술 색이 얼굴 피부색과 많이 다르면(화장 등) 판단 기준을 바꾼다 | 입술 vs 얼굴 피부 | `lip` vs `hair` (+마스크) |

```
     짧은 머리                    긴 머리
      ▓▓▓▓▓▓▓  ← hair1: 머리카락    ▓▓▓▓▓▓▓  ← hair1: 머리카락
     ▓ (o o) ▓                   ▓▓(o o)▓▓
       ( ▽ )                     ▓( ▽ )▓
      ░  ‿  ░  ← hair2: 피부/배경  ▓▓  ‿  ▓▓  ← hair2: 머리카락
     → hair1 ≠ hair2             → hair1 ≈ hair2
```

반환 순서 `[hair1, hair2, lip, hair]`는 **인덱스로 쓰이므로** 바꾸면 안 됩니다. Step 12의 `calc_histo`가 `hists[0]` vs `hists[1]`, `hists[2]` vs `hists[3]`로 짝을 지어 비교합니다. 4번째 `hair`(머리 전체 박스)는 Step 12에서 마스크와 합쳐져 **얼굴 피부 영역** 역할을 합니다.

🧠 **비유: 미술 시간의 얼굴 비례법.** 얼굴을 그릴 때 "눈은 머리 높이의 절반, 입은 코와 턱 사이의 1/3 지점"처럼 **비율**로 위치를 잡습니다. 얼굴이 크든 작든 같은 비율을 쓰면 됩니다. `detect_object`는 얼굴 박스 크기(w, h)를 **자**로 삼아 모든 박스를 비율로 배치합니다.

## 11-2. 재료 준비: `w, h, center, gap1, gap2`

```python
w, h = face[2:4]                                 # face = [174, 71, 158, 158]
center = np.array(center)                        # (253, 150) → array([253, 150])
gap1 = np.multiply((w,h), (0.45, 0.65))
gap2 = np.multiply((w,h), (0.20, 0.1))
```

| 변수 | 계산 | 실측값 | 의미 |
|---|---|---|---|
| w, h | `face[2:4]` | 158, 158 (numpy int32) | 얼굴 박스 크기 = **자** |
| center | | [253, 150] | 얼굴 중심 = **기준점** |
| gap1 | (158×0.45, 158×0.65) | **(71.1, 102.7)** | 머리 박스의 반폭, 반높이 |
| gap2 | (158×0.20, 158×0.10) | **(31.6, 15.8)** | 입술 박스의 반폭, 반높이 |

`np.multiply`는 짝끼리 곱합니다(Step 2에서 본 원소별 연산). 실제 출력은 `71.10000000000001`처럼 부동소수점 꼬리가 붙지만, 아래 `astype(int)`에서 사라지므로 신경 쓰지 않아도 됩니다.

`center`를 `np.array`로 바꾸는 이유: 튜플끼리 `-`는 에러이고, `+`는 이어 붙이기가 됩니다(`(253,150) + (0,47)` → `(253, 150, 0, 47)`). numpy 배열로 바꿔야 **좌표 덧셈·뺄셈**이 됩니다.

```python

pt2 = center + gap1      # 오른쪽 아래
```

| | 계산 | 값 |
|---|---|---|
| pt1 | (253 − 71.1, 150 − 102.7) | **(181.9, 47.3)** |
| pt2 | (253 + 71.1, 150 + 102.7) | **(324.1, 252.7)** |
| pt2 − pt1 | (142.2, 205.4) | 폭, 높이 |
| `hair` | `define_roi` (11-4) | **[181, 47, 142, 205]** |

얼굴 박스와 비교하면:

## 11-4. `define_roi`: 점 + 크기 → (x, y, w, h)

```python
def define_roi(pt, size):
    return np.ravel([pt, size]).astype(int)
```

| 단계 | 값 | shape / dtype |
|---|---|---|
| `[pt, size]` | [array([181.9, 47.3]), array([142.2, 205.4])] | 배열 2개짜리 리스트 |
| `np.ravel(...)` | [181.9, 47.3, 142.2, 205.4] | **(4,)** float64 |
| `.astype(int)` | **[181, 47, 142, 205]** | (4,) int64 |

`np.ravel`은 "몇 차원이든 **한 줄로 펴라**"입니다. (2, 2) 배열 `[[181.9, 47.3], [142.2, 205.4]]`을 펴서 (4,)로 만듭니다. `np.concatenate([pt, size])`도 같은 결과입니다(실측 동일).

### (가) `astype(int)`는 반올림이 아니라 "0 쪽으로 버림"

| 값 | `astype(int)` | `np.floor` |
|---|---|---|
| 3.7 | 3 | 3 |
| −0.5 | **0** | −1 |
| −3.7 | **−3** | −4 |

양수는 소수점 아래 버림이고, **음수는 0 쪽으로** 잘립니다. 박스 좌표가 음수가 되는 경우(11-8)에 차이가 생깁니다.

### (나) 이 형식이 좋은 이유

결과가 `(x, y, w, h)` 한 덩어리라서 Step 9-5에서 본 `cv2.rectangle(img, roi, color, thickness)` 문법에 바로 넣을 수 있습니다. 07의 21~23행이 그렇게 그립니다. int64 배열이어도 잘 그려집니다(실측).

## 11-5. 윗머리 (`hair1`)와 귀밑머리 (`hair2`)

```python
size = np.multiply(hair[2:4], (1, 0.4))    # hair 폭 그대로, 높이의 40%
hair1 = define_roi(pt1, size)              # 위쪽 끝에 붙임
hair2 = define_roi(pt2 - size, size)       # 아래쪽 끝에 붙임
```

| | 계산 | 값 |
|---|---|---|
| size | (142×1, 205×0.4) | **(142, 82.0)** |
| hair1 시작점 | pt1 = (181.9, 47.3) | |
| **hair1** | | **[181, 47, 142, 82]** → y 47 ~ 129 |
| hair2 시작점 | pt2 − size = (324.1−142, 252.7−82) | (182.1, 170.7) |
| **hair2** | | **[182, 170, 142, 82]** → y 170 ~ 252 |

### (가) 40 : 20 : 40 분할

```
 hair 높이 205 = hair1 82 (40%) + 가운데 41 (20%) + hair2 82 (40%)
                 y 47~129          y 129~170         y 170~252
```

가운데 20%(y 129 ~ 170)는 **눈과 귀 높이**입니다. 보정된 두 눈이 정확히 y = 130에 있습니다(Step 10). 이 줄은 눈, 귀, 안경테가 섞여서 머리카락 판단을 흐리기 때문에 일부러 뺍니다. hair1의 아래 끝(129)이 눈 바로 위에서 끝나는 것을 보세요.

### (나) 1픽셀 어긋남: 버림의 흔적

hair1의 x는 **181**인데 hair2의 x는 **182**입니다. `size`가 정수로 잘린 `hair[2:4]` = 142(원래 142.2)에서 계산됐기 때문입니다.
```
 hair1: x = 181.9 → 181
 hair2: x = 324.1 − 142 = 182.1 → 182      (142.2를 썼다면 181.9 → 181)
```
결과에는 영향이 없는 1픽셀이지만, 정수 변환을 **중간에** 하면 이런 어긋남이 쌓인다는 좋은 예입니다. 계산은 끝까지 실수로 하고 **마지막에 한 번만** 정수로 바꾸는 게 원칙입니다.

## 11-6. 입술 (`lip`)

```python
lip_center = center + (0, h * 0.3)     # 중심에서 0.3h 아래
lip1 = lip_center - gap2               # 왼쪽 위
lip2 = lip_center + gap2               # 오른쪽 아래
lip = define_roi(lip1, lip2 - lip1)
```

| | 계산 | 값 |
|---|---|---|
| lip_center | (253 + 0, 150 + 47.4) | **(253, 197.4)** |
| lip1 | (253 − 31.6, 197.4 − 15.8) | (221.4, 181.6) |
| lip2 | (253 + 31.6, 197.4 + 15.8) | (284.6, 213.2) |
| **lip** | 크기 (63.2, 31.6) | **[221, 181, 63, 31]** → 폭 0.4w, 높이 0.2h |

`center + (0, h*0.3)`에서 `center`가 numpy 배열이라 튜플 `(0, 47.4)`와 **원소별 덧셈**이 됩니다(11-2에서 배열로 바꾼 이유).

### (가) 🔢 "0.3h 아래에 입술이 있다"는 게 사실인가

> 📚 **복습: YCrCb 색 공간.** Chapter06에서 배운 색 공간 변환 중 하나입니다. Y = 밝기, **Cr = 빨간 정도**(빨강 − 밝기), Cb = 파란 정도. 입술은 주변 피부보다 Cr이 높습니다.

보정된 34.jpg에서 얼굴 중심 아래로 한 줄씩 내려가며, 가운데 41픽셀 폭의 **평균 Cr**을 쟀습니다.

```
 y     Cr 평균
 150   139.1   ← 얼굴 중심 (코 위쪽)
 162   143.1
 168   150.4   ← 콧망울 근처
 180   144.5
 186   147.0
 191   157.6   ← ★ 최대 (입술)   ← lip 박스 181~212 안 ✅
 198   149.6
 210   148.1
 222   147.6
```

34.jpg의 Cr 최고점은 y = 191, 중심에서 41줄 아래 = **0.26h**이고, lip 박스(y 181 ~ 212) 안에 들어옵니다.

같은 측정을 60장 전부에 했습니다(Cr이 가장 높은 줄 ÷ h).

| 통계 | 값 |
|---|---|
| **중앙값** | **0.302** |
| 가운데 50% 범위 | 0.26 ~ 0.333 |
| 0.2 미만 (측정 실패로 보임) | 8장 |

중앙값이 **0.302**로, 코드의 0.3과 거의 정확히 맞습니다. 0.2 미만으로 나온 8장은 콧망울이나 볼의 붉은 기가 입술보다 높게 잡힌 경우라서, 박스가 틀렸다기보다 **이 간단한 측정법의 한계**입니다. 박스 높이가 ±0.1h(=15.8px)라서 0.2 ~ 0.4 범위는 박스가 덮습니다.

## 11-8. ⚠️ 함정: 박스가 사진 밖으로 나가면

### (가) 60장에서는 아슬아슬하게 통과

머리 박스(hair)가 사진 경계와 얼마나 떨어져 있는지 60장 전부 쟀습니다.

| 방향 | 가장 가까운 사진 | 여유 |
|---|---|---|
| **위** | **25번** (얼굴 w = 162) | **2픽셀** 😰 |
| 아래 | 8번 | 39픽셀 |
| 왼쪽 | 17번 | 59픽셀 |
| 오른쪽 | 38번 | 41픽셀 |

60장 모두 안쪽에 들어왔지만, 25번은 2픽셀 차이였습니다. 얼굴이 사진 위쪽에 조금만 더 붙어 있었다면 터졌습니다.

### (나) 🔢 밖으로 나가면 무슨 일이: 34.jpg로 일부러 재현

얼굴 박스를 `[174, 10, 158, 158]`(위로 61px 올림)로 가정하고 같은 계산을 돌렸습니다.

```
 face_center = (253, 89)
 pt1.y = 89 − 102.7 = −13.7  →  astype(int) → −13       (11-4: 0 쪽으로 버림)
 hair1 = [181, −13, 142, 82]
```

이제 Step 12에서 `image[y:y+h, x:x+w]`로 잘라냅니다.

```
 image[-13:69, 181:323]
       └── 파이썬은 -13을 "뒤에서 13번째" = 349 − 13 = 336 으로 해석
 → image[336:69, ...]    시작(336) > 끝(69) → 빈 배열
 → shape (0, 142, 3)     ← 에러 없이 빈 영상!
```

그다음 연쇄 반응(실측):

| 단계 | 결과 |
|---|---|
| 빈 영상의 히스토그램 | 모든 칸이 0 |
| 정규화 `h / np.sum(h)` | 0 / 0 = **NaN** (`RuntimeWarning` 하나만 출력) |
| `cv2.compareHist(NaN 히스토그램, ...)` | **1.0** 😱 |
| 반환된 유사도 | **(1.0, 1.0)** = "완벽하게 같다" |

`compareHist`의 CORREL 계산에는 "분모가 0에 가까우면 1을 돌려준다"는 분기(`if abs(분모) > ε ... else 1`)가 있습니다. NaN과의 비교는 항상 거짓이라 이 분기로 빠져서 **1.0**이 나옵니다. 즉 프로그램은 죽지 않고, 경고 한 줄과 함께 **"윗머리와 귀밑머리가 완벽하게 같다 → 긴 머리 → 여성"**이라는 **틀린 답을 조용히** 냅니다. 에러로 죽는 것보다 훨씬 나쁜 버그입니다.

### (다) 고치는 법: 박스를 사진 안으로 자르기

```python
def clip_roi(roi, shape):
    H, W = shape[:2]
    x, y, w, h = roi
    x0, y0 = max(x, 0), max(y, 0)
    x1, y1 = min(x + w, W), min(y + h, H)
    return np.array([x0, y0, x1 - x0, y1 - y0])
```
위 예에서 `[181, −13, 142, 82]` → **`[181, 0, 142, 69]`**. 잘린 뒤 크기가 0이 되는 경우(박스 전체가 밖)에는 아예 "판단 불가"로 처리해야 합니다.

### (라) 그 밖의 가정들

- **원래 얼굴 박스를 보정된 사진에 그대로 씀:** Step 10에서 얼굴 중심을 회전 중심으로 했으므로 중심이 그대로이고, 회전해도 얼굴 크기는 같아서 문제없습니다. 보정 후 다시 검출한 박스 [180, 74, 149, 149]의 중심 (254, 148)과도 거의 같습니다.
- **비율은 이 검출기 전용:** 0.45, 0.65, 0.3은 `haarcascade_frontalface_alt2`가 그리는 박스 모양에 맞춘 값입니다. MediaPipe 같은 다른 검출기는 박스를 이마까지 더 크게 잡는 등 규칙이 달라서 비율을 다시 맞춰야 합니다. 요즘은 박스 비율 대신 **얼굴 랜드마크**(입술 윤곽 점 20여 개)로 입술 위치를 직접 받는 방식을 씁니다.
