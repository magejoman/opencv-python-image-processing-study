# ✏️ Step 4. 마우스 상태 기계와 도형 그리기 ⭐ Part A의 핵심

📄 대상 코드: [04.draw_command.py](../../chap11/04.draw_command.py)

🎯 **목표:** 마우스를 누르고, 끌고, 떼는 동안 30ms마다 화면에 무엇이 그려지는지 **프레임 단위로** 예측할 수 있게 되기

이번에도 GUI 없이 이벤트와 메인 루프 한 바퀴(프레임)를 번갈아 직접 실행해서 변수 값을 찍었습니다. 아래 추적표는 전부 실측입니다.

04에서 새로 생긴 코드는 크게 두 덩어리입니다.

```python
def draw(image, color=(200, 200, 200)):            # ① 도형 그리기 담당
    global draw_mode, thickness, pt1, pt2
    if   draw_mode == DRAW_RECTANGLE: cv2.rectangle(image, pt1, pt2, color, thickness)
    elif draw_mode == DRAW_LINE:      cv2.line(image, pt1, pt2, color, thickness)
    elif draw_mode == DRAW_BRUSH:
        cv2.line(image, pt1, pt2, color, thickness * 3)
        pt1 = pt2
    elif draw_mode == ERASE:
        cv2.line(image, pt1, pt2, (255, 255, 255), thickness * 5)
        pt1 = pt2
    elif draw_mode == DRAW_CIRCLE:
        d = np.subtract(pt1, pt2)
        radius = int(np.sqrt(d[0] ** 2 + d[1] ** 2))
        cv2.circle(image, pt1, radius, color, thickness)
    elif draw_mode == DRAW_ECLIPSE:
        center = np.abs(np.add(pt1, pt2)) // 2
        size = np.abs(np.subtract(pt1, pt2)) // 2
        cv2.ellipse(image, center, size, 0, 0, 360, color, thickness)
    cv2.imshow("PaintCV", image)

while True:                                          # ② 메인 루프 (30ms마다 한 바퀴)
    if mouse_mode == 1:                              #   뗐음 → 확정
        draw(image, Color)
    elif mouse_mode == 3:                            #   끄는 중
        if draw_mode == DRAW_BRUSH or draw_mode == ERASE:
            draw(image, Color)                       #     브러시/지우개는 바로 원본에
        else:
            draw(np.copy(image), (200, 200, 200))    #     나머지는 복사본에 회색 미리보기
    if cv2.waitKey(30) == 27:                        #   ESC면 종료
        break
```

여기에 Step 3에서 본 `onMouse`(줄 순서가 바뀐 버전)가 합쳐집니다. sub-step 8개로 나눠서 봅니다.

## 4-1. 🆕 상태 기계(State Machine)

### (가) 개념

🧠 **비유: 신호등.** 신호등은 항상 **딱 하나의 상태**(빨강/노랑/초록)에 있습니다. 정해진 사건(시간 경과, 버튼)이 생기면 정해진 다음 상태로 **넘어갑니다.** 지금 무엇을 할지는 **현재 상태만 보고** 정합니다.

이 그림판에서 그 "현재 상태"를 담는 변수가 `mouse_mode`입니다.

| mouse_mode | 이름 (제가 붙인 것) | 의미 | 메인 루프가 하는 일 |
|---|---|---|---|
| **0** | 대기 | 아무 일도 없음 | 아무것도 안 함 |
| **1** | 확정 | 그림 영역에서 버튼을 뗐다 | `Color`로 **원본에** 그림 |
| **2** | (경유) | 방금 눌렀다 | — (같은 함수 안에서 즉시 0이나 3으로 바뀜) |
| **3** | 드래그 | 그림 영역에서 누른 채 움직이는 중 | 미리보기 (브러시/지우개는 바로 원본에) |

### (나) 🖼️ 상태 전이 다이어그램

```
                         DOWN, x<125 (메뉴 위에서 누름)
                    ┌────────────────────────────────────┐
                    │                                    ▼
              ┌───────────┐   DOWN, x≥125         ┌───────────┐
   ┌─────────▶│  0  대기  │──────────────────────▶│ 3 드래그  │◀──┐
   │          └───────────┘    (2를 거쳐 3)        └───────────┘   │ MOVE, x≥125
   │            ▲     ▲   │                         │   │   └──────┘ (pt2 갱신)
   │            │     │   │ UP, 메뉴 아님           │   │
   │  UP, 도구  │     │   ▼                         │   │ MOVE, x<125
   │  아이콘    │     │ ┌───────────┐  UP, 메뉴 아님 │   │ (메뉴로 들어감)
   │  (i<6)     │     │ │  1  확정  │◀───────────────┘   │
   │            │     │ └───────────┘                    │
   │            │     │      │  DOWN                     │
   │            │     │      └──────▶ (0 또는 3으로)     │
   │            │     └──────────────────────────────────┘
   │            │
   └────────────┴──── (메뉴 클릭(command)은 상태를 바꾸지 않음)
```

중요한 전이만 문장으로 정리하면:
- **그림 영역에서 누르면** → 3(드래그)
- **드래그 중 움직이면** → 3 유지, `pt2`만 계속 갱신
- **그림 영역에서 떼면** → 1(확정)
- **메뉴 위에서 누르면** → 0
- **드래그 중 메뉴(x<125)로 들어가면** → 0 (미리보기 취소)

## 4-2. 분업 구조: 콜백은 메모만, 루프가 요리

🧠 **비유: 식당.**
- **웨이터(onMouse 콜백):** 손님(마우스)의 주문을 받아 **주문서(전역변수 `mouse_mode`, `pt1`, `pt2`)에 적기만** 합니다. 직접 요리하지 않습니다.
- **주방(while 루프):** 30ms마다 주문서를 보고, 적힌 대로 요리(그리기)해서 손님에게 내놓습니다(`imshow`).

```
 ┌─ onMouse (이벤트가 올 때만) ─┐         ┌─ while 루프 (30ms마다 계속) ──────┐
 │ mouse_mode, pt1, pt2 갱신     │  ───▶   │ mouse_mode 보고 draw(...) 호출    │
 │ (그리기는 안 함)              │ 전역변수 │ cv2.waitKey(30) ← 여기서 이벤트 처리│
 └───────────────────────────────┘         └───────────────────────────────────┘
```

**왜 이렇게 나눴나?**
1. **미리보기는 계속 다시 그려야 합니다.** 마우스를 멈춰도 화면에 회색 사각형이 떠 있어야 하는데, 마우스를 멈추면 이벤트가 안 옵니다. 루프가 주기적으로 그려야 유지됩니다.
2. **콜백은 짧게 끝내는 게 원칙입니다.** 콜백이 오래 걸리면 다음 이벤트 처리가 밀려서 화면이 버벅입니다.

`cv2.waitKey(30)`은 여기서 두 가지 역할을 합니다. ① 최대 30ms 쉬면서 **그동안 들어온 마우스 이벤트를 처리**하고(이때 `onMouse`가 불림), ② 키가 눌렸으면 그 키 코드를 돌려줍니다. 그래서 루프는 대략 **초당 최대 33번** 돕니다.

> 💡 30ms 사이에 MOUSEMOVE 이벤트가 여러 번 와도 루프가 보는 건 **마지막 `pt2` 하나뿐**입니다. 이 사실이 4-6 브러시에서 중요해집니다.

## 4-3. `x < 125` 가드: 메뉴 위에서는 그리지 않기

```python
if mouse_mode >= 2:                       # 방금 눌렀거나(2) 드래그 중(3)
    mouse_mode = 0 if x < 125 else 3
    pt2 = (x, y)
```

메뉴 폭은 120인데 기준이 125인 이유는 **5픽셀 여유**를 둔 것입니다. 메뉴 경계 바로 옆에서 시작한 도형이 메뉴를 살짝 덮는 일을 줄입니다.

🔢 **실측: 그림 영역에서 메뉴 쪽으로 끌고 들어가면**

| 이벤트 | mode | pt1 | pt2 | 프레임 동작 |
|---|---|---|---|---|
| DOWN (300,200) | **3** | (300,200) | (300,200) | 회색 미리보기 |
| MOVE (200,200) | **3** | (300,200) | (200,200) | 회색 미리보기 |
| MOVE (100,200) | **0** ← x<125 | (300,200) | (100,200) | **아무것도 안 함** (미리보기 사라짐) |
| UP (100,200) | 0 | | | (100,200)은 save 아이콘(i=7) 적중 → `command(7)` → 04에선 아무 일 없음 |

메뉴로 들어가는 순간 드래그가 **취소**됩니다. 다시 그림 영역으로 나와도 mode가 0이라 미리보기가 돌아오지 않습니다. 0에서는 [C] 블록이 실행되지 않기 때문입니다.

## 4-5. 러버밴드 미리보기: 왜 `np.copy(image)`에 그리나

`draw(np.copy(image), (200, 200, 200))`가 하는 일을 순서대로 보면:

```
 ① np.copy(image)        → 원본과 똑같은 새 배열(1.2MB)을 만든다
 ② 그 복사본에 회색 도형을 그린다
 ③ cv2.imshow로 복사본을 화면에 띄운다
 ④ 함수가 끝나면 복사본은 버려진다 (원본은 깨끗)
```

**만약 복사하지 않고 원본에 회색으로 그리면?** 드래그 중에 그려진 모든 중간 사각형이 원본에 **남습니다.**

```
 copy 사용 (실제 코드)          원본에 바로 그리면 (가상)
 ┌──────────┐                   ┌──┬───┬────┬─────┐
 │          │                   │  │   │    │     │   ← 프레임마다 그린
 │          │                   ├──┘   │    │     │      사각형이 다 쌓임
 │          │                   ├──────┘    │     │
 └──────────┘                   ├───────────┘     │
  마지막 것만 보임               └─────────────────┘
```

🧠 **비유: 투명 필름.** 원본 그림 위에 투명 필름을 한 장 얹고 거기에 연필로 그려 보는 겁니다. 마음에 안 들면 필름을 버리고 새 필름을 얹습니다. 30ms마다 필름을 새로 갈아 끼우는 셈입니다.

비용은 30ms마다 1.2MB 복사입니다. 요즘 컴퓨터에서는 눈에 띄지 않는 수준입니다.

**브러시와 지우개는 왜 예외인가?** 브러시는 **지나간 자국 전체가 결과물**입니다. 미리보기 후 확정하는 방식이 성립하지 않으므로, 드래그 중에도 바로 원본에 그립니다.

## 4-6. 📐 도형별 수학

드래그로 얻는 정보는 **두 점** `pt1`(누른 곳)과 `pt2`(현재/뗀 곳)뿐입니다. 도형마다 이 두 점을 어떻게 해석하는지가 다릅니다. 예시는 계속 pt1 = (200,100), pt2 = (300,180)입니다.

### (가) 사각형과 직선: 두 점을 그대로 사용

| 도형 | 두 점의 의미 | 호출 |
|---|---|---|
| 사각형 | **대각선의 양 끝** 꼭짓점 | `cv2.rectangle(img, (200,100), (300,180), …)` |
| 직선 | 선분의 양 끝 | `cv2.line(img, (200,100), (300,180), …)` |

### (나) 원: pt1 = 중심, 두 점 사이 거리 = 반지름

```python
d = np.subtract(pt1, pt2)                       # (200-300, 100-180) = (-100, -80)
radius = int(np.sqrt(d[0]**2 + d[1]**2))
```

📐 **피타고라스 정리:**
```
            pt2 (300,180)
              ●
             ╱│
       r    ╱ │ 80  (= |dy|)
           ╱  │
          ●───┘
     pt1 (200,100)
          100 (= |dx|)

 r = √(100² + 80²) = √(10000 + 6400) = √16400 = 128.06…  → int → 128
```
실측: `d = [-100, -80]`, `r = 128.06248…`, `int → 128` ✅

d가 음수여도 제곱하면 양수가 되므로 **끄는 방향은 상관없습니다.**

```
            ╭───────────╮
          ╭─╯           ╰─╮
         │       ● pt1    │──── 반지름 128
          ╰─╮      ╲    ╭─╯
            ╰───────●───╯
                    pt2 (원 둘레 위의 점)
```

### (다) 타원: 두 점 = 타원을 감싸는 사각형의 대각선

```python
center = np.abs(np.add(pt1, pt2)) // 2          # 중점
size   = np.abs(np.subtract(pt1, pt2)) // 2     # 가로·세로 반지름
cv2.ellipse(image, center, size, 0, 0, 360, color, thickness)
```

| 계산 | 식 | 값 |
|---|---|---|
| 더하기 | (200+300, 100+180) | (500, 280) |
| 중점 `center` | (500, 280) // 2 | **(250, 140)** |
| 빼기 | (200−300, 100−180) | (−100, −80) |
| abs | | (100, 80) |
| 반축 `size` | (100, 80) // 2 | **(50, 40)** |

```
 (200,100) ┌─────────────────┐
           │   ╭─────────╮   │
           │  │  ●center  │  │  ← 가로 반지름 50, 세로 반지름 40
           │   ╰─────────╯   │
           └─────────────────┘ (300,180)
```

`cv2.ellipse(img, 중심, (가로반지름, 세로반지름), 회전각, 시작각, 끝각, 색, 두께)`에서 `0, 0, 360`은 "회전 없이, 0°부터 360°까지 = 한 바퀴 전부"라는 뜻입니다.

반대로 끌어도(pt1 = (300,180), pt2 = (200,100)) 실측 결과가 똑같이 center (250,140), size (50,40)입니다. 반축 쪽은 `abs`가 음수를 없애 주기 때문입니다. 반면 `np.add` 결과는 원래 양수라서 center 쪽의 `abs`는 사실상 하는 일이 없습니다.

> 💡 실측에서 `center`는 `int64` numpy 배열이었는데 `cv2.ellipse`가 문제없이 받았습니다. Step 3-5에서 **색**은 numpy를 거부했던 것과 다릅니다. OpenCV 파이썬 바인딩이 점/크기와 색(Scalar)을 다르게 변환하기 때문입니다. 헷갈리면 "색은 항상 파이썬 int 튜플"로 외워 두면 됩니다.

### (라) 브러시: 짧은 직선을 이어 붙이기 + `pt1 = pt2`

```python
cv2.line(image, pt1, pt2, color, thickness * 3)   # 두께 9
pt1 = pt2                                          # 끝점을 다음 시작점으로
```

🧠 **비유: 점 잇기 그림.** 매 프레임 "지난번 위치 → 지금 위치"로 선을 하나 긋고, 지금 위치를 다음 출발점으로 기억합니다. 짧은 선분이 이어지면 곡선처럼 보입니다. 미적분에서 곡선을 짧은 직선 조각의 합으로 근사하는 것과 같은 원리입니다.

🔢 **실측 추적** (브러시 아이콘 클릭 후, (200,300)에서 누르고 오른쪽 아래로 끌기):

| # | 무슨 일 | mode | 프레임 전 pt1 | pt2 | 그려진 선분 | 프레임 후 pt1 | 바뀐 픽셀 |
|---|---|---|---|---|---|---|---|
| 1 | DOWN (200,300) | 3 | (200,300) | (200,300) | | | |
| 2 | [프레임] | 3 | (200,300) | (200,300) | 길이 0 → **점** | (200,300) | 81 |
| 3 | MOVE (210,300) | 3 | | (210,300) | | | |
| 4 | MOVE (220,305) | 3 | | (220,305) | | | |
| 5 | [프레임] | 3 | (200,300) | (220,305) | (200,300)→(220,305) | **(220,305)** | 227 |
| 6 | MOVE (260,320) | 3 | | (260,320) | | | |
| 7 | [프레임] | 3 | (220,305) | (260,320) | (220,305)→(260,320) | **(260,320)** | 475 |
| 8 | UP (260,320) | **1** | | (260,320) | | | |
| 9 | [프레임] | 1 | (260,320) | (260,320) | 길이 0, 이미 칠한 자리 | (260,320) | 0 |

#3의 (210,300)은 #4가 오기 전에 프레임이 돌지 않아서 **건너뛰어졌습니다.** 루프는 (200,300)에서 (220,305)로 바로 직선을 긋습니다(4-2의 💡). 그래서 **마우스를 아주 빨리 휘두르면 브러시 선이 각진 꺾은선**처럼 보입니다.

`pt1 = pt2`를 바꿔야 하므로 `draw()` 맨 위에 `global pt1`이 꼭 필요합니다(Step 3-7 규칙: 대입하면 global 필요).

### (마) 지우개: 흰색으로 칠하는 굵은 브러시

```python
cv2.line(image, pt1, pt2, (255, 255, 255), thickness * 5)    # 두께 15, 색 인자 무시
```

원리는 브러시와 똑같고, 색이 항상 흰색이며 더 굵을 뿐입니다. 진짜로 "지우는" 게 아니라 **흰 물감으로 덮는** 겁니다. 그래서 Step 5에서 사진을 불러온 뒤 지우개를 쓰면 사진이 하얗게 칠해집니다.

| 도구 | 두께 (thickness=3일 때) | 색 |
|---|---|---|
| 사각형/원/타원/직선 | 3 | Color |
| 브러시 | 9 | Color |
| 지우개 | 15 | 항상 (255,255,255) |

## 4-7. 🔍 `mouse_mode == 1`은 계속 유지됩니다

4-4 표의 #8과 #9를 다시 보세요. 떼고 나서 **mode가 1인 채로 남아서**, 매 프레임 같은 사각형을 원본에 **또 그립니다.** 그런데 이미 칠해진 픽셀을 같은 색으로 다시 칠하니 **바뀌는 픽셀이 0개**입니다(실측). 그래서 눈에는 아무 문제가 없어 보입니다.

같은 작업을 몇 번 반복해도 결과가 같은 성질을 **멱등성(idempotent)**이라고 합니다. 엘리베이터 버튼을 여러 번 눌러도 한 번 누른 것과 같은 것과 비슷합니다.

이 상태는 다음 DOWN이 올 때까지 계속되고, 숨어 있던 부작용이 Step 5에서 드러납니다.
- **CLEAR**로 캔버스를 지워도 다음 프레임에 마지막 도형이 **다시 그려집니다.**
- **트랙바**로 두께를 바꾸면 마지막 도형이 **새 두께로 덧그려집니다.**

그래서 05의 CLEAR와 트랙바 콜백에 `mouse_mode = 0`이 들어갑니다.

## 4-8. ⚠️ 시뮬레이션으로 찾은 04의 문제 두 가지

### (가) 메뉴에서 누르고 그림 영역에서 떼면 메뉴 위에 도형이 그려짐

🔢 실측 (사각형 도구, (30,30)=rect 아이콘에서 누르고 (400,300)에서 뗌):

| 이벤트 | mode | pt1 | pt2 | 결과 |
|---|---|---|---|---|
| DOWN (30,30) | 2 → **0** (x<125) | **(30,30)** ← 메뉴 안 | (30,30) | |
| MOVE (300,200) | 0 | | | mode 0이라 무시 |
| UP (400,300) | 메뉴 적중 없음 → **1** | (30,30) | (400,300) | |
| [프레임] | 1 | | | (30,30)~(400,300) 사각형 확정. **메뉴 영역 2040픽셀 덮임** |

원인: DOWN 때 x<125 가드가 `mouse_mode`는 0으로 바꾸지만 **`pt1`은 이미 메뉴 좌표로 기록된 뒤**입니다. 그리고 UP 블록은 "누를 때 메뉴였는지"를 확인하지 않고 무조건 1로 만듭니다.

고치는 방법 중 하나: UP 블록에서 `if mouse_mode == 3:`일 때만 `mouse_mode = 1`로 바꾸기 (드래그 상태에서 뗀 경우만 확정). 05에도 이 문제는 그대로 남아 있습니다.

### (나) `command()`의 창 이름 오타

[04.draw_command.py:15](../../chap11/04.draw_command.py#L15):
```python
cv2.imshow("paintCV", image)     # ← 소문자 p
```
메인 창 이름은 `"PaintCV"`입니다. OpenCV는 창 이름 문자열로 창을 구분하므로 이름이 다르면 **다른 창**으로 취급합니다. 시뮬레이션에서도 팔레트 클릭 시 `imshow`가 `'paintCV'`로 불렸습니다. 그래서 04에서 팔레트를 클릭하면:
- **새 창 "paintCV"**가 하나 더 뜨고 거기에 바뀐 색 아이콘이 보입니다.
- 메인 창은 다음에 무언가를 그릴 때까지 색 아이콘이 갱신되지 않습니다.

[05.PaintCV.py:89](../../chap11/05.PaintCV.py#L89)에서는 `"PaintCV"`로 고쳐져 있습니다.
