## 13-1. 규칙 두 줄을 판단 나무로

```python
def classify(image, sims, no):
    criteria = 0.25 if sims[0] > 0.2 else 0.1     # 얼굴-입술: 비슷하면(큰값) 남자
    value = sims[1] > criteria
    text = "Woman" if value else "Man"
```

`sims[0]` = sim1 (입술-피부), `sims[1]` = sim2 (윗머리-귀밑머리)입니다.

```
                       sim1 (입술-피부) > 0.2 ?
                     ┌──────────┴──────────┐
                   예 (입술≈피부)        아니오 (입술≠피부, 화장?)
                     │                     │
            기준 = 0.25 (엄격)        기준 = 0.1 (느슨)
                     │                     │
            sim2 > 0.25 ?            sim2 > 0.1 ?
             ┌────┴────┐             ┌────┴────┐
           Woman      Man          Woman      Man
```

해석:
- **주 판단은 머리카락**(sim2)입니다. 윗머리와 귀밑머리 색이 닮았으면 긴 머리 → Woman.
- **입술은 기준을 조절**합니다. 입술 색이 피부와 확연히 다르면(sim1 ≤ 0.2, 립스틱 가능성) 머리카락 기준을 0.1로 낮춰 Woman 쪽으로 기울이고, 입술이 피부와 비슷하면 0.25로 올려 Man 쪽으로 기울입니다.

🧠 **비유: 면접관 두 명.** 머리카락 면접관이 점수를 매기고, 입술 면접관은 "합격선을 올릴지 내릴지"만 정합니다. 입술 면접관 혼자서는 결과를 정하지 못합니다.

## 13-4. 09의 키보드 루프

```python
no, max_no, cnt = 0, 60, 1
while True:
    no = no + cnt
    image, gray = preprocessing(no)
    if image is None:
        print("%02d.jpg: 영상 파일 없음" % no)
        if no < 0 : no = max_no
        elif no >= max_no: no = 0
        continue
    ... (Step 7 ~ 13 전체 파이프라인) ...
    key = cv2.waitKeyEx(0)
    if key == 2490368: cnt =  1          # ↑ 다음
    elif key == 2621440: cnt = -1        # ↓ 이전
    elif key == 32 or key == 27: break   # Space, ESC 종료
```

### (가) 2490368과 2621440은 어디서 온 숫자인가

```
 2490368 = 0x260000 = 0x26 << 16      0x26 = Windows 가상 키 코드 VK_UP
 2621440 = 0x280000 = 0x28 << 16      0x28 = VK_DOWN
```

Windows에서 `waitKeyEx`는 화살표 같은 특수 키를 "가상 키 코드를 16비트 왼쪽으로 민 값"으로 돌려줍니다. 일반 `waitKey`는 OpenCV 3.2부터 **아래 8비트만**(`& 0xFF`) 돌려주므로 `0x260000 & 0xFF = 0`이 되어 위·아래 화살표를 구분할 수 없습니다. 그래서 `waitKeyEx`를 씁니다. 이 숫자는 **Windows 전용**입니다. Linux(GTK)에서는 65362(↑), 65364(↓) 같은 다른 값이 나오므로 이 코드는 다른 OS에서 화살표가 안 먹힙니다.

### (나) 🔢 번호가 실제로 어떻게 움직이나

| 상황 | 계산 | 결과 |
|---|---|---|
| 프로그램 시작 | no = 0 + 1 = **1** | **01.jpg** ← 00이 아님! |
| ↑로 59까지 간 뒤 ↑ | 59 + 1 = 60 → 파일 없음 → no = 0 → continue → 0 + 1 = 1 | **01.jpg** ← 00을 또 건너뜀 |
| 01에서 ↓ | 1 − 1 = 0 | 00.jpg |
| 00에서 ↓ | 0 − 1 = −1 → `'%02d' % -1` = `'-1'` → `images/face/-1.jpg` 없음 → "-1.jpg: 영상 파일 없음" 출력 → no = 60 → 60 − 1 | **59.jpg** |

**00.jpg는 ↓로 내려갈 때만 볼 수 있습니다.** 시작할 때도, 위로 한 바퀴 돌 때도 건너뜁니다. 그리고 경계를 넘을 때마다 "영상 파일 없음"이 한 줄씩 찍힙니다.

깔끔하게 고치면:
```python
no, max_no, cnt = -1, 60, 1
while True:
    no = (no + cnt) % max_no       # 60 → 0,  -1 → 59  (파이썬 %는 음수도 양수로 돌려줌)
```

### (다) 그 밖의 동작

- 화살표·Space·ESC가 아닌 키(예: Enter)를 누르면 `cnt`가 그대로라서 **마지막 방향으로 한 장** 더 갑니다.
- 얼굴이나 눈을 못 찾으면 메시지만 찍고 `imshow`를 안 하므로, **창에는 이전 사진이 그대로** 남은 채 키를 기다립니다. 60장은 전부 검출에 성공해서 이 상황은 생기지 않습니다(Step 9).

## 13-7. 입술 규칙은 도움이 되나, 그리고 96.7%를 믿어도 되나

### (가) 머리카락만 쓰면?

sim2 하나에 기준선 하나만 쓰는 가장 단순한 규칙으로 가장 좋은 기준값을 찾아봤습니다.

| 규칙 | 최선의 오답 | 틀리는 사진 |
|---|---|---|
| sim2 > t 하나만 (t = 0.168 ~ 0.2085) | 3장 | 38, 39, 40 |
| **코드의 규칙** (입술로 기준 조절) | **2장** | 39, 40 |

입술 규칙이 살린 사진은 **38번 하나**입니다. 38번은 빨간 립스틱이 뚜렷해서 sim1 = 0.07 → 느슨한 기준 0.1 → sim2 = 0.169로 Woman이 됩니다. 머리카락만 보면 0.169는 남성 6/23번(0.168), 14번(0.18)과 섞여 있어서 구분이 안 됩니다.

다만 13-5 표에서 sim1 평균은 오히려 **여성이 더 높습니다**(0.253 vs 0.206). "입술이 피부와 비슷하면 남자"라는 코드 주석의 가정이 데이터 전체로는 뒷받침되지 않고, 립스틱이 뚜렷한 일부 사진에서만 효과가 있습니다.

### (b) 기준값을 조금씩 흔들어 보면

| 바꾼 값 | 오답 사진 |

| 갈림길 0.15 ~ 0.20 | 39, 40 (그대로) |
| 갈림길 0.22 | 39, 40 + **14** |

### (다) ⚠️ 96.7%는 "시험 문제로 공부한 점수"

기준값 0.2, 0.25, 0.1은 이 60장을 보면서 정했을 가능성이 높습니다. **같은 사진으로 기준을 정하고 같은 사진으로 채점**했으니, 처음 보는 사진에서는 이보다 낮게 나온다고 봐야 합니다. 게다가 같은 사진이 3쌍 들어 있습니다.

🧠 **비유:** 기출문제 60개로 공부하고, 시험도 그 60개로 본 점수입니다. 실력을 재려면 **처음 보는 문제**(기준을 정할 때 쓰지 않은 사진)로 따로 채점해야 합니다. 머신러닝에서 데이터를 학습용과 시험용으로 나누는 이유가 이것입니다.

## 13-8. 이 방식의 한계, 그리고 요즘은

### (가) 가정 자체의 한계

이 분류기는 사실 **"긴 머리 검출기"**입니다. 다음 경우에는 구조적으로 틀립니다.

| 경우 | 결과 |
|---|---|
| 짧은 머리 여성 | Man |
| 긴 머리 남성 | Woman |
| 배경색이 머리카락과 비슷함 (14번처럼) | Woman 쪽으로 기움 |
| 한쪽에 그림자, 조명 변화 (39번) | Man 쪽으로 기움 |
| 모자, 후드, 목도리 (40번 스웨터처럼) | 예측 불가 |

이 60장에서 96.7%가 나온 큰 이유는 **데이터가 가정에 맞게 골라져 있기 때문**입니다. 여성 29명이 전부 긴 머리, 남성 31명이 전부 짧은 머리입니다.

### (나) 요즘 방식

요즘은 사람이 "머리카락 박스"를 설계하지 않고, 수만~수백만 장의 얼굴로 **CNN**을 학습시켜 특징을 스스로 찾게 합니다. 정확도는 훨씬 높지만, 학습 데이터의 인구 구성에 따라 특정 집단에서 오류가 커지는 **편향** 문제가 잘 알려져 있습니다. 또 겉모습으로 추정한 성별이 그 사람의 실제 성별과 같다는 보장도 없습니다. 이런 이유로 Microsoft는 2022년에 Azure Face 서비스에서 얼굴로 성별을 추정하는 기능을 중단했습니다. 이 장의 성별 분류는 **히스토그램 비교 기법을 연습하는 예제**로 받아들이는 게 맞습니다.

> 🚗 **AVM 연결:** 이 장의 흐름, 즉 "검출 → 기하 보정 → 비율로 ROI → 히스토그램 비교 → 손으로 정한 기준값"은 초기 주차 칸 점유 판단과 거의 같은 구조입니다(예: 칸 안쪽 ROI의 색 히스토그램이 빈 아스팔트와 닮았으면 '빈 칸'). 그리고 실패 방식도 같습니다. 39번의 그림자는 주차장 기둥 그림자, 14번의 어두운 배경은 검은 차량과 젖은 노면입니다. 그래서 실무에서는 ① 기준값을 정한 데이터와 **다른 주행 기록**(낮·밤·비·지하주차장)으로 검증하고, ② 결국 학습 기반 분류기로 옮겨 갑니다.

<br>

**정답**
1. sim1 0.15 ≤ 0.2 → 기준 0.1 → 0.12 > 0.1 → **Woman**. sim1 0.25 > 0.2 → 기준 0.25 → 0.12 ≤ 0.25 → **Man**. sim2가 같아도 입술 값에 따라 판정이 갈립니다.
2. 윗머리와 귀밑머리의 **밝기**가 달라지면 같은 머리카락이라도 64칸 히스토그램의 다른 칸에 들어가서 sim2가 낮아지기 때문입니다(39번: 아래쪽이 약 2배 어두움 → 0.068).
3. 시작 = 01.jpg → ↓ → 00.jpg → ↓ → no = −1 → 콘솔에 **"-1.jpg: 영상 파일 없음"** → no = 60 → **59.jpg**.
4. `waitKey`는 아래 8비트만 돌려주는데 `0x260000 & 0xFF = 0`, `0x280000 & 0xFF = 0`이라 두 화살표가 둘 다 0이 되어 구분할 수 없습니다.
5. ① 기준값을 정한 바로 그 60장으로 채점해서 점수가 부풀려졌습니다(학습 데이터 = 시험 데이터, 게다가 중복 3쌍). ② 데이터가 "여성 = 긴 머리, 남성 = 짧은 머리"로 골라져 있어서 가정에 맞지 않는 사진(짧은 머리 여성 등)이 하나도 없습니다.
