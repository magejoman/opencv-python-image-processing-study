## 6-2. 개념 지도: Step별로 배운 것

| Step | 핵심 개념 | 한 줄 요약 | 대표 코드 |
|---|---|---|---|
| 1 | 좌표계, ROI, 브로드캐스팅 | numpy는 `[y,x]`, OpenCV는 `(x,y)`, 크기는 `(w,h)` | `image[y:y+h, x:x+w]` |
| 1 | 튜플 반복 | `(60,60)*2` = `(60,60,60,60)` | `np.multiply(icons, size*2)` |
| 2 | **HSV** | H=물감 종류(0~179), S=진하기, V=조명 | `cv2.COLOR_HSV2BGR` |
| 2 | 3줄 규칙 | 최대=V, 최소=V(1−S/255), 나머지는 H가 결정 | — |
| 2 | dtype 함정 | float64는 에러, float32는 H 0~360 규칙 | `.astype('uint8')` |
| 2 | 인덱스=명령 번호 | 사각형 목록의 순서가 곧 기능 번호 | `icons[PALETTE]` |
| 3 | **콜백** | OpenCV가 waitKey 안에서 대신 불러줌 | `setMouseCallback` |
| 3 | Hit-test | 반만 열린 구간 `x0 ≤ x < x0+w` | `for i, (x0,y0,w,h) in enumerate(icons)` |
| 3 | 좌표 뒤집기 | `(x,y)[::-1]` → `(y,x)` | `image[pt2[::-1]]` |
| 3 | 색 타입 | OpenCV 색 인자는 파이썬 int 튜플만 | `tuple(map(int, pixel))` |
| 3 | `global` | 대입하면 필요, 내용만 바꾸면 불필요 | `global Color` |
| 4 | **상태 기계** | `mouse_mode` 0 대기 / 1 확정 / 3 드래그 | `if mouse_mode == 1:` |
| 4 | 콜백-루프 분업 | 웨이터는 메모만, 주방이 요리 | `while True: … waitKey(30)` |
| 4 | 러버밴드 | 복사본(투명 필름)에 미리보기 | `draw(np.copy(image), 회색)` |
| 4 | 도형 수학 | 원=피타고라스, 타원=중점+반폭, 브러시=선분 잇기 | `pt1 = pt2` |
| 4 | 멱등성 | 같은 도형 재그리기는 변화 0 | — |
| 5 | **numpy view** | 같은 땅, 두 주소 | `canvas = image[:, 120:]` |
| 5 | dst 인자 | 결과를 제자리에 써 넣기 | `cv2.resize(tmp, size, canvas)` |
| 5 | `shape[1::-1]` | (h,w,c) → (w,h) | `canvas.shape[1::-1]` |
| 5 | **포화 연산** | 255·0에서 멈춤, 정보 손실 | `cv2.add`, `cv2.subtract` |
| 5 | `[:] =` vs `=` | 내용 수정 vs 이름표 옮기기 | `canvas[:] = (255,255,255)` |

**Part B에서 다시 나오는 것:** ROI 슬라이싱, `shape[1::-1]`, dst 위치 인자(이번엔 함정으로), HSV/히스토그램, 로컬↔전체 좌표 변환. Part A가 Part B의 기초 공사입니다.

   ```python

   ```
6. 브러시로 빠르게 그렸더니 선이 각졌습니다. 원인을 "이벤트"와 "프레임"이라는 단어로 설명하세요.

<br>

**정답**
1. 아이콘이 50이면 마지막 아이콘은 (50, 250, 50, 50) → y+h+2 = **302**. 하지만 메뉴 폭은 이제 50×2 = 100이라 **120은 틀린 값**이 됩니다(하드코딩). `x < 125` 가드와 `canvas`의 `w*2`도 같이 맞춰야 합니다. 하드코딩된 숫자가 왜 위험한지 보여주는 예입니다.
2. hue=100 → H=150 (300°, 마젠타). S=127, V=125 → 최대 125 (B와 R), 최소 125 × (1 − 127/255) ≈ 62 (G) → **약 (125, 62, 125)**
3. DOWN: pt1=(400,300), mode=3 → 프레임: 복사본에 회색 원 미리보기 → MOVE: pt2 갱신 → UP: mode=1 → 프레임: 원본에 확정. 반지름 = √(3² + 4²) = **5**
4. 어두워지지 않습니다. `canvas`는 image의 x 120~799 부분만 가리키는 view이고, `cv2.subtract`의 결과도 그 영역에만 써지기 때문입니다.
5. 첫째는 결과를 **canvas가 가리키는 메모리(=image)에 써 넣으므로** 화면이 바뀝니다. 둘째는 새 배열을 만들어 이름 `canvas`를 거기로 옮기므로 image는 안 바뀝니다(그리고 `global canvas`가 있으면 이후 모든 명령이 image와 끊깁니다).
6. 30ms(한 프레임) 사이에 MOUSEMOVE **이벤트**가 여러 번 와도 루프는 **프레임**마다 마지막 pt2 하나만 보고 직선으로 잇습니다. 그래서 중간 점들이 건너뛰어집니다.

## 6-5. 🛠️ 실습 과제 (난이도순)

### 과제 1. 채우기 도형: `flags` 인자 써 보기 ⭐

Shift를 누른 채 그리면 **속이 꽉 찬 도형**이 되게 만들어 보세요.
- 지금까지 무시했던 `onMouse`의 `flags`를 씁니다. 실측 값: `EVENT_FLAG_SHIFTKEY = 16`, `CTRLKEY = 8`, `ALTKEY = 32`, `LBUTTON = 1`
- flags는 **비트 합**입니다. 왼쪽 버튼 + Shift = 1 + 16 = 17. 확인은 `flags & cv2.EVENT_FLAG_SHIFTKEY`
- OpenCV 도형 함수에 두께 `-1`(= `cv2.FILLED`)을 주면 속이 채워집니다(Step 5-6 실측에서 rectangle −1이 OK였습니다).
- 힌트: 전역변수 `filled = False`를 하나 만들고, DOWN에서 flags를 보고 정한 뒤, `draw()`에서 두께를 고르세요.

### 과제 2. 되돌리기 (Undo, Ctrl+Z) ⭐⭐

- **언제** 저장할까요? 도형이 원본에 그려지기 **직전**, 즉 그림 영역에서 DOWN이 올 때 `canvas.copy()`를 리스트에 `append`합니다.
- 메인 루프에서 `waitKey` 반환값이 `26`(Ctrl+Z)이면 `pop()`한 것을 `canvas[:] = …`로 되돌립니다. 여기서 `canvas = …`로 쓰면 왜 안 되는지는 Step 5에서 배웠습니다.
- 복원한 직후 `mouse_mode = 0`도 필요합니다. 이유는 Step 4-7(멱등 재그리기)을 떠올려 보세요.
- 메모리: 한 번 저장할 때마다 680×500×3 ≈ 1MB입니다. 최대 20개 정도로 제한하는 이유를 생각해 보세요.

### 과제 3. 스포이트(현재 픽셀 색 보기) ⭐⭐

- 마우스가 그림 영역 위에서 움직일 때(MOUSEMOVE) 그 픽셀의 BGR과 HSV를 창 제목이나 콘솔에 표시해 보세요.
- `cv2.cvtColor`에 1×1 이미지 `image[y:y+1, x:x+1]`을 넣으면 픽셀 하나의 HSV를 얻을 수 있습니다. Step 2의 3줄 규칙을 거꾸로 검산해 볼 수 있습니다.

### 과제 4. 🚗 같은 구조로 "4점 클릭 탑뷰 툴" 만들기 ⭐⭐⭐ (AVM 연결)

PaintCV의 뼈대(**hit-test + 상태 기계 + 콜백-루프 분업 + 러버밴드 미리보기**)는 실무 캘리브레이션 도구의 뼈대와 같습니다.

- 도로나 주차장 바닥 사진을 OPEN
- 바닥의 사각형(주차 칸 등) 꼭짓점 4개를 클릭 → 점마다 번호 원을 표시. 상태 기계로 0~3번 점을 순서대로 받기
- 이미 찍은 점을 다시 누르고 끌면 위치 수정. **hit-test를 아이콘 사각형이 아니라 "점 주변 반경 8px 원"으로** 바꾸면 됩니다(거리 계산은 Step 4-6 피타고라스).
- 드래그 중에는 4점을 잇는 다각형을 회색 러버밴드로 미리보기
- 4점이 다 찍히면 `cv2.getPerspectiveTransform` + `cv2.warpPerspective`로 위에서 내려다본 직사각형 영상 만들기 ([chap08/11.perspective_event.py](../../chap08/11.perspective_event.py), reference의 04_가상광고판과 같은 수학)

AVM 탑뷰 캘리브레이션에서 바닥 패턴의 기준점을 찍고 보정하는 작업을 아주 작게 축소한 버전입니다. 원하시면 Part B를 마친 뒤 이 과제를 같이 만들어 봐도 좋습니다.
